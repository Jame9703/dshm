## 1. 需求 1：三端语音朗读，Speech Kit + 小艺音色

### 1.1 现状核实（重要）

项目**已经在用 Speech Kit**，`platform/src/main/ets/system/ReadAloud.ets` 是三端共用的平台层单例：

- 首选 `TextReader`（`@kit.SpeechKit`）——自带播放面板 / Minibar / 通知 / AVSession / 后台播放；
- 失败降级 `textToSpeech`（`@kit.CoreSpeechKit`）——无面板，仅播报；
- 原先兜底音色写死 `person: 13`。

所以"替换"不是从无到有，而是在既有 Speech Kit 链路上**补上音色选择能力**。

### 1.2 SDK 依据（本地知识库 + SDK 声明）

| 事实 | 来源 |
|---|---|
| `VoiceInfo` 字段：`language` / `person` / `style` / `gender` / `description` / `status` | `sdk/.../@hms.ai.textToSpeech.d.ts:450` |
| `status`: `INSTALLED` = 已下载，`GA` = 可下载但未下载 | `knowledge: dev-faq/faqs-core-speech-7` |
| 中文 `person`: **13 = 凌晓珊女声（推荐）**，0 也可用；21 = 凌飞哲男声（需下载） | 同上 d.ts 的 `VoiceInfo.person` 注释 |
| `listVoices(VoiceQuery)` 查询已支持的语言与音色 | 同上 d.ts:689；`VoiceQuery` = `requestId` + `online:1` |
| **Core Speech Kit 没有名为"小艺"的音色枚举** | 全部本地文档与 SDK 声明均未出现"小艺"作为 `person` 值 |

### 1.3 改动

`platform/.../ReadAloud.ets`：

1. 新增 `resolveXiaoyiPerson(): Promise<number>`，**一次启动只查一次**并缓存：
   - `listVoices` 结果里若有 `description` 含「小艺」/`Xiaoyi` 且 `status === 'INSTALLED'` 的音色 → 用它的 `person`；
   - 否则回落到 **13**（SDK 推荐的中文女声，等价于系统默认朗读音色）；
   - 查询/解析任何异常都回落到 13，**不阻断朗读**。
2. `startFallback` 改为先解析音色再 `createEngine`，`person` 从写死 13 换成动态解析结果。
3. 三端自动生效：`platform` 是共享 HAR，`entry` / `phone` 两个壳的 `bridges.readAloud` 都指向这里的 `ReadAloud` 单例，**无需改壳**。

### 1.4 明确不做

- 不调用 `downloadVoice` 下载男声（21）：首次朗读会多一次网络与存储成本，与"朗读是系统能力"的定位冲突。
- 不把 `TextReader` 换成 TTS 作为首选：`TextReader` 有播放面板与后台播控，体验优于无面板 TTS；音色选择只在兜底链路生效。
- 不修改三端权限面（仍为 entry 19 / phone 9）。

### 2.1 SDK 依据

### 2.2 实现链路

```
会话区「加号」(input[type=file])
  → phone WebApp .onShowFileSelector 拦截（return true）
  → 动作面板：扫描文档 / 提取表格 / 从文件中选择 / 取消
  → 选择扫描：Stack 内挂载 DocumentScanner
       DOC  → supportType [DOC],   saveOptions [JPG, PDF]
       SHEET→ supportType [SHEET], saveOptions [EXCEL]
  → onResult(code=200)：临时 URI → persistScanResults() 复制到 <filesDir>/dsh/scans/
  → event.result.handleFileList(沙箱 URI[]) → 网页按 input[type=file] 正常接收为附件
```

### 2.3 文件分工

| 文件 | 改动 |
|---|---|
| `platform/src/main/ets/system/DocumentScan.ets`（新增） | `ScanSaveKind`、`scanExtension()`、`persistScanResults()`、`scanUris()`；把临时 URI 复制进沙箱，单条失败不影响其余，失败留痕但不抛 |

### 2.4 设计取舍（必须知道）

1. **只改 phone 壳**，符合三端隔离；`entry` 的文件选择行为逐字不变。
2. **拦截的是所有 `input[type=file]`**，不是精确识别"加号"按钮——原生层拿不到网页按钮身份。为避免能力退化，动作面板保留「从文件中选择」（走 `picker.DocumentViewPicker`），所以用户仍能选普通文件，只是多一次选择。若未来能在 Web 垫片里精确识别加号，可改为只在该路径弹出扫描面板。

4. **不申请任何新权限**：相机/相册由系统扫描组件自己拉起；本模块只做沙箱内复制。权限面 entry 19 / phone 9 未变。

## 5. 真机反馈修正：扫描入口必须注入到网页「加号」菜单（2026-11-25 14:12）

### 5.1 现象与根因

首版 Beta 用户实测：**手机端点会话区加号，看不到「扫描文档 / 提取表格」选项**。

用户补充的现象是关键证据：点加号**先弹网页自己的菜单**，再点里面的项才触发系统文件选择器。
这解释了首版为何无效：

- 首版只在 `onShowFileSelector`（`input[type=file]`）拦截，而它在**第二层**才触发；
- 加号**第一层**是网页自己的 React UI，原生层拿不到它的 DOM 结构；
- 因此用户第一眼看不到任何扫描选项 —— 不是能力判定失败，而是拦截层级不对。

### 5.2 修正方案：Web 垫片在加号旁注入按钮

`phone/WebApp.ets` 新增 `SCAN_SHIM_JS`，作为一条 `ScriptItem` 加入 `pickerShimScripts`
（注意：`javaScriptOnDocumentStart` 的参数是 `Array<ScriptItem>`，不能直接拼字符串，
首版因此编译报 `string is not assignable to ScriptItem[]`，已修正）。

垫片逻辑：

1. 用 `MutationObserver` + 定时重试找加号按钮（aria-label / title 含「添加文件」/ `input.commands` / `attach` / `附件`）；
2. 在它旁边插两个按钮：`扫描文档`、`提取表格`；
3. 点击时**先**调同步桥 `startScan(mode)` 打标，**再**在用户手势内 `input[type=file].click()`
   —— 程序化 click 必须在用户激活上下文里，否则 ArkWeb 会拦；
4. 网页若没有现成 file input，垫片临时建一个隐藏 input 再 click（兜底）。

原生侧：

- `methodList` 与 `bridges` 新增同步方法 `startScan(mode: number): string`，只设 `pendingScanMode`；
- `onShowFileSelector` 看到 `pendingScanMode >= 0` 时**直接**显示对应 `DocumentScanner`，跳过中间动作面板；
- 普通 `input[type=file]`（不经过垫片）仍弹原动作面板，「从文件中选择」能力保留；
- `canIUse('SystemCapability.AI.Component.DocScan') === false` 时清标记并 `return false`，走系统选择器。

### 5.8 五次反馈：点击仍无反应 —— 改 window capture + 可见反馈（2026-11-25 15:10）

图标已正常，但点击仍无反应。判断：菜单项自己的 listener（无论冒泡还是目标 capture）都晚于
React root 的事件委托，菜单被先关掉。本次改为在 **window capture** 上统一分发：

- `window.addEventListener('click', handler, true)` 在 IIFE 顶层注册，是 DOM 事件传播最外层，
  早于 document 与 React root；
- handler 从 `e.target` 沿 `parentElement` 回溯，命中 `#dshm-scan-doc` / `#dshm-scan-sheet` 就分发；
- **不** `stopPropagation` —— 让 React 照常关闭菜单，避免破坏网页交互；
- 菜单项自身不再注册 click listener（防重复触发）；
- 新增**可见诊断**：点击后把子项文字改成「启动中…」，用户可直接看到 handler 是否执行，
  不必先抓日志。

诊断口径：
- 看到「启动中…」但没进扫描 ⇒ handler 已跑，问题在 `input.click()` 未触发 `onShowFileSelector`，继续查原生触发方式；
- 连「启动中…」都没出现 ⇒ 事件未命中菜单项，需按真机 DOM 调整 id 匹配。

### 5.9 六次反馈：事件重入根因 + 三级诊断（2026-11-25 15:31）

用户确认：菜单子项文字变成「启动中…」，但扫描起不来；并指出**最早那版**（按钮在输入框旁）
功能是能正常生成 XLSX 附件的。据此对照两版差异：
