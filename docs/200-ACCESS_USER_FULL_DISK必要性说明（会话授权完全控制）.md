# 200 · ACCESS_USER_FULL_DISK 权限必要性说明（会话授权完全控制）

> 日期：2026-11-21
> 背景：1.1.8 上架审核二次驳回 ——「应用申请了 `ohos.permission.ACCESS_USER_FULL_DISK`，但应用内未见必须使用此权限的功能场景」。
> 用途：AGC 申诉/说明文案底稿 + 截图口径；也是 `entry/src/main/module.json5` 中 `perm_full_disk_reason` 的依据。
> 关联：`docs/archive/223`（首次申请回复，历史档）；`JD-009`（权限 reason 合规化）。

---

## 1. 一句话

DSHM 是本地 AI 编程工作台。用户选择一个本地文件夹作为「**会话工作区**」后，**整段会话**内的文件读写、搜索、Python 与构建工具都要在该目录**及其全部子目录**里工作，并且**会话恢复 / 应用重启后仍要继续可用**；系统的文件选择器只提供「单次 / 单文件」授权，覆盖不了这些需求 ⇒ 全盘文件权限是唯一可行实现，且**仅用于用户主动选择的工作区**。

---

## 2. 权限用途（最小化口径）

- **触发条件**：仅在用户通过系统文件选择器**主动选定**一个目录作为工作区之后。
- **访问范围**：该工作区目录及其子目录；不访问其他目录。
- **数据流向**：只在本地会话内使用，不上传、不外发。
- **时机**：`usedScene.when = inuse`（仅应用在前台/使用时），不是 `always`。

---

## 3. 为什么系统单次授权不够（核心论证）

HarmonyOS 文件选择器的授权模型：

1. 以「单次选择 / 单文件或单目录句柄」为粒度；
2. 进程重启后需重新 `persist` + `activate` 才能恢复，且仍是**单目录**粒度；
3. 不承诺「目录树任意深度 + 符号链接 + 多次工具调用」的持续访问。

DSHM 的「**会话授权完全控制**」需求（评审工程师确认的关键场景）：

| # | 需求 | 说明 |
|---|---|---|
| 1 | **整段会话持续** | 一次会话可能有几十次工具调用（读文件、改代码、跑测试、生成产物），不能每次操作都弹一次选择器 |
| 2 | **目录树** | 项目包含 `src/`、`build/`、依赖目录等任意深度子目录，搜索与读写需要遍历 |
| 3 | **写操作** | 新建、删除、重命名、覆盖文件（AI 修改代码/生成产物） |
| 4 | **符号链接** | 项目内 symlink 需要跟随（monorepo / 依赖链接常见） |
| 5 | **重启恢复** | 长任务中断后恢复会话，仍需继续访问同一个工作区 |

**上述任意一条都超出 picker 的能力**；五条叠加即「整段会话对该目录的完全控制」，这是全盘权限的直接、必要用途。

---

## 4. 代码事实（边界可核）

| 点 | 位置 | 作用 |
|---|---|---|
| 工作区来源 | `entry/.../view/FolderPicker.ets`、`platform` 的目录选择器 | 只接受用户主动选择的目录 |
| 路径校验 | `platform` 的 `isPathWithin` | 所有文件工具入口限制在用户所选工作区内 |
| 授权恢复 | `restoreFolderGrants`（`EntryAbility.onCreate`） | 启动时对已登记目录 `activatePermission`，对应 §3 第 5 条 |
| 工具链 | 随包 Python / 终端 / Git / ripgrep | 在工作区内执行，不越界 |

> 结论：权限的真实使用面 = 用户所选工作区目录树；不是「全盘任意读写」。

---

## 5. AGC 截图建议（申诉时上传）

1. **选择工作区**：系统文件选择器界面 + 选中后的工作区路径（证明由用户主动授权）。
2. **会话内读取**：AI 工具调用轨迹里显示读取的绝对路径位于该工作区内（证明会话内持续访问）。
3. **会话内写入**：AI 修改/新建文件后，系统文件管理器中该文件确实变化（证明写操作）。
4. **重启恢复**：关闭并重启应用 → 恢复会话 → 仍能读写同一工作区（证明 §3 第 5 条，也是「完全控制」的最强证据）。
5. （可选）**子目录 / 符号链接**：访问工作区深层子目录或 symlink。

## 6. 与 `reason` 的对应

`entry/src/main/resources/{base,en_US}/element/string.json` 的 `perm_full_disk_reason` 已按本文 §2/§3 改写为「会话工作区 + 全子目录 + 会话恢复/重启 + 单次授权无法覆盖 + 仅限所选工作区」。
`module.json5` 的注释同步记录了 2026-11-21 二次驳回的补充口径。
