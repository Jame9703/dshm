# HarmonyOS 系统语音识别与会议模式 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将 DSHM 普通语音输入从移植的 SenseVoice 模型切换到 HarmonyOS Core Speech Kit，并新增一个原生会议模式，完成录音、实时中文转写、WAV/Markdown 保存、会话内容交接。

**Architecture:** ArkTS 进程统一持有 Core Speech Kit 引擎；普通听写由 Host 写文件队列请求 ArkTS 识别，会议模式由原生页面直接采集 `AudioCapturer` PCM 并送入长语音会话。音频流式写盘，不在内存保存整场会议；转写结果采用“已定稿 + 当前分句”状态机合并。

**Tech Stack:** ArkTS、ArkUI、Core Speech Kit、Audio Kit、Background Tasks Kit、Core File Kit、Ability Kit、Node Host 文件队列、ohosTest/Hypium、现有 DSHM 构建与真机门禁。

**Spec:** `docs/HarmonyOS生态能力接入/2026-10-18-系统语音识别与会议模式施工方案.md`

## 1. 现状与决策

### 1.1 当前语音链路

现有普通语音输入链路为：

```text
Web 麦克风按钮
  → WebApp 原生 AudioCapturer
  → Host speech provider
  → $DSH_HOME/speech-to-text/hms-bridge/<id>.req
  → ArkTS HmsSpeechBridge
  → SenseVoiceRecognizer（当前优先）
  → <id>.done / <id>.fail
  → Web 输入框
```

当前问题：

1. `HmsSpeechBridge` 初始化后优先使用 SenseVoice。
2. Host provider 会下载并准备约 228 MB 的模型。
3. SenseVoice 引入模型下载、模型目录、预热和 sherpa-onnx 运行依赖。
4. 项目没有原生会议模式。
5. Core Speech Kit 已存在回退实现，但不是主路径。

### 1.2 目标链路

普通听写：

```text
Web 麦克风按钮
  → WebApp 原生 AudioCapturer
  → Host speech provider
  → ArkTS HmsSpeechBridge
  → SystemSpeechRecognizer(short/long)
  → Web 输入框
```

会议模式：

```text
会议模式入口
  → 原生 MeetingPanel
  → 麦克风权限检查
  → AudioCapturer(16k/mono/PCM16)
  ├─ WAV 流式写盘
  └─ SystemSpeechRecognizer(long)
       → onResult 合并
       → 实时转写 UI
  → 结束
  → Markdown + WAV
  → 可选择插入当前 DSH 会话
```

### 1.3 明确不做

- 不直接拉起小艺慧记。
- 不读取小艺慧记或备忘录私有数据。
- 不实现常驻唤醒词监听。
- 不新增任何权限。
- 不把整场 PCM 保存在 ArkTS 数组或字符串中。
- 不自动向 DSH 模型发送会议全文。

## 3. 核心接口

### 3.1 共享系统识别器

```ts
export type SystemSpeechMode = 'short' | 'long';

export interface SystemSpeechEvents {
  onTranscript(live: string, text: string): void;
  onState(state: string, detail: string): void;
}

export class SystemSpeechRecognizer {
  constructor(mode: SystemSpeechMode, events: SystemSpeechEvents);
  start(): Promise<void>;
  writePcm(chunk: Uint8Array): void;
  finish(timeoutMs?: number): Promise<string>;
  cancel(): void;
  currentText(): string;
}
```

约束：

- 模块内维护一个全局 lease，同一进程只允许一个活动引擎。
- `start()` 顺序：创建引擎 → `setListener()` → `startListening()` → 等 `onStart`。
- `writePcm()` 只接受 640 或 1280 字节块。
- `finish()` 调用 `engine.finish()`，等待 `onComplete`，超时后释放引擎并返回已收到的定稿文本。
- `cancel()` 调用 `engine.cancel()`，随后必须 `shutdown()`。
- 短模式保持普通听写行为；会议模式固定使用 `recognizerMode: 'long'`。

## 4. 数据与状态规则

### 4.1 转写合并

Core Speech Kit 的中间结果可能包含此前已经出现的文本。合并规则：

```ts
interface MeetingTranscriptState {
  committed: string;
  live: string;
  text: string;
}

function appendSegment(committed: string, incoming: string): string {
  if (incoming.length === 0) return committed;
  if (committed.length === 0) return incoming;
  if (committed === incoming || committed.endsWith(incoming)) return committed;
  if (incoming.startsWith(committed)) return incoming;
  return committed + '\n' + incoming;
}
```

- 非 final：只保留当前分句累计文本中超出 `committed` 的部分。
- final：把当前分句追加到 `committed`，清空 `live`。
- 任何结果都不得直接用 `transcript += result.result`。

### 4.2 会议状态机

```text
idle
  → starting
  → recording
  → stopping
  → stopped

starting / recording / stopping
  → error

starting / recording
  → stopped（用户取消）
```

启动顺序：

1. 检查麦克风权限。
2. 创建引擎并等待 `onStart`。
3. 打开 WAV 文件并写 44 字节占位头。
4. 创建 AudioCapturer。
5. 注册 `readData`。
6. `capturer.start()`。
7. 状态切到 `recording`。

停止顺序：

1. 状态切到 `stopping`。
2. 注销 `readData`。
3. 停止并释放 AudioCapturer。
4. 把不足 640 字节的尾音补零后送入引擎。
5. `engine.finish()`。
6. 回写 WAV 的 RIFF/data 长度。
7. 生成 Markdown。
8. 状态切到 `stopped`。

### 4.3 文件输出

目录：

```text
Download/<bundleName>/meetings/
```

文件：

```text
meeting-YYYYMMDD-HHmmss.wav
meeting-YYYYMMDD-HHmmss.md
```

Markdown 固定结构：

```md
# 会议名称

- 开始：YYYY-MM-DD HH:mm:ss
- 结束：YYYY-MM-DD HH:mm:ss
- 时长：HH:mm:ss
- 录音：绝对路径

## 转写全文

识别文本
```

容量基线：16 kHz、16 bit、单声道 WAV 约 `1.92 MB/分钟`、`115.2 MB/小时`。

### Task 5: 会议采集与流式落盘

**Files:**
- Create: `entry/src/main/ets/speech/MeetingSession.ets`

**Interfaces:**
- Consumes:
  - `SystemSpeechRecognizer('long', events)`
  - `audio.createAudioCapturer()`
  - `fileIo.openSync()`、`writeSync()`、`closeSync()`
- Produces:
  - `MeetingSession`
  - `MeetingSnapshot`

实现规则：

```ts
const options: audio.AudioCapturerOptions = {
  streamInfo: {
    samplingRate: audio.AudioSamplingRate.SAMPLE_RATE_16000,
    channels: audio.AudioChannel.CHANNEL_1,
    sampleFormat: audio.AudioSampleFormat.SAMPLE_FORMAT_S16LE,
    encodingType: audio.AudioEncodingType.ENCODING_TYPE_RAW
  },
  capturerInfo: {
    source: audio.SourceType.SOURCE_TYPE_MIC,
    capturerFlags: 0
  }
};
```

- 开始录音前写入 44 字节 WAV 头。
- `readData` 中的 ArrayBuffer 必须立即复制。
- 复制后的 PCM 直接写文件，不加入长期内存数组。
- 维护最多不足 640 字节的 `pending`。
- 每凑满 640 字节送 `writePcm()`。
- UI 更新频率不高于 5 次/秒。
- 停止时把尾音补零到 640 字节后送出。
- 停止后回写 RIFF chunkSize 和 data chunkSize。

## 8. 回滚方案

触发回滚的条件：

- PC long 模式无法输出有效文本。
- 普通听写从可用变成稳定失败。
- 后台录音导致 Host 数据连接中断。
- 会议模式出现可复现 OOM。
- 权限面或 APK 面门禁失败。

回滚顺序：

1. 关闭会议入口，不删除已经生成的用户文件。
2. 普通听写恢复为旧核心包和旧 HmsSpeechBridge。
3. Core version 回退到回滚前版本。
4. 保留新增会议代码但禁用入口，或整体回退本次提交。
5. 真机使用同签名覆盖安装。
6. 不删除 Download 下会议文件，不卸载 App，不清用户数据。
