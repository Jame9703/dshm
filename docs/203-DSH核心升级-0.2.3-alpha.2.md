# 203 — DSH 核心升级到 0.2.3-alpha.2（2026-11-25）

## 1. 版本确认

- npm `registry.npmmirror.com` 的 `@deepseek-ai/dsh`：`latest = 0.2.2-rc.5`（本地已是），
  唯一更新的版本是预发线 `0.2.3-alpha.2`（2026-11-22 发布）。
- 本地配方 `hostcore/core-recipe.json`：`0.2.2-rc.5+dshm.1` → `0.2.3-alpha.2+dshm.1`。

## 2. 升级过程中修正的四类问题

升级不是改一个版本号即可。`pack-core.mjs` 有 165 处 `die()` 锚点校验，逐条报出并修正：

| # | 失败 | 判定 | 处理 |
|---|---|---|---|
| 1 | `终端 bundle 行补丁：配方版本与新旧终端布局不符` | 版本白名单未覆盖 0.2.3，但布局与 rc.5 **逐字一致** | 6 处版本数组加入 `0.2.3-alpha.2`，走已核实的"新布局"分支 |
| 2 | `fs-local 权限文案：rc.2 原生 errno 归一化契约不完整` | 上游精简了 import（去掉 `FsTargetKey`/`FsVersion`），其余 7 个 errno 锚点未变 | 接受两种已核实 import 形态，未知形态仍 die |
| 3 | `subagent 的 parseSubagentChatAddress() 实现已变化` | 0.2.3 **真逻辑变化**：新增 `decodeURIComponent` + `url.search === ''` 早退 | 保留上游 decode 逻辑，仅把 query 来源换成 armor 提取值（ArkWeb 下 query 被并进 path 会误触发早退） |
| 4 | `自带插件的 dsh peer 精确钉法与树里的运行版本不一致` | 10 处插件 peer 钉在 rc.5 | 统一改为 `0.2.3-alpha.2`（脚本给出精确清单） |

**纪律**：全程没有"静默跳过"任何锚点；每处都在代码里注明判定依据，未知形态一律 die。

## 6. 真机测试重点

0.2.3 是**预发版**，相对 rc.5 有 88 个包版本变化、cordis 4.1→4.2.0-alpha.1，且新增
`dsh-session-persistence-sqlite`（依赖 koffi / node-addon-system）等包。建议重点验证：

1. 宿主能否起来（BOOT_00 → BOOT_70 全程）；
2. 插件装载：fs 服务、workspace claim、PTC runtime（这三处是补丁重点）；
3. 会话：新建、发消息、附件（含上一轮的扫描附件链路）；
4. 终端：guest VM / 原生 PTY 的启动与键盘 resize；
5. 市场 / 插件安装（profile-pnpm 进程内通道）。

如果关键路径失败，回退方式：配方改回 `0.2.2-rc.5+dshm.1`、10 处插件 peer 改回 rc.5、
`pack-core.mjs` 的版本白名单与两个锚点适配保留（对 rc.5 无影响），重跑 `pack-core --place-in-app`。
