## 3. 补丁适配①：`allowOriginList()` 随上游重构搬迁

**上游改写**（`@deepseek-ai/dsh-client-connection/lib/index.js`）：

```js
// alpha.1：内联在 isTrustedApiRequest 里的 try/catch
	const origin = header$1(request.headers, "origin");
	if (origin === void 0) return true;
	try {
		return new URL(origin).host === hostUrl.host;
	} catch {
		return false;
	}
```

```js
// alpha.2：抽成独立函数（isTrustedApiRequest 里改成 `return isSameAuthorityOrigin(origin, host);`）
function isSameAuthorityOrigin(origin, host) {
	let originUrl;
	try {
		originUrl = new URL(origin);
	} catch {
		return false;
	}
	const scheme = originUrl.protocol === "https:" ? "https:" : originUrl.protocol === "http:" ? "http:" : void 0;
	if (scheme === void 0) return false;
	const hostUrl = parseAuthority(host, scheme);
	return hostUrl !== void 0 && originUrl.host === hostUrl.host;
}
```

**补丁改法**：`pack-core.mjs` 的 `allowOriginList()` 现在**两种形态都认**（新形态优先，旧形态保留
以支持老树增量重打包），找不到任一才 `die`。幂等标记仍是 `DSHM_ORIGIN_LIST`（同时认旧标记 `HDSH_ORIGIN_LIST`）。

**语义要点（这条差点写错，见 §4）**：注入后的函数**不能**照抄上游的 http(s) 白名单 ——
鸿蒙客户端 `libwebsockets` 附上来的那条候选恰恰是 `ws://`，它正是本次要放行的值。

```js
	// 注入后的循环体（节选）
	if (originUrl.host === "") continue;   // 非层级 scheme（file:/data:）host 为空 ⇒ 天然不匹配
	const scheme = originUrl.protocol === "https:" || originUrl.protocol === "wss:" ? "https:" : "http:";
	const hostUrl = parseAuthority(host, scheme);
	if (hostUrl !== void 0 && originUrl.host === hostUrl.host) return true;
```

## 4. 自查抓到的一条真回归：`ws://` 被误拒

第一版注入块照抄了上游的 `scheme === void 0 ⇒ 不认`：

```
duplicated   origin = "http://127.0.0.1, ws://127.0.0.1:3137"   期望 101   实得 403   ← MISMATCH
```

`tools/check-origin-fence.mjs`（钉的是**行为**，不是树内标记）当场判红：

```
clean       101     101   ok
absent      101     101   ok
duplicated  101     403   MISMATCH
foreign     403     403   ok
no-cookie   401     401   ok
RESULT: FAIL
```

- 第二候选 `ws://127.0.0.1:3137` 的 `.host` 与监听 authority **本来就相等**；
  旧补丁（alpha.1 形态）用的是 `new URL(candidate).host === hostUrl.host`，**没有 scheme 白名单**，
  所以放行 —— 我加白名单等于**收窄了原有行为**。
- 修法：只跳过 `originUrl.host === ""`（非层级 scheme），把 `ws/wss` 归 http 族参与比较。
  安全边界不变：`foreign`（`http://evil.example`）仍 403、`no-cookie` 仍 401。
- 修后：**5/5 PASS**。

> 教训与 `docs/40 §5` 同源：**"照抄上游更严格"不等于"更对"** —— 我们的补丁是**有意偏离**上游的实现，
> 偏离的**理由**必须带上，否则下一次改写就会把理由丢掉。这里抓到它的是**行为门禁**，不是代码审查。

## 5. 补丁适配②：`patchFsSearchFallback()` 的 spawn 锚点

上游 `dsh-tool-fs-search/lib/index.js` 的 `runRipgrep` 里，**只有 workdir 一行变了**：

```diff
-	const workdir = exec.agent?.session.header.cwd ?? process.cwd();
+	const workdir = exec.agent === void 0 ? process.cwd() : await ctx.workingDirectory.ensure(exec.agent, exec.signal);
 	let handle;
 	try {
 		handle = ctx.subprocess.spawn({
 			argv: [
 				await resolveRgPath(),
 				"--no-config",
 				...argv
 			],
```

**补丁改法**：把锚点**收窄到 `let handle;` 起**（`oldSpawn`/`newSpawn` 都不再包含 workdir 行）。

- 为什么不用"改成 alpha.2 的那一行"：注入块里 `workdir` 只是**原样透传**，若把它写进替换文本，
  就等于把上游的行为改动**钉回旧语义**（`exec.agent?.session.header.cwd`），那是比"补丁没升级"更坏的静默事故。
- 收窄后该锚点在树内**唯一**（实测 1 处命中），且 `tailAnchor` / `oldOut` / `oldEmpty` 三段锚点
  **逐条复验仍在**（未改动）。
