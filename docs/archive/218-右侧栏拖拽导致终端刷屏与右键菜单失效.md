# 218 · 右侧栏拖拽导致终端刷屏与右键菜单失效

> 日期：2026-10-21 ｜ 工程：`com.dshm.dshclient` ｜ 设备：鸿蒙 PC `MNTXM-24B`

## 1. 现象

打开右侧栏终端后，左右拖动右侧栏宽度：

1. 终端会连续打印当前路径/提示符；
2. 拖拽后右键没有菜单。

## 2. 根因

### 2.1 提示符刷屏

右侧栏宽度变化会让终端容器逐帧触发 `ResizeObserver`。上游
`fitScreen()` 每次都同时执行：

```text
xterm.resize(cols, rows)
model.resize(cols, rows)
```

第一条只改本地 xterm，第二条会把新尺寸发给 PTY。交互式 shell 每次收到
`SIGWINCH` 都会重画提示符，因此拖动一帧就打印一次当前路径。

### 2.2 右键无菜单

ArkWeb 的 `WebAttribute.enableDefaultContextMenu` 默认值是 `false`。
事件日志里 `contextmenu`、`OnBeforeContextMenu` 都已经到达 ArkWeb，但宿主
没有启用默认菜单，所以用户侧表现为“右键没反应”。

## 3. 修复

- `tools/pack-core.mjs` 新增 `patchTerminalResizeCoalescing()`：
  xterm 本地视觉尺寸仍逐帧跟随；远端 PTY resize 防抖 120ms，只发送停手后的
  最后一组 cols/rows。终端卸载时清理挂起定时器。
- `entry/src/main/ets/pages/WebApp.ets` 在 `Web()` 上启用
  `.enableDefaultContextMenu(true)`。
- `check-core-openharmony-patches` 增加 `DSHM_TERMINAL_RESIZE_COALESCE`
  注入标记与上游原文消失的守卫。
- `check-feature-wiring` 增加“Web 默认右键菜单”的宿主接线检查。

## 4. 验证

- debug HAP 重新构建：`BUILD SUCCESSFUL`
- 覆盖安装成功，未卸载应用，el2 用户数据未动
- 使用 `uitest uiInput drag` 连续调整右侧栏宽度；终端不再按帧刷屏，
  只在拖拽停手后的最终尺寸变化时发生一次正常重排
- 修复前的 ArkWeb 日志为 `HandleContextMenu` +
  `OnBeforeContextMenu`，但默认菜单未启用；修复后宿主已显式打开该能力
