- 日期：2026-11-06
- 状态：**方案，待用户确认后执行**
- 目标口径（用户原话整理）：平板面积够 ⇒ **左栏默认一直展开**；无论打开右栏、切会话、设不设工作目录，都不许自动收起；只有用户点左上角那颗左侧栏按钮才收起；收起后按钮留在左上角（手机那套 ⊞ 方案），再点可呼出。

## 1. 为什么现在"进去只有会话区、左上角也没按钮"

两条，都是官方 0.2.2 的窄屏（`narrow = viewport < 1024`）逻辑，**不是 CSS 能改的**：

1. **默认收起**：`sidebarCollapsed = narrow ? !narrowExpanded : sidebar === 0`，`narrowExpanded` 初值 false ⇒ 平板（dp 视口 800~950）一进来就是收起态。
2. **左上角没有按钮**：官方只在 `leadingMounted = drawer || (darwin && sidebarCollapsed)` 时才渲染那颗 opener。平板既不是 drawer（<768）也不是 darwin ⇒ **DOM 里根本没有这颗按钮**，我们隐藏/显示 CSS 都无从谈起。

另外，官方还有三处会把 `narrowExpanded` 强制打回 false —— 这就是"打开右栏左栏就没了"的来源：

```js
selectPanel      : viewportWidth < 768            → narrowExpanded = false
setViewportWidth : 跨 768 / 1024 边界              → narrowExpanded = false
setRightbar      : 右栏首次显示 && viewport < 1024 → narrowExpanded = false
```

## 2. 结论：平板不能靠"点官方按钮"实现，必须自己接管左栏开合

官方在窄屏下没有常驻概念，也没有常驻按钮。所以平板档要**自己管**（手机档 1.1.7 就是这么做的，只是手机做成抽屉）：

| 能力 | 实现 |
| --- | --- |
| 默认展开 | 我们的状态属性初值 `expanded`（不读官方 `narrowExpanded`） |
| 一直不收回 | 我们的 CSS 直接给三列几何；**不监听、不跟随**官方那三处重置 |
| 只有用户能收起 | 只由左上角那颗按钮翻转我们的状态 |
| 收起后按钮还在 | 按钮常驻显示（不再只是"收起态才显示"） |
| 打开右栏不收左栏 | 第一列宽度固定 280px，与右栏互不影响 |

### 2.1 CSS（仅平板、仅 ≥768）

```css
@media (min-width:768px){
  html.dshm-tablet[data-dshm-sidebar="expanded"] .dshm-frame{
    grid-template-columns:280px minmax(0,1fr) auto !important }
  html.dshm-tablet[data-dshm-sidebar="expanded"] .dshm-sbcol{
    position:relative !important; transform:none !important;
    visibility:visible !important; width:280px !important }
  /* 收起态：把第一列压 0，第二列吃满（沿用手机 §A 的做法） */
  html.dshm-tablet[data-dshm-sidebar="collapsed"] .dshm-frame{
    grid-template-columns:0 minmax(0,1fr) auto !important }
}
```

- 第三列写 `auto`：右栏宽度仍由官方算，不改它的行为。
- `@media (min-width:768px)` 限定：万一平板被压到 <768（自由窗口），抽屉语义仍归官方，不与 `drawerMask(z:70)` 打架。

### 2.2 按钮（左上角常驻）

- 复用现有的 `ensureFab()`（手机那颗 ⊞ 的同一套图标/样式/尺寸），平板上**常驻显示**（展开/收起都在），不复用官方 opener（它不存在）。
- 点击行为：
  - 当前 `expanded` → 置 `manualTabletCollapsed = true` → 写 `collapsed`（用户主动收起，此后自愈不再抢）。
  - 当前 `collapsed` → 置 `manualTabletCollapsed = false` → 写 `expanded`。
- 与官方状态的衔接：同时尝试 `clickToggle()`（能找到官方 toggle 就同步翻一下，找不到就算了），保证"官方以为的状态"不至于长期背离。

### 2.3 默认与例外

- 首帧：`data-dshm-sidebar` 初值 `expanded`，**不需要等 20 秒静默期**，也不需要点任何官方按钮 ⇒ "进去就是常驻"。
- 启动静默期仍然保留给"点官方按钮"那条路（防止打断 WS 握手），但不影响我们自己的状态属性。
- 平板一旦被用户收起：按钮常驻、点一下恢复；状态在同一会话内保持，切会话/开右栏都不改它。

## 4. 验收

| 场景 | 期望 |
| --- | --- |
| 平板首次进入（未设工作目录） | 左栏**已展开**、内容正常；左上角有按钮 |
| 打开右栏 | 左栏**不收**；右栏正常出现 |

## 5. 风险与说明

- 这套做法等于**平板不再跟随官方的 `narrow` 判定**，官方以后若改窄屏规则，我们不受影响（但也吃不到它的改进）——这是用户明确要的"平板就该常驻"的必然代价。
- 会不会与官方 `drawerMask` 冲突？不会：遮罩只在 `data-sidebar-drawer`（<768）出现，我们的平板 CSS 限定 ≥768。
