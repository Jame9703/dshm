## 1. 先说一处与参考文档的**事实差异**（很重要）

用户给的方案里写 `FoldDisplayMode` 是 `INNER / OUTER / NORMAL`。**本机 SDK 不是这套**：

```text
@ohos.display.d.ts   enum FoldDisplayMode {
  FOLD_DISPLAY_MODE_UNKNOWN = 0,
  FOLD_DISPLAY_MODE_FULL    = 1,
  FOLD_DISPLAY_MODE_MAIN    = 2,
  FOLD_DISPLAY_MODE_SUB     = 3,
}
```

更关键的是 SDK 自己的注释写明：**内外屏各对应哪个值随机型不同** ——
一种机型"内屏 = `FULL` / 外屏 = `MAIN`"，另一种机型"内屏 = `MAIN` / 外屏 = `SUB`"。

⇒ **不能只靠 `FoldDisplayMode` 判定"是不是单屏"**。本实现把它降级为**读数与变化触发**，
判定改落在与机型无关的两条量上：

| 判据 | 取值 | 理由 |
|---|---|---|
| 物理折叠态 | `display.getFoldStatus() === FOLD_STATUS_FOLDED(=2)` | 与机型无关 |
| 宽度断点 | `宽度 < 600 vp` ⇒ compact | 折叠/外屏必然落在窄档，阔折叠展开必然 `>900` |

（`FoldStatus` 实测枚举：`UNKNOWN=0 / EXPANDED=1 / FOLDED=2`。）

## 2. 改了什么（四处接线 + 一道门禁）

| 面 | 文件 | 改动 |
|---|---|---|
| 判据 | `platform/src/main/ets/system/DeviceFacts.ets` | 新增断点常量 `FOLD_BREAKPOINT_COMPACT_VP=600` / `FOLD_BREAKPOINT_MEDIUM_VP=900`、纯函数 `foldLayoutTierOf(widthVp)`（compact/medium/expanded）、`isSingleScreenFoldState(foldStatus, widthVp)`、现场快照 `readFoldSnapshot()`（isFoldable + FoldStatus + FoldDisplayMode + 默认显示宽度 px→vp）与便利判据 `isFoldableSingleScreenNow()`。旧 `isFoldableSingleScreen()` **保留为兼容入口**（**phone 模块的 `platformSingleScreen` 桥在用它**，删了 phone 模块直接编译失败 —— 本轮实测踩到），语义升级为「委托新判据」 |
| 朝向 | `platform/src/main/ets/window/WindowRegistry.ets` | 新增 `applyFoldableOrientation(windowStage)`：**非折叠屏直接早退**（手机/平板/PC 既有行为一个字节不变）；折叠屏**单屏 ⇒ `PORTRAIT`**、**展开 ⇒ `AUTO_ROTATION_RESTRICTED`**（沿用原先的跟屏策略）。订阅 `foldDisplayModeChange` + `foldStatusChange`，**150ms 去抖**重算；`releaseFoldableOrientation()` 成对解绑 |
| 接线（朝向） | `entry/src/main/ets/entryability/EntryAbility.ets` | `onWindowStageCreate` 里紧随 `followScreenRotationOnHandheld(windowStage)` 调 `applyFoldableOrientation(windowStage)`；`onWindowStageDestroy` 里解绑 |
| 接线（朝向·phone 模块） | `phone/src/main/ets/entryability/EntryAbility.ets` | **同一改动也落在另一条壳层分支上**：折叠屏的 `deviceType` 就是 `phone`，移动壳层同样跑在折叠屏上；`onWindowStageCreate` 调 `applyFoldableOrientation(windowStage)`、销毁期解绑 |
| 接线（UI 档位） | `entry/src/main/ets/pages/WebApp.ets` | 桥 `platformForm()` 的折叠分支改为：`isFoldableSingleScreenNow() ? 'phone' : 'foldable'` ⇒ 单屏时答 `phone`，页面据此挂 `dshm-phone`，**设置面板那套手机化垫片（`SETTINGS_SHIM_JS`）自动生效**；展开态仍是 `foldable`（官方竖排，不动） |
| 门禁 | `tools/check-foldable-adaptation.mjs` | 静态判据 A–I（含 phone 模块：兼容谓词不许删、朝向必须同步）+ **8 条变异对照臂**（拆 compact 分支 / 拆桥的判据调用 / 拆 EntryAbility 调用 / 拆 foldStatusChange 订阅 / 单屏朝向换成跟屏 / 删兼容谓词 / phone 朝向不接 / 去掉非折叠早退，**逐条必须判红**） |

### 为什么"桥答 phone"就够了

页面侧本就有一个 **300ms 巡检**：`applyHandheld()` 每拍问一次 `platformForm()`，
**答案变化时就重挂 `<html>` 上的类**（原为 PC 模式动态切换而设计的可重入机制）。
所以折叠/展开时**不需要**新增任何页面侧监听 —— 桥的答案一变，`dshm-phone` 自动挂上/摘下，
设置面板立刻在"手机化（顶部横条 + 铺满）"与"官方竖排"之间切换。

## 3. 三档宽度的落地方式（按用户给的断点）

| 宽度（vp） | 档位 | 本应用怎么用 |
|---|---|---|
| `< 600` | compact（单列 / 手机形态） | 判为**单屏**：设置面板手机化 + 锁竖屏 |
| `600 – 900` | medium（双列） | 与平板同路（官方竖排 + 跟屏旋转） |
| `> 900` | expanded（多列） | 同 medium；阔折叠 / 三折展开都落这一档，官方多栏布局本就放得下 |

> 断点常量是**唯一真源**（`FOLD_BREAKPOINT_*`），门禁钉住其数值；将来要改只改一处。
> 页面侧的"多列"渲染仍由官方前端 + 既有市场多列垫片负责（`docs/132`），本次没有另写一套布局，
> 因为**用户报的毛病是"设置 UI 不竖屏"**，不是"列数不对"。

## 4. 覆盖到的三种形态

| 形态 | 折叠/外屏 | 展开 |
|---|---|---|
| **2 折**（Mate X） | 宽度窄 ⇒ compact ⇒ 手机化 + 竖屏 | 近正方形（约 600–900）⇒ medium ⇒ 官方竖排 + 跟屏 |
| **阔折叠**（Mate Xs） | 同上 | 超宽（`>900`）⇒ expanded ⇒ 官方多栏 + 跟屏 |
| **3 折**（Mate XT） | 同上 | 超长（`>900`）⇒ expanded ⇒ 官方多栏 + 跟屏 |

> 三种形态**共用同一条判据**，没有为某一机型写死分支 —— 这是刻意取舍：判据落在
> "折叠态 + 宽度"两个与机型无关的量上，新机型出厂即适配；`FoldDisplayMode` 只进日志做自证。

```sh

hdc shell hilog | grep -E "折叠屏朝向|foldDisplayModeChange|foldStatusChange"
```

期望读数：
- 折叠态：`折叠屏朝向：单屏（锁竖屏） / mode=? / 宽=? vp`，且界面横不过来；
- 展开态：`折叠屏朝向：展开（跟随屏幕旋转） / mode=? / …`，跟屏恢复；
- 设置面板在折叠态是"顶部横条 + 铺满"的手机化形态，展开态回到官方"左导航 + 右内容"。
