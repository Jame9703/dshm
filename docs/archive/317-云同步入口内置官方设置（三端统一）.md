## 2. 官方设置面板结构（实测）

`SETTINGS_SHIM_JS` 早就摸清了这个结构：

```text
[data-shortcut-modal="settings"]
  ├─ nav
  │    ├─ div（标题）
  │    └─ div（列表）← button × N（各设置分区）
  └─ div（内容区）
       ├─ div（header）
       └─ div（options）
```

**锚点是官方 JSX 里的字符串字面量 `data-shortcut-modal`**，压缩不改名 ——
所以判定它安全，与 `SETTINGS_SHIM_JS` 用同一判据。

## 3. 新垫片 `CLOUD_SETTINGS_ITEM_JS`

```text
每秒巡检 → 找到 [data-shortcut-modal="settings"]
        → 取 nav 里最后一个 div 作为列表
        → 追加一个 <button id="dshm-cloud-settings-item">云同步</button>
```

### 三条设计决定

**① 样式抄官方邻居，不硬编码**

```js
var peer = list.querySelector('button');
var cs = window.getComputedStyle(peer);
el.style.cssText = 'height:' + cs.height + ';padding:' + cs.padding
  + ';border-radius:' + cs.borderRadius + ';font-size:' + cs.fontSize
  + ';color:' + cs.color + ';font-family:inherit;';
```

硬编码尺寸在主题切换或官方改版时必然走样；抄计算样式则**自动跟随官方**。

**② 取最后一个 div 而不是"第二个 div"**

官方将来加一个标题也不影响；只有"列表是最末的 div"这个不变式。

**③ 幂等 + 三端同一份**

固定 id 判存在；**不区分 phone/tablet/desktop** —— 这正是"三端统一"的落点。
