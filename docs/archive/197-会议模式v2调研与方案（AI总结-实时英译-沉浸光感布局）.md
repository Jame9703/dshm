## 2. 调研：小艺 / 系统 AI 能力到底有什么

检索范围为 DevEco SDK `hms/ets/api` 与 `ets/api`（API 26）。

### 2.1 小艺（华为 AI）公开面

| 包 | 能力 | 对"会议总结"有帮助吗 |
|---|---|---|
| `@hms.ai.A2A`（AgentFrameworkKit，since 26） | `createA2AServer(agentCard, onData, want?)`：**我们把自己的 agent 暴露给小艺**，小艺来调我们 | ❌ 方向相反（我们要"调用"小艺做总结） |
| `@hms.ai.insightIntent`（IntentsKit） | 把小艺/系统侧的意图分享给系统做推荐 | ❌ 只是意图分享，不做生成 |
| `@hms.ai.nlp.textProcessing`（NaturalLanguageKit） | 实体识别、分词（`EntityConfig` / `WordSegmentResult`） | ❌ 无摘要、无翻译 |
| `@hms.ai.speechRecognizer` / `textToSpeech` | 语音识别 / 合成（本项目已用） | ❌ 无摘要/翻译 |

**结论**：小艺慧记的"AI 总结"没有对外 API（`docs/194` §6.3 已有同向结论）。任何"调小艺总结"的方案都要走
未公开接口，不能上架，也不该进代码。

### 2.2 替代路线：Host 侧本机模型（推荐）

DSHM 本身就是"Host（Node）+ Web 前端"的结构，Host 里已有 LLM 服务：

- 包 `@deepseek-ai/dsh-llm` 提供服务 `ctx.llm`；
- 官方插件 `dsh-session-title-llm` 的用法就是模板：
  ```ts
  const call = await ctx.llm.prepareCall({ maxTokens, ...route }, signal, (controls, model) => controls);
  for await (const chunk of call.stream({
      ...call.config, messages, system: prompt, sessionId, purpose: 'meeting-summary', signal
  })) { /* 累积文本 */ }
  ```
- 我们已有 10 个自带插件（`hostcore/plugins/dshm-*`），打包与加载链路成熟。

**协议**：沿用语音桥的**文件队列**（ArkTS ↔ Host 不共享内存，只有磁盘）：

```
files/meeting-ai/<id>.req     { kind: 'summary' | 'translate', text?, lines?, language?: 'en' }
files/meeting-ai/<id>.done    { ok: true, text: '…' }
files/meeting-ai/<id>.fail    { message }
```

### 2.3 系统翻译能力

SDK 检索 `translate` / `textTranslation` / `TranslationEngine`：**零命中**（`hms` 与 `ets` 两侧都没有）。
`TextProcessing` 只有实体/分词，不能翻译。⇒ 实时英译也只能走 Host 模型，或内置小词表（不可行）。

### 2.4 实时英译的两种接法（推荐 A）

| 方案 | 做法 | 延迟 | 成本/风险 |
|---|---|---|---|
| **A. 分批翻译（推荐）** | 每累积 1 句 or 3 秒，把新增中文段发一次 `translate` 请求；结果按 `seq` 贴回对应行 | 1.5–3 s | 请求数 ≈ 分钟级 20–30 次；失败只影响译文，不影响中文转写 |
| B. 流式逐字翻译 | 每个识别回调都发请求 | <1 s | 请求数爆炸、易被限流；识别结果还会回改，译文跟着抖动 |

A 的细化规则（写进实现）：
1. 只翻**稳定的整句**（以 `。！？` 或换行结尾），进行中的半句不翻；
2. 同一句只翻一次（`seq → en` 缓存，识别回改也复用）；
3. `EN 译文` 是**逐会议开关**（默认关，开启后实时页多一行蓝字）；
4. Host 不可用/未登录模型时，开关置灰 + 一行说明（不假装有译文）。

## 3. 布局稿（三态）

见 [`dist/mockups/meeting-v2-mockup.html`](../dist/mockups/meeting-v2-mockup.html)。要点：

### 3.1 实时会议

```
┌ ● 录音中  00:03:42                                    [✕] ┐   ← 右上角只有关闭
│ [产品周会 · 2026-10-19]      [EN 译文]          [最小化]   │
├───────────────────────────────────────────────────────────┤
│ A 发言人A 00:00:12                                        │
│   今天先把项目进度过一遍，然后看下三个风险项。            │
│   Let's go over the project progress first, then …        │   ← 英译（蓝字）
│ B 发言人B 00:00:26                                        │
│   进度方面，语音识别和会议模式都已经在 PC 上跑通了。      │
│ A 发言人A 00:01:03                                        │
│   那历史记录和 AI 总结这块，今天能不能一起收掉？          │
│ …（识别中，末尾有光标）                                   │
│ ▁▃▅▇▅▃▁▂▄▆▄▂▁  ← 电平波形                                 │
├───────────────────────────────────────────────────────────┤
│ (🎙静音) (⏸暂停) (⏹结束会议)              [AI总结][插入][保存] │  ← 左下三键 + 右侧动作
└───────────────────────────────────────────────────────────┘
```

- 三键：**静音 / 暂停 / 结束**，胶囊形、`systemMaterial(REGULAR, interactive)`、结束键红；
- 暂停 = 暂停识别与计时（WAV 继续录，避免丢音频），恢复后继续；
- 静音 = 切掉麦克风采集（`AudioCapturer.stop` 再 start），界面显示"已静音"。

### 3.2 历史会议 + AI 总结卡

列表行显示**名称 / 时长 / 发言人数 / 字数 / 总结状态**；选中行下方直接挂 AI 总结卡
（三条要点：进度 / 决策 / 待办），底部 `插入总结 / 打开录音 / 重新总结 / 删除`。

### 3.3 最小化

会议继续录，面板收成右下角**悬浮胶囊**（红点 + 计时 + 展开图标）。
展开回到实时页；关闭胶囊才走二次确认。实现上只是 WebApp 里 `@State meetingMinimized` 两态渲染，
`MeetingSession` 生命周期不变（已有 `aboutToDisappear` 兜底）。

## 4. 实施拆解（确认后执行）

| 阶段 | 内容 | 预计 |
|---|---|---|
| P1 | 面板改版：会议软件布局（发言人/时间戳/波形/三键/右上仅关闭/最小化胶囊） | 1 天 |
| P2 | 历史会议详情 + AI 总结卡（先只展示，无生成） | 0.5 天 |
| P3 | 新增 Host 插件 `dshm-meeting-ai`（summary），结束会议后自动生成，写入 Markdown `## AI 总结` | 1 天 |
| P4 | 实时英译（分批 + 缓存 + 开关），同插件加 `translate` 分支 | 1 天 |
| P5 | 门禁扩展（`check-meeting-mode` 加 AI/翻译/最小化判据 + 对照臂）、真机验收 | 0.5 天 |

**门禁新增（草案）**：
- 面板必须含 `最小化` / `三键` / `SymbolGlyph` / `EN 译文` 开关；
- 总结协议三侧逐字一致（ArkTS 写 `.req` ↔ 插件读 `.req` ↔ 写 `.done/.fail`）；
- 翻译：只翻稳定整句（半句不翻）、同句复用缓存、失败不改中文；
- 反向臂：把"半句也翻"塞回去必须判红。

**风险与边界**：
- 模型不可用（未登录/断网）⇒ 总结显示"未生成，可重试"，不阻塞会议保存；
- 把转写发给模型属于**用户数据出端**，需在面板明确提示（"AI 总结会把转写发送到当前模型"，可在设置里关）；
- 总结/翻译都消耗 token，长会议（>1 小时）需截断策略（优先"最近 20 分钟 + 全部决议句"或分段总结再合并）。

| 桌面快捷方式 / 外部 want | `shortcuts_config.json` 的 `id_meeting` 改 `visible: false`；`applyLaunchAction()` 对 `dshAction=meeting` 先判开关，隐藏时打 `会议模式已隐藏，忽略 dshAction=meeting` 并 return（旧快捷方式留在桌面也拉不起面板） |
| 面板 / 最小化胶囊 | `if (MEETING_MODE_VISIBLE && this.meetingOpen)` 才挂载 `MeetingPanel` 与胶囊（即使 state 被某条旧路径置真也不会出现浮层） |

### 6.2 重新打开

把 `MEETING_MODE_VISIBLE` 改回 `true`，并把 `shortcuts_config.json` 的 `id_meeting.visible` 改回 `true`，
重编即可。会议实现（`MeetingPanel` / `MeetingSession` / 语音桥 / 总结与英译）一行未动。
