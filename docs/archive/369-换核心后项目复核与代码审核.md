## 5. 代码审核发现

### C-1（既有设计事实）8 处 patch 目标 id 在当前 profile 里不存在，属 `warn-and-skip`

静态解析：上游 5 份 bundle patch（`dsh-base` 1 份 + `dsh-web-app` 主文件 + `presets/{standard,ptc,minimal,cordis}`）+ 本 profile patch，做 id 闭包后仍有 **8 个引用无定义**：

```
speech-to-text / speech-to-text-sensevoice / api-speech-to-text / ui-voice-input      ← dsh-experimental-voice-input-bundle
optional-persistent-terminals / optional-terminal-registry / optional-terminal-bash / optional-tool-terminal  ← dsh-experimental-terminal-bundle
```

- **不是本轮引入**：`rc.5` 树里这 8 个 id 同样只出现在上述两个 experimental bundle 里，而两个 bundle 都不在 profile 的 `bundles` 清单（`dsh-base`、`dsh-web-app`）。
- **不是静默失败**：`applyEntryPatches` 的语义是"按 id 更新已有条目，缺失仅告警跳过"，profile 自己在 `:404-407` 写明过这一点。
- **后果要说准**：这 8 条覆盖**当前不生效**；但**不等于语音/终端不可用**——端侧语音走的是**原生 ArkTS 桥**（`entry/src/main/ets/speech/SystemSpeechRecognizer.ets`、`HmsSpeechBridge.ets`，由 `WebApp.ets` 注入），与 dsh 的 `speech-to-text` **服务行**不是同一条路。真正缺的是"dsh 侧那两套服务面"，是否需要有产品口径。
- **需要确权**：这两块 dsh 服务面是"有意不启用"（端侧用原生替代），还是"漏加载 bundle"。若是前者，建议在 profile 里补一行注释说明，避免下次有人当缺陷去"修"。

### C-2（真隐患，有时间窗）`bin/dsh` 的"最新核心"判定与宿主不一致

- 宿主侧（ArkTS）用 `newestVersion()` + `compareVersions()`：**逐段数值比较**，`0.2.2-rc.1+dshm.10` > `+dshm.9`（`Naming.ets:114-158`）。
- `bin/dsh` 垫片（`hostcore/app/main.js:3266-3273`）用 **shell glob 字典序取最后一个**：

```sh
for _d in "$_cores"/*/; do ... _dshbin="${_d}node_modules/@deepseek-ai/dsh/lib/bin.js" ... done
```

字典序下 `"0.2.2-rc.1+dshm.10" < "0.2.2-rc.1+dshm.9"` ⇒ **同一上游版本内 dshm 序号跨到两位数时，终端里的 `dsh` 会选到较旧的那棵树**。

- 现状：当前是 `+dshm.1`，**今天不受影响**；按每轮都递增的节奏，到 `+dshm.10` 前必须修。
- 建议（择一）：① 宿主安装/切换核心时写 `cores/.current`，垫片优先读它（最简单且与宿主同源）；② 垫片内按 `+dshm.<n>` 取数值比较（纯 shell 可实现，但要小心 `case` 与 `[` 的字面支持）。

### C-3（文档漂移）`docs/355` 的前置判据表过期

`355` 标题与 §0 写的是 `1.1.7 / versionCode 1010009 / core 0.2.1-rc.5+dshm.109`；实际已是 **`1010014` / `0.2.2-rc.1+dshm.1`**。该文自称"只登记代码里真的接了的能力"，最容易被人当现状引用。建议随下次改动一次性刷新版本行（不必重写正文）。

### C-4（低危）`bin/dsh` 的 `_cores` 兜底路径是 entry 专用

`_cores` 在 `$_sb/dsh/cores` 不存在时兜底为 `/data/storage/el2/base/haps/entry/files/dsh/cores`（`main.js:3264`）。phone 档的 haps 目录是 `phone`，兜底会指错。因为正常路径由脚本自身位置推导，触发概率低；若要修，应与 C-2 一起改成"读 `.current`"。
