# 243 · 1.1.6 升级数据迁移、会话 flock 与多 HAP 本地安装修复

> 日期：2026-10-24
>
> 版本：`1.1.6 / 1010007`
>
> 核心：`0.2.1-rc.3+dshm.93`

## 1. 用户现象

1. 1.1.4 手机升级到 1.1.6 后，会话、工作区和已装插件显示为空；回退
   1.1.4 后原数据恢复。
2. 1.1.6 新建会话或发送消息失败：

```text
Error loading shared library
.../haps/phone/files/dsh/cores/0.2.1-rc.2+dshm.91/
node_modules/@deepseek-ai/node-addon-system-linux-arm64/bin/musl/system.node:
No such file or directory
```

3. 本地侧载或 Hokit/DevEco 安装返回：

```text
9568287 install invalid number of entry hap
```

## 2. 根因

### 2.1 模块改名造成手机文件目录切换

1.1.4 的 AGC 包同为 `com.dshm.dshclient`，手机使用名为 `entry` 的 HAP：

```text
/data/storage/el2/base/haps/entry/files
```

1.1.6 把手机拆成独立的 `phone` HAP：

```text
/data/storage/el2/base/haps/phone/files
```

`$DSH_HOME=<filesDir>/dsh/home` 原本承诺跨核心版本共享，但不能跨 HAP
模块名自动共享。新目录为空，因此会话、工作区注册和 `profiles/ondevice`
下的插件看起来全丢；旧 `entry` 数据仍在，所以回退后又出现。

### 2.2 旧 `.91` 核心树被复用，平台占位文件没有进入新树

核心中的 `system.node` 是 73 B 占位。真正加载时由原生重定向改到共享
HSP 的：

```text
libs/arm64-v8a/libsystem.so
```

第一层修复把 `flock.c` 固定进仓库并让 CMake 产出 `libsystem.so`。但设备
已经解包过同版本 `.91`，而 `.91` 早期树没有
`node-addon-system-linux-arm64/bin/musl/system.node`；同版本更新容易继续
命中旧树，于是仍报同一条错误。

最终修复同时做三件事：

1. 核心版本升到 `.92`，设备必须解包一棵全新的树；
2. `.92` 明确带 `node-addon-system-linux-arm64` 的 `package.json` 与
   `musl/glibc system.node` 占位；
3. `CoreStore.verifyStagedTree()` 增加平台包哨兵，树缺该占位就拒绝激活，
   不再等到首个会话才暴露。

### 2.3 `9568287` 不是 HNP，也不是插件包

产物本来就有两个合法 entry HAP，按设备类型互斥：

| 模块 | deviceTypes |
|---|---|
| `entry` | tablet / 2in1 |
| `phone` | phone |
| `hostruntime` | shared |

AGC `.app` 可以在同一 App Pack 中按设备类型选择 entry；本地安装器一次
只接受一个 entry。把 `.app`、`all/` 或 DevEco 的混合输出目录直接交给
本地安装器，就会报 `9568287`。仓库没有 `hnpPackages`，该错误与 HNP
分发无关。

## 3. 修复

### 3.1 一次性、只复制不删除的手机数据迁移

新增 `phone/src/main/ets/system/LegacyStorageMigration.ets`：

- 源：`haps/entry/files`；
- 目标：`haps/phone/files`；
- 复制 `dsh/home`：sessions、profiles、plugins、credentials、workspace registry；
- 复制 `workspace`：应用沙箱内的工作区文件；
- 目录合并、目标已有文件优先，不覆盖新版本写入；
- 不复制 `host-ready.json`、`host-exit-mode`、`host-stop-request`；
- 旧目录只读保留，回退 1.1.4 仍可读取；
- 任一复制失败不写完成 marker，下次启动可继续补齐；
- Host 启动链等待迁移完成，避免先用空目录初始化会话状态。

该逻辑也覆盖已经装过坏 1.1.6、`phone/files` 已被创建为空目录的设备。

### 3.2 固定 flock 原生源

`hostruntime/src/main/cpp/vendor/node-addon-system/flock.c` 从
`@deepseek-ai/node-addon-system@0.1.2`（BSD-3-Clause）固定进仓库。
共享 HSP 构建不再依赖可清理的 `dist/core/work`；源或 `libnode` 缺失时
CMake 直接失败。

### 3.3 本地安装始终只给一个 entry

- `tools/update-device.mjs` 按设备选择 `entry` 或 `phone`；
- 默认安装 `<module>-default-signed.hap` + shared signed HSP；
- 拒绝把 `.app` 当成本地安装输入；
- 数据保全指纹按实际模块目录读取；
- `tools/stage-sideload.mjs` 生成 `pc/`、`tablet/`、`phone/` 三个目录，
  每个目录严格只有一个 entry HAP + 一个 HSP。

AGC 仍上传完整多设备 `.app`；只有本地侧载必须拆分。
