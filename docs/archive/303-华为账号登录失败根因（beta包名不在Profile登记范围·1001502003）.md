## 0. 结论：**不是代码问题，是 beta 包名与 AGC Profile 不匹配**

| 事实 | 值 | 来源 |
|---|---|---|
| **Profile 登记的 bundle-name** | **`com.dshm.dshclient`** | `.certs/multihap-20261024/…p7b` 实读 |
| Profile 的 app-identifier | `6917614360926110054` | 同上（**与你给的 Client ID 逐位一致**） |
| **设备上装的包** | **`com.dshm.dshmbeta`** | beta 出包规格 |
| beta 出包会改 bundleName | **是**（`tools/build-beta.mjs:243`） | 源码实读 |

⇒ **系统拿 `com.dshm.dshmbeta` 去要华为账号服务，而 Profile 只授权了 `com.dshm.dshclient`**
⇒ 服务端判定 `Invalid clientId or profile` ⇒ **1001502003**。

> **你之前核对的 Client ID / 证书指纹 / Profile 全都没错** —— 错的是**包名**这一维，
> 它不在你给的对照表里，也不在你已核的清单里。

## 1. 为什么 1001502003 不在你的对照表里

你给的表覆盖的是「能力/协议/登录态」类错误：

| 错误码 | 含义 | 本例是否符合 |
|---|---|---|
| 1001500001 | 指纹校验失败 | ❌ 不是（指纹确已核对一致） |
| 1001502014 / 1001500003 | scope 未开通 | ❌ 不是 |
| 1001502001 | 系统未登录华为账号 | ❌ 不是（面板能弹出且能勾协议） |
| 1001500002 | 请求处理中 | ❌ 不是（首次点击就报） |
| 1005300001 | 未接受协议 | ❌ 不是（已勾选） |
| **1001502003** | **clientId 或 profile 无效** | ✅ **就是它** |

**这条是「身份登记」类错误，与上面五类都不同类** —— 表里缺这一项，所以按表排查会全部落空。

## 3. 两条修复路线

### 路线 A（**推荐**）：用正式包 `com.dshm.dshclient` 测

因为 **Profile 只授权了这一个包名**，最省事的做法就是**测正式身份的包**：

```bash
# 出正式包（不是 beta）
hvigor assembleApp   # 或按项目既有出包流程
# 覆盖安装（同签名，只换 el1，不动 el2 用户数据）
hdc install -r dist/.../DSHM-*-combined-debug.app
```

> ⚠️ **注意**：`com.dshm.dshclient` 与 `com.dshm.dshmbeta` 是**两个不同的应用**，
> `hdc install -r` **不能跨包名覆盖**。装正式包会变成**新增一个应用**，
> 原 beta 的数据（会话/插件）**不会自动迁移**过去。
>
> 若要在正式包上验证，需确认它能否读到用户已有数据；不能的话这是**新的空环境**测试。

### 路线 B：把 beta 包名也加进 AGC Profile

在 AGC 重新生成 Profile，`bundle-name` 增加/改为 `com.dshm.dshmbeta`。

**可行性问题**：AGC 的 Profile 是**按应用（bundle）签发**的，
一个 Profile 通常只对应**一个 bundle-name**。要让 beta 包能登录，需要：
1. 在 AGC **为 `com.dshm.dshmbeta` 单独建一个应用**；
2. 为它单独申请 Profile；
3. **另外，华为账号服务（Client ID）也是按应用绑定的** ——
   新 bundle 需要**单独的 app-identifier / Client ID**，不能复用 `6917614360926110054`。

⇒ **路线 B 成本高**（要新建应用 + 新 Client ID + 新证书 Profile 一整套）。

### 路线 C：临时把 beta 包名改回正式包名出包

```js
// build-beta.mjs 临时改动：只改 label，不改 bundleName
```

代价是**会覆盖你现在的正式包**（如果装了的话），且失去"beta 与正式并存"的能力。
