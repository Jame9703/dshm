## 1. 三次失败复盘（每次的定性都不同）

| 轮次 | 做法 | 失败现象 | 真因 |
|---|---|---|---|
| **第 1 次** | 原生 ArkUI：`systemMaterial(THIN)` 挂自绘顶栏 | 看不出 | 顶栏与 Web 是**兄弟节点**，材质底下只有窗口底色（白）⇒ 取色/模糊作用在白上 |
| **第 2 次** | 布局改（A：顶栏改 Stack 浮层 + 官方 `--dsh-frame-top-clearance`）+ 档位改（B：REGULAR） | **按钮掉进会话区**，观感依旧 | A 与 B 同时改，且顶栏浮层与官方内容让位是两套机制 ⇒ **排版错位**（详见 `docs/280` §7） |
| **第 3 次** | 全部回滚，改**垫片 CSS**（`backdrop-filter` 挂列上） | 看不出 | ①`:before` 被官方 `overflow:hidden` 裁掉；②伪元素参与 flex 布局；③**侧栏列根本没覆盖**；④**改完源码没重新出包**（17:06:50 改 / 17:02:58 包） |

**纪律固化**：

1. **布局类改动必须条件式 + 实验开关 + 真机截图对比**（第 2 次教训）；
2. **CSS 类改动必须「改源码 → 立即出包 → 核对产物 mtime 晚于源码 mtime」**（第 3 次教训，`docs/282` §9.2 给出自检命令）；
3. **没有 DOM 通道时，运行时探针是唯一事实来源** —— `diagGlass()` 的四项读数（`cssSupports` / `glassTop` / `cols` / `computedBackdrop`）直接推翻了三个错误假设。

## 2. 实现（垫片侧，顶栏零改动）

### 2.1 挂载（`SIDEBAR_SHIM_JS` 的 `tagLayout`）

```js
var glassKids = frame.children;
if (glassKids.length > 0) { addClass(glassKids[0], GLASS_SIDEBAR_CLASS); }  // 侧栏列
if (glassKids.length > 1) { addClass(glassKids[1], GLASS_COL_CLASS); }      // 中间列
```

- frame 用官方 `[data-shell-overlay]` 的父元素定位（**不认 CSS Modules 哈希类名**，与本仓既有范式一致）；
- 用**子元素序号**而不是"找 toggle 按钮"——后者在桌面档被我们隐藏，`findToggle()` 一旦失手整条特性失效；
- `addClass` 幂等，`tagLayout()` 每 300ms 拍跑一次 ⇒ 官方重建 DOM 后自愈。

### 2.2 样式（直接挂列自身，不用伪元素）

```css
html.dshm-glass-top .dshm-glasscol,
html.dshm-glass-top .dshm-glassside {
  backdrop-filter: blur(40px) saturate(180%);
  background: rgba(214,223,240,0.86) !important;   /* 亮色：**真的蓝灰**，不是白 */
  box-shadow: inset -1px 0 0 rgba(120,140,180,0.28);
}
html[data-ds-dark-theme].dshm-glass-top … {
  background: rgba(38,44,58,0.82) !important;
}
```

**为什么不用 `:after`/`:before`**：官方的列有 `overflow:hidden`（`:before` 会被裁）+ 伪元素参与 flex 布局（挤占内容）；
而 `backdrop-filter` 本来就可以直接施加在元素自身（模糊"背后的东西"），无层级、无布局副作用。

**档位 fail-closed**：`dshm-glass-top` 只在 `desktop` / `tablet` 挂；手机与 PC 模式不挂 ⇒ 规则一条不生效。
且该标记已纳入 `applyHandheld()` 的**快路径自愈**（与 `dshm-tablet` 同级）——官方重写 `<html>` class 时不会被抹掉。

### 2.3 运行时探针（`diagGlass`）

前 3 拍 + 每 200 拍（约 1 分钟）各记一次：

```text
[dshm-sidebar] glass diag: cssSupports=yes glassTop=13 cols=1 \
  computedBackdrop=blur(40px) saturate(1.8) computedBg=rgba(214, 223, 240, 0.86) frameKids=[…]
```

这五项是判定"生效/没生效"的唯一可靠依据。

## 3. 关于「亮色下到底能看出多少」——必须诚实

`docs/282` §9.1 的结论我接受：**亮色主题下"玻璃"的观感增量有物理上限**。

- 背景是纯白，`backdrop-filter: blur()` 模糊白色仍是白色，**不产生任何可辨纹理**；
- 因此亮色下的"玻璃感"只能靠**带色偏移的材质**（本次 `rgba(214,223,240,0.86)`，比原来的白/`249,250,251` 明显偏蓝）；
- **深色主题才是唯一能一眼看出的组合**（暗底材质叠白内容，反差足）；
- 继续加深亮色材质会滑向 `docs/196` 的**染蓝**风险（当时 WebApp 整块铺材质就染蓝糊字）。

⇒ **验收建议**：亮色看"是否有可见的蓝灰偏移与列边界"，深色看"是否真有玻璃质感"。
