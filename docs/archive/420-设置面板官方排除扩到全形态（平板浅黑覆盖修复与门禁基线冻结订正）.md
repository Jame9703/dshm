## 1. 根因链（事实）

1. 官方结构：设置面板 = `@deepseek-ai/dsh-client-ui-settings-general` 的 body-portaled overlay + `.mask` + `.panel`；`.panel` 带 `data-shortcut-modal="settings"` / `role=dialog` / `aria-modal=true`（源在核心树 `dist/core/work/dsh-core-0.2.2-rc.3+dshm.1/node_modules/@deepseek-ai/dsh-client-ui-settings-general/src/client/SettingsRoot.tsx`）。
2. 官方 CSS：`.mask` 用 `var(--dsw-alias-bg-mask-1)`（浅色 `#0000003d` = 24% 黑 / 深色 `#00000080` = 50% 黑，`--dsw-mask-blur: none`）；`.panel` 不透明 `--dsw-alias-bg-layer-2`（浅近白）。rc.1 ↔ rc.3 设置 CSS 零差异（核心升级未改观感）。
3. 我方玻璃皮肤（docs/359 一期，entry 独有、phone 0 命中既定分工）：`findDialogs` 给 `[role=dialog]`/`[aria-modal=true]` 打玻璃标 ⇒ 平板上设置面板被改成半透明白 ⇒ 叠官方 24% 黑遮罩 ⇒ 面板发灰发黑，即用户看到的「浅黑覆盖」。
4. 2026-11-14 PC 先例（HANDOFF §1 11-14 条目 + `spec/pc-settings-chrome-20261114/findings.md`）：同一问题 PC 形态已修（删 webModal 桥 + `findDialogs` 加 `dshm-desktop` 条件）；当时「普通平板和非设置 dialog 保留原有行为」是**刻意的范围决策**，2026-11-17 用户实测 verdict 将设置面板的排除扩到全形态（非设置弹层维持玻璃不变）。

## 2. 修法（代码事实）

entry `WebApp.ets` 玻璃皮肤 `findDialogs`（`GLASS_SKIN_JS` 内）：删 `dshm-desktop` 条件，凡 `closest('[data-shortcut-modal="settings"]')` 命中（设置面板及其内部 dialog）一律跳过，与形态无关；非设置弹层照常打标。玻璃从此只剩侧栏与非设置弹层两个面。

## 3. 顺带收尾（验证中发现的既有缺口）

- **`topBarBg`/`topBarBgNow()` 退役**：11-16 沉浸起顶栏不画自己的底色（`TopBar` 用 `Color.Transparent`，窗口底色由 `applySystemBarTheme` 的 `setWindowBackgroundColor` 统一为 `chrome.bg`）⇒ `topBarBgNow()` 成死代码。本轮删除方法、`@State topBarBg` 与其唯一写点，并订正两处过时注释（顶栏取色块「三个值」→「这个值」；三键让位注释的「底色取 topBarBgNow()」句改写为透明顶栏 + 窗口底色口径）。`topBarFg`/`topBarFgNow()` 仍在用（DotsMenu 三点取色），保留。
- **两门禁改钉**：`check-pc-settings-chrome.mjs` 的 TopBar 断言从 `topBarBgNow()` 改钉 `Color.Transparent`（变异体同步改 `#66000000` 注入）；`check-decor-button-mode.mjs` 的前提锚从 `this.topBarBg =` 改钉 `this.topBarFg =`（对照臂 A–X 不受影响）。
