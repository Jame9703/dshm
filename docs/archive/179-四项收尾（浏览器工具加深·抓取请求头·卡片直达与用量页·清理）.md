## 2. 抓取管线（核心树补丁 ㉑）

- `dsh-web-fetch-http` 的 `requestOnce()` 请求头补：
  - `accept-language: zh-CN,zh;q=0.9,en;q=0.8`
  - `referer: <url.origin>/`（同源来源）
- 依据：UA（docs/177）已换浏览器 UA，但"只有 UA、没有语言/来源"的请求仍会被反爬中间件打低分。
- 只加两个头，不动 method / 重定向 / SSRF 策略。
- **边界（如实）**：`web_fetch` 仍只有 GET（上游形态）、没有按站点 UA 表；POST-only 端点与 WAF UrlACL 场景继续走浏览器路。
- 门禁：`check-core-openharmony-patches` **29 处注入补丁 / 233 断言 全绿**（新增 `㉑ web 请求头`，反向判据=上游仅含 user-agent/accept 的 headers 原文必须消失）。

## 6. 紧急修订：自动关闭会把海泰卡死 → v10 改为「单标签只最小化」

**用户反馈**：「海泰浏览器直接打不开了」。

**真机取证**（`hilog -x`）：

- 卡死进程 `10840` 反复刷 `GetCurrentDisplay … oh_window_id:-1`（窗口句柄已没了）；
- AMS 报 `LIFECYCLE_TIMEOUT … ability:EntryAbility terminate timeout`；
- 内存充足（13GB available），不是 OOM；
- `force-stop` 后 `aa start -b com.haitai.htbrowser` 报 `10103101`（无 ability 匹配），改用
  `aa start -a EntryAbility -b com.haitai.htbrowser` 成功拉起；v9 扩展随即重连（ws_3 / 0.9.0）。

**根因**：自动关闭（v8 的 `close`）在**单标签页窗口**上执行 `chrome.tabs.remove` 删掉最后一页 ⇒
海泰的 EntryAbility 开始终止并卡在 `terminate timeout`，进程活着、窗口没了 ⇒ 再点图标也起不来。

**修法（扩展 v10 / 0.10.0 / `dshm-host-bridge-10`）**：

- 多标签页窗口：**只删 `sessionTabId` 那一页**（窗口保留，安全）；
- 单标签页窗口：**只 `windows.update(minimized)`**（离开前台、保持进程存活，不触发终止）；
- **绝不 `windows.remove`**（删窗/删最后一页正是事故路径）。

门禁 `check-browser-autoclose` 扩为 **19 断言 + 6 变异臂**（新增：删最小化守卫 / 把 windows.remove 加回来 ——
都必须判红）。扩展 v10 已部署到 `<下载>/com.dshm.dshmbeta/dshm-browser-ext-v10`（sha 双匹配），待用户重载。
