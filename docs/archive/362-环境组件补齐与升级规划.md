## 1. 分期（按"能验证"排序）

### P1 签名能力（本轮完成）
- pack-core `findBinarySignTool()`：原生 ELF 优先 → jar+java 兜底；
- 原生调用 `sign -inFile … -outFile … -selfSign 1 -signAlg SHA256withECDSA`，签后 `chmod 0755`；
- 验证：重打核心，签名计数应从「47 通过/1 未检出」上升；容器内 rg 带 `.codesign`；
- 门禁：`check-toolchain-sign` 增加"原生工具优先"断言。

### P2 guest 工具闭包（本轮做 4/5/7，6 暂缓）
1. `libcurl` + 依赖（openssl/pcre2/zlib/brotli/nghttp2/libidn2/libunistring/ca-certificates）；
2. `pnpm`（9.15.9 `pnpm.cjs` + 包装器，走 guest node）；
3. `dsh` guest wrapper（`node <core>/bin.js`）；
4. 放进 `resfile/vm/guestpkgs/`，扩展 `GUEST_PKG_FILES` 与 `place-vm-assets`；
5. vm.js 的 git/通用 bootstrap 解包模式加入这些包；
6. 门禁：`check-vm-bash`（脚本/资产清单）+ 新 `check-guest-pkgs`（清单 ↔ resfile 逐项）。

### P3 guest 资源（取证后做）
- `-smp` 改为可配（`DSHM_VM_CPUS`，默认仍是 1）；
- guest 内存档位增加一档（256→384），仅在 ≥8 GB 可用内存时启用；
- 先在 PC 上对照跑 `gh/npm`，再上手机。

### P4 Node 运行时升级（阻塞项，单独立项）
- 需要 **OpenHarmony arm64 musl 的 libnode ≥ 24.9**（共享库，不是静态 node）；
- 来源核查结论：系统 `/system/lib64` 无 libnode；SDK 无；`node-brew` 单体静态无法拆；
- 可选路径：让 Node 官方/移植方出 OHOS shared-libnode 构建，或自行交叉编译 Node（工作量大，需单独评估）；
- 到位后：换 `hostruntime/libs/arm64-v8a/libnode.so.137` → 过 io_uring 中性化门禁 → 升 0.2.2-rc.1 → 迁移 31 个补丁 → 三端回归。

### P5 回归与出包
- 全量离线门禁 + 三端复测（PC v10 / 手机 guest / 平板沉浸）；
- 出 `1010014+` 测试包，附新 `dshm-verify` 报告。
