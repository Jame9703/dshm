# 163 · 「关于」页客户端版本改为运行时读取（写死版本号的 P0 修复）

> 日期：2026-10-15。来源：用 `app-metadata-audit-skill` 做上架元数据自检（AGC Connect API 实拉）时
> 抓到的一条 **P0** —— 应用内「设置 → 设备 → 关于 → 客户端版本」显示 `1.1.0 (1010000)`，
> 而实际包是 `1.1.2 (1010002)`。
>
> 同一轮里**商店文案**的 `appDesc` 也犯过同一个病（正文写着"本版本 1.1.0（versionCode 1010000）"），
> 那条已在 AGC 侧用 `language-update` 改掉；本档只记**代码**这一半。

## 1 根因

`appstate/src/main/ets/model/StubData2.ets` 的 `aboutInfo()` 把 `appVersion` **写死**成
`'1.1.0 (1010000)'`。

讽刺的是同一文件顶部的注释写得很清楚：这些数字**必须派生不能写死**，否则"界面在说谎"
（端点/流式/能力三个数字都从 `dshcompat` 实时派生）—— **版本号就是漏网的那一个**：
它是手抄的常量，包一路发到 1.1.2，界面还停在 1.1.0。

## 2 修法（三处，最小改动）

| # | 文件 | 改动 |
|---|---|---|
| ① | `platform/src/main/ets/system/FilePicker.ets` | 新增 `readAppVersionText()`：`bundleManager.getBundleInfoForSelfSync(GET_BUNDLE_INFO_DEFAULT)` → `${versionName} (${versionCode})`；读不到返回**空串** |
| ② | `platform/src/main/ets/Index.ets` | 导出 `readAppVersionText`（附口径注释） |
| ③ | `appstate/src/main/ets/model/StubData2.ets` | `appVersion: readAppVersionText()`，删掉写死的常量 |

**为什么放 `platform`**：它是本仓的设备能力层（"只提供机制、不含产品策略"），而 `bundleManager`
在 `FilePicker.ets` 里已经有**单一住所**（`readBundleName()` 的注释原话："两处各写一遍
`bundleManager` 调用迟早会分叉"）。appstate 本来就依赖 platform（`oh-package.json5`），方向合规。

**UI 侧不用改**：`SettingsDevice.aboutRow()` 对空串本来就如实显示「—」。

## 3 为什么不"改个常量"

把 `1.1.0 (1010000)` 改成 `1.1.2 (1010002)`，只是把下一次漂移延后到下次发版。
版本号是**运行时事实**，判据只能是问系统；读不到就显示「—」——
**宁可显示未知，也不显示一个写死的假版本**（这条与 `docs/162` 记录的"信息需与内容相符"同源）。

## 5 边界

- 本档**不含**商店文案与隐私政策的修改（那两件在 AGC 侧，后者被平台拒绝 API 更新：
  `204144850 agreement not allow update`，协议 `status=2 已完成` ⇒ 只能控制台改）。
- 版本号只有一个来源（`platform/readAppVersionText()`）；后续再出现"某处手抄版本"，
  应按本档的判据改成消费这个来源，而不是新增常量。
