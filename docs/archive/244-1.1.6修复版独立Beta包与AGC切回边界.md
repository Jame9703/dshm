## 0. 分发模型

本项目是“一多”工程，但不是三个 HNP：

- 桌面/平板的 `entry` HAP：`deviceTypes=["tablet","2in1"]`，覆盖
  MatePad Edge、Pro Max 和 2in1；
- 手机 `phone` HAP：`deviceTypes=["phone"]`；
- 二者共享一个 `hostruntime` HSP。

AGC 上传一个完整 `.app`，系统按 `deviceTypes` 选择对应 entry。本地
`hdc`/Hokit 一次只接受一个 entry，因此侧载必须拆成：

```text
pc/     entry HAP + shared HSP
phone/  phone HAP + shared HSP
```

把 `.app` 或同时放入两个 entry 的目录交给本地安装器，才会报
`9568287 install invalid number of entry hap`；该错误与 HNP、插件包无关。

MatePad Edge 与 MatePad Pro Max 同属大屏类，实包仍只有一个
`entry(tablet,2in1)`。两者的差异只在系统上报的原始形态：

- Pro Max 通常原生上报 `2in1`；
- Edge 可能上报 `tablet`，由 `DeviceFacts` 归一为同一个 desktop 大屏路线。

下层的 Host 原生终端、共享 HSP、权限面和会话存储都消费归一后的
`desktop` 事实，不再按机型拆第二套代码。早上日志里的 Edge 崩溃是旧包的
ArkWeb 渲染进程/时序问题：`KillRenderProcess`、页面被清后调用
`SetRenderProcessMode` 得到 `web engine is nullptr`，以及 renderer 的
`SIGSYS` 处理冲突；不是“声明了 2in1”本身导致，也不是 Pro Max 与 Edge
被打成了两个 entry。

## 1. 目的

正式包名、正式 release Profile 和 AGC 签名出包。

### 2.1 ACL 阻塞（不可跳过）

这个侧载件虽然签名有效、权限声明完整，但当前 beta App ID 的调试 Profile
`allowed-acls=[]`。设备安装时会把 HAP 请求的 ACL 权限逐条与 Profile 比对，
不在 Profile 中就会按 `PERMISSION_ACL_RULE` 拒装。因此本次侧载件只用于
**设备上已经安装同签名 `com.dshm.dshmbeta` 的覆盖升级**；不能用于全新安装，
也不能分发给没有既有 beta 权限记录的设备。

AGC 实读结果：给 beta App ID 创建带 7 条 ACL 的 Profile 返回
`204144764 not allow to use some acl permissions`。独立 bundle 不会自动继承
正式 `com.dshm.dshclient` 的 ACL 审批；debug 签名也不会绕过 ACL 校验。

正式对外分发前仍需满足以下任一条件：

1. 给 beta App ID 取得与正式 App ID 相同的 7 条 ACL，然后重新创建调试 Profile；
2. 改用正式 bundle `com.dshm.dshclient` 的调试 Profile（会覆盖安装正式应用，
   不是隔离 beta）；
3. 明确接受裁剪 ACL 后只测部分能力（不满足“最全 PC 7 条 ACL”要求）。

`tools/build-beta.mjs` 和 `tools/check-mobile-upgrade-migration.mjs` 已加入
ACL 门禁：Profile 没有完整 7 条 ACL 时会直接失败，避免再次产出“签名能过、
设备必拒装”的假交付。

## 3. Beta 边界

Beta 走 debug 侧载，保留完整权限声明；不修改正式应用权限申请，也不把
beta 的 AGC App ID 当作正式发布身份。测试完成后直接停用 beta 包即可，
正式 `com.dshm.dshclient` 安装与数据不受影响。

Beta 是独立 bundle，系统隔离意味着它读不到正式
`com.dshm.dshclient` 的私有 el2 目录。若测试组原先运行的是正式 1.1.4，
不能通过这个 beta 验证“正式历史数据原位迁移”；该场景必须用正式修复
候选在保留数据的设备上覆盖验证，或使用曾经安装过旧
`com.dshm.dshmbeta` 的数据集。

## 4. 安装

只允许覆盖安装，不卸载：

```bash
node tools/update-device.mjs --skip-build --target <connect-key> \
  --bundle com.dshm.dshmbeta --module phone|entry \
  --hap <pc|phone>/DSHM-1.1.6-beta-<module>-debug.hap \
  --hsp <pc|phone>/DSHM-1.1.6-beta-hostruntime-debug.hsp
```

安装前后脚本按 beta 的实际模块目录
`haps/phone/files/dsh/home` 做数据指纹比对。

## 5. 可复现构建与自动恢复

```bash
node tools/build-beta.mjs
```

脚本会临时切换 AppScope、product、快捷方式/AgentCard 和 Host 包名，
构建结束在 `finally` 中逐字恢复正式配置，并重新执行
`place-host-app.mjs`。门禁
`node tools/check-mobile-upgrade-migration.mjs` 会检查：

- 构建后源码仍是 `com.dshm.dshclient`；
- beta HAP 是 `com.dshm.dshmbeta / 1010007`；
- beta phone 保留 8 条权限、desktop/tablet entry 保留 16 条；
- beta debug Profile 覆盖完整 7 条 ACL；
- 两个 APP 各自只含一个 entry；
- 两个 APP 的可见名称均为 `DSHM Beta`；
- beta HSP 的 Host 资源也切到 `com.dshm.dshmbeta`，不残留正式包名路径。

## 6. Beta 通过后切回 AGC

源码当前已恢复正式身份，不需要反向手工改包名。切回步骤：

1. 确认 `AppScope/app.json5` 与 `build-profile.json5` 为
   `com.dshm.dshclient`；
2. 确认 debug/release signingConfig 分别指回正式 multihap debug/release Profile；
3. 重新跑 release `assembleApp`；
4. 用 `hap-sign-tool verify-app` 验签；
5. 确认 Profile 为 release、App ID `6917614360926110054`、7 条 ACL；
6. 上传 `dist/release-test/` 中新的正式 `.app` 到 AGC。

本批没有覆盖正式 AGC 测试版本，也没有删除任何正式签名物料。
