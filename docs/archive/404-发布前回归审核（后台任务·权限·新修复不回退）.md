## 3. 权限与 ACL

| 项 | 值 | 证据 |
|---|---|---|
| 源码权限面 | entry **17** / phone **9** | `check-permission-surface` PASS，reason 无孤儿 |
| Beta 包 | entry **18**（构建期临时注入 `ACCESS_USER_FULL_DISK`）/ phone 9 | module.json 实测 |
| AGC 包 | entry **17** / phone **9**，**无**全盘权限 | module.json 实测 |
| 正式 Profile ACL | **7 条**，与 `build-agc` 的 `EXPECTED_ACLS` 逐条一致 | p7b 解出 allowed-acls |
| Profile 身份 | `com.dshm.dshclient`、type=release、app_gallery | p7b 解出 |
| 构建后恢复 | `AppScope/app.json5` 仅保留 1.1.8/1010015 与云同步开关（非 Beta 残留）；`build-profile.json5` 无 diff | git diff |

ACL 七条：`ALLOW_EXTERNAL_NATIVE_CODE` / `CUSTOM_SANDBOX` / `FILE_ACCESS_PERSIST` /
`READ_PASTEBOARD` / `READ_WRITE_DESKTOP_DIRECTORY` / `READ_WRITE_DOCUMENTS_DIRECTORY` /
`READ_WRITE_DOWNLOAD_DIRECTORY`。

> 说明：仓库里没有比 `DSHM-multihap-release-20261024-newacl.p7b` 更新的 Profile 文件。
> 若 AGC 后台又批了**新的** ACL，需要把新 p7b 放进 `.certs/` 并同步 `EXPECTED_ACLS`，
> 否则 `build-agc` 会按 7 条严格校验并失败 —— 这正是为了防“包里声明了、Profile 没批”。
