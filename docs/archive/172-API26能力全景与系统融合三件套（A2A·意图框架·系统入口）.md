## 4. API26 全量要点（来源：KB `os-new-feature-2600.md`，按 Kit 提炼）

- **Ability**：`appMemoryOptimizer`（释放文件页缓存）；AgentCard / ArkTS Skill 脚本 / `scriptManager`；
  ModularObjectExtensionAbility（应用间模块化调用，Beta2）；`pluginBundleManager`（自分发插件管理，需权限）。
- **ArkUI**：V2 组件族（ChipV2/ChipGroupV2/CounterV2/PopupV2/TreeViewV2/SwipeRefresherV2）；
  智慧手势（`SmartGestureController` + 交互属性）；Lazy 系列布局（LazyColumn/LazyDynamic/LazyVWaterFlow）；
  `SelectionContainer`（跨节点文本选择）；系统材质（`systemMaterial` 全组件 + 沉浸光感）；
  `WithEnv`/`@CustomEnv`；窗口模式设置；闪控球销毁事件；`OverlayManager.openOrderOverlay`。
- **ArkWeb**：Chromium 132 → **144**；安全配置类；cookie 隐私模式 / partitioned cookies。
- **ArkData**：datashare 多值类型发布。
- **Audio**：设备增强管理器；录音降噪模式 API。
- **AVSession**：播控中心自定义按钮布局；倍速 / 循环列表。
- **Background Tasks**：倒计时提醒 repeatInterval / repeatCount。
- **Core File**：`UNCACHE` 打开标志；`listFileExt` 递归列举；文件 `mmap`；应用沙箱目录共享（捐献）。
- **Core Vision**：图像超分；文本语义搜图。
- **Data Augmentation**：知识加工邮件模块（分类/摘要/待办）。
- **Desktop Extension**：快捷栏能力查询、组合图标 + 进度条（需权限）、状态栏 hover / 能力查询。
- **FAST**：排序 / 哈希表 / FFT / 多项式求根 / 向量运算 / **调度优化**。
- **Image**：GIF/JFIF/TIFF/PNG/AVIS 元数据类 + XMP。
- **Input**：输入事件注入（需 `CONTROL_DEVICE`，排除）。
- **Live View**：卡片辅助区百分比进度环。
- **Media**：PCM 处理回调、广告插播（AVAds）、离线缓存（AVDownloader）、录屏暂停。
- **Notification**：锁屏通知开关查询；半模态拉起通知设置。
- **PDF**：自定义渲染风格 / 内存加载 / 坐标互转。
- **Pen**：跟手性加速（需权限，排除）。
- **Preview**：文件打开加速（C API，可用性查询 + 事件上报）。
- **Remote Communication**：国密 TLCP、MPTCP、QUIC、流式上传。
- **Scan**：默认/自定义界面扫码能力查询。
- **Share**：PC/2in1 与平板侧碰一碰轻碰坐标。
- **Service Collaboration**：碰一碰场景 API（需权限，排除）。
- **Spatial Recon / XEngine / Graphics Accelerate / Map / MDM / 企业系**：与本产品无交集或需资格。
- **UI Design**：HdsColorPicker（颜色选择 + 收藏）；HdsSnackBar/ListItemCard 增强。
- **新增 Kit**：AccessoryKit（配件，需权限）、AODNavigationKit、LinxKit（CPU 加速，C API）、ServiceSupportKit（硬件检测）。
- **性能**：HiDebug 内存快照导出监听；JS Crash 记录 so 加载失败（NativeModuleErrorInfo）。

### 5.2 ① 桌面快捷方式（本轮实施）

**设计**（复用既有"启动参数 → AppStorage → 页面消费"链路）：

```
shortcuts_config.json（wants.parameters.dshAction）
  → EntryAbility.onCreate / onNewWant → applyLaunchParams()
  → parseWindowParams()（platform 跨窗口契约，新增 PARAM_ACTION='dshAction'）
  → AppStorage 'dshLaunchAction'
  → WebApp.ets（生产入口 = Web 壳页）applyLaunchAction()：消费即清空 + 白名单
  → controller.runJavaScript(NEW_SESSION_SCRIPT)：DOM 点击前端「新建会话」按钮
```

**三个接线点修正（真机暴露的，比功能本身更值钱）**：

1. **生产入口是 `pages/WebApp`（Web 壳），不是 `pages/Index`**。`Index` 是原生 UI 旧壳
   （R1 §9 已注明"生产入口走 WebView ⇒ 原生 UI 层当前休眠"）；第一版把消费逻辑接在 Index，
   真机零日志（该页面从未实例化）。**通道层（platform / EntryAbility）可复用，消费层必须在 WebApp**。
   撤销 Index 侧改动的理由是"一处实现"：两处都写会让后来者以为休眠壳里那条也在工作。
2. **消费点要三层**：`aboutToAppear`（冷启动）+ `onPageShow`（后台→前台）+
   **`@Watch('onLaunchActionChanged')`（前台热启动）**。真机实测：应用已可见时外部 startAbility
   走 `onNewWant` 更新 AppStorage，但 `onPageShow` 不触发、aboutToAppear 早已跑过 ⇒
   没有 @Watch 这条，动作会静默丢失（日志里 `DSHM-LAUNCH` 有、页面侧一行没有）。
   三层都走同一个 `applyLaunchAction`（消费即清空）⇒ 幂等。
3. **动作执行 = DOM 注入点击**，锚点是官方 i18n 文案
   （`aria-label = t("session.new.label")`："新建会话" / "New session"）。前端快捷键服务
   （`dsh-client-shortcuts`）的 keydown 处理**不检查 isTrusted**（合成事件可用），但默认绑定
   取决于用户目录 ⇒ 点击按钮语义更直白。类名是构建期哈希（`hHd-Xa_…`）不可用。
   **前端没有 "command-palette"**（那是原生旧壳的概念）⇒ 快捷方式只保留「新建会话」一条。

**白名单**（fail-closed：EntryAbility 是 exported，参数可被外部构造）：仅 `new-session`。

### 5.3 ② 意图框架（已实施 + 静态/设备侧验证，2026-10-16）

**接入方式**：**装饰器式**（API 20+，官方推荐）—— 自定义意图 `StartNewSession`。

**为什么不是标准意图**：官方标准意图清单（14 个垂域、约 95 个意图）**没有 AI 编码助手垂类**；
最接近的 `JumpFunctionPage`（ToolsDomain）语义是"跳转功能页"，且其 `llmDescription` / `keywords`
由系统按标准值覆盖 —— 无法表达"新建会话"。自定义意图自带 `llmDescription` / `keywords`，
语义匹配更准；`domain` 取 **`ToolsDomain`（实用工具）**（domain 必须落在官方 14 垂域内）。

**改动清单**：

| 文件 | 动作 |
|---|---|
| `entry/src/main/resources/base/profile/insight_intent.json` | 新建：`insightIntentsSrcEntry` 声明执行文件（约定路径，**无需** module.json5 引用） |
| `entry/src/main/ets/insightintents/StartNewSessionImpl.ets` | 新建：`@InsightIntentEntry` 自定义意图 + `onExecute()` |

**执行链路**（复用桌面快捷方式通道）：`onExecute()`（`UI_ABILITY_FOREGROUND`，与 EntryAbility /
WebApp 页面**同进程同主线程**）只做 `AppStorage.setOrCreate('dshLaunchAction', 'new-session')`
→ WebApp 三层消费点接住 → DOM 注入点击前端「新建会话」按钮。
真机判据：hilog 先出现 `DSHM-INTENT`（本文件）、后出现 `DSHM-ACTION`（页面侧）。

**平台导入的两个坑（2026-10-16 实测踩到并修复）**：

1. **AgentCard 必须带 `appInfo` 的 Bundle/Module/Ability 映射**。官方
   `agent-extension-configuration` 文档的字段表只列了 `appInfo.deviceTypes` / `minAppVersion`，
   但 **SDK schema（`toolchains/modulecheck/agentCard.json`）里 `appInfo` 还有
   `bundleName` / `moduleName` / `abilityName` 三个字段**（对应官方检查清单里的
   "AgentCard 的 Bundle、Module、Ability 映射与工程一致"、FAQ 里的"改包名要同步更新 AgentCard 的 bundleName"）。
   平台导入器依赖它把卡片关联到应用 —— **缺了它，导入后"选择 Agent"下拉框为空、提示"内容不能为空"**。
2. **平台导入件要用正式包名**。平台关联的是 AGC 正式应用（`com.dshm.dshclient`），
   而 beta 工程里的 `appInfo.bundleName` 是 `com.dshm.dshmbeta` ⇒ 交付一份**仅 bundleName 不同**的
   导入件 `dist/agentcard/dshm-agent-config.json`（与工程件逐字段核对：除 bundleName 外逐字等价）。
   → 已同时加入 `AGENTS.md` 的 beta-only 差异清单（同步正式版时必须还原包名）。

3. **平台导入件与工程件的字段集进一步收窄（2026-10-16 第三轮实测）**：带
   `category:"productivity"`（英文）+ `extension:"{}"` + `appInfo` 的版本仍被平台拒（NaNKB / 下拉框空）。
   对照**最新官方文档**（`celia/agent2agent-inapp`，抓 `.md` 原件）与**官方样例仓库**
   （`gitcode.com/openharmony/applications_app_samples` 的 AgentExtensionAbility 样例）：
   平台导入件的示例只含 `agentId/name/description/iconUrl/version/capabilities/
   defaultInputModes/defaultOutputModes/skills`，**不含 category / extension / appInfo**；
   官方样例里 `category` 为**中文**（"生活服务"）。⇒ 平台导入件改用上述最小字段集 +
   `iconUrl:"https://example.com/icon.png"`（官方文档示例值），图标最终在平台"基础信息"里单独上传。
   **工程件（端侧 schema 校验用）保持全字段不动** —— 两份文件的用途不同，不要互相覆盖。
   （该轮"最小字段集"无 category 版被平台明确报"category不能为空"，见下第 4 条。）

   `required`（含 `category`，仅要求非空字符串、无枚举限制）；**NaNKB 是平台 UI 的显示 bug**（文件被正常解析）。
