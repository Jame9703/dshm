## 1. 为什么本批不动壳

三端归属（PC / 平板 / 手机+折叠）刚在 `docs/386` 落地并稳定，两个 `WebApp.ets` 是**形态差异的落点**：平板顶栏、侧栏 56px 轨、手机抽屉、PC 三键托盘都靠各自分支。此时抽共享层会把「刚验证过的差异」和「长期累积的复制」一起搬动，风险与收益不成比例。故本批只做两件事：

1. 新增 `tools/check-dual-shell-parity.mjs`：把 7 个纯共享 ArkTS 文件钉成逐字节一致，任一侧单独改动立即判红（防漂移继续恶化）。
2. 输出本设计稿，供下一轮立项时按批次执行。

**结论**：债务不在分层（五层 HAR 依赖图无环、无反向依赖），而在「整文件复制后微调」这一维护方式。注释/`module.json5`/语音桥措辞的漂移都是它的衍生物。

## 3. 目标结构

新增一个共享 HAR（暂名 `webshell`，`deviceTypes` 必须覆盖 `phone/tablet/2in1` 三设备面）：

```
webshell/                        ← 新增共享 HAR（真源，入库）
  src/main/ets/
    shared/                      ← 7 个纯共享文件（第 1 批先搬）
    shim/                        ← *_SHIM_JS 常量（第 2 批）
    system/                      ← 语音桥 / 卡片 / 备份 / A2A 等公共桥类
entry/                           ← 只留 PC / 平板形态层
phone/                           ← 只留手机 / 折叠形态层
```

两个 HAP 只保留：设备面声明、权限面（entry 17 / phone 9 不变）、各自的顶栏与侧栏策略、以及 `WebApp.ets` 里的形态分支。**模块集合不变 ⇒ 覆盖安装安全**（这是 `docs/381` 用过的判据）。

## 5. 硬约束（任一违反即停）

- **权限面不变**：entry 恒 17 条 / phone 恒 9 条，判据唯一处 `tools/check-permission-surface.mjs`。
- **三端归属不变**：`docs/386` 矩阵；MatePad Edge / ProMax 强制 PC，不得因抽壳改判。
- **版本号不变**：1.1.8 / 1010015，除非用户明确要求升级。
- **核心侧改动必须重打容器**：涉及 `hostcore/**` 时固定链 `pack-core.mjs --skip-install --place-in-app` → 重出全部包 → 核验 `APP → hsp → 核心 zip → 插件` 三层标记。
- **每阶段只动一个变量**：用户明确反对「修一个坏一个」，禁止把共享化与功能修复混在同一批。
