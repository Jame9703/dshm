# 266 · 手机快捷方式目标模块错配与 Beta 验证（1.1.6）

> 日期：2026-10-26
>
> 版本：`1.1.6 / 1010007`
>
> 核心：`0.2.1-rc.3+dshm.96`

## 1. AGC 审核反馈

审核反馈为：桌面长按应用后出现“会议模式”“新建会话”，点击后没有反应，
快捷方式名称与实际功能不匹配。

## 2. 根因

双端多 HAP 改造后：

| 包 | 实际模块 | 旧快捷方式目标 |
|---|---|---|
| `entry-default.hap` | `entry` | `entry/EntryAbility` |
| `phone-default.hap` | `phone` | **`entry/EntryAbility`** |

手机只安装 `phone-default.hap`，不会安装仅支持 tablet / 2in1 的
`entry-default.hap`。因此手机会显示快捷方式菜单，但点击时 Want
指向不存在的 `entry` 模块，`EntryAbility` 不会被启动，表现为完全无响应。

审核时的“会议模式”还可能来自旧版本启动器缓存。旧版曾把该快捷方式设为可见，
仅改成 `visible: false` 不能保证升级后清除所有设备上的旧启动器项。

## 3. 修复

- [手机快捷方式](../phone/src/main/resources/base/profile/shortcuts_config.json)
  的“新建会话”目标由 `entry/EntryAbility` 改为 `phone/EntryAbility`。
- 手机快捷方式配置不再声明 `id_meeting`；会议功能代码保留，仅移除手机快捷入口。
- [会议与快捷方式门禁](../tools/check-meeting-mode.mjs) 同时校验 `entry`、`phone`：
  Want 的 bundle / module / ability 必须与实际 HAP 匹配，手机不得重新声明
  会议快捷方式；新增两个变异对照臂，任一回退必须判红。
- [Beta 构建器](../tools/build-beta.mjs) 在签名 HAP 入包前直接读取
  `shortcuts_config.json`，再次校验目标模块与 beta bundle，防止源码正确而产物回退。
- 正式包 Host 继续使用 `127.0.0.1:3120`，Beta 固定使用
  `127.0.0.1:3121`。真机复核发现正式包与 Beta 同时运行时，Beta 曾回落到
  3120 并报 `EADDRINUSE`；运行期包名现优先从
  `UIAbilityContext.applicationInfo.name` 读取，`bundleManager` 只作兜底。
- 浏览器自动化桥也按同一偏移隔离：正式包使用 `19390`，Beta 使用 `19391`。
- 新增 `check-host-port-isolation.mjs` 与 5 个变异对照臂，Beta 构建前强制运行。

## 6. 手动验收

1. 使用 Beta 覆盖安装，不卸载、不清应用数据。
2. 冷启动后长按 `DSHM beta`，点击“新建会话”，应进入并创建一个新会话。
3. 应用已在前台时再次点击“新建会话”，应再次创建会话，不应静默丢失动作。
4. 全新安装的手机快捷方式菜单不应再出现“会议模式”。
5. 正式包保持运行时，Beta 的 Host 应监听 3121，并正常生成本次进程的
   `host-ready.json`；正式包的 3120 不受影响。
6. 正式包保持运行时，Beta 浏览器桥应监听 19391，正式包继续使用 19390。
7. 若旧设备仍显示升级前缓存的会议快捷方式，记录设备型号和截图；不得通过
   卸载或清理 el2 数据来处理。
