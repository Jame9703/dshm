## 1. 数据形态（这次是照着真实设备与源码核的）

真机 `$DSH_HOME/sessions` 实测：

```text
sessions/
  --data-storage-el2-base-haps-entry-files-dsh-home-whale-work--/
  --storage-Users-currentUser-data-DSHM-deveco-workspace--/
  --storage-Users-currentUser-test--/
```

目录名就是上游 `projectKey(cwd)` 的输出。编码规则（源码逐字）：

- `/` `\` `:` → `-`（连续折叠成一个）
- `[A-Za-z0-9._-]` 原样保留
- 其他字符 → `~XXXX`（4 位大写十六进制）
- 首尾包 `--`，总长上限 251

会话目录内的文件名（上游 `sessionFormatLogFilename` + 压缩后缀）：

| 代际 | 文件名 |
|---|---|
| v0 | `session.jsonl.zstd`（**无编号**） |
| vN | `session.vN.jsonl.zstd`（N 不允许前导零） |

对应判据正则（上游原样）：

```js
/^session(?:\.v([1-9][0-9]*))?\.jsonl$/
```

## 2. 新增了什么

| 文件 | 作用 |
|---|---|
| `platform/src/main/ets/system/SessionSyncScope.ets` | 清单扫描：`buildManifest` / `generationVersionOf` / `isExcludedName` / `toManifestJson` / `relativePathOf` |
| `platform/src/main/ets/Index.ets` | 导出上述能力 |
| `tools/check-session-sync-scope.mjs` | 门禁：26 条判据 + 3 个对照臂（已入 CI） |

### 2.1 三条硬纪律（写进文件头注）

1. **只扫描、不写入** —— 本模块不修改任何会话文件（恢复是 P4）。
2. **排除面显式**：`cache` / `cores` / `node_modules` / `*.tmp` / `*.stale` / `.dsh-mkdir-*`
   一律不进清单。其中 `cores` 最要命：每棵约 350 MB，传上去既无意义又烧流量。
3. **不猜路径** —— `sessionsRoot` 由调用方传。

### 2.2 两个容易被忽略但必须做对的设计

| 设计 | 为什么 |
|---|---|
| 清单**排序** | 不排序时 `listFileSync` 顺序不稳定 ⇒ 两次扫描 diff 假阳性 ⇒ 每次同步都"发现变更"退化成全量重传 |
| 对外 JSON **不含绝对路径** | 云端索引里出现 `/data/storage/el2/...` 既泄漏本机结构，也让跨端比对失效 |

## 3. 门禁：`check-session-sync-scope`

### 3.1 判据（26 条）

| 组 | 内容 |
|---|---|
| A（11） | 代际解析：`session.jsonl`→0、`session.v3.jsonl.zstd`→3；`v01` / `v0` / 大写 / `.tmp` / 非 session 前缀 ⇒ -1 |
| B（10） | 排除面：`cache`/`cores`/`node_modules`/临时文件判真；工作区目录名、普通名不误伤 |
| C（3） | 对外 JSON 不含绝对路径、带 schema 号、只留 `version`/`bytes` |
| D（2） | `relativePathOf` 与上游命名同形 |

### 3.2 对照臂（3 个，全红）

| 变异 | 结果 |
|---|---|
| 排除面去掉 `cores` | ✅ 判红（会把 350 MB/棵 核心树传上去） |
| 放宽前导零规则（`v01` 当成 `v1`） | ✅ 判红（2 条） |
| 对外 JSON 带出本机 `root` 路径 | ✅ 判红 |

### 3.3 这条门禁也在**真跑**行为

与 `check-cli-shim-semantics` 同一手法：从 `.ets` 里抽出函数体、剥掉类型标注、
用 `new Function` 求值后**真的调**，断言输入 → 输出。正则 grep 证明不了"`v01` 会不会被误收"。

## 4. 本轮踩的三个坑（都写进了代码/门禁注释）

| 坑 | 现象 | 处置 |
|---|---|---|
| **ArkTS 禁止内联对象字面量类型** | `Array<{ version: number; bytes: number }>` 报 `arkts-no-obj-literals-as-types` | 拆成具名接口 `ManifestGeneration` / `ManifestSession` |
| **`.ets` 的类型标注不能直接 `new Function`** | `Unexpected token ':'` | 门禁里加 `stripTypes()`，只做最小改写（去参类型/返回类型/`as`） |
| **`String.replace` 只换第一处** | 变异瞄到注释里的同一段正则，实现没动 ⇒ 变异"生效"但判据不红 | 按行定位再替换 |

第三个坑和前几轮"删掉 `exit 1` 但末尾还有兜底 `exit 1`"是**同一类**：
变异体本身写错时，门禁会给出"假的没牙"结论。**变异生效 ≠ 行为改变**。

### 6.1 需要你决定的一件事：工作区怎么对齐

会话目录按 **cwd 绝对路径** 分组（`--storage-Users-currentUser-test--`）。同一台 PC 和手机路径不同：

```text
PC：  .../Download/com.dshm.dshclient/我的项目
手机：.../Download/com.dshm.mobileclient/我的项目
```

两种做法：

- **A 自动按目录名匹配**（末段相同就当同一工作区）：省事，但同名不同项目会串；
- **B 首次同步时让用户确认一次**（"云端工作区 X ↔ 本机工作区 Y"）：多一步，但不会串。

规划里我建议的是 **B**。你确认后我按此实现映射表。
