# 272 · 平板侧栏收口（不干预官方）+ 自绘顶栏窗口拖动

> 日期：2026-10-28 ｜ 状态：**已落地**（含 Beta 重编与交付）
>
> 用户报告（普通平板，`deviceType=tablet`，非 Edge / Pro Max）：
> ① 冷启动进去**只有会话区，左侧边栏根本不显示**；
> ② 新建工作区目录之后，**点一下右侧边栏才出现**；
> ③ **频繁自己展开收起**（抖动）。
> 用户口径：**"把侧边栏的逻辑就保持官方默认的即可，我指的是 PC 那种 —— 没人手动点击收起的话，
> 他就一直展开，不论什么时候都是展开的"**，并按评审结论执行 1–3；另报：
> ④ **自由窗口下窗口拖不动**。

---

## 1. 复核结论（先说清"为什么会这样"，再改）

### 1.1 口径沿革（两份文档打架，以晚者为准）

| 文档 | 日期 | 普通平板侧栏口径 |
|---|---|---|
| `docs/247` | 10-24 | 平板**不画原生顶栏**；左侧栏**横屏常驻、竖屏默认收起只留入口**；竖屏进入只自动收起一次 |
| `docs/262` | 10-25 | 平板**恢复 PC 风格原生顶栏**（横竖屏常显）；左侧栏**默认展开并保持常驻**；官方 Web 按钮隐藏，由原生顶栏按钮接管 |

⇒ 262 之后，代码里多了一条**点击式常驻自愈**（`ensureTabletExpanded()`：每 300ms 巡检，
看到"非用户收起"就点开官方按钮）与一条**平板专属几何**（收起后 56px 窄轨）。

### 1.2 三个症状的根因（都在"我们自己的干预"上，不是官方）

**① 冷启动只有会话区** —— 两条我们自己的规则叠出来的：
- 通用规则 `html[data-dshm-sidebar="collapsed"] .dshm-frame{grid-template-columns:0 … !important}`
  **对所有档生效**；而平板那条 56px 窄轨只在 `<html>` 真的挂了 `dshm-tablet` 时才赢
  ⇒ **`dshm-tablet` 未挂上/迟到时（桥还没答、首帧），平板左栏被压成 0 列**（连窄轨都没有）。
- 点击式自愈**只认官方按钮的 `aria-label`**，与官方**真实布局**不同步：官方按窄视口切了自己的
  形态而读数仍说"展开"时，自愈**什么都不做** ⇒ 冷启动就一直是"没有左栏"。

**② 点右侧边栏才出现** —— 同一条 0 列规则的"解除条件"变了：点右栏会触发 React 重排 ⇒
`[data-sidebar-collapsed]` 消失/重建 ⇒ `stateOf()` 翻成 `expanded` ⇒ 我们的 0 列规则不再命中
⇒ 官方几何回来（所以看起来是"点右栏把它点出来了"，其实与右栏无关）。

**③ 频繁自己展开收起** —— `clickToggle()` 的**乐观应用 + 20ms 对账**（`docs/136` 为点击延迟加的）
与自愈互相覆盖：乐观先写一个状态、官方没真翻时 500ms 后纠回、下一拍自愈又点一次
⇒ 周期性 展开→收起→展开；而且自愈只在"用户手点官方按钮"时才置 `manualTabletCollapsed`，
**自己的自动点击不置位** ⇒ 没有"放弃"出口。

### 1.3 ④ 拖不动的根因

我们把系统标题栏隐藏了（沉浸链），系统那条"拖标题栏移动窗口"的路就没了；而 SDK 明确写了：
**关掉标题栏拖拽后，要用 `window.startMoving()` 在应用自己的热区里拖**。
实测本仓 `startMoving` **零命中**、自绘顶栏**没有任何触摸处理** ⇒ 自由窗口里抓顶栏拖不动。

## 2. 改了什么

### 2.1 侧栏：删掉我们的全部干预（按用户 1–3）

| # | 改动 | 位置 |
|---|---|---|
| 1 | **删除点击式常驻自愈整条链**：`ensureTabletExpanded()` 及其 tick 调用、`manualTabletCollapsed`、`lastTabletKeepOpenAt`、`programmaticToggleClick`（连同"记录用户点击意图"的捕获监听）、`clickToggle(manual)` 的 manual 分支 | `SIDEBAR_SHIM_JS` |
| 2 | **删除平板专属几何**：那条 56px 窄轨整条撤除（用户口径"不需要窄轨"）；并把"收起 ⇒ 整列 0"**收窄到非平板档** ⇒ `html:not(.dshm-tablet)[data-dshm-sidebar="collapsed"] …` | 同上 |
| 3 | **`dshm-tablet` 只保留"入口接管"**：隐藏官方 Web 侧栏按钮（中英文两条 `aria-label`，含 300ms 内联自愈）、不创建页面浮动 ⊞；抽屉媒体规则继续带 `:not(.dshm-tablet)`（防平板被当成覆盖式抽屉） | 同上 |

⇒ 平板的**状态与几何全交官方**：官方展开就展开（= 用户要的"没人手动收起就一直展开"），
官方收起是什么样就什么样。我们只负责"入口长在原生顶栏按钮上"。

### 2.2 `shouldShowAppTopBar()` —— **不需要改**（回答用户提问）

它现在是：

```text
phone                                => false
tablet + desktopForced（Edge/ProMax/MateBook） => 原"仅横屏"策略
tablet + !desktopForced（普通平板）  => true（横竖屏常显）
PC / 2in1                            => true
```

本次要改的是**侧栏的状态与几何**，而普通平板"顶栏恒显"正是**保留"原生顶栏按钮作为侧栏入口"**
的前提（262 的口径）：一旦不显顶栏，平板就只剩官方那颗被我们隐藏的按钮，等于没有入口。
⇒ **这一条保持不动**；Edge / ProMax / MateBook 的 desktopForced 分支也不动。

### 2.3 自由窗口拖动：给自绘顶栏接 `startMoving()`（用户 ④）

```ts
private beginWindowDrag(): void   // window.getLastWindow(...) → win.startMoving()
```

- **绑在顶栏尾部空白区**（原来是 `Blank()`），**不绑整条顶栏** —— 整条绑会让"按下按钮"也起拖；
- 时机按 SDK 硬约束：只在 `onTouch` 的 `TouchType.Down` 里调；
- 非自由窗口/能力受限时 SDK 抛 `1300004` / `801`，属预期 ⇒ **只记一行 info**，不打扰用户；
- 加 `windowDragBusy` 闸门（`startMoving()` 是异步的，连点会触发 SDK `1300001`）；
- **只动 entry（PC / 平板）壳层**：phone 模块没有自绘顶栏（手机全屏无此需求），未改。

## 6. 需要你真机复验 / 一个待决问题

请重点看这三件事：

1. **普通平板冷启动（横屏）**：左栏应当**直接是展开的**，且不再抖动；
2. **点原生顶栏左上按钮**：收起/展开一次到位（收起形态由**官方**决定，我们不再声明窄轨）；
3. **自由窗口**：抓**顶栏中部空白**（不是按钮）应当能把窗口拖走。

**待决**：如果**竖屏**下官方自己把侧栏切成"收起/抽屉"（官方是宽度驱动的），那按"保持官方默认"
它就会是收起的 —— 与你要的"不论什么时候都是展开的"不一致。真机若确实如此，
我再做一版**纯几何**的平板档覆盖（把官方的窄视口收起压回展开态，**不再用点击式自愈**，
因此不会抖）；要不要做，等你竖屏实测后拍板。
