# 234 · API 23 工作区能力误报修正（1.1.9）

> ℹ️ **历史轮次号，非当前发布版本**：当前基线为 1.1.8 / 1010015（见 `AppScope/app.json5`）。

> 日期：2026-10-24
>
> 设备证据：`2026-10-24 07_14_04.log`，API 23 手机云调试。

## 1. 实测结论

- 清除云调试旧任务后，DSHM 主进程 PID `64852` 与 ArkWeb renderer `723`
  均正常启动。
- 日志中没有应用崩溃、AppFreeze 或 JS Runtime 致命错误。
- 用户点击添加工作区后仍直接使用专属下载目录，没有出现可操作的手动目录
  选择浮层。
- 仅检查 `canIUse(SystemCapability.FileManagement.UserFileService.FolderSelection)`
  不够：该能力位在目标设备上可能报可用，但实际 FOLDER 选择不可用，最终仍
  进入旧兜底。

## 2. 修法

手持端同时检查系统 API 版本：

```text
isHandheldForm() && deviceInfo.sdkApiVersion < 26
  ⇒ 直接打开应用内工作区目录浏览器
```

只有 API 26 手机/平板和 2in1 才继续参考 `canIUse()` 并调用系统
`DocumentViewPicker`。

内置浏览器继续提供：

- 应用专属 `Download/com.dshm.dshclient`；
- 应用沙箱 `files/workspace`；
- 子目录、上一级、新建目录、取消、确认。
