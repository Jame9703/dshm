**问题一：滑动消息区时输入框跟着滚出屏幕**（MatePad Pro 13.2 / WEBW00 复现）

两份独立证据指向同一层：

1. 核心 `0.2.1-rc.5 → 0.2.2-rc.1`，`composerSeat@active` 新增 `will-change:transform`。它把元素提升为独立合成层，Chromium（ArkWeb 内核）下 sticky 在滚动容器里不再重算钉住位置。
2. 只要滚动区里存在 `[data-conversation-composer-overlay]`（轨迹 / 统计视图根节点，keep-alive 时不可见也在 DOM 里），官方 `:has()` 分支把座位切成 `position:absolute` —— absolute 在滚动容器里必然跟着滚。

修法：两壳新增 `COMPOSER_PIN_SHIM_JS`，仅在**会话正文**（存在 `[data-conversation-scroll]`）且**非 hero 态**时给 `[data-composer-seat]` 挂 `dshm-seat-pin`：

```css
.dshm-seat-pin{position:sticky !important;bottom:0 !important;
  top:auto !important;left:auto !important;right:auto !important;
  will-change:auto !important}
```

`will-change:auto` 是消掉合成层这个根因，而不只是把定位改回 sticky；`left/right/top:auto` 清掉 absolute 分支遗留的偏移。不满足条件（欢迎页 / 设置 / 插件页）就摘类，官方布局不动。

**问题二：顶部栏按钮点不动**

`files/diag-top-inset` 原文显示 `sysTop=78` → `apply topPx=78` 之后 1ms 又出现 `apply topPx=0`，多次重复（11:20 / 11:30 / 12:10 / 12:16）。`applyTopInset` 只在值变化时落盘，说明这个 0 确实被写入。

唯一入口是 `onTopAvoidChanged()` 直接把系统回调的 `opt.area.topRect.height` 交进来；窗口装饰重建 / 状态栏临时隐藏时系统会发 0 ⇒ 顶部让位清零 ⇒ 自绘顶栏上移到状态栏下面被系统层盖住 ⇒ 按钮"看得见但点不动"。

修法：`applyTopInset` 对 `0` 保留已有的非零值（真正的 0 只在 PC / 手机档首次 arm 出现，不受影响）。诊断会记一行 `skip topPx=0（保留上次非零）`。

**门禁**：`tools/check-composer-pin.mjs` —— 两壳垫片存在且接入、仅会话正文、排除 hero、钉底四条规则齐全、entry 让位含 0 保护、模板字符串干净闭合；6 个变异体全部判红。

**边界**：本机无 hdc，真机需复核"长会话滑动时输入框不动""顶部按钮可点"两项。
