## 1. 为什么两套入口是缺陷而不是"更多入口"

官方设置面板的分区列表由官方 React 渲染。插件 `@deepseek-ai/dshm-cloud-sync` 经
`settings.section` 注册后，「云同步」**已经在官方导航里**（与「通用设置/内置插件」同构）。
此时再往 navList 末尾 append 一颗同名按钮，用户看到的是**两行「云同步」**；
且注入那颗未登录时点了没反应（#2）。结论：注入入口是 `docs/317` DOM 注入时代的遗留，
分区方案落地后就该退场。

## 2. 为什么删掉 startAbility 登录绕路

`launchType: specified` 下，`startAbility` 自己会走 `onNewWant`（前台）或新实例（后台），
于是需要 EntryAbility 发布参数 → AppStorage → 页面三层消费（aboutToAppear / onPageShow / @Watch）
才能保证各路径都弹登录。而**当前页面本来就能直接挂 `CloudSyncSettings` 面板**——
entry 壳一直就是直接置两个状态。绕路徒增一条静默失效链（上一轮就因此补过三层消费），
删掉后行为与 entry 完全一致、代码少约 120 行。
