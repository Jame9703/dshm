## 1. 留档：为什么"读不到其他目录"不是我们的代码缺陷（已按用户指示不再处理）

实测（本机 2in1，应用域 `u:r:develop_tools_hap:s0`，uid `20020319`）：

| 路径 | 列出 | 读已知路径 | 写已知路径 |
|---|---|---|---|
| `~`（用户根） | EPERM | — | — |
| `…/Download`、`…/Documents`、`…/Desktop`（三个根） | **EPERM** | — | **可以** |
| `…/Download/com.dshm.dshclient`（本应用认领目录） | 可以 | 可以 | 可以 |
| `…/data/DSHM-deveco-workspace`（已授权目录） | 可以 | 可以 | 可以 |
| `…/data/AGC-operations`、`…/data/HarmonyOS-KB`（未授权） | EPERM | **EPERM** | EPERM |

三条判据把性质钉死了：

1. **报的是 EPERM 而不是 EACCES**（`ls`/`open` 都是 "Operation not permitted"）⇒ 不是普通读写位；
2. `ls -Z` 显示这些目录**标签完全相同**（`u:object_r:hmdfs:s0`）⇒ 也不是 SELinux 标签差异；
3. 「`Documents/` 根**能写文件却禁止枚举**」这一组只可能来自**按应用的文件策略层**
   （三个根给"文件级读写"、不给枚举；其余目录要**逐个授权**）。

而「已授权目录」的证据在应用自己的诊断里（`files/diag-folder-grants`，实读）：

```text
remember persisted=true path=~/data/DSHM-deveco-workspace uri=file://docs/… 登记=ok persist=ok check=[true]
restore 2/2 已启用：…/DSHM-deveco-workspace=ok | ~/test=ok
```

⇒ 扩展访问面的**唯一合法途径**是 **picker 授权一次并持久化**（`FILE_ACCESS_PERSIST`，本包已声明）；
本机 2in1 + API 26，系统目录选择能力可用（`folderSelectionAvailable()` = `canIUse(FolderSelection)`）。

**结论**：不是代码缺陷、也不是 chmod/权限声明能修的（另有一条 `ACCESS_USER_FULL_DISK`
属 `manual_settings` 类，配合"全盘权限"再谈）。本轮**未做任何改动**。

## 2. 根因：两个漏点叠出来的"点了不跳浏览器"

### 漏点 ① 垫片只接管"新窗口"锚点（`WebApp.ets` 原点击分支）

```js
if (anchor.getAttribute('target') !== '_blank') { return; }   // ← 只认新窗口
```

官方正文里的 Markdown 链接 `[文字](https://…)` 渲染出来**不带** `target` ⇒ 这条判据直接
`return`，**一条普通外链都不接管**。于是点下去就是 ArkWeb 默认行为。

### 漏点 ② Web 组件没有 `onLoadIntercept`

`multiWindowAccess=false`（默认）⇒ `target="_blank"` / `window.open` **一律丢弃**；
而**普通锚点 / `location` 赋值 / 表单提交**走**页内导航** ⇒ 外部页在**应用自己的 WebView**
里加载 —— 把界面替掉。授权页更严重：`docs` 早有定论（本文件的同源垫片头注）——
**授权页绝不能在本 WebView 内打开，否则应用页面被 204 空页替换**。

⇒ 两个漏点合起来就是用户看到的现象：**既不跳系统浏览器，界面还可能被外部页顶掉**。

## 3. 修法（两侧互补）

### 3.1 网页垫片：接管**所有** http(s) 锚点，并放行应用自身

```js
var href = anchor.href;
if (!isHttpUrl(href)) { return; }
if (isSameOriginAsApp(href)) { return; }   /* 应用自身页面（Host 在本机回环）⇒ 放行 */
```

新增 `isSameOriginAsApp(url)`：拿 `location.origin` 比前缀。没有它，上面那句会把
**应用自己的导航也拦成外开**（这正是不该出现的反向错误）。

### 3.2 原生层兜底：`.onLoadIntercept(...)`

```ts
.onLoadIntercept((event: OnLoadInterceptEvent): boolean => {
  const target: string = event.data.getRequestUrl();
  if (!this.isExternalNavigation(target)) { return false; }   // 放行本机回环与内部协议
  openExternalUrl(target).then(...);                          // 交系统浏览器
  return true;                                                // 拦下页内导航
})
```

新增**纯判据** `isExternalNavigation(url)`：只把 `http(s)` 且**非本机回环**
（`127.0.0.1` / `localhost` / `[::1]`）的目标当外链；`about:` / `data:` / `blob:` /
`javascript:` 与 `resource://`、`file://` 等一律放行（内部资源，拦了会弄坏界面）。
判据用 `startsWith/substring/split` 写，不用正则字面量（ArkTS 支持面窄于浏览器）。

**两侧分工**：垫片给"点击即二次确认"的 UX（授权页仍走 `auto` 直接外开），
原生回调保证"**无论怎么发起**都不在应用内打开外链"（`location` 赋值、表单、脚本注入都兜住）。
拦下与失败都落痕迹：`files/diag-openlink` 增写 `nav <url>` 行，失败只 `warn` 不弹窗打扰。

本轮两个漏点正是从这里漏出去的。现补：

  G0 能切出 `OPEN_LINK_SHIM_JS` 模板体、**且体内无第二个反引号**（见 §5 教训）；
  G1 不许再有"只认 `target=_blank`"的判据；G2 必须有 `isSameOriginAsApp`；
  G3 原生侧有 `isExternalNavigation` 纯判据；G4 Web 组件挂了 `onLoadIntercept` 且取

## 5. 本轮踩到的坑（值得记）

我在垫片的 JS 注释里写了反引号（`…`），而**垫片整体是一个 ArkTS 模板字面量** ⇒
反引号会提前闭合模板，**编译期才会炸**。这与 `docs/272` 那次（`check-sidebar-shim-css`
抓到同类问题）是同一个坑。⇒ 新增的 G0 把这条判据挂在**本门禁**上，往后写垫片注释的
反引号会在提交前就被拦住。

另一个自证细节：G0 的切片最初把**模板自己的开定界反引号**也算进了"体内"（`shimStart`
落在声明行首），以及最初用裸名字 `OPEN_LINK_SHIM_JS` 定位——而它在注释里出现过多次
（第 73 行「见 OPEN_LINK_SHIM_JS」）⇒ 切到了**别的垫片**的终止符。两处都已改成
"锚在声明 + 从开定界符之后切"。

## 8. 真机复验清单

1. **正文里的 Markdown 链接**（`[文字](https://…)`）：点一下应弹「打开外部浏览器？」→ 确认后
   **跳系统浏览器**（不再是把外部页加载进应用内）；
2. **授权链接**（`/dsh/authorize`、`/oauth/authorize`）：应**直接外开**，且应用页面**不被 204 空页替换**；
3. 落痕：`files/diag-openlink` 应出现 `confirm <url>` / `auto <url>` / **`nav <url>`**；
   `files/diag-web-console` 里应出现 `[dshm-link] deliver confirm|auto <url>`；
4. 反例保护：应用**自身**页面的跳转（同源、`127.0.0.1:<port>`）必须照旧在 WebView 内完成，
   不能被当成外链弹窗。
