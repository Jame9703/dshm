## 1. 手机首启进不去（日志实证 → 修法）

### 1.1 证据（`2026-10-31 08_32_01.log`，手机）

```text
08:30:3x  mission 12314（进程 42309）运行中
08:31:03  用户从最近任务划掉 → RecentDelete / mission 销毁
08:31:05  42309 exit code:0；同一秒 nwebspawn 43772 被 signal:9
08:31:10  再点图标 → 新进程 44591 → mission 12315
08:31:10  44591  E/C01317/AppKit: [JAS935]get 'onAcceptWantAsync' object failed   ← 关键
08:31:10  sceneboard: startSceneFromOther{... launchType:2, isNewInstance:false,
                         appInstanceKey:}                                        ← key 为空
```

SDK 原文（`@ohos.app.ability.AbilityStage.d.ts`）：

> Starting from API version 20, this callback (`onAcceptWant`) is **not triggered** when
> `AbilityStage.onAcceptWantAsync` is implemented.

即：只实现同步版时，系统要走"先找异步版、找不到再回落"的路径；这条回落路径在
**进程刚被杀 / 首次安装** 的冷启时刻并不总能走通，于是启动被搁置 —— 正是用户描述的
"点不进去，杀进程再点才行"。

### 1.2 修法

`phone` 与 `entry` 的 `AppAbilityStage` 各补一个 `onAcceptWantAsync(want): Promise<string>`，
与同步版**共用同一个判定函数** `resolveInstanceKey(want)`（防两份逻辑漂移）：

- 异步版**绝不 reject**（reject = 拒绝本次启动 = 点了图标毫无反应）；
- 解析异常已在 `resolveInstanceKey` 内兜底为主窗 key；
- 打一条 `onAcceptWantAsync → 实例 key` 日志，作为首启/多窗口排查的第一手证据。

## 2. 登录改为分区内静默授权（方案 C）

### 2.1 旧链路的割裂点

```text
官方设置分区（React）[点登录]
  → 桥 cloudSyncAction('login')
  → 原生置 cloudSyncOpen = true
  → 整屏盖上 800×min(800,vh-48) 的原生 ArkUI 面板          ← 割裂 ①（尺寸/材质换了一套）
  → 面板内再叠官方 LoginPanel（协议勾选 + 多种登录方式）    ← 割裂 ②（第三种视觉）
```

### 2.2 新链路

```text
官方设置分区（React）[点登录]
  → 桥 cloudSyncAction('login')
  → 原生 silentSignIn()：authentication.LoginWithHuaweiIDRequest{ forceLogin: false }
       ├─ 系统已登录华为账号 → 直接拿 unionID → 分区就地变"已登录"
       └─ 未登录 → 错误码 1001502001 → 分区里就地提示"请先在系统设置中登录华为账号"
  （全过程不出现任何第二界面）
```

### 2.3 实现要点

| 项 | 做法 | 理由 |
|---|---|---|
| API 选择 | `@kit.AccountKit` 的 `authentication`（不是 `LoginPanel`） | `forceLogin=false` 就是"静默"：已登录直接给凭据，未登录回错误码而不弹页 |
| 凭据面 | **只取 `unionID`**；`authorizationCode` / `idToken` 不读、不存、不上报 | 同步只需要"是谁"；少读一个字段就少一条泄漏路径 |
| 失败语义 | `SilentSignInKind` 四档（ok / not_signed_in / unsupported / failed） | 不把"系统没登录账号"说成"登录失败"——那是状态描述 + 可执行下一步 |
| 并发 | `loginBusy` 闸门 | 连点不会发多次请求 |
| 文案 | 撤掉"登录即表示同意……" | 静默授权**没有**协议勾选步骤，那句文案等于替用户确认了他没点过的事；改为陈述事实："登录只读取账号标识用于同步归属" |
| 面板 | `CloudSyncSettings` 移除 `LoginPanel` / `loginParams` / `loginController` / `showLoginPanel` | 登录不再离开分区 |

> **`brand_app_name` / `brand_icon` 仍保留**：它们是 platform 自己的资源，虽不再被登录面板使用，
> 但属于已生成资产；如后续确认无引用可一并清理（本次未删，避免超范围改动）。

## 3. 性能收口（CPU / 内存）

日志读数结论：三份日志**均无** OOM / lowmemorykiller 命中；`XPERF_SERVICE` 失败、
`AceWeb no registered processId`、`sched_setscheduler set FIFO failed` 均属**系统侧**噪音
（render_service / privacycenter / 系统组件自身也在打），不是我们的问题。

属于我们、已改的三处：

| # | 问题 | 改法 | 效果 |
|---|---|---|---|
| 1 | 云同步分区**每秒**轮询，且页面不可见时照跑 | `POLL_MS` 1000 → **1500**；`visibilitychange` 失焦**停摆**；可见瞬间补一拍；`MIN_REFRESH_MS=800` 限流 | 后台轮询归零；跨 ArkWeb 边界调用减少约 40% |
| 2 | 原生 `cloudSyncState()` 每次调用都触发一次 RDB 统计查询 | 两壳 `refreshCloudStats()` 加**时间节流** `CLOUD_STATS_MIN_GAP_MS = 3000`（只做并发去重不够：上一查刚结束下一次又发） | 面板长开时的 RDB 查询从"每轮询一次"降到最多每 3s 一次 |
| 3 | Host 每次冷启动做一次**注定失败**的 `dlopen(pty.node)`，真机固定刷 3 组 `MUSL-LDSO ... errno=22` | 结论缓存到 `$DSH_HOME/runtime-facts.json`，只缓存"仍被系统拦"这一稳定结论；`DSHM_PTY_DLOPEN_PROBE=on` 可强制重探 | 冷启动少一次必然失败的 dlopen + 数行框架日志 |

> **诚实边界**：`MUSL-LDSO` 那几行由 **musl 动态加载器**打印，应用无法关闭；
> 我们能做的是"不再每次都去撞一次"。E44 模式（闭包缺）**不缓存**，因为它会随依赖装配而变。

## 7. Web 内品牌素材与标题（追加项）

用户口径：「web 里面左上角原来 deepseek harness 品牌素材换成新 logo 的黑色版本，还有会话区的品牌素材
和 title，根据惊鸿一瞥做一下发散换成一句话，最好四字，惊鸿换成鲸鸿，润色一下再替换」。

### 7.1 左上角品牌标

上游 `sidebar.brand.mark` 槽位放的是**单色鲸鱼 SVG**（`dsh-client-ui-sidebar` 的
`_brandMark`，24px）。做法：

| 步骤 | 实现 |
|---|---|
| 出素材 | `tools/make-icon.py` 新增产出 `entry/src/main/resources/rawfile/web_brand_mark.png`（96px 黑剪影）与 `_dark`（白剪影） |
| 内联 | 从黑色剪影**逐行游程**抽出 SVG path（982 B），作为 ArkTS 常量 `BRAND_MARK_PATH` 内联进垫片 —— ArkWeb 页面拿不到 `rawfile`，内联是唯一稳妥路径 |
| 上色 | 用 CSS `mask` + `background:currentColor`：浅色主题黑、深色主题白，**一个 path 两套主题**，不必出两张切图 |
| 作用面 | `[class*="_brandMark"]`（侧栏）与 `[class*="_titleGroup"]::before`（会话区 Hero） |

> **为什么是单色剪影**：那个槽位是 **24px 单色图标位**，彩色 logo 在 24px 下会糊成色块，
> 也与侧栏其它单色图标语汇冲突。用户说的"黑色版本"正是这个口径。

### 7.2 会话区文案

原句「开始一个任务」→ **「鲸鸿一瞥」**。

发散过程（保留"一瞥"的轻灵感，去掉"惊"换"鲸"）：

| 候选 | 评价 |
|---|---|
| **鲸鸿一瞥** ✅ | 与"惊鸿一瞥"同音近形、四字、直接点名品牌、保留"一眼惊艳" |

| 鲸跃云海 / 鲸起鸿飞 | 意象远，丢了"一瞥"的轻 |
