## 0. 一页结论

| 问题 | 答案 |
|---|---|
| 官方 AI 的 API 说法对吗 | **核心正确**：`uiMaterial`（`@ohos.arkui.uiMaterial.d.ts`，API 26）、`systemMaterial`（`CommonMethod` 通用方法）、`ImmersiveMaterial`/`ImmersiveStyle`/`MaterialState`/`MaterialLevel` 全部在 SDK 实存——**我 279 的结论错了，需要修正** |
| "生效范围"约束（仅标题栏/TabBar）对吗 | **SDK 无此原话**，且**与仓内真机证据冲突**（MeetingPanel 在普通 Column 上挂 `systemMaterial`，docs/196 真机验证过生效）。该约束**不可采信为硬规则**，但"官方建议局部使用"的方向是对的（docs/196 的染蓝教训也支持） |

## 2. 修正 279 的错误

| 279 的结论 | 修正 |
|---|---|
| "沉浸光感 = backgroundBlurStyle + AdaptiveColor + ThemeColorMode 三件套" | **错**。那是 API 10-14 的**老材质体系**；API 26 的沉浸光感是 **`uiMaterial`/`systemMaterial`/`ImmersiveMaterial`**（我漏搜了 `api/` 目录） |

## 3. 重新规划（基于求证后的真实面）

### 3.0 现状盘点（可复用的资产）

| 资产 | 状态 |
|---|---|
| 应用级开关 | ✅ 两模块 `UIMaterial.state=enable` 已配（10-11） |

| 染蓝教训 | ⚠️ WebApp 整块铺材质 ⇒ 染蓝糊字（docs/196）；**材质只挂常驻外壳/小控件** |
| 手机档 | 未接（phone 的 WebApp 无材质代码） |

### 3.1 分层目标（修正后的"全 UI 走鸿蒙特性"）

```
层 0  应用级        UIMaterial.state=enable（已有，勿动）
层 1  弹窗/半模态    AlertDialog/Sheet/Popup/Menu 的 options.systemMaterial（全页面生效，SDK 实锤）
层 2  常驻外壳      自绘 TopBar / 侧栏按钮 / About-Meeting 面板壳（小面积，MeetingPanel 先例直接复制）
层 3  交互控件      顶栏按钮/菜单项 REGULAR+interactive（按压光感——"沉浸光感"的动效半边）
层 4  Web 本体      ❌ 不可穿透（SDK 实锤，两轮一致）→ 不做；Web 内部如需毛玻璃由前端 CSS 自理
```

### 3.2 三步落地（每步独立验收、独立回滚）

| 步 | 内容 | 依据 | 验收 |
|---|---|---|---|
| **① 弹窗层（最低风险）** | `confirmOpenExternal`/`launchExternal` 失败提示/卸载确认等 `showAlertDialog` 调用处加 `systemMaterial: new uiMaterial.ImmersiveMaterial({ style: ImmersiveStyle.THICK })`；复用 MeetingPanel 的 `materialOf()` 兜底模式（提为共享工具函数） | #10（AlertDialogParam 实锤） | 弹窗呈材质；`sdkApiVersion<26` 时无材质不崩 |
| **② 顶栏外壳（中风险）** | 自绘 `TopBar()` 底色从 `topBarBg`（实色）改为 `systemMaterial(THIN)`，明暗跟随交给材质系统；`topBarBg/applyTopBarTheme` 保留为降级路径 | #8（通用属性）+ docs/196 教训（只挂外壳条带，不铺大面） | 顶栏浮于网页；**必须真机看是否染蓝**（Web 上方是内容密集区） |
| **③ 交互控件 + 手机档（低风险）** | 顶栏菜单按钮/侧栏开关挂 `REGULAR+interactive`（按压光感）；phone 模块同步 ①②③ | #7（interactive 选项实锤） | 按压有触点光感；手机档一致 |

### 3.3 纪律（从先例继承，门禁可钉）

1. **`materialOf()` 兜底必须双保险**（API<26 + try/catch → `undefined`）——历史真机闪退教训（`ImmersiveStyle` undefined）；
2. **永不整块大面铺材质**（染蓝糊字教训）——只挂外壳条带与小控件；
3. **不与 backgroundColor/borderWidth/shadow 同点设置**（SDK 原话），颜色用 `materialColor`；
4. 门禁：`check-meeting-mode` 已有材质判定臂（M7 口径）；新步落地时给 `TopBar`/弹窗路径**各加一条"兜底存在"判据 + 对照臂**；
5. 连锁门禁：`check-decor-button-mode`（顶栏底色↔三键配色接线——步② 需同步改）、`check-design-tokens`、`check-brand-surface`。

### 3.4 明确不做 / 做不到

- **Web 页面本体毛玻璃**：SDK 实锤不可穿透，不尝试；
- **读"用户设置的沉浸光感强度"**：无公开 API（`MaterialLevel` 是设备算力档、SDK 明言不可改）；若产品要"应用内自选强度"，映射 `ImmersiveStyle` 五档自建设置项（产品决策，不在本轮）；
- **"普通组件仅标题栏生效"当硬规则**：SDK 无此原话 + 仓内真机反证；但**采纳其方向性建议**（局部使用）——与本仓染蓝教训一致。

| 顶部条带 y8–40 | 亮度 **165–178**、**B−R=+30**、std≈23.6 | 半透明毛玻璃顶栏（背景冷色透上来） |
| 主体 y120–200 | 亮度 185–190、B−R≈+15~18、std 16–17 | 内容区（也带透色感） |

| 对照：我们原顶栏 | `#FFFFFF`，B−R=0、亮度 255 | **纯白实底**——三处全不符合 |

### 6.2 A：让材质有背景可采样（结构性根因）

**根因**：`Column{ TopBar; Stack{ Web } }` —— 顶栏与 Web 是**兄弟节点**，材质底下只有窗口底色（白），
毛玻璃取色后仍是白 ⇒ THIN/REGULAR 都白做。这是布局问题，不是 API 问题。

**改法**：
1. `TopBar` 从 Column 顶部**移进 Stack 作为浮层**（`.align(Alignment.Top)`）；
2. 内容让位走**官方 Web UI 自己的变量**（`@deepseek-ai/dsh-client-ui-layout` 实读）：
   `--dsh-frame-top-clearance: 48px`（内容让位量）与 `--dsh-frame-overlay-top`
   ⇒ 垫片把它压成我们的顶栏高度 `--dsh-frame-top-clearance:38px`，
   只在**有自绘顶栏**的档位（`html.dshm-desktop:not(.dshm-pc)` / `html.dshm-tablet`）生效，
   官方自己按这个量排版 —— 不必给 Web 加 padding，也不会双份让位。

**⚠ 编译期踩坑**：`@Builder` 返回 `void`，不能在调用处链 `.align()`（`Property 'align' does not
exist on type 'void'`）⇒ 对齐只能写在 `TopBar` 内部的 Row 上。门禁 C2 已把"调用处链属性"列为缺陷。

### 6.3 B：材质档位 THIN → REGULAR

`shellMaterial()` 从 `THIN` 提到 `REGULAR`。依据：参考形态（透背景色 + 中间档模糊）THIN 达不到；
且顶栏已浮在内容之上、面积仍只是条带（未触犯 docs/196 的"整块大面染蓝"教训）。
**降级路径不变**：`shellMaterial()` 返回 undefined 即回纯色（一档之差可随时退回）。

### 6.4 门禁扩写

`check-immersive-material.mjs` 新增 **C2**（TopBar 必须是 Stack 浮层 + 必须覆盖官方 top-clearance
**赋值形态** + 禁止在 Builder 调用处链属性）与 **C3**（外壳材质必须 REGULAR），
并加 3 组对照臂。**自检 6 条臂全红**。

> 判据教训（本轮）：判据最初写裸名字 `--dsh-frame-top-clearance`，而**注释里也有同一个名字**
> ⇒ 变异臂删掉代码仍被判绿（门禁被注释"养绿"）。改为钉**赋值形态** `--dsh-frame-top-clearance:38px}`。

### 7.1 真机现象（截图 wechat_2026-10-29_162328_703.png，2640×1588）

ffmpeg 分行扫描取证：顶部 **0–40px 全白无任何内容**（原顶栏按钮应在此），按钮的暗色像素落在

### 7.2 失败归因（复盘，为重新规划用）

| # | 问题 | 根因 |
|---|---|---|
| 1 | 按钮下移 | `--dsh-frame-top-clearance:38px` 是**官方 web UI 内容**的让位变量，但**自绘顶栏本身在 Stack 浮层**里的排版与它无关——两套机制各管各的，按钮位置取决于浮层在 Stack 里的实际排布，38px 的让位只作用在 Web 内容上，顶栏浮层与 Web 内容发生了**错位重叠**（按钮落到了 Web 内容区上沿） |
| 2 | 材质仍不可见 | REGULAR 挂上了，但顶栏底下是 Stack 的空白与 Web 的白底——**采样背景仍然近似纯白**；参考图的"透出冷色"来自其顶栏下方有真实丰富的内容在滚动 |
| 3 | 方法论失误 | 在**没有真机预演**的情况下同时改了布局结构（A）与档位（B）两个变量，出问题无法归因单变量 |

### 7.4 重新规划的方向（待用户拍板，不动代码）

沉浸光感要"看得见"，本质上需要**顶栏下方有真实内容在动**。可行路径按风险排序：

| 路径 | 做法 | 风险 | 预期效果 |
|---|---|---|---|
| **P1 渐进式（推荐）** | 不动布局。只把弹窗（THICK 全页面生效）做扎实，顶栏维持 THIN 纯感官"存在但不强调" | 零风险 | 弹窗有材质；顶栏保持现状 |
| **P2 半沉浸** | Web 上移**只在材质生效时**（`topBarShellMaterial !== undefined` 才把 Web 的 marginTop 设 -38、Column 加 padding-top 38 补偿），且**先出实验版真机验证排版**再合并 | 中（本次踩的就是排版坑，但条件式 + 实验版把爆炸半径缩到"材质不可用即完全回退"） | 顶栏透出 Web 内容，接近参考图 |
| **P3 状态栏联动** | 放弃顶栏本体，把沉浸光感落在**状态栏区域**（窗口装饰层，系统级材质，Android/iOS 同款"状态栏毛玻璃"） | 低 | 系统级观感，与顶栏无关 |

**关键教训（进纪律）**：布局类改动必须"条件式 + 实验开关 + 真机截图对比"三件套先行；
本次 A 是"结构性改动直接全量上"，违反了本仓对几何类改动的既有纪律（docs/272 当年就是靠
"官方默认 + 收窄适用面"收敛的）。
