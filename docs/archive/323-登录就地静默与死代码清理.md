## 1. 缺陷复现（修复前）

```text
Web 分区点「登录华为账号」            client.src.js:528  act('login')
  → 桥 cloudSyncAction('login')      ──► decideCloudAction 返回 ok
  → 壳 this.cloudSyncOpen = true      phone/WebApp.ets:3683  entry:3893
  → 整屏面板 CloudSyncSettings         width(800) + 遮罩 #4D000000
  → 面板 aboutToAppear → signIn()      才轮到静默登录
```

`silentSignIn()` 本身零弹窗，但被包在**整屏面板的 aboutToAppear** 里，
用户仍要先经历一次"整屏换 UI"——正是原话「点登录会跳转一个二级菜单，不需要这样」。

**为什么上一轮没发现**：门禁断言写的是"登录分支必须置 `cloudSyncOpen`"，
把缺陷当成了预期行为（判据方向错了）。

## 2. 修复

### 2.1 语义变更

| 动作 | 旧 | 新 |
|---|---|---|
| `login` | 打开原生面板，面板里登录 | **就地静默登录**，不产生任何界面 |
| `restore` | 打开原生面板 | **不变**（逐项多选确实需要面板） |

`SyncActions.decideCloudAction()` 的 login 分支文案由
`'已打开华为账号登录'` 改为 `'正在登录华为账号…'`，并注明"不再打开任何面板"。

### 2.2 两壳实现（同一口径）

```ts
case CLOUD_ACTION_LOGIN:
  this.runSilentLogin();   // 不置 cloudSyncOpen / cloudSyncAutoLogin
  break;

private runSilentLogin(): void {
  silentSignIn().then((result) => {
    if (result.kind === SilentSignInKind.OK) {
      SyncEngine.adoptLogin(result.unionId);   // 状态回流：分区下一拍即已登录
      this.toast('已登录华为账号');
    } else {
      this.toast(result.reason);                // 未登录系统账号等如实提示
    }
  })
}
```

结果如何回到界面：`cloudSyncState()` 是网页分区每秒轮询的状态源，
`adoptLogin()` 之后分区自然变成已登录态，不需要任何额外回执或界面。

### 2.3 死代码清理

| 对象 | 原因 |
|---|---|
| `SyncEngine.onUi()` / `requestLogin()` / `SyncUiListener` / `uiListener` | LoginPanel 时代"菜单请求拉登录面板"的通道，**全仓零调用方** |
| `entry` 的 `bindSyncUi()` 及其两个调用点 | 同上 |
| `huaweiLoginButtonParams()` + export + `loginComponentManager` import | 官方登录按钮时代遗留，零引用 |
| `platform/src/main/resources/**`（`brand_app_name` ×2 + `brand_icon.png`） | LoginPanel 的 `appInfo` 专用，零引用 |
| `tools/make-icon.py` 的 brand_icon 产出 | 同上 |

## 3. 门禁修正（关键）

`check-cloud-sync-plugin` 的原断言是**反的**——它要求"登录分支必须置 `cloudSyncOpen`"。
现改为：

| 新断言 | 咬住什么 |
|---|---|
| 两壳登录分支必须调 `runSilentLogin()` | 改回旧实现 |
| 登录分支**不得**含 `cloudSyncOpen = true` | 用户明确反对的整屏跳转 |
| 登录分支**不得**含 `cloudSyncAutoLogin = true` | 诱使壳开面板 |
| `runSilentLogin()` 内部必须调 `silentSignIn()` | 空实现 |
| 判据只在**代码行**上匹配，跳过注释 | 注释里写"旧实现置 cloudSyncOpen"时不会误判（本轮踩过） |

**负向对照已做**：把 `this.cloudSyncOpen = true;` 加回登录分支 ⇒ 门禁当场判红。
