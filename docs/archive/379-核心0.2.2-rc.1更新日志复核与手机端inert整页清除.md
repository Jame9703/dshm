## 2. 手机端：从「只清侧栏列」改为「整页清 inert」

### 2.1 为什么上一版不够

上游把 `drawer` 态的整屏可交互性交给 HTML `inert` 属性（`dsh-client-ui-layout`）：

- `CenterColumn` / `RightbarColumn`：`inert = drawerOpen`
- `sidebarCol`：`inert = drawer && sidebarCollapsed`
- `bottomRow` / `leadingSeat`：`inert = drawerOpen`

`drawer = viewport < 768 && !windowsTitlebar` —— 手机恒为 true。于是**只要抽屉展开，主区（含设置面板、DeepSeek 账号登录、插件入口、终端面板）整棵子树被 `inert` 冻结**：视觉变灰、点击穿透被吞。这与云调试日志完全吻合：**无崩溃、无终端堆栈**，一切「点不到」都是命中测试被吞。

上一版判断错了：当时只清 `sidebarCol` 的 `inert`，理由是「主区/右栏的 inert 是官方抽屉语义，不能动」。代价是**整台手机都没法用**。而 1.1.7 基线里 `inert` 出现 0 次——这个语义在本产品历史上从未存在过。

### 2.2 现在怎么做的（`phone/src/main/ets/pages/WebApp.ets`）

```ts
function clearDrawerInert() {
  var nodes = document.querySelectorAll('[inert]');
  for (var i = 0; i < nodes.length; i += 1) {
    try { nodes[i].removeAttribute('inert'); } catch (e) { /* 单节点失败不影响其余 */ }
  }
}
```

外加一次性 MutationObserver，把「上游在同一帧写回 `inert`」也压掉：

```ts
inertObserver = new MutationObserver(function (records) {
  for (var i = 0; i < records.length; i += 1) {
    var el = records[i].target;
    if (el !== null && el.hasAttribute && el.hasAttribute('inert')) {
      try { el.removeAttribute('inert'); } catch (e) { /* 忽略 */ }
    }
  }
});
inertObserver.observe(document.documentElement, { subtree: true, attributes: true, attributeFilter: ['inert'] });
```

`tick()` 顺序：`tagLayout(); watchInert(); clearDrawerInert(); syncState();`
—— 300ms 巡检兜底 + 属性写回同帧清除，双保险。

**边界**：只改 `phone` 壳。`entry`（平板/2in1）壳的 `clearDrawerInert`/`watchInert` 计数恒为 0，平板端维持官方抽屉语义不动。

### 2.3 同一根因的另一半：`data-sidebar-opener`

新核心在顶栏新增**常驻**的 `[data-sidebar-opener]`，`aria-label` 恒为「打开侧边栏」（不再随状态切换）。旧版 `findToggle()` 会把它当成状态按钮 ⇒ `state()` 恒 `collapsed` ⇒ 合成 ⊞ 常驻 + `dshm-sbcol` 挂到错误的列。修法（上一轮已落地）：

1. `findToggle()` 两个循环都 `continue` 跳过 `[data-sidebar-opener]`；
2. CSS 隐藏官方 opener：`html.<handheld> [data-sidebar-opener]{display:none !important}`；
3. 展开态让位：`html.<compact>[data-dshm-sidebar="expanded"] #<FAB>{display:none !important}`，恢复 1.1.7「收起才出现 ⊞」。

## 3. 平板端：PC 型号白名单收窄

用户口径：**只有 MatePad Edge 与 MatePad Pro Max 走 PC 形态，其余平板都是移动端**（符合移动端 App 的使用特性）。此前 `EDGE_FAMILY_TOKENS = ['QXS','MRX','MRR','MRD','MRO','DRA']` 把普通 MatePad 一并判成 desktop ⇒ 系统「最近任务」显示为「PC 应用」，终端也被切到宿主原生 PTY 路线。

现在：

```ts
const EDGE_FAMILY_TOKENS: string[] = ['QXS'];
```

保留的判定链（不会漏掉真该走 PC 的设备）：`productModel` 前缀 `QXS-`、市场名 `MatePad Edge` / `MatePad Pro Max`、`MateBook` 前缀、`PROMAX`+`MATEPAD` 联合判定。
