## 2. 自检中抓到的两个自身缺陷（值得记）

### 2.1 子进程输出被吞 → 只看得到一行 `Command failed`

第一版用 `execFileSync(..., { stdio: 'inherit' })`，失败时只拿到异常，看不到内层到底哪条判红。
改成 `spawnSync` + 自己打印 stdout/stderr。**受限沙箱里管道/pty 都可能 EPERM，抓回再打印是唯一稳的形态。**

### 2.2 D 判据形同虚设（自检抓出来的真漏洞）

第一版这样写：

```js
translator.resolve({ text: 'x'.repeat(config.maxTextChars + 10), ... })
```

文本长度**跟着配置一起变**。于是"把 `maxTextChars` 调到 1e8"这个变异体让超长文本也涨到 1e8+10
—— 永远刚好超限，判据**照样绿**。

变异体自检当场判红（"maxTextChars 调到极大"未被判红）⇒ 改为固定 5000 字。
**这就是为什么自检必须是"改坏再跑"，而不是"读代码觉得它在起作用"。**

### 2.3 三个变异体

| 变异 | 必须判红通过 |
|---|---|
| 目标语言改成 `en`（译文不再含汉字） | ✅ |
| `maxTextChars` 调到 1e8（超长不再抛） | ✅ |
| provider 断言期望值改错 | ✅ |

## 3. 环境受阻 ≠ 通过

核心树不在（干净检出）时以**退出码 2** 结束并打印"环境受阻"，与仓库口径一致。
CI 接入时用 `|| [ $? -eq 2 ]` 把它当"跳过"而不是"失败"，目的是
**"有树时一定跑"**，而不是"没树时也判绿"。
