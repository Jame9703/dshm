## 1. 界面设计：为什么这样组织

### 1.1 从「三个测试入口」到「一个生产入口」

改造前顶栏「应用」菜单里是：

```text
华为账号与云同步     ← 测试面板
端云同步验证         ← 测试面板
Asset 资产同步验证    ← 测试面板
```

**问题**：三个都是**诊断工具**，普通用户不该看到；而且它们并列在菜单里，
让人分不清哪个是"正经功能"。

改造后：

```text
华为账号与云同步
    └─ 云同步设置页（生产界面）
         ├─ 华为账号   ← 登录 / 退出
         ├─ 云同步     ← 开关 / 立即同步 / 待同步会话
         ├─ 同步范围说明（合规）
         └─ 诊断       ← 两个测试面板收在这里
```

### 1.2 视觉规范落地（对齐本仓 `HarmonyTheme`）

本仓已有成熟的设计 token 体系（`appstate/ui/Tokens.ets` + `HarmonyTheme.ets`），
新页面**一律走它**，不写裸数字：

| 维度 | 用法 | 出处 |
|---|---|---|
| **颜色** | 全部 `$r('sys.color.*')` 语义资源 | `HarmonyColor.TEXT_PRIMARY` 等 |
| **间距** | `Sp.XS/S/M/L/XL` | `Tokens.ets` |
| **字号** | `Fs.CAPTION/SECONDARY/BODY/TITLE_M` | 同上 |
| **圆角** | `Radius.S/M` | 同上 |
| **最小可点** | `Sz.TOUCH_MIN`(44) / `Sz.HEADER`(52) | 同上 |

> **为什么不用手写十六进制**：`HarmonyTheme` 头注写得很清楚——
> "手工色值在深色模式下必然有一处看不清，而那是真机上才发现的缺陷"。
> 系统语义色让深浅色、品牌色、对比度**由系统保证**。

### 1.4 交互细节

| 场景 | 处理 |
|---|---|
| 未登录 | 只显示"华为账号"分组，云同步分组**整块不渲染** |
| 登录面板 | 页面内 `Stack` 叠加（SDK 明确不能用于 Dialog） |
| 操作中 | 顶栏显示 `LoadingProgress`，按钮 `enabled(false)` |
| 成功/失败 | 顶部提示条（✓ 绿 / ⚠ 橙），**不静默** |
| 错误分类 | 按 Account Kit 错误码给中文说明（取消/缺权限/未登录/未同意协议/身份不匹配） |

## 2. 状态中枢 `SyncEngine`

### 2.1 职责边界

| 管 | 不管 |
|---|---|
| 登录态（UnionID，展示时脱敏） | 不持有授权码 / Access Token |
| 同步开关 | 不直接读写会话文件 |
| 待同步范围统计 | 不猜路径（会话根由宿主注入） |
| 诊断入口路由 | 不持久化敏感信息 |

### 2.2 为什么登录态**不落盘**

持久化登录态需要先回答：凭据存哪、谁能读、设备被拿走怎么办。
本仓已有 `SecretStore`，但**威胁模型没定之前不写盘**——这是有意的选择，
不是遗漏。退出登录只清内存态，**不动本机会话数据**。

### 2.3 待同步统计复用已有能力

直接调用 `docs/301` 完成的 `SessionSyncScope.buildManifest()`：

```ts
const manifest = buildManifest(sessionsRoot);
return { sessionCount: manifest.sessionCount, totalBytes: manifest.totalBytes };
```

**那 26 条门禁判据继续有效**（排除 cache/cores、代际解析、无绝对路径）。

## 3. 一个必须说清楚的点：同步执行器还没接

当前 `SyncEngine.syncNow()` 是**占位实现**：

```ts
static async syncNow(): Promise<string> {
  ...
  return '同步执行器尚未接入：当前仅完成登录与状态管理';
}
```

界面会把这个结果**原样显示在提示条上**，而不是转个圈说"同步成功"。

> **为什么这样处理**：本仓有一条明确原则——"界面不撒谎"。
> 一个假的"同步完成"比一个"尚未接入"危险得多：用户会以为数据已经备份了。
