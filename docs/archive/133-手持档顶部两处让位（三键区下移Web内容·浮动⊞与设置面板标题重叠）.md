## 1. 现象

### 1.1 A：平板右上角三键压住「面板 / 预览」按钮

用户给的是**截图**（MatePad Edge，裁的右上角）：只有「最小化」「关闭」两个键在图内
（最左那颗「全屏」被裁掉），而**关闭键外面套着一个方框** —— 那个方框就是官方 Web 壳自己那排
顶部按钮最右侧那颗「面板 / 预览」开关，它和三键**落在同一条带上**。

### 1.2 B：手机左上角浮动 ⊞ 压住「插件」标题

真机截图（设置面板 → 插件档）：`⊞` 正好盖住面板标题「插件」的「插」字。同屏还能看到
该行的说明文字（「安装、启用和配置插件」）紧贴按钮下沿。

## 2. 根因

### 2.1 A：窗口标题栏那一条**没人画**

`EntryAbility.afterWindowStageReady()` 里这一串是**所有档**都会试的：

```ts
win.setWindowDecorVisible(false);
win.setWindowDecorHeight(38);
win.setDecorButtonStyle({ colorMode: COLOR_MODE_LIGHT });
```

- **PC / 2in1**：自绘顶栏整条 38vp 高、正好补上这条带子（三键浮在它右边）⇒ 观感与逻辑都自洽；
- **手持档**：`WebApp.build()` 里 `if (!this.handheld) this.TopBar()` ⇒ 自绘顶栏**不渲染**，
  于是这条 38vp **没有任何人画**；而窗口仍处于「自由窗口 + 三键可见」的状态 ⇒ Web 内容
  顶到窗口第一行，官方壳自己的顶部按钮就落进三键底下。

即：**这不是"页面把按钮放错了位置"，而是"三条路里少了一条"**。手机档不出现，是因为手机是
**全屏**（`setWindowDecorVisible` 抛 801）⇒ 根本没有三键（真机读数见 §5.1）。

### 2.2 B：⊞ 与设置面板**不在同一条让位链上**

`SIDEBAR_SHIM_JS` 造的 ⊞ 是 `position:fixed` 钉在视口左上角（`top/left = 6px`，36×36）。
它会盖住页面自己第一行的左上角 —— 会话标题行因此靠官方变量横向让开：

```css
html.dshm-handheld[data-dshm-sidebar="collapsed"]{--dsh-frame-leading-clearance:66px}
```

而**设置面板**不是会话页：它是 body 上的 portal + 全屏覆盖层（`dshm-set-overlay`），
另一条渲染链，没有那条变量可用 ⇒ 面板标题正好落在 ⊞ 底下。

## 3. 修法

### 3.1 A：整块 Web 内容按三键区高度下移

`WebApp.build()` 的 Stack 上：

```ts
.padding({ top: this.decorTopInsetNow() })
```

- 让位是 **padding**（压缩内容布局高度）而不是"把 Web 往上挪"：给页面喂 `100%` 时
  `getBoundingClientRect()` 会缩到 `y1 = 38`，三键不再压住页面那排按钮；
- 让位那一条的底色 = `topBarBgNow()` —— 手持档没有顶栏，**这条就是"顶栏"的替身**；
- PC 上这个值是 0，且底色与 `applySystemBarTheme` 写给窗口的底色同源 ⇒ 即使露出来也看不出差别。

### 3.2 判据收在一个纯函数里

```ts
function decorTopInsetVp(handheld: boolean, decorPresent: boolean, titleButtonHeightVp: number): number {
  if (!handheld || !decorPresent) { return 0; }
  return titleButtonHeightVp > 0 ? titleButtonHeightVp : TOP_BAR_HEIGHT;
}
```

三条输入**互不替代**：`handheld` 决定"谁需要让位"、`decorPresent` 决定"有没有三键"、
读数决定"让多少"。抽成纯函数是为了让门禁**直接求值断言**（含"PC 必须恒为 0"与"按键兜底"）。

### 3.3 「有没有三键」用**调用事实**，不用 `getTitleButtonRect()`

`EntryAbility` 里那一串装饰调用**成功 ⟺ 自由窗口 ⟺ 三键在**（全屏抛 801）—— 判据就在手上：

```ts
AppStorage.setOrCreate<boolean>(KEY_DECOR_KEYS_VISIBLE, true);   // 成功
AppStorage.setOrCreate<boolean>(KEY_DECOR_KEYS_VISIBLE, false);  // 全屏 / 无装饰
```

**false 必须显式写**：AppStorage 是**进程级**的，会话窗或上一次发布会把 `true` 留在仓里。

页面侧：`@State decorRectHeightVp`（只存**读数**）+ `@StorageProp(KEY_DECOR_KEYS_VISIBLE) decorKeysVisible`，
让位在**渲染期现算**（`decorTopInsetNow()`）—— 能力层的发布时机在 `loadContent` 回调里
（页面首帧之后），`@StorageProp` 才能跟上；现算则不会出现"两份结论"。

诊断行 `diag-decor-top`（**只记变化**，含 `inset=0` 的那次 —— 否则 PC 档一个字节都不写，
事后没法证明 `applyDecorRect` 真跑过）：

```
2026-10-10T02:09:58.112Z handheld=true keys=false rect.w=0 rect.h=0 inset=0
```

### 3.4 B：把 ⊞ 的带子从面板顶部让出来（并让两侧**共用**同一组数）

按钮几何提成模块常量，两个垫片**插值**进去（都是模块级模板字符串，插值在编译期完成，
运行时仍是纯 JS 字面量）：

```ts
const HANDHELD_FAB_EDGE = 6;                 // 距视口上/左的留白
const HANDHELD_FAB_SIZE = 36;                // 按钮边长
const HANDHELD_FAB_BAND = 48;                // = 6 + 36 + 6（再给下方内容留 6）
const SIDEBAR_STATE_ATTR = 'data-dshm-sidebar';  // 侧栏状态属性（collapsed / expanded）
```

- 按钮侧：`top:${EDGE}px;left:${EDGE}px;width:${SIZE}px;height:${SIZE}px`，显隐判
  `html.dshm-handheld[${STATE_ATTR}="collapsed"] #fab{display:flex}`；
- 面板侧：**单独一条规则、只写 padding** ——
  `html.dshm-handheld[${STATE_ATTR}="collapsed"] .dshm-set-panel.dshm-set-ready>nav{ padding:${BAND}px 0 0 }`
  —— **判的就是同一个属性、同一个值**，与按钮的显隐**逐字同源**；
- ⚠️ 这条 padding **不能**顺手塞进旁边那条 `P>nav{display:flex;…;padding:0;…}`：那条是
  docs/132 用来压 dshmarket 自带 `display:none` 的**反制规则、必须无条件**（收进任何作用域都
  可能让反制失效，那正是"修好后面、前面又坏"）。第一版把它俩合成了一条，复核时抓到 ⇒ 拆成
  两条：无条件那条照旧，只管 padding 的这条特异性更专，稳赢。

各写一个死数就会漂移（改了按钮尺寸却忘了让位，重叠又回来）—— 这是本仓反复踩过的那类坑，
故直接做成**不可能漂移**的形状。

> 【为什么让位要跟着 `collapsed` 走，而不是无条件留白】按钮只在收起态出现；无条件留白会让
> **侧栏展开档**（按钮不显示、今天本来不重叠）平白多出一条 48px 空白 —— 那是"修好后面、
> 前面又坏"。判同一个事实之后：按钮在 ⇒ 让位在；按钮不在 ⇒ 让位也不在（**一致**）。

### 3.5 为什么 PC / 2in1 不受影响

- A：让位由纯函数给出，**非手持恒 0** ⇒ 那条 padding 在 PC 上是 0；写成"减法"的话系统若把
  rect 报成 39/40 就会在 PC 上挪几个 vp ——「不误伤 PC」是硬要求，故**直接返 0**；
- B：`SIDEBAR_SHIM_JS` / `SETTINGS_SHIM_JS` 都以 `html.dshm-handheld` 起头，而那个类名
  由原生桥 `platform.isHandheldForm()` 决定 ⇒ PC 上两条规则**一条都不落地**（不是"落地了但看不出"）。
