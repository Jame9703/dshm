# 170 · 启动期状态栏同色 + 多任务"交还系统"= 显式透明（手机端两条复报）

> 用户 2026-10-16（附两张手机截图）：**"再看看，这俩图都没沉浸，一个启动的时候 APP 区跟状态栏就不是一个色，
> 后台任务也是不对，手机端都这样。"**

## 1. 先把颜色取准（逐点取色，不靠肉眼）

| 图 | 位置 | 实测 | 说明 |
|---|---|---|---|
| ① 启动中 | 状态栏那一条（y≈30） | `#FFFFFF` | 纯白 |
| ① 启动中 | 启动页区（y≈227/340/708） | `#F3F6FB` | 即品牌启动页的 `#F3F7FB` |
| ② 多任务 | 状态栏那一条（y≈30） | `#151517` | **正是本仓深色外观的状态栏色** |
| ② 多任务 | 同一条下面的壁纸（y≈154） | `#321B69` | 紫蓝壁纸 —— 本该透出它 |

⇒ 两条互不相干：① 是**启动期三处浅色没对齐**；② 是**我们前台的写入在多任务视图里没被收走**。

## 2. 启动期：结论是"只能让启动页取白"

**改动前**三处浅色各说各话：`start_window_background = #FFFFFF`（首帧窗口底色）、启动视图自己画的
`#F3F7FB`、窗口外观的浅色 `#FFFFFF`（状态栏 / 窗口底色）。

**先试了"让状态栏取启动页色"**（新增 `SPLASH_BG` 常量 + `color.json` 同步 `#F3F7FB` + 按 phase 取色 +
把启动视图扩进顶部安全区），真机三时间点复测：

```
启动 1.5s : 状态栏 #FFFFFF   启动页 #F3F6FB
启动 4.0s : 状态栏 #FFFFFF   启动页 #F3F6FB
启动 7.0s : 状态栏 #FFFFFF   启动页 #F3F6FB
```

hilog 里我们确实按 phase 写了 `状态栏已跟随启动页：light bg=#F3F7FB`（无异步拒绝），但**系统在这一阶段
固定把状态栏画成白色、不采用我们写的色**（`expandSafeArea` 扩顶部也没有改变这一点）⇒ 方向只能反过来：

**定稿修法**：把**启动页取白**（`SPLASH_BG = '#FFFFFF'`，`start_window_background` 同值），
于是"状态栏（系统画的 `#FFFFFF`）↔ 启动页（我们的 `#FFFFFF`）"天然同色；而且白正好是**浅色应用界面**
的窗口/状态栏底色 ⇒ 从启动页切到应用界面那一跳也没有色差；深色外观等首帧就绪后再换 `#151517`
（由 `phase` 的 `@Watch` 触发，见下）。

保留的两处结构改动：
1. `SPLASH_BG` 常量 + `color.json` 的 `start_window_background` **同值**（门禁钉死，防止再漂）；
2. 启动视图 `.expandSafeArea(...)` 在**手持档**同时扩 `TOP`（对齐"底层容器各扩各的"这条既有口径；
   本机上它没改变观感，但换到"启动期状态栏透明"的设备上，那一条会是我们的底色而不是桌面）。

## 3. 多任务：把"不写"改成**显式写透明**

机理：`setWindowSystemBarProperties` 是**窗口级的一次写入**，谁最后写谁说话。"切后台 / 自由窗口时什么都不做"
（docs/168 的第一版）只是**不覆盖** ⇒ 前台的 `#151517`（深色外观）会一直留在系统状态栏上
——用户图② 那条黑就是这么来的。

**定稿修法**：新增 `platform` 常量 `SYSTEM_BAR_HANDOFF_BG = '#00000000'`（全透明），
两条链在"不拥有状态栏"时**显式写入它**：

- 页面 `applySystemBarTheme`：`!statusBarOwnedByApp(...)` ⇒ 写透明（不再空分支）；
- 能力层 `reassertWindowChrome`：`!ownStatusBar`（含 `onBackground` 传 `foreground=false` 那条）⇒ 同样写透明。

**不动图标颜色**：交还之后那格背景不是我们的（壁纸 / 多任务），无从判断深浅；实测正常路径里系统/启动器
会在接管时自己重画状态栏（对照截图：多任务下状态栏透明 + 深色图标）。
