# 357 · 录屏脚本：JIT 受限权限申请视频（时长目标 55–70 秒）

> 用途：随 AGC 受限权限申请（`ohos.permission.kernel.ALLOW_WRITABLE_CODE_MEMORY`）提交的使用场景视频。
> 设备：鸿蒙 PC / 2in1（横屏，建议 1920×1080）。
> 核心要求：**同一台设备、连续录制、有可读的数字对比**。
>
> ⚠️ **口径边界（2026-11-04 校正）**：主宿主进程以 `--jitless` 常驻；应用另有子进程
> Node CLI 路径。镜头 2–4 若用 `node`（默认模式）跑出"有 JIT"读数，字幕/旁白必须写明
> 这是**子进程 Node CLI**，不得剪成"应用整体有 JIT / 没有该权限就全都没有 WASM"。
> 口径依据见 `docs/356` §1.6；录屏前先按那份边界复核一遍。

---

## 0. 录制前准备（5 分钟，把这一步做完再开录）

### 0.1 把命令写进文件，避免录屏时打错

在终端里执行一次（只做一次）：

```sh
cat > ~/jit-demo.sh <<'EOF'
echo "=== 有 JIT ==="
node -e 'let t=Date.now(),s=0;for(let i=0;i<2e7;i++){s+=Math.sqrt(i)*0.5|0}console.log("耗时(ms)",Date.now()-t)'
echo "=== --jitless ==="
node --jitless -e 'let t=Date.now(),s=0;for(let i=0;i<2e7;i++){s+=Math.sqrt(i)*0.5|0}console.log("耗时(ms)",Date.now()-t)'
echo "=== WebAssembly 可用性 ==="
node -e 'console.log("有 JIT :",typeof WebAssembly)'
node --jitless -e 'console.log("jitless:",typeof WebAssembly)'
EOF
chmod +x ~/jit-demo.sh
```

### 0.2 录屏设置

| 项 | 建议 |
|---|---|
| 分辨率 | 1920×1080（或设备原生，保持横屏） |
| 光标 | 打开"高亮点击"（便于评委跟视线） |
| 字体 | 终端字号调到 **16–18**，保证录制后能看清数字 |
| 桌面 | 关掉通知、聊天软件、邮件预览（避免弹出无关内容） |
| 账号信息 | 不要出现任何真实账号、手机号、API Key |

### 0.3 先跑一遍彩排

```sh
sh ~/jit-demo.sh
```

确认四条命令都正常输出（有 JIT 约 **350 ms**、jitless 约 **1900 ms**、`object` / `undefined`）。

## 1. 分镜脚本（6 个镜头，合计约 60 秒）

### 镜头 1（0:00–0:06）· 应用与运行时身份

| 项 | 内容 |
|---|---|
| **画面** | 打开 DSHM → 点右上角头像/设置 → 关于；镜头停在版本信息 |
| **动作** | 鼠标缓慢移过"版本 1.1.7 / 内核 Node.js 24.2.0"这一行 |
| **字幕**（屏幕上方） | `DSHM · 内置 Node.js 24.2.0 + V8 运行时` |
| **旁白** | 「这是 DSHM，一个跑在鸿蒙 PC 上的本地 AI 编程工作台。它内置了完整的 Node.js 运行时，用 V8 引擎执行用户本机安装的 JS 工具链。」 |

### 镜头 2（0:06–0:16）· 打开终端，展示有 JIT 的耗时

| 项 | 内容 |
|---|---|
| **画面** | 切到终端面板，输入 `sh ~/jit-demo.sh`（或直接粘 `node -e '…'` 第一条） |
| **动作** | 回车后**等结果出现**再停 1 秒，让数字留在屏幕上 |
| **字幕** | `Node 默认模式（子进程 CLI）：约 345 ms` |
| **旁白** | 「先看同一台设备上 Node 默认模式跑一次纯计算负载，20 轮百万次浮点运算，耗时 345 毫秒。」 |

> ⚠️ 数字以你机器实测为准，**不要念死数字**，先说"三百多毫秒"，等结果出来再补具体值。
> 如果这个"默认模式"跑的是子进程 Node CLI，字幕必须保留括号里的限定。

### 镜头 3（0:16–0:26）· 同一负载，jitless 慢 5 倍

| 项 | 内容 |
|---|---|
| **画面** | 紧接着执行第二条 `node --jitless -e '…'`，**不要切镜头**（保持同一终端、同一屏） |
| **动作** | 结果出来后停顿 1.5 秒 |
| **字幕** | `--jitless（主宿主当前模式）：约 1902 ms（慢 5.5×）` |
| **旁白** | 「同一台设备、同一段代码，改用 `--jitless` —— 也就是主宿主现在的模式 —— 需要一秒钟以上，慢了五倍多。这就是我们为主宿主申请该权限的原因。」 |

> 这是全片最关键的一镜：**两条命令必须在同一次录制、同一终端里连续执行**，证明是同一设备。

### 镜头 4（0:26–0:34）· WASM 直接不可用

| 项 | 内容 |
|---|---|
| **画面** | 执行后两条：`node -e 'console.log(typeof WebAssembly)'` 与 `node --jitless -e …` |
| **动作** | 用手指/光标分别点一下两行输出 |
| **字幕** | `Node 默认：object ｜ --jitless（主宿主）：undefined` |
| **旁白** | 「更直接的证据：主宿主进程里 WebAssembly 是 undefined。依赖它的组件只能退回纯 JS 垫片，部分 WASM 工具链也走不了。」 |

### 镜头 5（0:34–0:48）· 真实使用场景被拖慢

| 项 | 内容 |
|---|---|
| **画面** | 在 DSHM 里新建/打开一个工作区，让 Agent 或终端执行一次真实的 JS 工具链命令（例如 `pnpm install` 或任意本地构建） |
| **动作** | 展示命令在跑、耗时明显 |
| **字幕** | `实际使用：安装/构建耗时被显著放大` |
| **旁白** | 「这不是跑分问题。用户在本机装依赖、跑构建、执行脚本，都会被这个降级模式放大数倍，体验明显变差。」 |

> 若 `pnpm install` 太久（>15 秒），可换成任一能在 5–8 秒内结束的本地脚本，**关键是有真实工具在执行**。

### 镜头 6（0:48–0:58）· 收尾与承诺

| 项 | 内容 |
|---|---|

## 2. 逐字旁白稿（可直接照念，约 150 字/分钟）

> 【镜头1】这是 DSHM，一个跑在鸿蒙 PC 上的本地 AI 编程工作台。它内置了完整的 Node.js 运行时，用 V8 引擎执行用户本机安装的 JavaScript 工具链。
>
> 【镜头2】先看正常情况下的一次纯计算负载：两千万次浮点运算。
>
> 【镜头3】同一台设备、同一段代码，在没有 JIT 权限的 jitless 模式下，耗时被放大了五倍多。这就是我们申请该权限的直接原因。
>
> 【镜头4】更直接的证据：主宿主进程里 WebAssembly 直接不可用。依赖它的组件只能退回纯 JS 垫片，部分 WASM 构建工具也走不了。
>
> 【镜头5】这不是跑分问题：用户在本机安装依赖、执行构建、运行脚本，都会被这个降级模式拖慢数倍。
>
> 【镜头6】申请这个权限，只是让 V8 回到默认的工作方式。它只作用于本应用进程内的 JS 执行，不采集、不上传任何用户数据。

## 5. 常见驳回点（提前规避）
