# 187 · 手机端底部使用统计与系统手势条避让

> 2026-10-18。内测反馈：手机端系统手势小白条压在 Web 底部的
> “轮次 / 步数 / token / 缓存 / 上下文占用”统计栏上。
> 本轮只处理这一条 UI 冲突；分屏旋转与 QEMU/QGA 报告不在本档范围。

## 1. 现象与分层

真机 `62T0225B18039433`、Dark Mode、竖屏：

- 系统避让：`TYPE_SYSTEM.bottom=0`、
  `TYPE_NAVIGATION_INDICATOR.bottom=98px`，即 `28vp`。
- Web 壳底部统计栏是固定定位；页面自己的
  `env(safe-area-inset-bottom)` 没有把它抬出手势区。
- 白色手势条与统计栏文字发生重叠，输入框和统计栏本身均可交互，不是 Web 崩溃。

根因是 `docs/130` 的实现让 **Web 组件自身也 `expandSafeArea` 到屏底**。
旧版 Web 壳的内层容器会消费 `env(safe-area-inset-bottom)`；新版 Web 壳把底部统计栏
改成固定定位后，这个页面内预留不再覆盖它。

## 2. 两条未采用路径

### 2.1 `avoidVisibleViewportBottom(28)`

调用成功，端侧诊断读到：

```text
webAvoid=28vp reason=controller-attached
```

但真机截图显示固定统计栏仍停在物理底边，说明该 API 的可见视口上移
没有移动这层固定栏，因此不满足本次要求。

### 2.2 Web 组件级 `padding-bottom: 28vp`

ArkTS 编译与安装均正常，但 ArkWeb 内部固定栏仍贴物理底边，
组件 padding 没有改变它的定位基准。

两条实验代码均已撤回，不留在最终实现中。

## 3. 最终修法

保留底部沉浸的**绘制层**，收回 Web 的**内容层**：

- 根 `Column`、`Stack`、启动页覆盖层、错误覆盖层继续按避让读数
  `expandSafeArea([SYSTEM], [BOTTOM])`，负责把当前主题底色铺到屏底。
- Web 组件不再向下扩进系统安全区，内容框止于安全区上沿。
- 因此整个 Web 页面（含固定使用统计栏）整体上移 `28vp`；
  小白条只覆盖原生主题底色带，不再盖住页面功能。

这修订了 `docs/130` 中“Web 自身也要扩”的旧取舍；`docs/130` 的避让读数、
分档闸门和底色绘制链仍有效。

## 5. 边界

- PC / 2in1 的 `bottomInsetVp=0`，`expandSafeArea([],[])` 无效果；
  移除 Web 的底部扩展不改变桌面档布局。
- 本轮真机只验证手机；平板仍需后续实机复核。
- 手工小白条/三键导航切换、分屏旋转组合不在本轮验证范围。
