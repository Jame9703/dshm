# 139 · 上游「向上找项目根」撞上路径闸门：**每轮运行失败**（面外探测应当当作"没有标记"）

> 用户转来的那一屏：
>
> ```
> 本轮运行失败路径在 DSHM 的允许范围之外，已拒绝访问：/storage/Users/.git
> 本应用只允许访问两处：① 应用沙箱（/data/storage/el1/base、/data/storage/el2/base）；
> ② 用户目录（~、~/Download/com.dshm.dshclient）以及它们之下的一切。
> …
> ```
>
> 紧跟一句：**「直接报错」**。

---

## 1 结论（先给判定）

`docs/137` 那层**路径闸门判得对**：`/storage/Users/.git` 确实在允许面之外。
**错的是调用方** —— 上游 `@deepseek-ai/dsh-agent-instructions` 的「向上找项目根」把
**"允许面之外的探测"当成了致命错误**，于是整个 `agent/pre-step` 被打断，
面板上就成了"本轮运行失败"。

修法只有一处（`coreVersion` 升 `+dshm.31`）：**面外探测 ⇒ 当作"这里没有标记"**（返回 false，继续向上）。
**闸门本身一个字节没改**：模型/工具主动要面外内容的读与写，照样 `FS_PERMISSION_DENIED`。

---

## 2 根因链（逐跳）

### 2.1 上游怎么找"项目根"

`node_modules/@deepseek-ai/dsh-agent-instructions/lib/index.js`：

| 位置 | 代码 | 作用 |
|---|---|---|
| `:16` | `const DEFAULT_PROJECT_ROOT_MARKERS = [".git"];` | 根标记默认是 `.git` |
| `:574-582` | `findProjectRoot(cwd, markers, fileSystem, signal)` | 从 cwd **逐级向上**：`<dir>/<marker>` 存在即返回该目录；到 `/` 仍没有就 `return resolve(cwd)` |
| `:545-563` | `existsAsMarker(path, fileSystem, signal)` | **只把 `FS_NOT_FOUND` 当成"这里没有标记"**；其余错误 `throw error`（它是故意的：探针坏了就该响） |
| `:1237-1244` | `const fileSystem = ctx.get("fs"); … findProjectRoot(…)` | 探针走的是 **`ctx.fs`** —— 也就是**我们这一层的后端** |

### 2.2 为什么恰好是 `/storage/Users/.git`

真机（PC 档）默认工作区是 `~/Download/com.dshm.dshclient`，
而这条链上**一层 `.git` 都没有**（2.3 有实测读数）。于是：

| 跳 | 探测路径 | 在允许面内？ | 结果 |
|---|---|---|---|
| 1 | `…/com.dshm.dshclient/.git` | 是 | `FS_NOT_FOUND` ⇒ 继续 |
| 2 | `…/Download/.git` | 是 | `FS_NOT_FOUND` ⇒ 继续 |
| 3 | `~/.git` | 是 | `FS_NOT_FOUND` ⇒ 继续 |
| 4 | **`/storage/Users/.git`** | **否**（允许面的根是 `…/currentUser`） | 闸门 `FS_PERMISSION_DENIED` ⇒ **`throw`** |

第 4 跳的异常是在 `compose()` 里被 await 的（`:1406-1424` 的 `agent/pre-step` 钩子，无人捕捉）
⇒ **每轮的第一步就死**，报文正是闸门那段文案。

### 2.3 真机取证（PC 档 `86E0226429000417`，应用身份，非 shell 身份）

`hdc fport tcp:13120 tcp:3120` → `GET /dshm-python/run-get?token=…`（宿主进程 pid=27876）实测：

| 路径 | 读数 |
|---|---|
| `/storage/Users` | `lstat` **通**（`0o40711`），但 `listdir` → **`Errno 1 Operation not permitted`** |
| `/storage/Users/.git` | `FileNotFoundError`（不存在） |
| `~` | `0o42771`（存在）；`.git` 不存在 |
| `~/Download` | 存在；`.git` 不存在 |
| `~/Download/com.dshm.dshclient` | 存在；`.git` 不存在 |
| `~/harness` | 存在；`.git` 不存在 |

环境（同一次读数）：`HOME=/data/storage/el2/base/haps/entry/files`、
`DSHM_PUBLIC_DOWNLOAD=~/Download/com.dshm.dshclient`、
`PWD=~`。

⇒ `/storage/Users` **不是** `currentUser` 的别名（别名会 `lstat` 与 `listdir` 一起通），
它是**同级的别人的目录**（自己都列不出来）⇒ 闸门拒绝它是**正确**的。

> 顺带记一条读日志的坑：这条故障在 `dshm-host.log` 里**一个字都没有**（宿主只记 HTTP 进出行），
> 而 `files/dsh/home` 是 `0700`、**`hdc shell`（uid 2000）读不到**
> ⇒ 「`grep` 了主日志、没有痕迹」**不等于**"设备上没发生过"。

## 3 修法：`patchAgentInstructionsScopeWalk()`（pack-core 第 24 处注入补丁）

位置：`tools/pack-core.mjs` 的 `patchAgentInstructionsScopeWalk()`，打的是
`node_modules/@deepseek-ai/dsh-agent-instructions/lib/index.js`，**两处**（标记 `DSHM_SCOPE_WALK_TOLERANT` ×2）：

| # | 改哪里 | 改动 |
|---|---|---|
| 1 | `isMissingProviderPathError()` 旁 | 新增同族判据 `isScopeDeniedProviderPathError(error)`：`code === "FS_PERMISSION_DENIED"`（闸门唯一的拒绝码；**不 import 闸门**，上游文件不依赖端侧插件） |
| 2 | `existsAsMarker()` 的 `catch` | `if (isMissingProviderPathError(error) \|\| isScopeDeniedProviderPathError(error)) return false;` |

语义（写进树里那份注释）：这一问是"**此处有没有标记**"⇒ **无权看就是没有**，继续向上；
走到 `/` 之后由上游自己 `return resolve(cwd)` 收尾（上游既有兜底）。
**只多认这一个码** —— 其余错误（含取消、裸 `EPERM`）照旧上抛，闸门的错误语义没有被放宽。

**没动**：`fs-fence.js`（两份副本）、三个入口的接线、`docs/137` 的任何判据。

## 4 门禁（两条，缺一不可）

### 4.1 `tools/check-core-openharmony-patches.mjs` ㉔ 组（**179** 项，174 → 179）

钉"这棵树里到底有没有这段注入"：标记 ×2、两处注入形态在、
**上游两处原文（helper 段、单码判断行）已消失**。

### 4.2 新增 `tools/check-agent-instructions-scope-walk.mjs`（**6 / 0**，带四条对照臂）

不读标记，而是**真跑**树里那份 `dsh-agent-instructions`：把包复制到临时舞台
（`node_modules` 用 junction 指回核心树供裸导入解析），给它一个"像闸门一样"的假 `ctx.fs`，
看它**炸不炸**：

| 臂 | 配置 | 期望 | 为什么必须有 |
|---|---|---|---|
| A 正臂 | 已修 + 面外 ⇒ `FS_PERMISSION_DENIED` | **不炸**，且**确实探到了**面外那一跳 | 少了"确实探到"这半条，"根本没走到那一跳所以没炸"也会绿 |
| B 对照臂 | **上游原文** + 同一个 fs | **必须炸** `FS_PERMISSION_DENIED` | 这条就是真机 P0 的**复现**；它绿才说明注入的容忍真的在起作用 |
| C 对照臂 | 已修 + 面外抛**别的**码（裸 `EPERM`） | **仍必须炸** | 证明只多认那一个码，不是"一律吞" |
| D 对照臂 | 已修 + cwd 下就有 `.git` | 正常返回，且**一次都不往 cwd 上面探** | 证明"项目根识别"语义没被改坏 |
| E 对照臂 | 上游原文 + 面外"根本不存在"（无闸门） | **不炸** | 证明 B 的炸来自闸门那个码，不是夹具自身有病 |

> 夹具踩的坑（已修）：模块里一律用 `node:path` 处理路径，Windows 上
> `~` 会被 `resolve` 成 `<盘符>:\storage\Users\currentUser`
> ⇒ 断言里必须比较**同一口径**的字符串。第一版正臂就以"没探到 `/storage/Users/.git`"红了一次，
> 而那条红**恰好**说明这条断言是有牙的（否则正臂永远是"没探到所以没炸"的假绿）。
