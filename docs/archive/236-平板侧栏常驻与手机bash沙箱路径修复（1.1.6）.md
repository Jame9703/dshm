# 236 · 平板侧栏常驻与手机 bash 沙箱路径修复（1.1.6）

> 日期：2026-10-24
>
> 用户口径：平板横屏、竖屏以及回到会话区时，左右侧栏入口都常驻；只有手机在
> 右侧栏打开时隐藏左侧入口。不要再依赖点击右侧栏按钮触发恢复。

## 1. 最新日志

复查 `2026-10-24 07_49_11.log`：

- 平板显示面为 `2800×1840`；
- DSHM 主进程、NWeb/renderer 与 Host 均能启动；
- 没有新的 DSHM FATAL、AppFreeze、JS Runtime 致命错误或 Host 崩溃；
- 问题仍属于侧栏入口的可见性状态机，不是应用启动失败。

## 2. 根因

旧样式只把左侧浮动入口的显示条件绑定在官方侧栏处于 `collapsed` 时；同时还有
一条全局规则在右侧栏打开时隐藏入口。因此：

1. 侧栏展开后左侧入口消失；
2. 返回会话区或旋转后，入口要等下一次状态变化或点击右侧栏才恢复；
3. 平板与手机共用同一条右栏隐藏规则，平板也被错误隐藏。

## 3. 修法

三端 `WebApp.ets` 的侧栏垫片统一为：

- `dshm-handheld:not(.dshm-compact)`：平板左侧入口常驻；
- `dshm-pc`：PC / 2in1 左侧入口常驻；
- `dshm-compact` 且 `data-dshm-right="open"`：仅手机 / 折叠屏单屏隐藏左侧入口；
- 删除按右栏状态全局隐藏左侧入口的规则；
- 官方侧栏尚未挂载、状态未知时仍默认显示左侧入口。

`entry` 垫片补上 `COMPACT_CLASS` 常量。PC 工程不会给平板或 2in1 挂
`dshm-compact`，手机 / 折叠屏单屏由移动壳的 `platformSingleScreen` 判定。

这次只改可见性规则，不改用户手动展开/收起状态，不再用临时点击修复入口。

## 6. 手机端 bash 127 的追加修复

装机后复查 `node-output.log` 发现 VM 本身完全正常：

```text
QGA 就绪（+6694 ms）
guest 探测段：/bin/bash 已在（1212 ms）⇒ 跳过安装段
guest 侧已就绪：/bin/bash 可用
```

真正失败点是插件镜像宿主路径时写死了 entry 模块：

```text
/data/storage/el2/base/haps/entry/files -> /mnt/share
```

手机实际沙箱是 `haps/phone/files`，因此 QGA 执行
`/bin/bash /data/storage/el2/base/haps/phone/files/vm/tmp/run-*.sh`
时脚本路径不存在，`guest 命令结束 … rc=127`。平板同样使用不同的模块名，属于共用根因。

修法是让 `guestSandboxFilesPath()` 从 `DSHM_SANDBOX_HOME` 取实际沙箱路径，再建立
`/mnt/share` 链接；不再写死 entry。核心升到 `0.2.1-rc.2+dshm.89`。

随后用本轮 r5 调试包对手机执行普通 `hdc install -r -p …/phone`：手机仍是
`1.1.6 / 1010006`，运行核心从 `.88` 切到 `.89`，`dsh/home` 指纹仍为
`links=9 size=3440`。PC 在 r5 安装时已从 HDC 掉线，因此本轮只确认了手机；
PC 的 r4 仍是同版 1.1.6，但核心为 `.89` 之前的 `.88`。

修复后手机新启动实测多条 guest 命令（含 `pwd`、管道、算术、中文输出、文件写入/读取/删除）
均返回 `rc=0`：

```text
guest 命令结束：pid=90 rc=0
guest 命令结束：pid=102 rc=0
guest 命令结束：pid=104 rc=0
guest 命令结束：pid=111 rc=0
```

新增 `tools/check-vm-bash-sandbox-path.mjs --self-test`：覆盖 entry / phone / tablet
三种路径，并带 3 个变异对照臂。
