# 221 · 浏览器任务冷启动与结束后自动关闭验收

> 日期：2026-10-21 ｜ 输入：`~/harness/DSHM-ENV-TOOLCHECK-2026-10-21.md`（含 23:05 复测）

## 1. 目标

恢复并确认 PC-only 工程仍保留移动端剥离前的浏览器任务能力：

1. 浏览器没启动时，任务可直接冷启动海泰浏览器；
2. 扩展自动回连；
3. 任务结束后关闭本次由 DSHM 拉起的浏览器页面；
4. 不关闭用户自己已经打开的浏览器。

用户给出的历史扩展目录：

```text
~/Download/com.dshm.dshmbeta
```

当前海泰实际加载的扩展仍是 `DSHM Browser Bridge 0.11.0`，桥协议与当前
`hostcore/browser-extension/` 同版。

## 2. 接线

现有代码链完整：

```text
browser_navigate
  → ensureClient()
  → /dshm-open-link（bundle=com.haitai.htbrowser）
  → ArkTS OpenLinkBridge.startAbility
  → 海泰启动并打开目标 URL
  → 扩展 Service Worker 回连 ws://127.0.0.1:19390/browser-bridge
  → browser_navigate CDP Page.navigate
  → session/event turn/end
  → 扩展 close
```

关键接线：

- `hostcore/plugins/dshm-tool-browser/lib/index.js`：`ensureClient()` 冷启动；
- `hostcore/app/main.js`：`/dshm-open-link` 成功后 `armAutoClose`；
- `entry/src/main/ets/system/OpenLinkBridge.ets`：显式启动海泰；
- `hostcore/browser-extension/background.js`：`close` 只处理本次 `sessionTabId`。

## 3. 真机冷启动验收

先强停海泰浏览器，桥状态确认：

```json
{"ok":true,"port":19390,"clients":[]}
```

随后通过真实 Agent 任务要求调用 `browser_navigate` 打开
`https://example.com`。日志读数：

```text
GET /dshm-open-link?...url=https%3A%2F%2Fexample.com&bundle=com.haitai.htbrowser
browser-autoclose: armed url=https://example.com
GET /dshm-open-link 151ms status=200
browser-bridge: extension connected id=ws_2
browser-bridge: extensionInfo id=ws_2 {..."build":"dshm-host-bridge-11"...}
browser_navigate → {"ok":true,"load":"complete","via":"cdp-pagenavigate"}
```

确认冷启动、扩展回连和导航均成功。

## 4. 自动关闭验收

任务完成后日志：

```text
session/event(turn/end turn=6)
browser-autoclose: disarm (turn-end turn=6)
browser-autoclose: close result {"ok":true,"via":"minimize-single-tab","windowId":1960787817}
```

语义与旧版适配一致：

- 多标签窗口：只关闭 DSHM 使用的那一个标签页；
- 单标签窗口：最小化窗口，绝不删除最后一个标签页；
- 不关闭用户自己已经开着的浏览器，因为只有 `/dshm-open-link` 成功拉起后才武装关闭。

单标签只最小化是海泰的已知安全边界：删最后一页会使 EntryAbility
`terminate timeout`，之后浏览器窗口句柄失效，只能强制停止恢复。
