## 0. 先承认一句：平板的口径我一直理解错了

用户原话：**「它的逻辑看齐 PC，只是没有顶栏」**。

我前几轮把它当成「手机逻辑（抽屉）」来做，越修越偏。正确口径是：

| 维度 | 平板应有 | 我此前实现 |
| --- | --- | --- |
| 顶栏 | **没有**（已达成 ✓，换壳生效） | 无 |
| 左栏 | **常驻、占位、不自动隐藏**（PC 那样） | 抽屉式，会被官方按 narrow 收起 |
| 右栏 | 同 PC：按需打开、占位 | 未处理 |
| 入口 | 不需要 ⊞（常驻了就不需要入口） | 收起态才给 ⊞ |

⇒ 平板 = **PC 的三栏布局**，唯一差别是没有原生顶栏。这条写进 `MEMORY.md` 之前必须改。

## 1. 为什么现在它会自己收起来（机制）

手机壳里平板的 `platformForm === 'tablet'`，落到官方 layout 的这条判定上：

```js
narrow = viewport < 1024
drawer = viewport < 768 && !windowsTitlebar
sidebarCollapsed = narrow ? !narrowExpanded : sidebar === 0
```

- 平板 CSS 视口宽度实测没到 1024（Pad 类设备按 dp 折算常在 800~950），于是 `narrow = true`；
- `narrowExpanded` 初始为 false ⇒ **默认收起**；且「跨断点/切面板」都会被强制重置回收起；
- 我上一轮加的常驻自愈走 `clickToggle()`，但**只有当判定为 `collapsed` 时才点**；如果官方那一下只把它推到"窄轨"而不是 280 全宽，看起来仍是"没显示/没常驻"。

## 2. 平板方案（看齐 PC）

在 `phone` 壳的垫片里新增**平板专属分支**（不再走手机的 compact/drawer 那套）：

1. **强制三栏几何**：`html.dshm-tablet .dshm-frame { grid-template-columns: 280px minmax(0,1fr) auto !important }`
   —— 用 `!important` 压掉官方 inline style；第三列留 `auto` 以免把右栏宽度写死。
2. **侧栏列常驻可见**：`html.dshm-tablet .dshm-sbcol { position: relative !important; z-index: auto !important; width: auto !important; transform: none !important; visibility: visible !important }`
   —— 覆盖 drawer 态的 `position:absolute / transform:translate(-100%) / visibility:hidden`。
3. **封掉官方抽屉遮罩**：平板档每拍把 frame 内 `z-index:70` 的遮罩节点 `display:none`（它会在内容上盖一层半透明+模糊并吃点击）。
4. **强制官方 state=expanded**：每拍若 `data-sidebar-collapsed` 存在就点一次 opener（800ms 节流），确保 React 渲染的是全宽侧栏内容而不是图标轨。
5. **隐藏 ⊞**：平板常驻后不需要入口。
6. **diag 行补 `w=<innerWidth>`**：下次日志能直接看出落在 768 以下还是 768~1024。

## 3. 终端：先看历史，再定修法

### 3.1 历史文档的结论（用户要求核对）

- `docs/123` / `docs/125`：端侧终端走 **guest VM + virtconsole**，一直靠 `dshm-vm-bash` 接管 `ctx.subprocess.spawnTerminal` 才成立；UI 的 shell 列表是 `/bin/sh`、`/bin/bash`（**不是** profile 里那个 `/usr/bin/zsh` 默认值）。
- 同一批文档记录了「**手机档内 bash 垫片不生效**（`ash` 被 MAC 拒绝 exec）⇒ 终端在手机档起不来」——所以手机能不能用终端，**完全取决于 VM 是否可用**。

### 3.2 与 0.2.1 的差异（已比对）

`dsh-terminal-bash` 在 0.2.2 有一处改动：

```diff
- const currentMode = state.sessionProjections.stateOf(session, "sandboxMode") ?? … 
+ const currentMode = state.sandboxPolicy.overrideOf(session) ?? …
- inject: ["terminal", …, "sessionProjections"]
+ inject: ["terminal", …, "sandboxPolicy"]
```

`overrideOf` 在 0.2.1/0.2.2 的 `dsh-sandbox-policy` 里都存在 ⇒ **这一处不是回归点**（但要写进门禁，防以后再次错判）。

### 3.3 当前最可能的两条（按概率）

1. **VM 根本没起来（或极慢）**：本轮已把探测段瘦身（只挂载 + 判 `/bin/bash`），并加了 5s 心跳
   `VM 启动中：阶段=<phase> 已 <n>s`。但用户交上来的三份日志里**一条应用日志都没有**（只有 CEF/ArkWeb 噪声），所以这段结论仍未证实。
2. **guest 里没有 zsh**：`handle.js` 的白名单把 `zsh` 映射成 guest `/bin/zsh`，而镜像里**只有 `/bin/bash`**（`docs/123` 实读）。若终端某次以 `zsh` 起，就是 ENOENT ⇒ 表现为"一直启动中"。修法：`zsh → /bin/bash` 兜底（一致化），并在日志里标明"已降级"。

### 3.4 终端方案（分三步，先证据后改法）

1. **埋点（先做，代价最小）**：
   - `dsh-api-terminal-controller` 侧：`[dshm-terminal] create args=…`
   - 我们的接管点：`[dshm-terminal] 接管命中/未命中（argv[0]）`
   - 失败时把 VM `stage + 已耗时 + 串口尾部前 200 字` 一起塞进终端错误文案（UI 可见）。
2. **确定修法**：`zsh → /bin/bash` 白名单兜底；`profile` 的 `terminal-bash.shellPath` 改 `/bin/bash`（与 UI 的 shell 列表一致，去掉那个不存在的 zsh）。
3. **兜底体验**：VM 未就绪时终端面板显示「虚拟机正在启动（阶段 X，已 Ys）」，而不是无限 spinner。
