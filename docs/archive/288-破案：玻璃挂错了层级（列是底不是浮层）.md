# 288 · 破案：玻璃挂错了层级（列是"底"不是"浮层"，模糊背后永远是自己）

> 日期：2026-10-29 18:45 ｜ 状态：**只读诊断，未改任何代码**

## 0. 结论：用户这个观察**直接锁定根因**

> **沉浸光感（`backdrop-filter`）一直有效，但它挂在"整列的底色"上——
> 而列的 `background` 就是最底层，`backdrop-filter` 模糊到的永远是**列自己的底色**，
> 永远不可能是上方滚动的内容。**
>
> **官方输入框能看到玻璃，是因为它 `position:absolute` + `z-index:-1` 浮在滚动内容**之上**，
> 背后是真的在滚动的文字。**

**⇒ 不是"白底盖住了玻璃"，是"玻璃挂错了层级"。** 这是本轮最重要的修正。

## 1. 用户观察为什么是决定性的

用户说的现象：**在会话区上方滑动时，输入框位置能看到玻璃质感。**

这条线索的价值：
- 它证明 `backdrop-filter` **在 ArkWeb 上真实有效**（不是能力缺失）；
- 它证明玻璃质感**真的能被肉眼看到**（不是"物理上限看不出来"）；
- 它把范围**精确锁定在"输入框 vs 我们挂的列"的差异**上。

⇒ 只要比较这两者的 CSS 结构，就能定位根因。

## 2. 官方输入框的实现（实读，`dsh-client-ui-conversation/lib/client.js:16832`）

```css
._7yHdaG_dock {
  box-sizing: border-box;
  width: calc(…);
  margin: 0 auto calc(0px - var(--dsh-composer-stack-gap) - 3px);
  flex: none;                      /* ← 不伸缩，浮在兄弟之上 */
}

._7yHdaG_panel {
  isolation: isolate;              /* ← 建立独立层叠上下文 */
  overflow: hidden;
  position: relative;
}

/* 玻璃层：独立伪元素，垫在面板内容后面 */
._7yHdaG_panel:before {
  z-index: -1;                     /* ← 关键：只垫在**本面板内容**之后 */
  border-radius: inherit;
  background: var(--dsw-specific-menu);
  backdrop-filter: var(--dsw-menu-backdrop-filter);
  content: "";
  position: absolute;
  inset: 0;
}
```

材质令牌（`dsh-client-ui-theme` 实读）：

```text
--dsw-menu-backdrop-filter: blur(40px) saturate(150%)
--dsw-specific-menu: #f8f9faf0     （亮色，f0 = 94% 不透明）
                     #303136f0     （暗色，94%）
```

### 2.1 这组数据推翻了我们此前的两个假设

| 此前的假设 | 官方数据 | 结论 |
|---|---|---|
| 「86% 太不透明，所以看不出」 | 官方 **94%**，比我们**更不透明** | **假设错误** |
| 「白底上模糊无意义」 | 官方的 `#f8f9fa` 同样是近白色 | **假设不完整** |

⇒ **透明度和颜色都不是原因。** 唯一剩下的差异是 **层级**。

## 3. 我们挂的列（`dsh-client-ui-layout/lib/client.js`）

```css
._pI_x6G_centerCol {
  background: var(--dsw-alias-bg-base);   /* ← 列自身就是背景 */
  border-radius: var(--dsh-windows-content-radius) 0 0 0;
  corner-shape: round;
}
._pI_x6G_centerCol {
  flex-direction: column;
  display: flex;
  overflow: hidden;                        /* ← 裁掉溢出 */
}
```

滚动容器在列**内部**（`dsh-client-ui-conversation`）：

```css
._<hash>_scrollBody {
  scrollbar-gutter: stable;
  flex: 1;
  min-height: 0;
  overflow-y: auto;      /* ← 真正滚动的是这个 */
}
```

### 3.1 层级关系图（这是全篇的核心）

```text
┌─────────────────────────────────┐
│ .centerCol  background: 实色     │ ← 我们在这里挂 backdrop-filter
│  ┌───────────────────────────┐  │
│  │ .scrollBody  overflow:auto│  │
│  │   会话文字 / 图片（在滚动）│  │
│  └───────────────────────────┘  │
└─────────────────────────────────┘

问题：backdrop-filter 作用于 centerCol 时，
      它"背后"是什么？→ 是 centerCol 自己的 background（实色），
      而不是它内部那些正在滚动的文字。
```

**CSS 的 `backdrop-filter` 模糊的是"元素背后已经绘制的内容"。**
`centerCol` 是最底层的一块板子，它的背后什么都没有（只有画布）；
而它内部的 `scrollBody` 内容在它**前面**、**内部**，**不在背后**。

⇒ **给列挂 `backdrop-filter`，物理上永远看不到滚动内容。** 这不是参数问题，是**结构问题**。

### 3.2 对比官方输入框为什么能

```text
┌─────────────────────────────────┐
│ .centerCol（底）                 │
│  ┌───────────────────────────┐  │
│  │ .scrollBody  滚动的文字 ──┼──┼──┐ 背景被模糊的是这个
│  └───────────────────────────┘  │  │
│  ┌───────────────────────────┐  │  │
│  │ .dock 面板（浮在上方）     │◄─┼──┘
│  │  :before{z-index:-1} 玻璃  │  │
│  └───────────────────────────┘  │
└─────────────────────────────────┘
```

**输入框是"浮在滚动内容之上的板子"** ⇒ 它的背后**真的是**正在滚动的文字
⇒ `blur()` 有东西可模糊 ⇒ **肉眼可见的玻璃**。

## 4. 修正后的认知（推翻前面几篇的部分结论）

| 文档 | 原结论 | 本轮修正 |
|---|---|---|
| `282` §8.2 | 「白 72% 叠白画布 = 零增量」 | **不完整**。真正的零增量不是颜色，是**背后没有内容** |
| `283` §3 | 「亮色观感有物理上限，只能靠偏色」 | **偏色不是解**。官方 94% 近白同样好看，因为它背后有内容 |
| `284`/`285` | 「深色/亮色规则生效了」 | **仍然成立**（规则确实生效），但**生效在一个看不见的位置** |

**新结论**：

> **玻璃的观感来源 = 背后有正在移动的内容。**
> 挂在不动的底色上，无论什么颜色、什么模糊强度，都只是一个色块。

## 5. 正确做法：把材质挂到"浮层"上

### 5.1 可以挂材质的元素（必须满足"浮在滚动内容之上"）

| 元素 | 是否合适 | 原因 |
|---|---|---|
| `.centerCol` / `.sidebarCol`（我们现在的做法） | ❌ **不可** | 是最底层板子，背后无内容 |
| **官方输入框 `.dock` / `.panel`** | ✅ **已经自带** | 官方已实现，无需介入 |
| **自绘顶栏**（DSHM 那条） | ✅ 可 | 浮在内容上方，滚动时能透出 |
| **侧栏的顶部/底部浮层**（如新建会话条） | ✅ 可 | 同上 |
| 侧栏列本身 | ❌ 不可 | 同 centerCol |

### 5.2 若确实想让「整列」有玻璃感，只有两条路

**路线 A：让列透明，让内容浮在全局背景上**

```css
.centerCol { background: transparent }        /* 列不再有不透明底 */
.scrollBody { background: transparent }       /* 内容也透明 */
/* 全局背景（壁纸/渐变）在最外层： */
body::before { position: fixed; inset: 0; z-index: -1; background-image: … }
```

⇒ 此时列**本身不需要玻璃**，因为整页就是"内容浮在壁纸上"的效果。
**这正是 `docs/287` 说的"先有背景，再谈材质"** —— 而且和皮肤插件路线天然契合。

**路线 B：把材质挂到真正浮在内容上的元素**

即官方输入框那种结构。我们需要的是同样的"浮层"，而不是"列"。

### 5.3 推荐组合（结合 `docs/287` 的皮肤插件）

```text
皮肤插件负责：
  ① 全局背景（壁纸/渐变/噪点）  ← 提供"可被模糊的内容"
  ② 令牌：--dsw-alias-bg-base 改成半透明  ← 让列不再是不透明板子
  ③ 材质：给**浮层**（顶栏/输入框区/侧栏浮条）挂 backdrop-filter
DSHM 负责：
  ④ 删掉挂在列上的玻璃（当前实现）
```

## 6. 验证方案（怎么确认这个结论）

### 6.1 立刻可做的对照实验

```js
// 在会话列内部找一个"会滚动"的后代，把列的背景设为透明，看玻璃是否出现
document.querySelector('.dshm-glasscol').style.background = 'transparent';
```

**预期**：如果列的 background 变透明、背后的画布是白的 ⇒ 仍然看不到内容模糊
（因为背后的画布也是空的）⇒ **进一步证明"必须有背景内容"**，
配合 `body::before` 放一张图即可立刻看到玻璃。

### 6.2 决定性实验（推荐）

在 `body` 上铺一张有明显纹理的图，**不改任何其他 CSS**：

```css
body::before{
  content:""; position:fixed; inset:0; z-index:-1; pointer-events:none;
  background-image:url(<任意照片>); background-size:cover;
}
```

**预期**：
- 列保持现状（86% 不透明 + blur）⇒ 透过 14% 能看到背景图被模糊 ⇒ **玻璃感出现**；
- 把列设成 `background:transparent` ⇒ 玻璃感**更强**。

⇒ 这一步就能在**不改架构**的前提下验证"背景内容"这个变量。

## 8. 一句话交接

**用户"输入框能看到玻璃"这个观察直接破了案**：`backdrop-filter` 从来没问题，
**是我们把它挂错了层级** —— 列的 `background` 是最底层板子，
`backdrop-filter` 模糊到的永远是**列自己的底色**，而不是它内部正在滚动的文字；
官方输入框能看到玻璃，是因为它 `z-index:-1` **浮在滚动内容之上**，背后有真内容可模糊。

**关键数据**：官方输入框底色 `#f8f9faf0`（**94% 不透明**）比我们的 86% **更不透明**，
却更好看 ⇒ **透明度和颜色都不是原因，背后有没有内容才是。**

**正确方向**：材质挂**浮层**，底色靠**半透明令牌**，内容靠**全局背景（壁纸/渐变）**
—— 后两条正是皮肤插件的强项，与 `docs/287` 的 R2 规划完全吻合。
