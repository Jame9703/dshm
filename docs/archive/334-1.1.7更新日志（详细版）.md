## 本次更新（9 条）

**1.【华为账号与云同步】** 接入华为账号，仅读取账号标识用于同步归属，**不保存登录凭据**；
会话、插件清单与工作区可云端备份并跨设备恢复，**插件只同步清单**、默认不自动安装；
同步内容显式排除核心运行时与 API Key。

**2.【连接稳定性】** 修复冷启动持续提示「连接异常」：系统 Web 内核把本机误判为离线，
导致连接循环休眠、不再发起尝试；现不再采信该判断，并改为失败后**自动退避重连**。

**3.【平板界面】** 侧边栏恢复常驻显示，手动收起后不会被自动拉回。

**4.【登录与通知】** 登录并入设置分区、不再跳二级页面；Agent 任务完成时在通知栏提示。

**5.【模型配置】** 保留官方通用自定义模型 API，服务地址、协议、模型与凭据由用户配置；专用本地模型入口及开箱可用承诺已撤回。

**6.【插件环境】** 随包提供独立 Node（子进程 JIT）与 PC 端 ffmpeg / ffprobe，
在「设置 → 插件」安装插件后即可使用，**无需自行配置**。

**7.【平台差异】** 平板 / PC 提供系统原生终端与媒体环境；
手机端因平台权限限制改为随包 guest 环境提供 bash，并以目录选择器授权工作区。

**8.【稳定性】** 修复**手机首次安装后偶发无法进入应用**；
修复**长时任务在息屏时被系统回收导致的后台连接中断**（续期重试 5 秒起、最多 8 次）；
修复重复入口与登录绕路问题。

**9.【精简与合规】** 权限精简为平板 / PC 15 条、手机 7 条；
思考过程翻译改为默认关闭，不再预设个性化设置。

**升级保障**：覆盖安装完整保留已有会话、插件、工作区、凭据与关键设置，**不清理任何用户数据**。

# 附录 A · 详细版（12 条，含逐条依据）

## 本次更新（12 条）

### 1.【华为账号】账号接入

- 只读取账号标识（`unionID`）作为同步归属；
- `authorizationCode` / `idToken` 等凭据字段**不读、不存、不上报**；
- 系统已登录华为账号时**静默完成授权**，不弹任何第二界面；
- 未登录时**就地提示**「请先在系统设置中登录华为账号」，不跳转二级页面。

### 2.【云同步】会话 / 插件清单 / 工作区

| 能力 | 说明 |
|---|---|
| 上传 | 规划器 + 执行器 + 真实进度；五个阶段都上报，失败/跳过也计入进度 |
| 拉取与导入 | 六道校验闸，`sha256` 导入前必验 |
| 插件清单 | 只同步清单（几 KB），**不传 `node_modules`**；默认不自动安装，用户勾选后才装 |
| 会话 | 按工作区稳定 ID 归属，换设备不会错位 |
| 内容排除 | 显式排除核心树与**凭据**，杜绝把 API Key 传上云 |

入口并入官方设置面板的一个分区（`settings.section`），**三端统一**，与「通用设置 / 内置插件」同构。

### 3.【连接稳定性】冷启动「连接异常」根治

**之前**：三端冷启动左下角持续提示「连接异常，刷新重试」，需手动点一下才连上。

**真正原因**：核心服务一直是好的（日志能看到它正常接受 TCP 连接）。问题在**系统 Web 内核把"本机自身"误判成"设备离线"**，连接模块据此认为没网，**整个重连循环进入休眠、不再发起任何尝试**；而唤醒它要等一个"网络已恢复"事件，可网络从头到尾都是通的，那个事件永远不会来。**不是连不上，是根本不试了。**

**现在**：页面本身从本机加载时（说明本机可达），不采信那个"离线"判断。附带把"失败即永久放弃"改为**自动退避重连**（0.5s 起、逐次加倍、封顶 10s）。

### 4.【平板界面】侧边栏常驻

官方界面在**窗口宽度 < 1024px 时默认收起**，平板竖屏/窗口化正好落在该区间。现在与 PC 一致：不主动收起就常驻展开，手动收起后不会被自动拉回，重启恢复常驻。

### 5.【登录体验】设置内就地完成

登录不再弹出尺寸与材质都不同的原生面板，也不再叠一层官方登录面板；全过程无第二界面。顺带撤掉「登录即表示同意……」文案——静默授权没有勾选步骤，那句话等于替用户确认了他没点过的事。

### 6.【通知】任务完成提示

接入通知权限；Agent 任务完成时在通知栏提示，点击可直接回到应用。

### 7.【模型配置】专用本地模型承诺已撤回

原「PC / 2in1 零代码接入本机模型」发布承诺已撤回，不再提供专用本地模型 / Ollama 入口与配置说明。官方通用自定义模型 API 保留；已有模型配置、凭据及其他用户数据不清理，系统语音听写保留。

### 8.【插件环境】装插件即可用（**1.1.6 起延续，非本版新增**）

APP **不内置**第三方插件本体，但公共运行环境随包提供，用户从「设置 → 插件」装上插件即可直接使用：

| 环境 | 内容 | 归属端 |
|---|---|---|
| 独立 Node | 随包 `node-cli`（≈51 KB），复用宿主 `libnode.so.137`；**子进程走 JIT** | 三端 |
| 媒体工具 | 随包 `ffmpeg` / `ffprobe` 9.0.1（28 个动态库，≈43 MiB） | **PC / 2in1** |
| Fetch 标准面 | 补齐 `headers.getSetCookie()`（多 `Set-Cookie` 逐条返回） | 三端 |

关键设计：宿主进程保持 `--jitless`（轻量），**插件子进程用 JIT**——否则 Node 原生 `fetch` 初始化会失败（`WebAssembly is not defined`），插件所有联网命令当场报错。

> 该能力自 **1.1.6** 起提供（`docs/264`）。本版更新日志把它写清，是因为它回答的是用户最常见的疑问「装了插件为什么还要自己配环境」。

### 9.【平台差异】执行能力按端划分

| 能力 | 平板 / PC | 手机 |
|---|:---:|:---:|
| 系统原生终端（bash / pwsh、持久会话） | ✅ | ❌ |
| guest 环境 bash（随包 QEMU，真 Linux 真 bash） | — | ✅ |
| 插件 Node 运行环境（JIT 子进程） | ✅ | ✅ |
| 插件 ffmpeg / ffprobe 媒体环境 | ✅ | ❌ |
| 个人目录直接读写 | ✅ | ❌（改为目录选择器授权） |
| 华为账号与云同步 / 插件安装 / 语音输入 / 通知 | ✅ | ✅ |

**原因**：手机端不能申请 `CUSTOM_SANDBOX` 与 `ALLOW_EXTERNAL_NATIVE_CODE`（权限表里确实没有）⇒ 无原生终端，改为随包 QEMU guest 里跑真 bash（一次 `execve` 都不发生）；也不能直接读写个人目录 ⇒ 改目录选择器一次性授权、可跨启动保留；ffmpeg 是原生动态库闭包且只随 PC HAP 分发 ⇒ 手机端不提供媒体环境。

### 10.【稳定性】三处真机问题

| 问题 | 结论 |
|---|---|
| 手机首次安装后偶发进不去 | 启动竞态，已修复并实测通过 |
| 熄屏后后台连接中断 | 长时任务续期被系统回收；已加屏幕状态感知与续期重试（5s 起、最多 8 次） |
| 二次审核发现的 5 处缺陷 | 双入口同屏、注入按钮点了没反应、手机登录绕路、Beta 出包器写死旧品牌、AGC 元数据旧品牌 |

### 11.【精简与合规】

- 移除未完成的**会议模式**（代码冻结备份，**语音输入保留**）；
- 权限 **17/9 → 15/7**：移除两条无实际功能使用的网络信息权限（平板 / PC 15 条、手机 7 条）；
- **思考过程翻译默认关闭**，不再预设个性化设置；已装过该插件的设备升级后也会自动关闭。

### 12.【升级保障】无损升级

覆盖安装完整保留：会话、插件、工作区、凭据（API Key）、关键设置。
升级只替换核心程序，`cores/` 与 `home/` 物理分离，**不清理任何用户数据**。

### 9.4 连接（docs/330–333）

**三个叠加缺陷**：

| # | 缺陷 | 修法 |
|---|---|---|
| 1 | `connect()` 因 `phase === CONNECTING` 早退，宽限期新 token 进不来 | 并发闸改用独立 `connecting` 标志（5 个出口复位） |
| 2 | 首次失败立刻 `connectSettled = true` + 写 `hubError` | 轮询窗口结束时 `settleAutoConnect()` 才做结论 |
| 3 | **keep-open 每拍点按钮，打断 WebSocket 握手** | **启动静默期 20 秒** |

**第 3 条是「三端齐刷刷出现」的真因**：

```text
16:47:58  IN-UPGRADE GET /api/remote.mux upgrade=websocket key=yes ver=13
16:47:58  URLRequestCanceled error:ERR_WS_UPGRADE(-173)
```

**为什么剥离会议后才出现**：docs/332 把 phone 的 keep-open 同步进 entry，
三端同时进入「每拍点按钮」状态。

## 11.1 本轮复核额外查出的两个构建链缺陷

整理更新日志时复核产物，发现两个**与功能无关、但会影响每次出包**的问题：

### 11.1.1 打包不可复现

| 项 | 内容 |
|---|---|
| 现象 | 同一个核心版本、同一棵源树，**三次连打得到三个不同 sha256**（`85a1447b` / `e0b0391a` / `571077f3`） |
| 根因 | 包内 `dshm-core.json` 的 `builtAt` 取的是 `new Date()`，即**打包时刻** |
| 后果 | 「三方一致」门禁失去意义：`check-resfile-core-zip` 断言 resfile ↔ 配方 ↔ 本次产出相等，而"本次产出"每次都变 ⇒ 重打一次包，之前放进 resfile 的那份立刻"不一致"；也无法回答"设备上跑的这棵树是不是就是仓库这一份" |
| 修法 | `builtAt` 改为 `reproducibleStamp()`：优先 `SOURCE_DATE_EPOCH`（可复现构建标准），否则取 `hostcore/core-recipe.json` 的 mtime（配方随核心版本变化 ⇒ 同配方同 sha） |
| 验证 | 三次连打 sha 完全一致（`ce881d27…`） |

> 语义也更准了：这里记的不该是"什么时候打的包"，而是"**这份核心内容什么时候成形的**"。

### 11.1.2 `--place-in-app` 开关根本不存在

| 项 | 内容 |
|---|---|
| 现象 | 按 AGENTS.md 跑 `pack-core.mjs --place-in-app`，命令**静默成功但 resfile 里什么都没有** |
| 根因 | 本仓库的 `pack-core.mjs` **从未实现这个开关**（`process.argv` 里查不到），文档记录的行为已丢失 |
| 后果 | 正是 AGENTS.md「三个坑」第 1 条描述的事故形态：新包留在 `dist/core/`，HAP 里带的还是旧容器，而链上自检只看设备树目录名 ⇒ 一路绿灯 |
| 修法 | 补实现：清掉其它旧容器（只留本次）→ 拷贝 → **回读 sha256 与本次产出比对**，不一致直接判错退出 |
| 目标目录 | ⚠️ 必须放 **`hostruntime`** 的 resfile。先误放了 entry ⇒ `entry-default.hap` 从 66 MB 涨到 **161 MB**（整个 .app 507 → 607 MB），因为核心由共享 HSP 承载，两个 HAP 都不该带它 |

## A.3 关于「启动变快」的诚实归因

用户在真机上反馈"冷启动/热启动/杀后台再启都变快"，但**无法归因到任一版代码改动**：

| 可能来源 | 是否成立 |
|---|---|
| 本轮诊断代码（同步环 / require 计时） | ❌ 它只加记账，且**默认关闭** |
| 核心 `.105` 的回环网络豁免 | ✅ **最可能**——此前会卡在"连接异常"等重试，现在不卡 |
| 核心树已解包（首启那 8 秒不再重复） | ✅ 确定成立，与代码无关 |
| 设备热缓存 / 后台更干净 | ⚠️ 无法排除 |

**结论**：体感提升是真实的，但功劳主要在 `.105` 的连接修复与"解包已付清"，
**不在本轮新增的诊断代码**。发布说明里不应把"启动加速"写成本版卖点。
