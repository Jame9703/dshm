## 1. 会议模式剥离

### 1.1 为什么剥离

会议模式自 2026-10-19 起就被 `MEETING_MODE_VISIBLE = false` 隐藏（用户要求），
但**代码与资源仍在包内**：一个跑不完的功能留在上架包里，对审核（权限用途、功能完整性）
和包体都是负担。用户决定：代码冻结备份，等有空再做。

### 1.2 备份（可完整还原）

```text

```

含：两个壳的 `MeetingPanel/Session/AiBridge/SenseVoiceRecognizer`、`platform/notify/MeetingKeepAlive`、
`appstate/model/Meeting`、`OhosTest/Meeting.test`、`hostcore/plugins/dshm-meeting-ai/`、
以及被改过的 WEBAPP / EntryAbility / module.json5 / string.json / shortcuts_config.json 的**原始版本**。

| 壳接线 | 两壳 WebApp 的 `@State meeting*`、`MeetingPanel` 挂载块、最小化胶囊、菜单项「会议模式」、`dshAction=meeting` 分支、`insertMeetingTranscript()` |

### 1.4 保留了什么（重要）

**语音输入**（`HmsSpeechBridge.ets` + `SystemSpeechRecognizer.ets`）**保留**——
它是上游 `dsh-experimental-voice-input-bundle` 的独立能力，不是会议专属：
语音按钮随时可用，Host 侧 speech-provider 被动等请求。

但 `SystemSpeechRecognizer` 原先 import 了 `appstate/model/Meeting.ets` 的
`updateMeetingTranscript / emptyMeetingTranscript / appendSegment`（用于合并引擎反复回调的累计文本）。
会议文件删掉后这条依赖会断，故**内联进使用点并改名**：

| 旧（Meeting.ets） | 新（SystemSpeechRecognizer.ets） |
|---|---|
| `MeetingTranscriptState` | `SpeechTranscriptState` |
| `emptyMeetingTranscript()` | `emptySpeechTranscript()` |
| `updateMeetingTranscript()` | `updateSpeechTranscript()` |
| `appendSegment()`（私有） | 同名，私有 |

> 逻辑**逐字等价**（四条判据顺序与空串早退都未改）——它是"识别结果文本合并"，与会议无一字关系，
> 搬进唯一使用点比留一个只为它存在的 `Meeting.ets` 更诚实。

## 2. 权限面收口：17/9 → 15/7

### 2.1 删除的两条

```text
ohos.permission.GET_NETWORK_INFO
ohos.permission.SET_NETWORK_INFO
```

### 2.2 为什么删

AGC 前置检查的硬要求：**声明的权限必须有功能在用**（`docs/249` 已按此条撤掉
`DISTRIBUTED_DATASYNC`）。逐条核对 17 条的运行时消费点后发现：

- 这两条是 `docs/249` 为「设备互联」**预研**加的，原文写着"运行时授权待设备互联入口接线后触发"；
- 而**设备互联功能至今没有实现**：产品代码里搜不到 `setAppNet` / `getConnectionProperties` /
  `hasDefaultNet` 等任何消费点（只有 `entry/pages/Index.ets` 的一句注释提到权限名，以及测试文件）；

⇒ 与 `DISTRIBUTED_DATASYNC` 完全同形。用户拍板删除。

### 2.3 改动面

| 项 | 改动 |
|---|---|
| `entry/src/main/module.json5` | 17 → **15** 条 |
| `phone/src/main/module.json5` | 9 → **7** 条 |
| `tools/check-permission-surface.mjs` | EXPECTED / PHONE_EXPECTED 同步；自检的合成用例（`reasonKeys`、`phoneStrEntries`）同步 |
| 两模块 `string.json` | 删 `perm_get/set_network_info_reason`（无孤儿） |
| `AGENTS.md` | 铁律表述改为「entry 恒 15 条 / phone 恒 7 条」 |

> **未动**：`CUSTOM_SANDBOX` / 两条 `kernel.*` / 三个目录读写 / `VIBRATE` / `MICROPHONE` /
> `KEEP_BACKGROUND_RUNNING` —— 它们都有实测的运行时消费点或执行域前提（删了会灾难性降级）。

### 2.4 自检里也被同步抓到的问题

改 EXPECTED 后 `--self-test` 判红 2 项（"真·15 条"与"phone 真·7 条"未被判绿）：
原因是自检**合成用例**的 `reasonKeys`（16 个）与 `phoneStrEntries`（9 个）仍含已删的两条 reason，
按**下标**取 reason 时错位。同步后自检恢复 `✅ 真·15/7 条判绿`。
