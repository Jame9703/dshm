## 2. 为什么同步清单而不是目录

| | 同步 `node_modules` | 同步清单 |
|---|---|---|
| 体积 | **143 MB** | **几 KB** |
| 跨架构 | ❌ 含 `.node` 原生模块，架构不同必坏 | ✅ 清单与架构无关 |
| 跨版本 | ❌ 装好的产物绑定 Node/ABI 版本 | ✅ 到端按当时环境重装 |
| 完整性 | ❌ 传一半就坏 | ✅ 安装器自带校验 |

**结论**：传意图，不传结果。

## 3. 三条纪律（写进代码）

### 3.1 基础包不进清单

```ts
const BUNDLED_PREFIX: string = '@deepseek-ai/';
```

`@deepseek-ai/dsh-base`、`@deepseek-ai/dsh-web-app`、`@deepseek-ai/dsh-subagent-codex`
等**随核心树附带**，版本跟随 `core-recipe.json`。若把它们当"用户插件"同步，
换端时会被当成用户安装，**与核心树自带版本冲突**。

### 3.2 顺序以 `dsh.profile.bundles` 为准

`cordis.patch.yml` 头注明确写过 patch 应用顺序有意义：

```text
bundle 层 patch（按 dsh.profile.bundles 顺序）
  → profile 的 cordis.patch.yml
  → $DSH_HOME/cordis.patch.yml
  → --patch 覆盖层
```

所以清单必须按 `bundles` 排，**不能按 `dependencies` 的 JSON 键顺序**。

### 3.3 spec 原样保留

`github:XDTrees/dsh-xdpool#v2.5.0` 里的 `#v2.5.0` 是**版本锚点**，丢了就会装到主干最新版——
那是另一个版本。所以 spec **逐字不动**，不做任何规范化。

## 4. 到端怎么装：复用既有通道，不另造轮子

**不新建安装逻辑**，而是走已有的：

```text
$DSHM_HOME/install-queue/<id>.req     ← spec 文本
        ↓（Host 侧）
dshm-installer.js 的 installSpec(spec)
        ↓
结果写回 <id>.done / <id>.fail（JSON）
```

这样插件安装的**全部既有约束继续生效**：完整性校验（`verifyTarballIntegrity`）、
失败回执、并发控制。

### 两种模式（用户提到"自动安装或者批量安装"）

| 模式 | 行为 | 适合 |
|---|---|---|
| **自动** | 登录后检测到缺失插件 → **直接排队装** | 用户默认期望 |
| **批量** | 列出"云端有、本机没有"的清单 → **用户勾选后一次装** | 换新设备、或本机装了很多 |

两种都由同一个 `missingPlugins(remote, localDir)` 判据驱动。

## 6. 门禁：`check-plugin-manifest`

### 判据（14 条）

| 组 | 内容 |
|---|---|
| A | `@deepseek-ai/*` 判为基础包；非基础包不误伤 |
| B | 顺序按 `bundles`（`dsh-context` 在 `dsh-xdpool` 之前，与 dependencies 键顺序相反） |
| C | `github:` 与 npm 版本号 spec **逐字保留** |
| D | `bundles` 里有、`dependencies` 里没有的包 → 记进 `skipped`（不静默丢） |
| E | `specKind` 分类：`github:`→git / 版本号→npm / `file:`→local |
| — | payload 带 schema、只含 `name`/`spec`；非法 JSON 不抛错且有原因 |

### 对照臂（3 个，全红）

| 变异 | 结果 |
|---|---|
| 去掉基础包过滤 | ✅ 判红（3 条） |
| 跳过 bundles 那一轮（改用 dependencies 顺序） | ✅ 判红（2 条） |
| spec 丢掉 `#ref` | ✅ 判红（1 条） |

## 7. 本轮踩的两个坑

### 7.1 手写正则剥类型，连错两次

门禁要"真跑" `.ets` 里的函数，得先去掉类型标注。手写正则：

- 第一版：`for (let i: number = 0` 的标注**漏掉**；
- 第二版：`as Record<string, Object>` 被截断成 `, Object>` ⇒ `Unexpected token ';'`；
- 第三版：修正后**吃多了** ⇒ `Unexpected token ')'`。

**正解**：Node 26 自带 `module.stripTypeScriptTypes()`，官方类型擦除，一行搞定。

> 教训：**能用官方工具就别手写正则**。这和之前"猜 API 字段名"是同一类错误——
> 先查有没有现成能力，再动手。

### 7.2 变异体写错了，看起来像"门禁没牙"

第一个"顺序"变异体是**反转 `dependencies` 键顺序**，结果不判红。

原因：补 `dependencies` 那一轮只处理 bundles **之外**的包，反不反转都不影响最终顺序。
**变异生效 ≠ 行为改变** —— 改成"整体跳过 bundles 那一轮"才真正改变顺序来源。

> 这已经是**第三次**踩同类坑（前两次：删 `exit 1` 但末尾有兜底、`String.replace` 只换第一处）。

### 关于 `cordis.patch.yml`

这个文件是**用户手写的 patch 层**（本仓自己的那份有 40+ 行注释说明每条的依据）。
它可能含**本机专属**的覆盖（比如某条只在当前设备禁用的 bundle）。

**建议先不同步**，或者"同步但需用户确认"，因为盲目覆盖可能禁用掉目标设备必需的 bundle。
