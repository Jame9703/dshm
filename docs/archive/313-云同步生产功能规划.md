## 1. 生产功能边界

### 1.1 首版同步内容

| 类型 | 云端单元 | 首版策略 |
|---|---|---|
| **会话代际** | 一个 `.jsonl.zstd` 代际 = 一个不可变 unit | 同步；不改上游格式 |
| **附件** | 一个内容寻址对象 = 一个 unit | 同步；保证会话附件不成为死链 |
| **技能** | 一个技能文件 = 一个 unit | 同步；体积小 |
| **插件清单** | 整份规范化清单 = 一个 unit | 同步清单，**不同步 `node_modules`** |
| **工作区索引** | 一份工作区公开信息 = 一个 unit | 同步名称与稳定 ID，不同步绝对路径明文 |

### 1.2 明确排除

```text
profiles/ondevice、node_modules、核心树、依赖树
cache、cores、session_projcache、cost-meter、shots/covers
.credentials.yaml、authorizationCode、accessToken、设备标识、运行时状态
cordis.patch.yml（含本机专属覆盖，首版不同步）
```

### 1.3 首版不承诺

- 自动实时后台同步（先做可靠的“开启后自动 + 手动立即同步”，后续再接 Host 变更事件）；
- 删除远端会话（首版本地删除不级联云端，防止误删）；
- 插件本机私有配置同步；
- 云端字节级实时传输进度（见 §4）。

## 2. 数据模型：一张表、统一 unit，先定死 schema

### 2.1 为什么统一为 `sync_units`

会话、附件、技能、插件清单都可以表达为“**不可变内容 + 元数据**”。
统一表避免四套上传/下载/校验代码，也避免每种内容分别踩一次 Asset 的坑。

### 2.2 本地表（AGC 必须逐字对应）

```sql
CREATE TABLE sync_units (
  unit_id TEXT PRIMARY KEY,
  kind TEXT,
  workspace_id TEXT,
  session_id TEXT,
  version INTEGER,
  sha256 TEXT,
  bytes INTEGER,
  updated_at INTEGER,
  metadata TEXT,
  payload ASSET
);
```

| 字段 | 含义 |
|---|---|
| `unit_id` | 全局稳定 ID；跨端去重主键，禁止自增 |
| `kind` | `session` / `attachment` / `skill` / `plugin_manifest` / `workspace` |
| `workspace_id` | 稳定工作区 ID；非本机绝对路径 |
| `session_id` | 会话类记录的会话 ID，其它类型可空 |
| `version` | 会话代际号；其它类型按内容版本/0 |
| `sha256` | 内容字节校验，导入前必验 |
| `bytes` | 文件字节数 |
| `updated_at` | 毫秒时间戳 |
| `metadata` | **有 schema 的小 JSON**：显示名、原文件名、迁移代际、来源信息；不放密钥、不放本机路径 |
| `payload` | 文件本体对应的 Asset；本体放 `distributedFilesDir` |

### 2.3 AGC 云侧

```text
容器：DSHM
数据类型名称：dshmsyncunits（可字母数字，供 AGC 标识）
本地表名称：sync_units
端侧去重主键：unit_id
payload：Asset
其余字段：String / Integer（按上表）
```

⚠️ **云侧实施后列只能增不能改**，所以上表是施工前需要你确认的对象之一。
`metadata` 留作未来兼容扩展，避免频繁加列。

## 3. 工作区映射与冲突规则

### 3.1 工作区映射：稳定 ID + 首次确认

不直接拿 cwd 绝对路径跨端合并。

```text
云端：workspace_id + 显示名 + 来源 projectKey 的摘要/建议
本机：workspace_id ↔ 当前设备 projectKey/cwd 的映射
```

- 首次同步检测到云端工作区时，弹出「云端工作区 X ↔ 本机工作区 Y」；
- 同名候选只作为**建议**，不自动合并；
- 用户未确认前，该工作区保持“待映射”，不导入任何会话；
- 映射存本机，云端不存本机绝对路径。

### 3.2 冲突：不可变优先、本地活动数据优先

| 情况 | 处理 |
|---|---|
| 云端与本机 `unit_id + sha256` 相同 | 跳过，不重复下载/导入 |
| 同 `unit_id` 但 sha256 不同 | 标记异常，**不覆盖**，交用户选择 |
| 云端有、本机无 | 可拉取导入 |
| 本机有、云端无 | 可上传 |
| 本机会话正在使用/写入 | **不覆盖、不替换**；放入“待导入” |
| 版本更新的会话代际 | 按代际新增，不把新代际当旧代际覆盖 |

首版冲突处理保守：**宁可不导入，也不能把本机现有会话弄坏。**

## 4. 登录与同步页面：统一信息架构和鸿蒙视觉规范

### 4.0 统一原则（本轮审核后补充）

登录不是孤立弹层，同步也不是另一套工具页；二者采用**同一信息架构**：

```text
账号与空间 → 同步概览 → 内容清单 → 任务与进度 → 异常与任务记录
```

- 顶栏保持「应用 / 编辑 / 云同步」三个 `MenuTitle`；
- 页面保持页内浮层与返回行为，不改成另一套 `Navigation`；
- 组件沿用 `SettingGroup` / `SettingLine`，新增进度条、清单行、任务卡也用同一套间距与圆角；
- 颜色只用 `sys.color.*`，间距/字号/圆角继续用 `Sp/Fs/Radius`；
- 状态颜色统一：品牌色=进行中/已连接，警示色=需处理，错误色=失败，三级文字=未启用；
- 同一事实只有一个来源：`SyncEngine`，顶栏菜单、账号卡、同步概览、清单不得各算一份；
- 同一动作只保留一个主入口：菜单负责“进入/直接登录”，页面负责“管理与执行”。

### 4.1 登录页：产品介绍区 + 官方登录区 + 说明区

登录页在未登录时显示，分三段，不再只是一个孤立的“登录”按钮：

```text
┌────────────────────────────────────────┐
│ ‹ 返回       华为账号与云同步          │
├────────────────────────────────────────┤
│ [应用图标] DSHM                        │
│ 让会话、附件和插件清单随华为账号流转   │
│ 换设备后可拉取并导入，继续使用         │
├────────────────────────────────────────┤
│ 将同步这些内容                         │
│ ✓ 会话记录与附件  ✓ 技能  ✓ 插件清单   │
│ 不会上传核心树、缓存与账号凭据         │
├────────────────────────────────────────┤
│ [官方 LoginPanel / 华为账号登录按钮]   │
│ 登录即表示同意相关协议与隐私说明       │
└────────────────────────────────────────┘
```

**官方登录组件不重画**：`LoginPanel` 是官方账号 UI，按 Account Kit 规范承载；我们重新设计的是它外围的产品说明、同步范围说明、错误反馈和页面布局。

- 隐私协议文本仍通过 `privacyText` 配置；
- 加载中、取消、未登录系统账号、缺 scope、身份不匹配都显示可读原因；
- 不自制账号密码输入框，不保存授权码/token；
- `LoginPanel` 继续只渲染在页面内，不放进 `CustomDialog`。

### 4.1a 登录后账号卡：账号公开信息 + 云服务状态

登录后，同一个位置变为“账号与云空间”卡片：

```text
[头像/首字母占位]  用户昵称（有 profile 权限时）
                   华为账号 ****abcd
云服务状态         已连接 / 待开启 / 异常
同步内容           会话 · 附件 · 技能 · 插件清单
```

字段与来源：

| 字段 | 来源与降级 |
|---|---|
| 昵称、头像 | 需要额外 `profile` scope；只有授权成功才显示。无权限时显示“华为账号用户”与通用账号图标占位 |
| UnionID | 登录凭据已有，**只显示脱敏值** |
| 云服务状态 | 来自实际端云同步可用性；不以“登录成功”冒充“云空间已连接” |
| 云空间基础信息 | 见 §4.1b，不能编造总容量/剩余容量 |

### 4.1b 云空间基础信息：只展示有合法数据来源的内容

本机 SDK 核查结果：

- `LoginWithHuaweiIDCredential` 只有 openID/unionID/authorizationCode/idToken；
- 头像、昵称需另行 `AuthorizationWithHuaweiIDRequest(scopes:['profile'])` 授权；
- `cloudSyncManager` / `cloudStorage` 未提供可直接读取“华为账号云空间总容量、剩余容量”的现成接口。

因此首版账号卡显示：

```text
云服务：已启用 / 未开启 / 连接异常
同步范围：会话、附件、技能、插件清单
本机待同步：N 项 · X MB
云端可拉取：N 项（完成发现后）
```

**不显示**“云空间总容量 200 GB / 剩余 100 GB”这类无来源数字。
如果后续要展示容量，必须另行找到官方容量接口或经用户授权的服务端数据源，再单独立项。

## 5. 三段进度：上传、拉取、导入分开显示

### 5.1 上传进度

```text
扫描 → 准备 Asset → 写入同步表 → 云端同步 → 校验结果
```

显示：`已完成单元数/总单元数`、`当前项名称`、`成功/失败/跳过`、错误原因。

### 5.2 拉取进度

```text
发现云端变更 → 下载元数据 → 下载/确认 Asset → 进入待导入区
```

显示：`已拉取单元数/总数`、Asset 状态（待下载/下载中/可用/异常）。

### 5.3 导入进度（独立于拉取）

```text
读取待导入包 → 校验 → 建立工作区映射 → 暂存 → 原子落位 → 刷新索引 → 可用性验收
```

显示：`已校验/已落位/已可打开/失败`，**“下载完成”不等于“导入完成”**。

### 5.4 进度能力的诚实边界

SDK 的 `ProgressDetails.details` 提供：

```text
upload/download：total / successful / failed / remained
```

因此记录级进度有依据；**不能声称有官方字节级云端传输进度**。
字节数用于本地扫描与准备阶段，云端阶段以单元数为准。
页面必须区分“已准备字节”与“云端已确认单元”，不能把两者混成假百分比。

## 6. 导入必须可用：六道闸

1. **路径安全**：拒绝 `..`、绝对路径、越出目标目录；
2. **完整性**：文件字节数 + sha256 必须与记录一致；
3. **格式可读**：会话日志代际文件名与 header 版本、会话 ID 一致；
4. **映射确认**：未确认工作区映射时不写入正式会话目录；
5. **原子落位**：先写 staging，临时文件完成后 rename；失败清理暂存，不留半截；
6. **可用性验收**：导入后能出现在会话列表，且至少能读取 header/打开会话。

### 活跃会话保护

- 导入期间暂停本单元相关写入，或发现活动会话则只进入“待导入”；
- 绝不直接覆盖正在使用的日志；
- 同一 `unit_id` 已成功导入则幂等跳过；
- 部分失败有报告与重试，不把整批标成成功。

## 7. 插件导入后怎么安装回去

### 7.1 流程

```text
云端插件清单
  → 与本机清单比较（包名 + spec）
  → 生成缺失/版本漂移列表
  → 用户勾选（首版默认不自动安装）
  → 逐项写 install-queue/<syncId>.req（原 spec）
  → Host 既有 installSpec() 安装
  → 读取 .done/.fail
  → 显示每插件进度与结果
  → 提示重启应用以挂载插件
```

### 7.2 原则

- **不下载/恢复 `node_modules`**；
- 复用既有完整性校验、下载、解包、依赖安装与回执；
- 本机已有且 spec 相同：跳过；
- 本机已有但版本不同：标为“版本不同”，默认**保留本机**，由用户决定是否重装；
- 一个插件失败不阻断其它插件，最终显示成功/失败清单；
- bundle 型插件按既有规则写入 `dsh.profile.bundles`，**重启后生效**；
- `cordis.patch.yml` 不恢复，避免覆盖本机必要配置。

### 7.3 安装进度

```text
等待安装 → 下载中 → 解包/落位 → 已安装待重启 / 失败
```

Host 队列单线程安装，页面轮询 `.done/.fail`，同时显示当前包名与已完成 `n/N`。
安装完成后明确提示“重启应用后插件生效”，不能显示“已可用”。

## 10. 部署流程（生产）

### 10.1 AGC

1. 容器 `DSHM` 下创建 `sync_units` 数据类型与全部字段；
2. `payload` 选 Asset；端侧去重主键 `unit_id`；
3. 先在开发环境验证；
4. 确认字段无误后**实施变更到生产环境**；
5. 修改云侧配置后，设备退出华为账号再重新登录。

### 10.2 应用

1. 全量门禁与构建；
2. 出正式 release `.app`（`com.dshm.dshclient`，ACL 7 条完整）；
3. 上传 AGC；
4. 云调试验证上传、拉取、导入、插件安装；
5. 通过验收后发布测试/生产版本；
6. 旧版本不因 schema 变化而误读：`metadata` 带 schema，遇到不支持的版本拒绝导入而不是硬解。

### 10.3 上线顺序

```text
AGC schema 生产实施 → 设备重登账号 → 新版应用上传 → 双端验收 → 发布
```

反向会导致旧应用找不到新 schema。

## 11. 验收标准

| 场景 | 必须达到 |
|---|---|
| 首次上传 | 清单数量与本地一致；排除项为 0；失败有原因 |
| 第二端拉取 | 显示拉取与导入两段进度；不是只显示“同步成功” |
| 导入可用 | 新会话出现在列表并能打开；附件可读 |
| 重复导入 | 幂等，不复制、不覆盖 |
| 活跃会话 | 不被覆盖；进入待导入并解释 |
| 同名工作区 | 不自动串数据；必须用户确认映射 |
| 插件恢复 | 按 spec 安装；每个有结果；重启后生效 |
| 插件冲突 | 不静默覆盖本机版本 |
| 中断恢复 | 断网/杀进程后可重试，无半截文件 |
| 隐私 | 不上传凭据、核心树、缓存、本机绝对路径 |
| 生产界面 | 无诊断入口、无“尚未接入”、无假成功 |
| 未登录页 | 产品介绍、同步范围、官方登录区、隐私说明层次清晰；不自制账号密码表单 |
| 登录后账号卡 | 显示脱敏账号与真实云服务状态；无 profile 权限时不伪造昵称头像 |
| 云空间信息 | 不展示无官方来源的总容量/剩余容量数字 |

## 12. 本轮规划审核结论

### 12.1 风格一致性：已统一到一套页面语法

- 登录页、账号卡、同步概览、内容清单、任务进度都使用同一 `SettingGroup/SettingLine` 与 token；
- 登录与同步不再分成“产品页 + 技术验证页”两种风格；
- 顶栏、账号卡、清单都读取同一 `SyncEngine` 状态；
- 错误、空状态、加载中、未授权均有明确降级展示。

### 12.2 功能可实现性：六个关键边界已校正

1. **官方登录 UI 不可任意重画**：只重设计外围布局与说明，登录仍走官方 `LoginPanel`；
2. **昵称头像不是 ID 登录白送**：必须另申请 `profile` scope，首版做成可选增强；
3. **云容量没有现成来源**：不编数字，首版只显示连接状态和真实同步统计；
4. **端云进度是记录级**：不把记录数包装成云端字节级百分比；
5. **插件安装后需要重启**：安装完成 ≠ 立即可用；
6. **导入可用必须实测打开**：不能只以文件落盘作为成功。

### 12.3 生产部署风险：两项必须在施工前处理

- `sync_units` 是新的生产 schema，不能直接拿旧 `sync_probe/sync_assets` 冒充；必须在 AGC 新配置并实施；
- 首版上线前至少需要**两个同账号端侧环境**验证“上传 → 拉取 → 导入 → 打开”，单端自证不足以宣称跨端可用。

## 13. 需要你确认的七项

1. **同步范围**：按 §1.1（会话、附件、技能、插件清单、工作区索引），其余排除；
2. **表结构**：按 §2 的统一 `sync_units`，尤其是 `payload ASSET` 与 `metadata`；
3. **工作区映射**：稳定 ID + 首次用户确认，不按目录名自动合并；
4. **冲突策略**：本机活动数据优先，同 ID 不同 hash 不覆盖；
5. **插件恢复**：首版用户勾选后安装，不做无提示自动安装；
6. **登录与账号信息**：按 §4.1 重做登录页；昵称头像用可选 `profile` 授权，云容量不编数字；
7. **登录态**：本机可持久化 UnionID/昵称头像用于显示，但不持久化授权码/token。

确认后我按 **A → B → C → D → E** 施工，每批出包与验收，不一次性把所有链路堆给你。
