## 2. 缺陷 A 复测：`npm list` 非 profile 目录

### 2.1 修复后行为

```text
$ cd /tmp && npm list
pnpm(shim): 当前目录不是包目录（无 package.json）⇒ 改查当前 profile：…/profiles/ondevice
[{"name":"ondevice","path":"…/profiles/ondevice","private":true,
  "dependencies":{ "dshmarket":…, "@iasiv5/dsh-skins":…, "dsh-skin-market":… }}]
$ echo $?
0
```

✅ **三重问题全部解决**：
1. **不再误报**"端点到不可达"，改为明确告知"回退到 profile"；
2. **返回真实数据**（完整依赖树），而非空数组 `[]`；
3. **rc=0 语义正确**（这次真的成功了）。

### 2.2 三种 cwd 全覆盖验证

| cwd | 结果 |
|---|---|
| `/tmp`（无 package.json） | ✅ 回退 profile + 返回依赖树 |
| `…/dsh/home`（无 package.json） | ✅ 回退 profile + 返回依赖树 |
| `…/profiles/ondevice`（有 package.json） | ✅ 直接查询 + 返回依赖树 |

### 2.3 源码实现（开发端写得扎实）

`hostruntime/…/app/main.js:2733-2737`：

```js
'  LISTDIR="$(pwd)"',
`  if [ ! -f "$LISTDIR/package.json" ]; then`,
'    LISTDIR="$PROFILE_DIR"',
'    echo "pnpm(shim): 当前目录不是包目录（无 package.json）⇒ 改查当前 profile：$LISTDIR" >&2',
'  fi',
```

**更值得记的是它对根因的注释**（`:2740-2746`）：

> 随包 busybox 的 wget 在**连不上**与 **404** 两种情况下都返回 rc=1、stdout 都为空
> （实测：200 ⇒ rc=0 带正文；404 ⇒ rc=1 空；Connection refused ⇒ rc=1 空）。
> 原写法只用 `$?` 判，等于把这两种结局压成同一行"端点到不可达"——正是 `docs/293` §5.1
> 指出的"排障方向被带歪"。

⇒ **开发端不但修了表症，还定位到 busybox wget 的语义陷阱**，
改用「正文是否以 `[` 或 `{` 开头」判成功（`:2761-2764`），并区分两类失败（`:2769-2772`）。

## 5. 291 三个缺陷的复测（超出本次范围，但一并核实）

### 5.1 🟡 缺陷 1：`__DSHM_BRIDGES__` 报错 —— **降 46%，未根除**

**按速率对比**（因宿主重启，绝对数不可比）：

| 采样点 | 运行时长 | 次数 | **速率** |
|---|---|---|---|
| 初测（293 时，pid 1408） | — | 9,258 | **780 次/分钟** |
| 复测采样 1（pid 32603） | 2.2 分钟 | 987 | 449 次/分钟 |
| **复测采样 2** | **4.4 分钟** | **1,839** | **420 次/分钟** |

⇒ **从 780 降到 420 次/分钟（约降 46%）**，但 **仍以 7 次/秒持续产生**。

**新增关键线索**（本次首次捕获）：错误前紧邻这条日志：

```text
[oh_gin_javascript_bridge_dispatcher_host.cc:1028]
  OhGinJavascriptBridgeDispatcherHost::CheckIsInJsPermission:
  permission map is empty or no object_id(1) key
```

⇒ **桥对象的权限映射是空的**（`permission map is empty`），
这解释了为什么 `__DSHM_BRIDGES__` 找不到 —— **不是没注册，是没授权**。
这是比初测更精确的根因线索，建议开发端从这里查。
