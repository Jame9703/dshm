## 1. 手机端为什么看不到（根因）

### 1.1 官方 navList 是 React 渲染的

`dsh-client-ui-settings-general/lib/client.js`：

```js
div({ className: navList,
      children: rows.map((row) => button({ ... }))   // ← React 管理这批子节点
})
```

### 1.2 上一版的错

```js
function inject() {
  if (document.getElementById(ITEM_ID) !== null) { return; }  // 已存在就不再管
  list.appendChild(el);
}
setInterval(inject, 1000);   // 每秒查一次
```

**查到了就不管了**。但官方任何一次重渲染都会**重建 navList 的子节点**，
我 append 的那个 button 被一起移除。

### 1.3 为什么 PC 看起来正常、手机不正常

- **PC**：设置面板打开后基本不重渲染 ⇒ 注入项留住了；
- **手机**：`SETTINGS_SHIM_JS` 把 navList 改成 **横向滚动容器**
  （`flex-direction:row; overflow-x:auto`），布局计算、滚动状态变化都会触发重渲染
  ⇒ 注入项被反复冲掉。

### 1.4 修法：MutationObserver

```js
observer = new MutationObserver(function () { ensureItem(); });
observer.observe(list, { childList: true });
```

**从"查一次"变成"结构一变就保持存在"**，对重渲染免疫。
低频巡检（500ms）只负责"发现面板打开/切换时重新挂观察者"。

## 2. 菜单项加图标

按官方 `navCell` 的 DOM 形态构造（`[svg, span]` 两个子节点）：

```js
el.innerHTML = '<svg viewBox="0 0 16 16" width="16" height="16" fill="none" '
  + 'stroke="currentColor" stroke-width="1.3">'
  + '<path d="M8 3.5a3.5 3.5 0 0 1 3.42 2.75A2.75 2.75 0 0 1 11.5 11.5h-7'
  + 'A2.75 2.75 0 0 1 4.08 6.25A3.5 3.5 0 0 1 8 3.5Z"/></svg>'
  + '<span>云同步</span>';
```

样式仍抄官方邻居的计算样式（含 `gap`、`height`、`padding`、`fontSize`），
并加 `flex:none; white-space:nowrap` 以适配手机档的横向 pill 布局。

## 3. 面板 UI 对齐官方设置

用户口径：「**UI 就跟设置里面的一样，不要再单开**」。

### 3.1 官方设置面板的实测几何

从 `dsh-client-ui-settings-general` 的 CSS 常量提取：

| 部件 | 官方规格 |
|---|---|
| `.panel` | `width:800px`；`height:min(800px, calc(100vh - 2*24px))`；`border-radius:var(--dsw-radius-panel)`；`background:var(--dsw-alias-bg-layer-2)` |
| `.nav` | `width:188px`；`padding:22px 12px 0`；`gap:18px` |
| `.content` | `flex:1`；`flex-direction:column` |
| `.header` | `height:54px`；`padding:20px 14px 8px 10px` |
| `.options` | `flex:1`；`padding:0 24px 24px`；`overflow-y:auto` |
| `.navCell` | `height:40px`；`border-radius:var(--dsw-radius-md)` |

### 3.2 我们对齐了什么

| 部件 | 改前 | 改后 |
|---|---|---|
| 面板容器 | 全屏铺满 `100%×100%` | **`width:800`、`height:min(800, 100vh-48)`**、`corner_radius_level12`、`bg_secondary` |
| 遮罩 | 无（整屏被替换） | **`#4D000000` 暗色遮罩**，点击关闭 |
| 顶栏 | `minHeight:52` | **`height:54`**，`padding 10/14/20/8`（对齐官方 header） |
| 内容区 | `padding 16/16/16` | **`padding 0/24/24`**（对齐官方 options） |
| 标题字号 | `TITLE_M(18)` | `TITLE_S(16)` |

### 3.3 高度为什么用算的

官方是 `min(800px, 100vh - 48px)` —— **相对视口**。
写死 800 在自由窗口或手机上会超出屏幕底部，所以：

```ts
private panelHeight(): number {
  const H = this.viewportHeightVp;
  if (H <= 0) { return 800; }       // 量不到时退回官方默认值
  return Math.min(800, H - 48);
}
```

进入页面时用 `window.getWindowProperties().windowRect` 量一次视口高度。

## 7. 一个诚实的边界

**注入项不是官方 React 组件**，它是我们 append 的真实 DOM。
`MutationObserver` 能保证"官方重渲染后它还在"，但**不能保证它参与官方的键盘焦点环与分区切换逻辑**
（官方的 `aria-current`、`data-modal-autofocus` 那套属于 React 的状态管理）。

**表现上的影响**：用键盘 Tab 切到该按钮时，官方的高亮态不会套用；
点击打开的是原生面板（不切官方分区），所以不影响功能。

要做到完全原生一致，只能**把云同步实现成 dsh 插件**、走官方 `settings.section` 注册 ——
那是另一个量级的改动（需要插件化 + 打包链路），不在本轮范围。
