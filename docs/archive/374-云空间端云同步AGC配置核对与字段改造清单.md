# 374 · 云空间端云同步：AGC 配置核对与字段改造清单

> ⚠️ **路线回退说明（2026-11-06，覆盖原「已被 docs/375 取代」标注）**：`docs/375` 曾评估改走 Cloud Foundation Kit，但用户最终决定「**继续走云空间服务**——面向普罗大众，由使用者自行承担云空间费用」，且 Cloud Foundation Kit 自 2026-10-28 起停止新开发者接入 ⇒ **本文 §2 的容器名 / 数据类型名 / 字段清单重新生效，是端云同步的唯一配置口径**。「设备 + 日期必须显式建模」的结论仍有效。
>
> 2026-11-06 现场（用户订正）：**容器名已经是 `DSHM`，正确且不可删改**。AGC 数据类型配置表单有**两个独立字段**：「数据类型名称」有字符校验（仅字母数字、以字母开头，`sync_units` 因下划线被拒），「**本地表名称**」填 `sync_units`（允许下划线、必须与端侧表名逐字一致）。当前类型叫 `syncdshm` + 10 字段（含 `workspace`），其「本地表名称」若不是 `sync_units`、且字段未配齐 ⇒ `code=CLOUD_DISABLED schedule=2`。**代码一行都不用改**。
>
> 依据：`docs/308` §4「数据类型名称：任意（字母数字）／本地表名称：sync_units」、`docs/314` §7.1「数据类型名称：dshmsyncunits（字母数字）／本地表名称：sync_units ← 逐字一致」。官方部署指导 L111「数据类型名称需要和 ArkData 本地表名称保持一致」由表单里的「本地表名称」字段保证，**不是要求两个名字字面相同**。
>
> ⚠️ **正式 release 包连的是生产环境**（官方：证书 debug→开发环境、release→生产环境）。数据类型若已实施到生产而不能删改，就在同一容器下**新增**一个合法名字的数据类型（如 `dshmsyncunits`）并把「本地表名称」填 `sync_units`；配齐 12 字段后再「实施变更到生产环境」。云侧配置更新后，端侧须**退出华为账号重新登录**。

> 日期：2026-11-05 ｜ 依据：AGC 截图（容器/数据类型 `syncdshm` + 8 字段）+ `harmonyos-docs` 官方指南 + 本仓 `platform/src/main/ets/sync/*` 实读

> ⚠️ **时间窗口**：官方明确「一旦部署到生产环境，数据类型和字段不允许删除或修改」。现在还在**开发环境**，改一次几乎零成本；发布后再改就得新建容器重来。

## 0. 三条硬结论

1. **表单里「本地表名称」必须填 `sync_units`**（= 端侧 `SYNC_TABLE`，逐字一致）；「数据类型名称」只是云端标识，可用任意合法字母数字（如 `dshmsyncunits`），**不要求等于表名**。容器名 = 本地库名 **`DSHM`**（已正确，不动）。当前若「本地表名称」填错/没填 ⇒ 端云同步找不到对应表，必然 `CLOUD_DISABLED`。
2. **现有 8 个字段少了 2 个、错 1 个名**：缺 `kind`、`metadata`；`workspace` 应为 `workspace_id`。
3. **要支持"设备 + 日期"必须再加 2 个字段**：`device_id`、`uploaded_at`（现有的 `updated_at` 是**内容修改时间**，不是上传时间，用它当"日期"会把三天前的内容算成今天的快照）。

## 1. 官方要求（原文摘录，不是转述）

来自 `harmonyos-docs/guides/应用框架/ArkData（方舟数据管理）/同应用端云数据同步（分布式）/端云数据同步云侧环境部署指导.md`：

> - **容器名称需要和 ArkData 本地数据库名称保持一致**，例如 ArkData 的数据库名称为 `note.db`，容器名称则为 `note`（大小写保持一致，不用填写后缀）。
> - **数据类型名称需要和 ArkData 本地表名称保持一致。**
> - 云侧自定义字段名称及类型需要与本地数据接入云空间的字段名称及类型**保持一致**。
> - 类型映射：`Encrypted String/String ↔ TEXT`、`Integer ↔ INTEGER`、`Double ↔ DOUBLE`、`Bytes ↔ BLOB`。
> - **云端所有配置字段默认允许为空，ArkData 本地表所有字段定义不能设置 NOT NULL 属性。**
> - ArkData 本地表字段设置为主键时，需在云侧**高级设置 → 端侧去重主键**里勾选该字段。
> - 前置：AGC **在"API 管理或开放能力管理"里启用「云空间」** → 「全部功能 → 构建 → 云空间服务」创建容器 → 配置数据类型。
> - 用户侧需在**"设置 → 云空间"打开同步开关**；系统版本 ≥ HarmonyOS **6.1.0**、云空间版本 ≥ **6.3.0**；**仅中国大陆**。

本仓实读（`platform/src/main/ets/sync/SyncStore.ets`）：

```text
SYNC_DB    = 'DSHM.db'
SYNC_TABLE = 'sync_units'
CREATE TABLE sync_units (
  unit_id      TEXT PRIMARY KEY,
  kind         TEXT,
  workspace_id TEXT,
  session_id   TEXT,
  version      INTEGER,
  sha256       TEXT,
  bytes        INTEGER,
  updated_at   INTEGER,
  metadata     TEXT,
  payload      ASSET
)
```

## 2. 你需要在 AGC 上这样配（照抄）

### 2.1 容器

| 项 | 值 |
|---|---|
| 容器名称 | **`DSHM`**（= 本地库 `DSHM.db` 去掉 `.db`，**大小写一致**） |

> 容器 `DSHM` 已存在（官方：容器创建后**不可删除**），直接使用。数据类型若已实施到生产而不能删改，就在同一容器下**新增**一个合法名字的数据类型并把「本地表名称」填 `sync_units`（生产环境仅支持增加），旧的 `syncdshm` 留着不用。

### 2.2 数据类型（两个独立输入框，别混为一谈）

| 项 | 值 | 校验 / 约束 |
|---|---|---|
| 数据类型名称 | **`dshmsyncunits`**（沿用 `docs/314` §7.1；也可保留现有 `syncdshm`） | 仅字母数字、以字母开头；**`sync_units` 因下划线被拒** |
| **本地表名称** | **`sync_units`** | 允许下划线；必须与端侧 `SYNC_TABLE` 逐字一致 —— **这一项才是决定性字段** |

### 2.3 字段（12 个，逐字对齐；本地 DDL 实读 `SyncStore.ets`）

| # | 字段名 | 云侧类型 | 本地类型 | 说明 |
|---|---|---|---|---|
| 1 | `unit_id` | String（**端侧去重主键**） | TEXT PRIMARY KEY | 形如 `session/ws-1a2b3c4d/…`；**必须勾"端侧去重主键"** |
| 2 | `kind` | String | TEXT | **本次新增**——区分 `session / attachment / skill / plugin_manifest`，缺了它恢复端无法分类 |
| 3 | `workspace_id` | String | TEXT | ⚠️ 你建的是 `workspace`，**必须改名** |
| 4 | `session_id` | String | TEXT | 会话 id（合并去重的键） |
| 5 | `version` | Integer | INTEGER | 内容版本号 |
| 6 | `sha256` | String | TEXT | 内容摘要 |
| 7 | `bytes` | Integer | INTEGER | 字节数 |
| 8 | `updated_at` | Integer | INTEGER | **内容修改时间**（不是上传时间） |
| 9 | `metadata` | String | TEXT | **本次新增**——unit 元数据（模型、标题、插件 spec 等 JSON） |
| 10 | `payload` | **Asset** | ASSET | 资产本体。官方映射 `Asset↔ASSET`、`docs/314` §7.1「必须选 Asset」；你截图里现在是 `Bytes`，**若控制台类型下拉有 Asset 请改过来**（没有则告知我） |
| 11 | `device_id` | String | TEXT | **本次新增**——上传设备标识（型号 + 短哈希），支撑"按设备选" |
| 12 | `uploaded_at` | Integer | INTEGER | **本次新增**——本次上传时间，支撑"按日期选" |

> **时间戳类型（2026-11-06 订正）**：官方映射表是 `Integer ↔ INTEGER`，本地 SQLite `INTEGER` 为 64 位；此前「AGC Integer 是 32 位」的判断来自 Cloud Foundation Kit 的类型表，对云空间服务未必成立（用户截图里 `updated_at` 已是 `Integer` 且能保存）。稳妥做法：控制台**有 `Long` 就选 Long**（`updated_at` / `uploaded_at`），没有就沿用 `Integer`；`bytes` 用 `Integer`（单文件远小于 2.1 GB）。

> 计 12 列（含你已有的 8 列）。**全部不要设成必填/NOT NULL**（本地没有 NOT NULL，云端留空即可）。

### 2.4 高级设置

- `unit_id` → **端侧去重主键** 勾选（否则多端同步会按内部行 id 去重，而不是按业务主键，跨设备会出现重复条目）。
- `session_id` / `device_id` / `uploaded_at` → 建议勾"可检索/可排序"（你已默认勾上）。
- 加密：`payload` 与 `metadata` 里可能含会话正文，若要开"Encrypted String"请对 `session_id`/`metadata` 评估性能（官方提示加密字段影响同步效率）。

## 3. 为什么"设备 + 日期"必须新增两列（而不是复用现有字段）

| 你的需求 | 现有字段能否表达 | 原因 |
|---|---|---|
| 上传后按"设备 + 日期"存 | ❌ | `unit_id = kind/workspace/key`，**不含设备**；`workspace_id` 是项目路径的 FNV 哈希，两台设备同一项目算出**同一个** workspace ⇒ 无法区分来源设备 |
| "日期"是哪一天 | ❌ | `updated_at` 是**会话内容最后修改时间**；今天上传一个三天前的会话，`updated_at` 还是三天前 ⇒ 按它分组会错位 |
| 合并去重 | ✅ | `session_id` + `unit_id` 主键足够；合并时按 `session_id` 去重、保留本机（你要的口径） |

> 这也解释了为什么"上传成功但云端没数据"：即便日期/设备先不管，**容器名/表名/字段名不对时端云同步直接不认这张表**，本地写成功 ≠ 云端有数据。
