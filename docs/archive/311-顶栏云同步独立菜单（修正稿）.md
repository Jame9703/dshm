## 1. 方案演进（为什么最终是"菜单"而不是"图标"）

| 轮次 | 方案 | 结果 |
|---|---|---|
| 初版规划 | 拖动热区右侧加**云形状态图标**（四态着色 + tooltip） | ❌ 用户否决：「不是拖动，是让你移出来」 |
| 定稿 | **「编辑」后面加第三个菜单** | ✅ 与既有「应用」「编辑」同款形态，改动面最小 |

初版把用户"移出来"理解成了"做成常驻图标"，还绕着拖动热区做了整套避让设计；
用户要的其实是**与既有菜单并列的第三个菜单**——更简单、也更与顶栏现状一致。

> 教训：用户说「整体布局重新设计」不等于"发明新形态"；先确认是否就是
> 「沿用既有模式、加一个入口」。

## 2. 最终布局

```text
┌────────────────────────────────────────────────────────────────┐
│ [侧栏钮] [应用▾] [编辑▾] [云同步▾]      (拖动热区)       │三键│ │
└────────────────────────────────────────────────────────────────┘
```

「云同步」菜单展开后：

```text
云同步 ▾
├── 未登录华为账号        ← 状态行（置灰， amount 由 SyncEngine 决定）
└── 云同步设置…           ← 打开 CloudSyncSettings 浮层
```

登录后状态行变为 `已登录 ****abcd`（脱敏 UnionID，与设置页同一来源）。

### 2.1 为什么首行放状态而不是只有动作

- 登录/同步是**带状态**的功能：菜单项（纯动作）表达不了；
- `MenuElement.enabled` 官方支持置灰行（SDK `component/common.d.ts` 实读字段表：
  `value / icon? / symbolIcon? / enabled? / action`）；
- 菜单每次展开重新求值（登录发生在面板里、面板关闭触发本页重渲染），
  状态不会滞留旧值。

### 2.2 为什么诊断项不进这个菜单

诊断面板（连接/资产）已在 `CloudSyncSettings` 的「诊断」分组里（docs/308 的收口）。
再放进顶栏菜单会出现**两个入口打开同一面板**，用户无从分辨"哪个是正经的"。
菜单只留一个动作：`云同步设置…`。

## 3. 实施细节

### 3.1 「应用」菜单移除项（`WebApp.ets` appMenu）

移除 `华为账号与云同步` 及其注释，留一条指路注释说明去向。
剩余 4 项全部是**无状态动作**——菜单回归"动作集合"语义。

### 3.2 新增 `cloudMenu()`

```ts
private cloudMenu(): Array<MenuElement> {
  const st = SyncEngine.state();
  const status: MenuElement = {
    value: st.signedIn ? `已登录 ${st.maskedUnionId}` : '未登录华为账号',
    enabled: false,
    action: (): void => {}
  };
  return [
    status,
    { value: '云同步设置…', action: (): void => {
      this.bindSyncDiagnostics();
      this.attachSyncRoot();
      this.cloudSyncOpen = true;
    } }
  ];
}
```

### 3.3 顶栏挂载

```ts
this.MenuTitle('应用', this.appMenu())
this.MenuTitle('编辑', this.editMenu())
this.MenuTitle('云同步', this.cloudMenu())   // ← 新增
```

`MenuTitle` 是既有 @Builder（文本 + `bindMenu`），第三个菜单**零新样式**；
其后 `layoutWeight(1)` 拖动热区与 `decorPadRight` 三键避让**原样保留**。
