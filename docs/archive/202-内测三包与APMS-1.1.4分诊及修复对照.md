## 4. 与旧结论的冲突（必须纠正）

`docs/181` 曾写"SIGSYS 425 最后出现在 2026-10-16 21:23、构建脚本已有 libuv io_uring 无条件关闭补丁"。
本次 APMS 显示同一指纹在 **1.1.4 上 1951 次、末次 10-19 13:55**；但二进制取证（`docs/203`）证明：
**1.1.2→1.1.4 的 6 个已发 HAP 里 `libnode.so.137` 逐字节相同且 17 个 io_uring 系统调用槽全部中性化**，
1.1.4 HAP 内 61 个原生库活体 425 为 0 ⇒ **425 不来自我们的随包件**。所以既不能按 `docs/181` 说"已修、别管"，
也不能盲改随包 `.so`（改错会让 libuv 把 0 当成功、去用未初始化 ring，比现状更坏）。**下一步只能是取证**：
读循环设备已装 `libnode.so.137` 的 sha（`hdc file recv`，只读）或 APMS 控制台按机型下钻；
若取到的是"未中性化件"，用 `tools/patch-libnode-io-uring.mjs --apply` 把它按 17 槽表改回来即可。
