# 391-平板「去 PC 应用角标 + 去系统顶栏 + 状态栏沉浸 + 收起按钮居中」收口

- 日期：2026-11-07
- 输入：`Download/com.huawei.hmos.browser/2026-11-07 17_38_54.log`（24,793 行）、用户真机截图两张
- 触发：用户「1 显示为PC应用，这是平板APP；2 侧边栏按钮收起后不居中协调；3 状态栏不沉浸」
- 状态：**已落地**（代码 + 门禁 + AGC 包）

## 1. 日志与截图先说清楚的三件事

| 现象 | 证据（原文） | 归因 |
| --- | --- | --- |
| 多任务里是「PC 应用」 | 应用包 `entry` 的 `deviceTypes = ["tablet","2in1"]` | 系统按 **模块设备面** 打标（docs/381、386、239 同一结论） |
| 自由窗口多一条灰色「DSHM」标题栏 | `窗口外观重放（decor-status）：手持档 非全屏 status=4 ⇒ 状态栏交还系统` | 手持档 + `FLOATING` ⇒ `pcMode=true` ⇒ **保留系统装饰**（`setWindowDecorVisible(true)` 的等价行为） |
| 状态栏不沉浸、顶部一条黑 | `SCBStatusBarView: … statusBarOpacity is 1, immersive is false`；日志里**没有任何**「平板沉浸：layout-fullscreen 已开启」 | `enterTabletImmersive()` 在 `onWindowStageCreate` 里被调用时 `this.mainWindow` 还是 `undefined` ⇒ **直接 early-return，一次都没执行过** |

> 第 3 条是纯粹的执行时序 bug：函数体没问题，调用点在 `mainWindow` 赋值之前。

## 2. 设备面：为什么「再加一个只声明 tablet 的 HAP」不行

官方《HAP》硬约束：

> 多 HAP 场景下，App Pack 包中同一设备类型的所有 HAP 中最多只能包含一个 Entry 类型的 HAP。

- 现有 `entry` 已含 `tablet`；再加一个 `tablet` 的 entry HAP ⇒ 同一设备类型两个 entry ⇒ 安装器报 `9568287`；
- 加成 `feature` HAP 则由安装规则放行，但 `2in1` 仍随包存在，**角标不会消失**（且 feature 不能承担应用入口）；
- 而 MatePad Edge 的 PC 兼容又要求「同一个 HAP 同时声明 tablet + 2in1」（docs/239 §1）。

⇒ 「平板不是 PC 应用」与「同一包继续覆盖 PC/2in1」在单包结构下**不可兼得**。

**用户裁决（2026-11-07）：entry 直接去掉 `2in1`。**

```diff
  entry/src/main/module.json5
- "deviceTypes": ["tablet", "2in1"]
+ "deviceTypes": ["tablet"]
```

- 平板：系统不再按 PC 应用登记 ⇒ 多任务角标消失、回归普通平板应用；
- `phone` 仍是 `["phone"]`；`hostruntime` 仍 `["phone","tablet","2in1"]`（设备面覆盖仍齐全，`check-store-readiness` 的 `REQUIRED_DEVICE_TYPES` 断言不受影响）；
- **已知代价**：本包不再覆盖 PC/2in1 与 MatePad Edge 的 PC 应用兼容安装。若后续要恢复，需按 docs/239 §4 的结论**单独出 PC 包**（独立 HAP/独立发布），而不是往同一个包里加 HAP。

同步改动的契约文件：`tools/build-agc.mjs`、`tools/check-pc-api26.mjs`（含变异锚点）、`tools/check-store-readiness.mjs`、`tools/check-pc-only-surface.mjs`（含 `--self-test`）。

## 3. 顶栏：手持形态不再进入 PC 模式

> ⚠️ **本节已被 `docs/416` 取代（2026-11-12 用户裁决 A）**：本节把 `pcMode` 改为恒 `false` 时只登记了「失去四边缩放边框」,
> 漏登记了「系统标题栏同时是分屏唯一入口」——结果平板既不能分屏也不能拖拽. 现已恢复 `pcMode = 手持形态 && FLOATING`，
> 自由窗口/分屏里保留系统装饰与三键，全屏仍沉浸. 本节仅作历史记录，不得按它实施.


`EntryAbility.afterWindowStageReady()` 原逻辑：

```ts
const pcMode = isHandheldForm() && statusPre === window.WindowStatusType.FLOATING;
if (pcMode) { /* 保留系统装饰，拿四边缩放边框 */ }
```

平板一进自由窗口就被判成 PC 模式 ⇒ 系统标题栏回来了（截图那条 DSHM），状态栏也交还系统。

改为恒 `false`（PC / 2in1 本来就 `isHandheldForm() === false`，这一段对它们没有影响）：

```ts
const pcMode: boolean = false;   // 移动端 APP 没有顶栏
win.setWindowDecorVisible(false);
```

`refreshDecorCaps()` 同步：不再按「自由窗口 ⇄ 最大化」切换装饰；只要系统在状态切换后把装饰带重建出来（`decorHiddenOk` 为假），就再隐藏一次。

**取舍**：自由窗口不再有四边缩放边框，只剩角落拖拽点。用户已明确「平板就是平板 APP、移动端没有顶栏」，接受该代价。

## 4. 状态栏沉浸：修时序 + 平板恒透明

1. **修时序**：`enterTabletImmersive()` 从 `onWindowStageCreate` 移到 `afterWindowStageReady`（`this.mainWindow` 赋值之后、且仅主窗）。
2. **恒透明**：`reassertWindowChrome()` 里平板（`readDeviceFacts().form === TABLET`）在「由应用持有状态栏」时用 `SYSTEM_BAR_HANDOFF_BG`（全透明）而不是 `chrome.bg`；页面已 `setWindowLayoutFullScreen(true)` 铺到状态栏下方，透明后页面背景直接透上来，不再出现与页面不同色的条带。
3. 手机（phone 壳）与 PC/2in1 的状态栏策略一个字节不动。

新增纯函数 `isTabletDevice()`（只认 `FormFactor.TABLET`；手机 / 折叠屏 / PC 都不算）。

## 5. 侧栏收起按钮居中

平板收起态是 56px 图标轨，⊞ 仍按手机的「贴角 6px」定位 ⇒ 左 6 / 右 14，肉眼可见偏左 4px。补一条只在 ≥768（真有图标轨）生效的规则：

```css
@media (min-width:768px){
  html.dshm-tablet[data-dshm-sidebar="collapsed"] #dshm-sidebar-fab{left:10px;top:10px}
}
```

`(56 - 36) / 2 = 10`，与轨内官方图标同列居中；`<768` 抽屉态无轨，仍沿用 6px 贴角。
