## 1. 插件安装命令复核

1.1.6 可用链路保持在以下三处，不另造安装实现：

- 设置页/模型投递的 `.req`；
- `hostcore/app/dshm-install-command.js` 仅做无 shell 的参数解析；
- `hostcore/app/dshm-installer.js` 的 `installSpec` / `removeSpec`。

本轮没有改写安装语义。最终 HSP 已直接取出包内文件验证：

- `dsh plugin --profile ondevice add @scope/plugin@1.2.3 --save-exact`
  解析为 `@scope/plugin@1.2.3`、`ondevice`、`saveExact=true`；
- 包内 `main.js` 确实用解析后的 spec 调用 `installSpec`；
- `check-dshm-installer.cjs` 全链路 `88 passed / 0 failed`，覆盖 npm、
  递归依赖、GitHub 回退、镜像回退、市场桥和 profile 桥；
- `check-mobile-upgrade-migration.mjs` 新增最终 HSP 内的真实解析器执行，
  防止“源码正确但最终包漏文件”的假绿。

## 2. APP 体积修复

迁移到共享 `hostruntime` HSP 后，旧 `place-toolchain` 仍把
`libpython3.12.so.1.0` 写入 entry HAP，导致同一 20 MB 原生库在 `.app`
中出现两份。

现在：

- libpython 只随共享 HSP 一份；
- PC/平板 entry HAP 不再携带重复件；
- `check-mobile-upgrade-migration` 直接检查最终 APP 的两个包，少一份或重复
  都会判红；
- entry HAP 从约 43.5 MB 降到 23.2 MB；
- APP 从 `481,030,983 B` 降到 `460,569,633 B`，减少 `20,461,350 B`。

## 3. 项目清理

本轮只清理可再生成缓存、旧候选和重复交付，不碰：

- `.certs/`、签名材料；
- `hostruntime/libs/`、当前 `.95` 核心；
- 源码、`third_party/`；
- 用户目录或设备 el2 数据。

删除范围：

- 旧 Beta、旧 release 候选、旧侧载目录与重复 ZIP；
- 各模块 `build/`、`.hvigor/`、DevEco C++ 缓存、CMake 缓存；
- Python `__pycache__`；
- 已被裁剪版 HAR 取代的 `sherpa_onnx-1.1.3.har.bak`。

工作区由约 20 GB 收敛到约 2.6 GB。侧载工具不再复制一份重复 `.app`，并支持
`--no-zip`，避免同一大批 HAP/HSP 再生成一个近 1 GB 的 ZIP。
