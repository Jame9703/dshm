### 1.2 新增数据模型 `SyncModel.ets`

统一表 `sync_units`（**生产契约，AGC 必须逐字对应**）：

```sql
CREATE TABLE sync_units (
  unit_id TEXT PRIMARY KEY,   -- 全局稳定 ID，禁止自增
  kind TEXT,                  -- session / attachment / skill / plugin_manifest / workspace
  workspace_id TEXT,          -- 稳定工作区 ID（不是本机绝对路径）
  session_id TEXT,
  version INTEGER,
  sha256 TEXT,                -- 导入前必验
  bytes INTEGER,
  updated_at INTEGER,
  metadata TEXT,              -- 有 schema 的 JSON，扩展走这里而不加列
  payload ASSET               -- 本体在 distributedFilesDir
);
```

**字段一律不加 NOT NULL**（官方硬约束，违反时同步报 `schedule:2,code:1` 且极难定位）。

## 2. 批次 B：上传链路

```text
SyncPlanner（决定传什么） → UploadRunner（怎么传） → SyncStore（表与资产）
```

### 2.1 三条纪律（各有代价）

| 纪律 | 实现 | 不这么做会怎样 |
|---|---|---|
| 排除面显式 | `isExcludedPath()` | 误传 143 MB 核心树；**把凭据传上云** |
| 工作区稳定 ID | `workspaceIdOf()` FNV-1a 摘要 | 换设备后工作区全部错位 |
| 清单元数计进度 | `progressRatio()` 含失败/跳过 | 有一项失败进度条永远 99% |

### 2.2 五个阶段都上报

`SCAN → STAGE_FILE → WRITE_DB → CLOUD_SYNC → VERIFY`

失败不伪装成功：任一单元失败计入 `failed`，整批只有 `failed===0` 且云端 `code=SUCCESS` 才报成功。

## 3. 批次 C：可用导入（六道闸）

```text
① 路径安全   isSafeRelativePath()：拒绝 `..` / 绝对路径 / 空段 / 反斜杠
② 完整性     字节数 + sha256 必须一致
③ 格式可读   canonicalSessionFileName() 与上游逐字一致
④ 映射确认   未确认的工作区不写入正式目录
⑤ 原子落位   写 staging → 校验字节数 → rename
⑥ 可用性验收 重新打开读一次；失败则回滚删除
```

**活跃会话保护**：目标已存在同尺寸 → 幂等跳过；不同内容 → **绝不覆盖**，标记冲突。

> 第③道闸的关键：上游按文件名解析代际，名字不规范的文件会被**完全忽略** ——
> 导入看似成功，实际会话根本不存在。

## 4. 批次 D：插件恢复

```text
云端清单 → diffPlugins() 比对 → 用户勾选 → install-queue/*.req
        → Host installSpec() → .done/.fail → 汇总 + 提示重启
```

| 原则 | 实现 |
|---|---|
| 不传 `node_modules` | 只传清单（几 KB） |
| 默认不自动装 | 用户勾选后才装 |
| 版本不同保留本机 | `differing` 只标记不覆盖 |
| 单插件失败不阻断 | 逐个 try/catch，最后汇总 |
| 装完不等于可用 | `needsRestart` 为真时 UI 明确提示 |

## 7. 部署流程（生产）

### 7.1 AGC 云侧（**必须先做**）

```text
容器：DSHM（沿用，已存在）
数据类型名称：dshmsyncunits（字母数字）
本地表名称：sync_units          ← 逐字一致
字段：
  unit_id      String
  kind         String
  workspace_id String
  session_id   String
  version      Integer
  sha256       String
  bytes        Integer
  updated_at   Integer
  metadata     String
  payload      Asset             ← 必须选 Asset
端侧去重主键：unit_id
```

步骤：
1. 在**开发环境**先建，核对字段；
2. 确认无误后**实施变更到生产环境**（实施后列只能增不能改）；
3. 设备**退出华为账号再重新登录**（端侧才会拉取最新云侧配置）。

### 7.2 应用侧

1. 全量门禁（13 项 + 5 组自检）；
2. 出 release `.app`（`com.dshm.dshclient`，ACL 7 条完整）；
3. 上传 AGC；
4. 云调试验证：登录 → 上传 → 换端拉取 → 导入 → 打开会话；
5. 通过后发布。

### 7.3 上线顺序（反向会失败）

```text
AGC schema 生产实施 → 设备重登账号 → 新版应用 → 双端验收 → 发布
```
