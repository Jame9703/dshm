## 1. 侧栏：收起被**持久化**成了永久设定

### 1.1 为什么 docs/325 的修法没解决

docs/325 把纯函数改成了「没存过 ⇒ 常驻展开」，判据也在。但**规则对、数据错**：

```ts
async loadSidebarExpanded() {
  this.sidebarStored = await prefs.loadSidebarExpanded();   // 启动时读回
}
private toggleSidebarExpanded() {
  this.sidebarStored = next;
  prefs.saveSidebarExpanded(next);                          // 点一次就落盘
}
```

平板上只要**历史上点过一次收起**，preferences 里就留下 `'false'`；
此后每次启动都把它读回来 ⇒ `stored === false` ⇒ 常驻规则的 `return true` 分支**永远进不去**。
用户说的“不主动收起他就一直显示”，在旧实现下**做不到**。

### 1.2 修法：收起只对本次运行有效

| 项 | 旧 | 新 |
|---|---|---|
| 点收起 | 写内存 + **落盘** | 只写内存 |
| 启动 | `loadSidebarExpanded()` 读回旧值 | **不再读** |
| 重启后 | 沿用上次的收起态 | 回到常驻展开 |

- `Index.ets` 删掉 `loadSidebarExpanded()` 方法及其调用；
- `toggleSidebarExpanded()` 只改 `sidebarStored`；
- `sidebarExpandedForMode` 保持纯函数（`stored !== undefined ? stored : true`）不变。

本次运行内仍然尊重用户：收起后在 DOUBLE/TRIPLE 之间切窗口大小**不会自己翻回来**（形态依旧不参与判定）。

### 1.3 `check-layout-fixtures` 的既有判据仍成立

纯函数层 9 条断言逐条复核（直接执行，绕开该门禁本机的 `platform` 模块解析障碍）：

```text
没存过 + 三栏/双栏/单栏 ⇒ 全部 true
双栏未存过宽度 = 240（panel，不是 56 的 rail）
双栏用户收起 = 56；单栏 = 0
形态不影响展开态：double == triple（未存过、false 两种情形都成立）
```

新增**持久化契约**断言（纯函数判不了这一层）：`Index.ets` 不得出现
`loadSidebarExpanded` / `saveSidebarExpanded`。

## 2. 连接失败：**过早显示错误**

### 2.1 先排除两件事

- 日志里的 `BOOT_70_HTTP_READY GET / → HTTP 401` 是 Host 的**自探**（`probeHttpReady` 不带 token 请求 `/`），
  401 是预期响应，**不是**用户看到的问题。
- `Connection` 的自动重连是**无限持续**的（`scheduleReconnect` 的重试耗尽回调仍会继续排期），
  所以启动期的一次失败必然会被后续重试治愈 —— 连接本身没坏。

### 2.2 真因：首次失败立刻置 DEGRADED

三条失败路径都**无条件**把界面切成 `DEGRADED`（左下角横幅 + 「重连」按钮出现）：

| 路径 | 位置 |
|---|---|
| `authenticate()` 失败 | `connect()` |
| `conn.start()` 返回 false | `connect()` |
| 载体 `DISCONNECTED` 状态回调 | `handleConnectionState()` ← **首次启动的主路径** |

而这三种情况在冷启动时**很常见且可自愈**：Host 从启动到 `BOOT_65_AUTH_URL` 实测 **+6846ms**，
Web 侧首个请求与 Host 就绪之间还有近 1 秒错位。

### 2.3 修法：首次连接给 12 秒宽限

```ts
private enterDegradedOrGrace(message: string): void {
  if (this.everLive) { /* 已连上过 ⇒ 立刻降级，用户需要知道掉线了 */ }
  if (this.graceTimer !== -1) return;          // 已在宽限内：继续等，不刷屏
  this.graceTimer = setTimeout(() => { /* 窗口到点仍未连上 ⇒ 这才置 DEGRADED */ }, 12000);
  this.notify();                                // phase 仍是 CONNECTING
}
```

- 三处失败路径统一走这个入口；
- `CONNECTED` 与 `LIVE` 两处都置 `everLive = true` 并 `clearGrace()`
  （否则计时器会在 12 秒后把已经连上的界面又翻回 DEGRADED）；
- **宽限只用于"从没连上过的首次启动"**；一旦 LIVE 过，断线立刻如实显示。

### 2.4 为什么是 12 秒

| 依据 | 读数 |
|---|---|
| Host 冷启动到 authUrl | 实测 +6846ms（首解包更久） |
| Web 首个请求错位 | 近 1s |
| 重连退避 | 秒级起、持续递增，12s 内必然试过数次 |

取 12s ≈ 「足够的自愈窗口」又不会让用户对着空白等太久。
