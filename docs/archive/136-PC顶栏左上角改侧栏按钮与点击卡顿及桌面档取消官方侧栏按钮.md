# 136 · PC 顶栏左上角改侧栏按钮 + 点击卡顿 + 桌面档取消网页那颗官方侧栏按钮（含一次「括号被吃掉」的真机事故与它的门禁）

## 0. 一句话结论

三件事一条链：**左上角的鲸鱼换成官方的面板图标**（= 侧栏开关，点击去点网页里官方那颗按钮）、
**点击从"纯等待 0~300ms"改成"乐观应用 + 20ms 快速对账"**、**桌面档把网页里那颗官方按钮整体取消**
（功能由顶栏那颗替代）。

第三件在真机上**第一次没生效**，根因不是选择器也不是时序，而是：往那条**拼接出来的样式表**追加规则时，
追加点正好是 `@media` 的收尾大括号 —— 那一刀把大括号吃掉了，于是**新规则静默落进了媒体查询里**，
PC 窗口比 1024 宽 ⇒ 条件不成立 ⇒ 一条都不落地。修法是补回大括号 + 加一条**内联样式**（每个巡检周期重打）。
同一个坑做了一条门禁（`tools/check-sidebar-shim-css.mjs`，4 个变异体）。

## 1. 症状与请求

用户原话（2026-10-10，PC 端）：

- 「PC端顶栏左上角的鲸鱼也换成左侧边栏按钮吧，并且现在手动点击这个按钮过渡有点卡」
- 「PC端这个改动不能影响移动端手机 平板之前做的左侧边栏按钮」

即三条约束：① 图形语义对齐官方（那颗按钮在官方客户端里就是侧栏开关）；② 点击要跟手；③ **手机 / 平板一个字都不许改坏**。

## 2. 修法与根因

### 2.1 左上角图形：鲸鱼 → 官方面板图标

- 新增资源 `entry/src/main/resources/base/media/sidebar_toggle.svg` —— 官方 `IconPanelLeftOutlineRegular`
  的图形（外圆角矩形挖内圆角矩形 + 竖分隔），**转成填充版**（`fill-rule="evenodd"`）。
  为什么必须转填充：`Image.fillColor` 只作用于**填充**，描边式 SVG 会保留原色 ⇒ 主题跟随失效。
  几何用自写栅格化脚本验过（32×32 点阵）。
- `entry/src/main/ets/pages/WebApp.ets`：`@Builder FishMark(...)` → `@Builder SidebarToggleMark(size)`；
  `fishMarkColor()` → `topBarIconColor()`（**保留 `@State themeMode` 响应式** —— 那是 E379
  「标识不随主题」修好后留下的通道，不能顺手换掉）。
- 几何逐字不动：盒 20.4vp、图标 18vp 居中、右间距 8vp ⇒ 右侧「应用 / 编辑」不位移（改动前后截图比对）。
- 删掉两个**零读点**的常量（`FISH_LOGO_VIEWBOX_W/H`），原位留注释说明被删的理由，并保留那条教训：
  **贝塞尔控制点的包围盒 ≠ 曲线墨迹的包围盒**。

### 2.2 「点击有点卡」：乐观应用 + 快速对账 + hover 底色

垫片原先只有 **300ms 巡检**写状态属性，而 §A/§B 的 CSS 全挂在这个属性上 ⇒ 点下去到"布局真的开始动"
之间有一段 **0~300ms 的纯等待**；官方的 `grid-template-columns` 过渡又已经跑掉一截 ⇒ 观感是"两段式、发卡"。

- **乐观应用**：这颗按钮点一下**必然翻转**，所以先按 `before` 的反值把属性写下去（与官方动画同帧起步）；
- **快速对账**：每 20ms 读一次真值，**按钮自己翻了就采纳并停**（不拿还没重渲染的旧读数去"纠正"乐观值），
  500ms 还没翻才 `syncState()` 纠回；
- 300ms 巡检保留作"页面整段重建后自愈"的兜底链；
- 顶栏按钮本身补 **hover 底色**（`#2E808080`，与手持档浮动开关同值）——"卡"的观感有一半来自"没反馈"。

真机判据（`files/diag-web-console`，`(tap 乐观)` 与 `(tap 对账)`/`(poll)` 分开记）：

```
07:22:00.667Z [dshm-sidebar] state collapsed, grid=0px 1103.43px 0px (tap 乐观)   ← 点击后 ~10ms
07:22:01.017Z [dshm-sidebar] toggle expanded -> collapsed, frame=collapsed        ← 官方过渡完成
```

### 2.3 桌面档取消网页里那颗官方按钮（§E）

那颗按钮长在侧栏列头一行、字标「deepseek HARNESS」右边。桌面档已经有**常驻**的原生顶栏入口，
而它在收起态还会被 §A 的 0 宽裁掉（"时有时无"才是最坏的一致）⇒ 取消。

- 判据用**闭包变量**（`isDesktop`，由原生桥 `platformForm()` 的答案置位），不用 `<html>` 上的类；
- 落地机制是**内联样式**：`toggle.style.display = 'none'`，**每个巡检周期重打一次** ⇒ 官方重建节点或
  改写属性时最迟 300ms 自愈；
- 另有一条 `html.dshm-desktop …button[aria-label=…]` 的 CSS 规则作第一道网，选择器由
  `COLLAPSE_LABELS` / `OPEN_LABELS` 生成（与 `findToggle()` / `stateOf()` 同一份文案真源）；
- **只藏、不删**：`stateOf()` 仍要靠它的 `aria-label` 才知道现在是收起还是展开（§A/§B 全挂在这个读数上），
  `display:none` 的元素仍在 DOM 里、仍可 `querySelector`，也仍可 `.click()`（`clickToggle()` 走程序化点击）。

### 2.4 真机事故与根因：追加规则时**吃掉了 `@media` 的收尾大括号**

**第一次的写法**（只有 CSS、没有内联样式）在真机上**没藏掉**。排查过程与结论：

1. 真机读数（垫片里加了两行一次性诊断，`ticks===40` 打一次）：

```
[dshm-sidebar] diag2 matches=true styleEl=yes hasRule=true frameClass=pI_x6G_frame dshm-frame
[dshm-sidebar] diag  desktop=true htmlClass="dshm-desktop" candidates=1 :: 收起侧边栏 box=0x0 display=none inline=none id=-
```

   —— 选择器**命中**、样式表**在**、规则文本**也在**、`<html>` 上的类**没被覆盖**。
   也就是说"选择器 / 时序 / 类名被覆盖"三种猜测**全部排除**。

2. 于是换个问法：**把垫片真跑一遍、拿它注入的那串 CSS 数括号**。结果：`收尾 depth=1`（少一个右括号），
   而少的那一个正是 `@media (max-width:1023.98px)` 的收尾 ⇒ 那条规则**被落进了媒体查询里面**，
   PC 窗口比 1024 宽 ⇒ 一条都不生效（也正因如此，它在手机上反而看不出毛病）。

3. 事故形状：`+ '}'`（媒体查询收尾）那一行被**替换**成了 `+ hideNativeToggle;`，而不是**追加在它之后**。
   浏览器在 EOF 处会自动补上缺失的右括号，所以**症状完全不像语法错** —— 这正是它值一条门禁的原因。

修法两处都上：右括号补回（规则回到顶层）+ 内联样式照打（见 §2.3）。两条都在 ⇒ 首帧就静、重建也自愈。

## 4. 移动端（手机 / 平板）为什么不受影响

用户在本次改动里**明确要求**不许影响手持档，逐条对上：

- 判据侧：`isDesktop` 只在原生桥答 `platformForm() === 'desktop'` 时为真；手持档答 `handheld` ⇒
  内联样式那条**根本不执行**。
- CSS 侧：新增的规则**全部**以 `html.dshm-desktop` 起头；手持档的 `<html>` 上没有这个类 ⇒ 一条都不匹配。
- 手持档原有规则（`html.dshm-handheld[…]` 的抽屉 / 遮罩 / 拖动条隐藏、以及那颗浮动 ⊞）**文本一行未动**，
  且门禁 ④ 专门钉住"抽屉那条仍在媒体查询里"。
- 补回那个被吃掉的右括号，本身就是**把手持档的媒体查询结构还原成改动前的样子**。
- 唯一在手持档也会跑的新代码是那条**只读**诊断（`ticks===40` 打一行，不做任何写入）。

**未做**：本轮没有连接手机 / 平板（`hdc list targets` 只有 PC），所以上述是**代码 + 门禁层面**的结论，
不是手持档真机复验。设备连上后按 §6 的清单复验一次即可。

## 5. 诚实边界

- **主题跟随只做了"路径未变 + SVG 已转填充"的静态论证**，没做交互式切深浅色的肉眼复验；ES379 那条通道
  （`@State themeMode` → `topBarIconColor()`）本身未改动。
- **手持档未做真机复验**（设备不在线），见 §4 末尾。
- 那条一次性诊断（`diag` / `diag2`）**留在代码里**，每页各打一行。它的价值是：下次再"没生效"，
  能一眼分清是"选择器没命中"还是"规则落点错了"——本次就是靠它把三种猜测一次排除掉的。
- 桌面档取消的是"网页里那颗官方按钮"，**不是**官方按钮这个语义：语义仍由顶栏那颗承担，
  且仍走官方的 `toggleSidebar`（我们只是替它被点一下）。
