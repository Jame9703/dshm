# DSHM 1.1.8 更新说明（对外发布口径）

> **版本**：1.1.8（versionCode **1010017**）
> **随包核心**：`0.2.2-rc.4+dshm.1`
> **范围**：1.1.8 邀请测试发布之后，最终随 release 签名包落地的用户可感知改动。
> **口径**：只列最终生效、且非中途反复的修复；过程性调整、内部工程整理、以及改坏后回退的项均不列入。

---

## 一、本次新增（1010017）

- **启动更快**：启动链路改为并行 —— Web 引擎在宿主启动期间预热、首帧后不再人为等待、端口与就绪文件的探测粒度加细。用户感知为从点击图标到界面可操作的等待缩短；功能、数据与权限面不变。
- **手机 / 平板终端工具修复**：guest 环境里的 `pnpm` 不再长时间无响应。版本查询不再加载整包脚本；其余命令启用字节码缓存，并关闭启动期的更新检查与版本自管理。
- **工具链清理**：换代遗留的空备份目录自动清理，不再长期占用空间（非空备份保留，用于回退）。

## 二、会话与稳定性

- **修复一轮回复完成后界面仍长时间停在「深度求索中」**：轮次结束（含异常中断）现在会正确收敛任务状态，停止与继续操作恢复正常，无需手动退出应用；重启应用也不会把上一轮残留状态当成「进行中」。
- **通知**：点击完成通知可直接进入对应会话；多条通知按会话分组，不再被系统折叠成一条。
- **连接与启动**：宿主仍在启动或慢启动时不再被误判为「核心无法连接」；首次安装、清数据、升级等冷启动按实际耗时自适应等待。
- **长任务与内存**：长时任务在息屏时自动续期，减少后台连接中断；录音、终端会话等资源在退出后按代次回收，长时间使用更稳定。

## 三、终端（PC / 2in1）

- **修复 2in1 机型上 bash / tmux 启动即崩溃退出**：修正终端 terminfo 目录定位与 `TERM` 回退，交互启动、tmux 会话均恢复正常。
- 平板与手机不提供系统原生终端，通过随包 guest 环境提供 bash（与 PC 档路径不同）。

## 四、文件与权限

- **PC / 2in1 使用受限权限「全盘文件读写」`ohos.permission.ACCESS_USER_FULL_DISK`**：已通过应用市场审批，发布 Profile 的 `allowed-acls` 与包内声明一致（常驻生效），用于把用户选择的本地项目目录与随包工具链作为工作区直接读写。
- 手机端不申请该权限；三端权限面固定为平板 / PC 18 条、手机 9 条，用途说明均为中文。

## 五、插件

- **修复已安装的启动救援插件（dshm-boot-rescue）被内置版本顶掉、导致「安全中心」入口消失**：内置实现与外部同名插件的插件条目已分开，二者只运行一套 —— 外部插件存在且版本不更旧时由外部生效，否则回退到内置救援；插件页的启停开关对应真正在运行的那一套。

## 六、界面

- **「内容由 AI 生成」标识只在会话页输入框上方出现**：右侧边栏、设置、插件页、文件预览等位置一律不显示；离开会话页即从页面移除。
- 手机、平板、PC 各形态统一使用系统侧边栏入口，不再自绘浮动开关。

## 七、账号与云同步（1.1.7 起）

- 接入华为账号，仅读取账号标识用于同步归属，不保存登录凭据。
- 会话、插件清单与工作区可云端备份并跨设备恢复；插件只同步清单、默认不自动安装；同步内容不含核心运行时与 API Key。
- 云同步为可选功能，不开启不影响本地使用。
