## 1. 插件安装报错：`spawn pnpm EACCES`

用户截图原文：

```
无法获取插件信息：Command failed with EACCES:
pnpm view dsh-plugin-whale-pet name version description dsh --json '--config.fetch-retries=0'
spawn pnpm EACCES
```

### 1.1 为什么「进程内通道」没接住

端侧没有可 spawn 的 pnpm（EACCES 是内核在 execve 时拒的，docs/110 已有结论），
所以官方插件页的每个 pnpm 跳点都必须改道 Host 进程内的 registry / 安装队列。
`tools/pack-core.mjs` 的 `patchPluginManagerInspectBridge()` 已经补了 **view / registry / git**
三处，但只补在 `dsh-plugin-manager/lib/index.js`。

上游同一份实现有**两份**：

| 文件 | 用途 |
| --- | --- |
| `lib/index.js` | 包 main（服务/Web 侧） |
| `lib/types/operations.js` | 独立入口 `…/dsh-plugin-manager/operations`（CLI / operations 侧） |

「添加插件 → 检查安装包」这条链在 Host 侧走的是 **operations 那一份的 `namedSpecManifest()`**，
它的 `pnpm view` 没有被注入 ⇒ 仍然 `execa('pnpm', …)` ⇒ EACCES。

### 1.2 改法（与官方语义一致，只是把 spawn 换成进程内）

`tools/pack-core.mjs`：

- `patchPluginManagerInspectBridge()` 的站点支持 `file: 'index' | 'operations'`；
- 新增站点：在 `operations.js` 的 `namedSpecManifest()` 里、`const viewed = await execa(...)` **之前**
  插入 `bridgeViewProfilePackage(dir, parsed.spec, options, environment)` 分叉；
- 桥返回 `undefined` ⇒ 照旧 execa（PC/2in1 一个字节不变）；返回结果 ⇒ 与 execa 路径同样
  解析 JSON（失败抛 `无法获取插件信息（进程内 registry 通道）`，不再是裸 EACCES）；
- 幂等：每个站点按自己的标记 `DSHM_PLUGIN_MANAGER_BRIDGE:<tag>` 判重，不再因为
  `index.js` 已有标记就整段跳过（这正是上一版漏掉 operations 的原因）。

同一次构建还顺带刷新了随包 core（`pack-core --place-in-app`）。

## 2. 侧滑返回：从「回桌面」变成「逐级返回」

真机：平板/手机侧滑一下直接回桌面，且日志里**没有任何** `[dshm-back]` / 「手持档返回」
记录 ⇒ 这一记返回没有走到页面的 `onBackPress()`。

### 2.1 能力层先接住

`entry` 与 `phone` 的 `EntryAbility` 都新增：

```ts
onBackPressed(): boolean {
  // 手持档一律接住，转给页面做逐级消费；PC/2in1 保持 false
  AppStorage.setOrCreate<number>('dshBackTick', (AppStorage.get<number>('dshBackTick') ?? 0) + 1);
  return true;
}
```

页面 `WebApp` 新增 `@StorageProp('dshBackTick') @Watch('onBackTickRequest')`，
收到后执行与返回键**完全同一条链**（`consumeWebBack()`），
并用 `lastBackHandledAt` 与页面自己的 `onBackPress()` 做 400ms 去重（一次手势只退一层）。

逐级顺序沿用 BACK_SHIM：设置面板二级页返回按钮 → 右侧栏 → 顶层浮层（Escape）→ 抽屉 → 面板首页；
全都没有时才 `minimizeToBackground()`（系统默认）。

### 2.2 网页侧再补一条近边缘侧滑

系统「快速返回」手势在部分机型上由系统直接消费、应用收不到。BACK_SHIM 里新增
`touchstart/touchend` 判定：

- 起点距左/右边缘 ≤ 72px（避开系统手势的极边缘区）；
- 横向位移 ≥ 80px 且 ≥ 纵向 1.6 倍、时长 ≤ 700ms；
- 起点落在可横向滚动的容器里则跳过（不抢代码块/终端的横滚）；
- 命中后调用同一个 `consume()`。

两壳（entry / phone）同源。
