## 2. 为什么按「平板归 PC」切

平板（`deviceType=tablet`）当前走**手持档**规则（抽屉侧栏、返回手势、底部手势区避让），但横屏要显示 APP 顶栏；
更关键的是 MatePad Edge（`QXS-*` / 市场名命中）被 `DeviceFacts.isEdgePcSeries()` **强制识别为 desktop**。
若把平板划到手机工程，MatePad Edge 会装到手机包却要求桌面行为 ⇒ 手机工程反而必须保留全部 PC 分支，分离不产生隔离。
详见 `docs/213` §2-F3。

因此本工程组的分工是**按形态自洽**，不是按"移动/固定"直觉：

- PC 工程继续承载「手持档 + 桌面档」两套运行时分支（平板仍走手持档，行为零变化）；
- 手机工程只承载纯手持档场景，是 PC 工程的**子集**，不含任何桌面专属路径。

## 5. DevEco Studio 验收步骤

### 5.1 两个工程各自

1. `File > Open` 打开工程**目录本身**（不是父目录）。
2. 等待 sync；若提示缺依赖，执行 `ohpm install --all`（本地 HAR 均以 `file:` 引用，sherpa 走 `third_party/*.har`）。
3. `File > Project Structure > Signing Configs` → 勾 **Automatically generate signature**：
   - PC：Product `default`，Bundle name `com.dshm.dshmbeta`
   - 手机：Product `default`，Bundle name `com.dshm.mobileclient`
4. 构建 `entry:default`（HAP）。
5. 覆盖安装：`hdc install -r <hap>`。

### 5.2 装机目标

| 设备 | 装哪个工程 | 预期 |
|---|---|---|
| 2in1 / PC | PC 工程 | 托盘图标、关闭收进后台、taskKeeping 保活、浏览器自动化、原生终端 |
| 平板（含 MatePad Edge） | PC 工程 | 平板走手持档；MatePad Edge 走桌面档；横屏显示 APP 顶栏 |
| 手机 / 折叠屏 | **手机工程** | 无托盘、关闭即退出、只有 guest VM 终端、抽屉侧栏与返回手势正常 |

> ⚠️ PC 工程已不含 `phone`，手机工程已不含 `tablet/2in1`：装错设备的包会被系统按 deviceTypes 拒绝。

### 5.3 建议的验收清单（每端各跑一遍）

1. 首启：核心起来、页面 ready、无白屏
2. 会话：新建、发送、轨迹渲染
3. 工作区：选目录（手机走 `Download/<包名>` 兜底）、重启后仍在
4. 插件：安装、启停
5. 终端：guest VM 可起（PC 另验系统原生终端）
6. 语音输入：麦克风授权与听写
7. 覆盖安装：`install -r` 后 el2 数据仍在
8. 后台：手机切后台/回前台；PC 关闭窗口收进后台 + 托盘唤回
9. 退出：手机三键关闭 = 退出；PC 托盘右键退出应正常停核心
10. 卡片 / 快捷方式 / A2A 入口能拉起对应页面

## 6. 数据影响（必须知悉）

两个工程是**两个 bundle**，el2 数据互相独立：

- PC 工程沿用 `com.dshm.dshmbeta` ⇒ **原有 beta 装机数据（会话 / 工作区 / 插件 / 凭据）不受影响**。
- 手机工程用新包名 `com.dshm.mobileclient` ⇒ **首次安装是全新空数据**；原 `com.dshm.dshmbeta` 的会话不会自动迁移（跨 bundle 沙箱隔离，读不到对方 el2）。
- 需要迁移时的可行路径：在旧包内导出工作区/会话产物 → 通过系统 picker 在新包内导入。**本次未实现该迁移功能**，属待办。

## 10. 双端一致性门禁（已落地）

复制式拆分最大的长期风险是**只改一侧**：这类漂移不会让任何一端构建失败，往往等到真机上一个端好一个端坏才暴露。
因此分离完成当日即落地裁判 `tools/check-two-project-parity.mjs`（两端各一份，内容相同）：

```bash
node tools/check-two-project-parity.mjs             # 大小 + 路径集合（秒级）
node tools/check-two-project-parity.mjs --hash      # 追加逐文件 sha256（约 1 分钟）
node tools/check-two-project-parity.mjs --self-test # 注入漂移必须判红
DSHM_MOBILE_ROOT=/path/to/mobile node tools/...      # 指定对端工程（默认同级 DSHM-mobile）
```

判据是**白名单式**的：只比对「必须逐字节一致」的目录，白名单外的任何差异一律判红；
允许的差异必须写进 `ALLOWED` 并注明理由，不许静默放过。

- **必须一致（12 个目录）**：`hostcore/`、`connection/`、`dshcompat/`、`appstate/`、`platform/`、
  `hostruntime/`、`entry/src/main/ets/`、`entry/src/main/cpp/`、`entry/libs/`、
  `entry/src/main/resources/resfile/`、`tools/`、`third_party/`
- **允许不同（附理由）**：各模块 `module.json5`（deviceTypes 不同）、
  `entry/src/main/ets/backgroundability/`（PC 专属，手机已删）、
  `tools/check-permission-surface.mjs`（8 vs 7）、
  `tools/build-profile*.template.json5`（模板里的 bundleName 不同）

**2026-10-21 实测**：12 个目录共 3,538 个文件，`--hash` 全量 sha256 比对 **0 处差异**；
`--self-test` 注入漂移正确判红、移除后恢复绿。这条结果同时证明"核心只有一个"不是说法：两端的
`hostcore/`、五个 HAR、`entry/src/main/ets/`、`entry/libs`、`resfile` 逐字节相同。
