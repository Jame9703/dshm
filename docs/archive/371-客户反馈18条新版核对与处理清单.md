## 3. 未解决项处理计划

> 排期为**估算**（单人、无阻塞前提下），不是承诺；"验证标准"都是可判定的观察项。

### P0-1　熄屏/锁屏后任务停摆（#3、#5 合并）

| 项 | 内容 |
|---|---|
| 缺陷 | 保活已从 Electron 迁到 ArkTS 长时任务，但**判据过窄**：`KeepAlive.ets:248-267` 只在 `refs>0 || active` 时才校准；熄屏时若 `refs=0`（还没开始干活）直接跳过，之后任务在后台才启动则再也拿不到长时任务 |
| 影响范围 | 全部档位；手机/平板熄屏后 agent turn、定时任务、IM 通道**全部暂停**（数据不丢，只是停滞）；用户感知为"应用死了" |
| 依赖条件 | 需真机（本机 hdc 不可用）；需确认 `workload.json` 由谁写、写入频率（若靠 `setTimeout` 轮询，冻结后同样失效） |
| 方案 | ① 熄屏时**无条件**前置申请 `TASK_KEEPING`（有通知栏提示，可接受）或 ② 把"有 turn 正在跑"直接映射到 `refs>0`；③ 任务在后台启动时立即 `acquire()`（不依赖定时器） |
| 排期 | 0.5–1 人日改代码 + 门禁；真机验证另计 |
| 验证标准 | 熄屏 10 分钟 → `node-output.log` **无** `LOOP-GAP`；`diag-keepalive` 出现 `screen off ⇒ 申请保活成功`；亮屏后 turn 连续不断 |

### P0-2　云同步不可用（#13、#18、#19 合并）

| 项 | 内容 |
|---|---|
| 缺陷 | ① 缺 `ohos.permission.DISTRIBUTED_DATASYNC`（源码全仓无该串）⇒ 端云同步声明必然失败；② 登录态不落盘，冷启动只能 `silentSignIn()`；③ AGC 云侧配置未验证 |
| 影响范围 | 手机 + 平板全部；云同步功能整体不可用（38 个单元 10 MB 全部滞留本机） |
| 依赖条件 | **① 是权限面变更**：需 ACL 申请 + 发布 Profile `allowed-acls` 扩展（外部动作，周期不可控）；② 只依赖本地改动；③ 依赖 AGC 控制台 |
| 方案 | ② 先做（登录态落盘 + 冷启动读盘再静默兜底），可独立上线；① 走 ACL 申请流程（与 `docs/364` 的 W^X 申请同批提交，减少往返）；③ 由 AGC 侧核对包名/指纹/schema；另加"把原生错误码透出到设置面板"，结束"只显示异常"的黑盒 |
| 排期 | ② 1 人日；① 申请周期 1–2 周（外部）；③ 外部 |
| 验证标准 | `sync_units` 的 `cloud_gid` 不再全空、`naturalbase_cloud_meta_sync_units` 非全 0、`localTimeOffset` 被正常时差覆盖；设置面板能显示具体错误码 |

### P0-3　插件页空表 + 侧栏入口不可滚（#16，兼修 #2/#15 的触发链）

| 项 | 内容 |
|---|---|
| 缺陷 | ① 插件列表只按 `dependencies` 枚举，`bundles`/`node_modules` 都在时也渲染空；② profile 写入非原子，崩溃留半截文件；③ 侧栏入口列表容器不可滚（落点：核心树 `dsh-client-ui-sidebar-right`） |
| 影响范围 | 所有装了第三方插件的用户；入口数一超一屏就必然复现（插件生态越丰富越容易踩） |

| 排期 | ① 0.5 人日；② 0.5 人日；③ 0.5 人日 + 门禁 0.5 人日 |
| 验证标准 | 把 `dependencies` 清空仍能看到 13 个插件且可一键修复；杀进程模拟写入中崩溃后 profile 不再半截；入口 10 项时列表可滚、最后一项可达 |

## 5. 风险说明

1. **"已解决"必须靠复验，不靠代码推断**。本清单一条都没判"已解决"——因为反馈版本是 `dshm.109`，而中间经历了 `dshm.110–114` 与 `0.2.2-rc.1` 两轮大改，代码里"看起来修了"不等于用户那台设备上"确实好了"。**建议对判"部分解决/疑似已修"的（#3/#5/#7）先做一轮定向复验**，再决定要不要动代码，避免重复修改。
2. **云同步这条会撞权限面铁律**。加 `DISTRIBUTED_DATASYNC` 属权限面变更（当前仓里它是"无消费点已撤"的状态，`docs/249`）。现在有真实消费点（客户反馈 + RDB 端云同步），可以重新申请，但必须**先批准、后声明**，且要同步改 `check-permission-surface` 与 `AGENTS.md`。
3. **#16 的修法涉及核心树补丁**。`dsh-client-ui-sidebar-right` 是上游包，改它要进 `pack-core`，换核心时锚点会再次需要迁移——这是本仓已知的维护成本（`docs/365` §P0 的同一类风险）。
4. **本机无 hdc**，上表所有"验证标准"都只能到"代码 + 离线门禁"级别，真机复验必须另找设备，否则只能算"计划完成"而非"问题关闭"。
