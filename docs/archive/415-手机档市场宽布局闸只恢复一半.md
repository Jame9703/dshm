# 415 手机档市场变窄：只恢复「宽布局闸」，不改列数

**现象（手机 / 折叠单屏竖屏）**：点「插件市场」后内容只剩半屏、被挤成细长一条；同一页面「已安装」正常；**横屏正常**；折叠屏展开正常。

**状态更正（2026-11-12 最新真机反馈）：本方案未解决缩窄；下文“删除宽闸导致半屏”的因果归因撤回，不得作为已确认根因。** 本轮运行测试发现模板正则转义错误使带空格的真实查询不命中；同时市场宽闸只控制卡片分桶，不能证明控制整页宽度。详见[故障调查报告](../outputs/DSHM-故障调查报告-20261112.md)。以下保留的是包内标记差异与已尝试方案，不是功能验证结论。

**历史对比与已撤回的推断**

拿 2026-11-08 的 `dshm-1.1.8-1010015-…-20261108T121648.app`（用户确认该版正常）与出问题的包，逐项比对 `phone-default.hap` 内 ABC：

| 标记 | 1010015（正常） | 出问题的包 |
|---|---|---|
| `(min-width:681px)` 强置真（宽布局闸） | **有** | **无** |
| `data-dshm-cols` 列数改写 | 有 | 无 |
| `panelHost` / 祖先链拉宽 | 无 | 有 |

`dshmarket` 的 `useMediaWide()` 就是 `matchMedia('(min-width:681px)')`，它决定市场走宽布局还是窄布局。**旧包把这条件恒置真，市场在竖屏也按宽版渲染；新包把整块垫片（含这半段）一起删掉，市场退回窄布局 ⇒ 半屏。**

早先"卡片被压成两列"的截图，成因是同一垫片的另一半——按元素宽度把 CSS 改写成 `repeat(N)`。两半混在一起删，才导致"改列数的毛病没了、但布局塌了"。

**修法**

phone 壳 `MARKET_WIDE_SHIM_JS`：在 `html.dshm-compact`（直板机 / 折叠单屏）下，把 `matchMedia('(min-width:681px)')` 的匹配结果恒置真；**不碰任何 CSS、不改列数**。PC / 平板 / 折叠展开拿到原生 `matchMedia`，行为与官方一致。

同时删除上一轮无效的 `MARKET_FIT_SHIM_JS`（从 `panelHost` 逐级拉宽祖先链）——真机上未生效，说明宽度不是靠改这一条链能解决的，保留只会叠噪音。

**门禁**：`tools/check-market-panel-width.mjs` —— 闸查询必须是 681px、必须真正替换 `window.matchMedia`、假 MQL 必须 `matches=true`、必须限 `dshm-compact`、**不得出现 `data-dshm-cols` 或 `repeat(`**（列数改写一律判红）、模板字符串须干净闭合；7 个变异体全部判红。

**边界**：本机无 hdc，真机需复核"竖屏点插件市场满宽""横屏与折叠展开不变"两项。
