## 0. 总评

**结构亮点（实测确认）**：
- 五层 HAR 依赖图干净（connection 0 依赖 ← dshcompat 1 import ← appstate 9/9/8 ← HAP 装配），**无环、无反向依赖**。
- `hostruntime/runtime/RuntimePort.ets:204` 的 `buildHostEnv` 是全工程唯一 Host env 拼装点（20+ 键、空值不写、非法即拒）——最佳实践。
- 模块间 5 条通信通道中 4 条有单源纪律（`__DSHM_BRIDGES__` 聚合桥、HostEvents 常量、文件队列 `.req/.done` 原子协议、spawn env）。
- ArkTS **`as any` / `: any` 实际使用 0 处**；hostcore 松散 `==` 0 处；`tools/` 脚本头部/退出码/输出风格 149 个基本统一。
- `SecretStore.ets`（Asset Store + DEVICE_UNLOCKED + 失败不降级）、`fs-fence` realpath 防软链逃逸、vm-bash 的 `shq()` 转义与 argv 白名单、`/dshm-shot` 白名单代理——安全基本面扎实。

**债务集中点（一句话）**：结构性债务不在分层，而在**两个产品壳靠「整文件复制后微调」维护**（WebApp 5772 行相同、105/107 函数同名、7 个文件字节级相同），以及**原生/资源层三份物理拷贝中「真源」（HSP）反而未纳入版本控制**。其余漂移（注释、module.json5、语音桥措辞）均是其衍生物。

### 7.1 复核订正（P0-1 的表述）

上表 P0-1 写「vm.js 导出的 `stop()` 全仓零调用方」**不准确**。实读：
`vm.js:1511` 的 `stop()` **本就实现了 QMP `quit` 优雅关机**，`index.js:417` 也有
`export function shutdown() { stop(); }` 包装。真正断掉的一环是**宿主 `main.js`
的 `requestStop()` 从不调用插件的 `shutdown()`**（宿主 CJS 与插件 ESM 之间没有
import 关系，也没有别的接线）。缺陷等级与影响判断不变，修法从「新写关机逻辑」
收敛为「把已有入口接线并等它完成」，风险显著更低。

另外确认运行时真源：`main.js:7403 const resRoot = path.resolve(__dirname, '..', '..')`
指向 **hostruntime HSP 的 resfile**，故 P0-4 中设备读到的确实是 HSP 侧旧文档。
