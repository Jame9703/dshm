## 2. 彩色品牌标 + Hero 文案

### 2.1 为什么必须换实现方式

旧实现用 **SVG path + CSS mask** 画 logo —— 这只能表达**单色剪影**（mask 是用图当遮罩，
颜色由 `background` 给）。要彩色就必须用位图。

| 项 | 旧 | 新 |
|---|---|---|
| 素材 | `web_brand_mark.png`（黑白剪影）→ 抽成 SVG path | **`web_brand_color.png`（96px 彩色 PNG，4.5KB）** |
| 注入方式 | SVG path 内联（982B） | **PNG base64 内联**（6.1KB） |
| 渲染 | `mask` + `background:currentColor` | `background: var(--dshm-brand-mark) center/contain` |
| 深色主题 | 靠 mask 颜色反转 | 彩色图本身自带颜色，**深浅主题通用** |

内联仍是必需的：ArkWeb 页面拿不到 `rawfile`，垫片只能自带数据。

### 2.2 顺带修掉一个真缺陷

旧 CSS 把 `_brandMark` **同时**放进了两处：

```css
[class*="_brandMark"]{ mask:...; background:currentColor; }   /* 想画 */
[class*="_brandMark"], ... { display:none!important }          /* 又隐藏 */
```

⇒ **那个标其实从来没显示过**。新版把它从隐藏组里拿出来，只隐藏槽位里的上游鲸鱼 SVG
（`[class*="_brandMark"]>*{visibility:hidden}`）。
门禁加了回归守卫：**"含 display:none 的 CSS 段里不得出现 `_brandMark`"**，已用变异体验证判红。

### 2.3 Hero 文案

「鲸鸿一瞥」是为扣"惊鸿一瞥"硬造的，读着生僻。用户要求"换一个正常一点的"，取：

**「今天做点什么」** —— 平实、口语、贴合每日打开的节奏，与上游「开始一个任务」同一语感。

（同时把侧栏品牌名从 `>_` 终端符号改成 **logo + 鲸鸿**。）

## 3. 登录二次确认 + context 缺失修复

### 3.1 真机日志里的真错误

```
E/C04705/com.dshm.dshclient/huaweiId_framewrok_base:
  AuthenticationControllerConstructor:1609# AuthenticationControllerConstructor argc is empty.
```

SDK 原文（`@hms.core.authentication.d.ts`）：

> `constructor(context?: common.Context)` — **This parameter is mandatory when the
> HUAWEI ID sign-in and authorization screens need to be started. Otherwise error 401
> will be returned.**

我们之前调用的是 `new AuthenticationController()`（无参）⇒ 系统拿不到 context。
即便静默路径不弹登录页，系统在需要落协议/拉起授权组件时仍要它。

**修法**：`silentSignIn(context?)` 接收壳层的 `UIAbilityContext`，有就传进去：

```ts
const controller = context === undefined || context === null
  ? new authentication.AuthenticationController()
  : new authentication.AuthenticationController(context);
```

### 3.2 二次确认

用户要"还是弹出确认一下，界面与设置 UI 一致"。用 `showAlertDialog`（系统渲染，
主题/圆角/按钮排布与本机其它系统弹窗一致），**不自己描一套**：

```text
点「登录华为账号」
  → confirmCloudLogin()：标题「登录华为账号」
      正文：登录后可把会话、附件与插件清单同步到华为账号。
            本应用只读取账号标识用于同步归属，不会获取头像、昵称等资料。
      [取消] [登录]
  → 点「登录」才 runSilentLogin()
```

取消则什么都不做；弹不出确认框（无 UI 上下文）时**不静默登录** —— 宁可这次不登录，
也不绕过用户确认。

## 4. 任务完成通知

### 4.1 现有链路（早已完整，本次只调文案）

```text
Host 发 turn/end
  → SessionHub 收到 EVENT_TURN_END（SessionHub.ets:2697）
  → publishTurnNotice()（:4063）判定 failed = (reason.kind === 'error')
  → hooks.onTurn() → EntryAbility.publishNotice()
  → prepareNotify()（惰性申请通知授权，只弹一次）
  → notificationFor(input) → notifier.publish(draft)
```

`NotificationCenter` 已有 `ensureEnabled()`（`requestEnableNotification`）、
`ensureSlots()`、`publish()`、`withdraw()`，两个壳的 `EntryAbility` 都在 `setupNotifications()`。

### 4.2 本次改动

| 项 | 旧 | 新 |
|---|---|---|
| 通知标题 | `回答完成` | **`任务已完成`** |
| 理由 | 只描述"模型答完了" | 用户脑子里这件事就是"任务跑完了" |

### 4.3 权限

HarmonyOS 的通知**不需要** `requestPermissions` 声明（不走 module.json5 权限面），
而是运行时授权 `notificationManager.requestEnableNotification()` —— 已由
`ensureEnabled()` 在**第一次要发通知时**惰性触发（不在首启打扰）。
因此 **权限面 entry 17 / phone 9 保持不变**，`check-permission-surface` 仍全绿。
