## 1. 问题确认（代码实证）

```ts
function shouldShowAppTopBar(rawType: string, desktopForced: boolean, landscape: boolean): boolean {
  if (rawType === 'phone') {
    return false;   // ← 手机整条顶栏不渲染
  }
  ...
}
```

仓库里还有一条原生注释早就记录过这个事实：

> 「原生顶栏在手持档整条不渲染（**"移动端 APP 是没有顶栏的"**）」

所以 `docs/311` 加的第三个顶栏菜单**只在 PC/平板可见**——手机端用户根本找不到入口。
这是上一轮施工的疏漏。

## 2. 注入位置：官方账号菜单

用户给的截图就是官方左下角账号菜单：

```text
⚙ 设置
➤ 意见反馈
⇥ 退出登录
```

**为什么这个位置比侧栏注入更好**：

| 维度 | 账号菜单（选用） | 侧栏设置项 |
|---|---|---|
| 三端覆盖 | ✅ 三端都有 | ✅ 三端都有 |
| 用户心智 | ✅ "账号与同步"天然属于这里 | 🟡 设置项里再找一层 |
| DOM 稳定性 | ✅ 弹层内结构简单 | ⚠️ 侧栏结构较复杂 |
| 与官方冲突 | ✅ 追加一项，不改动原有项 | ⚠️ 可能影响布局 |

---

## 3. 注入策略：跟随菜单出现，不 hook 打开动作

```js
每秒巡检 → 找一个 role="menu" 且同时含「设置」与「退出登录」的浮层
        → 末尾追加「云同步」项（已存在则跳过）
```

### 三条设计决定

**① 用"菜单指纹"而非法 hook 打开动作**

不监听点击事件、不依赖官方内部实现；只看**页面上是否出现了那个菜单**。
官方改版换了打开方式也不影响判定。

**② 指纹要求同时出现「设置」与「退出登录」**

页面上还有别的 `role="menu"`（快捷键、右键菜单）。只对**同时含这两个文案**的菜单动手，
避免在无关浮层里冒出一个陌生项。中英文各一套指纹（`Settings` / `Sign out` / `Log out`）。

**③ 幂等**

用固定 `id = dshm-cloud-sync-item` 判存在，重复巡检不会叠加。

### 样式复用

从菜单的**第一个子项**读 `padding / fontSize / borderRadius` 套到新项上，
让它和官方项视觉一致，而不是硬编码一套尺寸（那在主题切换时必然走样）。

### 点击行为

```text
停止冒泡/默认 → 派发 mousedown/mouseup 让官方菜单收起
             → 调 window.__DSHM_BRIDGES__.openCloudSync()
             → 原生打开 CloudSyncSettings 面板
```

## 4. 桥与入口一致性

```ts
'openCloudSync': (): string => this.openCloudSyncPanel()

private openCloudSyncPanel(): string {
  this.bindSyncUi();
  this.attachSyncRoot();
  this.cloudSyncOpen = true;   // ← 与顶栏菜单完全同一条路径
  return 'ok';
}
```

**两个入口打开的是同一个面板、同一份状态**，不存在两套逻辑。

2. 打开应用；
3. 点左下角账号区 → 弹出「设置 / 意见反馈 / 退出登录」菜单；
4. **菜单末尾应多出「☁ 云同步」**；
5. 点它 → 打开云同步面板（与 PC 顶栏菜单打开的是同一个）。

**重点在手机/手持档上验**——那是原来完全没有入口的形态。

## 8. 已知边界

| 项 | 说明 |
|---|---|
| 依赖官方文案 | 指纹同时认中英文；若官方改成第三种文案，注入会失效（不报错，只是不出现） |
| 巡检频率 | 1 秒一次，只在页面存在时跑，代价可忽略 |
| 顶栏菜单 | 保留，PC 上仍是快捷入口；两入口共用同一面板 |
