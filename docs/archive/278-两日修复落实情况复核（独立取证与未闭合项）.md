## 1. 复核方法（本文结论的可重复性前提）

### 1.1 五类判据

| 类别 | 判据 | 取证方式 |
|---|---|---|
| ① 是否存在 | 文档声称的符号/接线**在源码里真实存在** | `grep` 工具逐符号定位（含行号） |
| ② 是否被改回 | 旧缺陷形态**必须 0 命中** | 搜旧写法（如 `target=_blank` 独占判据、`densityDPI` 换算） |
| ③ 行为是否成对 | 定时器 / 事件订阅的申请与清理成对 | 逐处读 `on`/`off`、`setInterval`/`clearInterval` |
| ④ 门禁是否真有牙 | 正例绿 **且** 对照臂红 | 跑 `--self-test` / 看变异体读数 |
| ⑤ 交付是否一致 | 包体积 / sha256 / 清单三方相符 | 实算 sha256 与 `SHA256SUMS` 比对 |

### 1.2 ⚠️ 本机检索工具的一个硬坑（本轮实地踩到，必须写进纪律）

复核开头用 `bash` 的 `grep -r` 搜外开三件套（`isExternalNavigation` 等），**返回 0 命中**，
据此一度判"外开修复整条没落地"。换用工具化检索后，同一批符号在 `entry/.../WebApp.ets` **命中 16 处**。

**根因**：本机 `grep` 是 **toybox 0.8.12 版**（`grep --version` 自证，非 GNU grep），
其递归搜索会**静默漏报**——不报错、退出码正常、只给出不完整结果。

**纪律（建议进 AGENTS）**：

> 在本仓做"某符号在不在"这类**判据性检索**，一律用工具化检索（`grep` 工具 / `ripgrep`），
> **不得用 shell `grep -r` 的零命中作为"不存在"的证据**。零命中必须换一种手段复核后才可采信。

**外溢风险**：`docs/276` 做了三轮"代码复核"，若其中任何一轮用 shell `grep` 得出过"某处不存在 / 已清除"的结论，
该结论需按同一手法重验。

### P1-2 · `check-vm-bash` 未隔离宿主设备事实环境变量（364/373）

**事实**

```text

  FAIL 白名单内 ⇒ 进 guest 通道；本机 VM 不在 ⇒ 如实 reject 且报文点名「端侧 VM 不可用」
```

**根因**（本轮定位到确切代码）

```js
export function nativeExecutionOnly(env = process.env) {
  if (String(env.DSHM_NATIVE_TERMINAL_ONLY || '').trim() === '1') return true;
  if (String(env.DSHM_DEVICE_FORM || '').trim().toLowerCase() === 'desktop') return true;  // ← 这里
  ...

```

而本机（鸿蒙 PC 2in1）的进程环境里**真实存在** `DSHM_DEVICE_FORM=desktop`，
门禁直接吃宿主 `process.env` ⇒ 走进"不接管终端"分支 ⇒ 断言按"应接管"写，全红。

**判定**：**产品逻辑没错**（PC/2in1 确实该走原生终端路线，`docs/207` 的口径），
错的是**门禁没有隔离环境**——这是"真机事实渗透进离线门禁"的污染，不是缺陷。

**建议修法**

- 与 `check-edge-desktop-policy` 已有做法对齐：在 `apply()` 正面臂之前显式
  `delete process.env.DSHM_DEVICE_FORM; delete process.env.DSHM_DEVICE_MODEL; delete process.env.DSHM_NATIVE_TERMINAL_ONLY;`
  （或用一个 `withCleanEnv(fn)` 包裹），**用完逐字还原**；
- `五项都报缺失` 那条同样是相对路径/环境相关（断言写成本机 `D:\` 时代的"没有端侧资产"），
  需改成按 `assetsPresent()` 的**纯判据**断言，而不是依赖运行目录；
- 建议加一条**对照臂**：设 `DSHM_DEVICE_FORM=desktop` ⇒ 必须判"不接管终端但仍接管 bash"（与 `docs/207` 一致）。
