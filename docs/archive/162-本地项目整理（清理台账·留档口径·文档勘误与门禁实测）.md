### 4.3 门禁的两处红：一条是门禁自己的锅，一条是清理的前提

**① `tools/check-web-fetch-jitless.mjs`（恒假红，已修）** —— 清理前就是红的，与本轮删除无关。
现象：A 臂（不挂钩子、用真 undici）4/4 断言失败、B 臂（本仓垫片）8/8 通过，判定却是
"A 臂失败了，但输出里没有 WASM 因果证据"。真因是**文案换代**：

```
A 臂输出：[probe] 真 undici 失败原因: WebAssembly is not supported in this environment, but is required for HTTP/1 parsing
门禁判据：/WebAssembly is not defined/            ← 只认 Node 20/22 的措辞
本机     ：node v24.19.0
```

⇒ 判据放宽成两种文案（**同一因果**：`--jitless` ⇒ 没有 WebAssembly ⇒ undici 的 WASM llhttp 装不起来），
并补一条自测用例钉住 Node ≥ 24 的措辞。修后：`--self-test` **14/0**、实跑 **PASS**。
（兄弟门禁 `check-worker-jitless.mjs` 的同类正则**不动**：它实测 rc=0，`ReferenceError: WebAssembly is not defined` 那条路仍然命中 —— 有牙就不改。）

**② `tools/check-native-closure.mjs`（判据源被我方清理删掉了）** —— 默认候选第一条是
`entry/build/default/intermediates/libs/default/arm64-v8a`，清理后不存在 ⇒ 退回 `entry/libs/arm64-v8a` 判定，
于是把**构建期由 SDK 复制进 HAP**的 `libc++_shared.so` 报成"无法解析"（`libnode.so.137` 与 `libvips-cpp.so` 各一条）⇒ rc=1。

按**已出的包**复验（更硬的判据）：

```
从 dist/sideload/…+dshm.50…hap 解出 libs/arm64-v8a/ → 61 个库
node tools/check-native-closure.mjs --dir <解出的目录>
⇒ RESULT: PASS（rc=0；两条 SONAME 不一致是既有的可接受告警）
```

⇒ 判据本身没坏，是"输入被清理"这一前提变了：**要跑这条门禁，先有一次构建**（或按已出 HAP 跑 `--dir`）。
`AGENTS.md` 的门禁清单里已补这条前置条件。
