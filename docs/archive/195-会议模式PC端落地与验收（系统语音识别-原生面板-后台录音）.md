## 3. 三个"只有真机才暴露"的坑（都已修，且写进门禁）

1. **`writeAudio` 送 `subarray` ⇒ 识别全空**
   引擎按**整个底层 ArrayBuffer** 读、忽略 byteOffset ⇒ 听写链路 `onResult` 全空（`len=0`），
   而探针（每次新建 640B 数组）完全正常。修法：`writePcm()` 每块**拷贝**成独立 640B 数组。
   ⇒ 门禁 M2 钉死。

2. **PC/2in1 上 `publicDownloadFolder()` 返回的路径并不存在**
   `~/…` 在 PC 上无法写入，而 UI 仍会显示"已保存 …路径"（假成功）。
   修法：会议目录必须**实测可写**（mkdir + 写 `.write-probe` + 删）才采用，否则回退
   `filesDir/meetings`；Markdown 写入结果进快照（`markdownWritten`），失败明确提示。

3. **WebApp.ets 行尾归一导致门禁对照臂失效**
   一次批量编辑把混合行尾统一成 CRLF，`check-handheld-back` / `check-decor-button-mode`
   的变异锚点（LF）全部对不上 ⇒ 报"替换没生效"。修法：`WebApp.ets` **保持 LF**
   （模板字符串里的锚点按 LF 写），改完立刻跑这两条门禁。

## 4. 架构决策：为什么会议面板不做成"鸿蒙插件"

- 插件（Host 侧 JS）**拿不到 ArkTS 能力**：`AudioCapturer`、`speechRecognizer`、
  `ContinuousTaskRequest` 都只在 ArkTS 侧可用；插件只能通过文件队列间接驱动，绕一圈
  还得回到 ArkTS 实现录音与 UI。
- 面板是**原生 ArkUI 浮层**，不依赖官方 Web DOM，也不新增 Web 桥协议 ⇒ 官方前端升级不会碰它。
- 将来若要"让 Agent 读会议纪要"，那部分**适合**做成插件（读 `meetings/*.md` 的只读工具），
  与录音/面板解耦 —— 留作后续，不在本轮。

### 6.2 探针资产裁定：**保留**（诊断专用）

`entry/src/main/resources/rawfile/probe-speech-16k.wav`（1,861,662 B）**随包保留**，理由：

1. 它是 `dshProbe long / short / dictation / speak` 四个自检的唯一声源；没有它，PC 上 TTS 的 `onData`
   又不回调（真机实测），整套回归就失去了可自动复现的输入；
2. 只在显式 `aa start … --ps dshProbe …` 时才被读取，**正常工作流一个字节都不碰**，不增加启动开销；
3. 成本 1.86 MB（HAP 约 419 MB 的 0.44%），远低于它换来的可回归性；
4. 若将来要随包移除：删 `rawfile/probe-speech-16k.wav` + 把 `HmsSpeechBridge` 的探针分支一并删掉即可，
   `tools/check-meeting-mode.mjs` 不依赖该资产，删掉不会让门禁变红。
