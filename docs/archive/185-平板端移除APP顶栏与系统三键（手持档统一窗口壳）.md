# 185 · 平板端移除 APP 顶栏与系统三键（手持档统一窗口壳）

> 2026-10-17。用户要求：平板端不要 APP 自绘顶栏和右上角系统三键，
> 与手机一致；避免不同平板尺寸下左右侧栏按钮与顶栏/三键重叠。

## 1. 结论

手机 / 平板本来就共用 `isHandheldForm()`：

- `phone`、`tablet` 都归手持档；
- `WebApp.build()` 只对非手持档渲染自绘 `TopBar()`；
- 所以平板不应出现 APP 顶栏。

真正缺的是**系统标题栏三键**：旧实现只调用
`setWindowDecorVisible(false)`，它隐藏标题栏文字/图标，但不保证隐藏
最大化、最小化、关闭三键。平板自由窗口下三键仍可能与 Web 侧栏顶部按钮重叠。

## 2. 修法

`EntryAbility` 在手持档启动与窗口状态刷新两条链中调用：

```ts
win.setWindowTitleButtonVisible(false, false, false);
```

官方 SDK 原文：该接口用于显示/隐藏主窗口标题栏的最大化、最小化和关闭按钮，
API 14 起可用。

分档：

- **phone / tablet**：尝试隐藏系统三键；
- **PC / 2in1**：返回 `desktop-skip`，三键与 APP 顶栏逐字保留；
- **能力受限返回 801**：保留既有 24vp Web 顶部落位兜底，不伪装成“已隐藏”。

`decorPresentOf()` 增加 `titleButtonsHiddenOk`：

- 三键隐藏成功 ⇒ `present=false`，页面不再保留 24vp 顶部落位；
- 隐藏失败 ⇒ 继续按窗口状态 / 装饰高度判断是否需要让位。

## 3. 门禁

`tools/check-decor-button-mode.mjs` 新增：

- 手持档必须调用三键隐藏 API；
- PC / 2in1 必须显式跳过；
- 启动与刷新两条链都重放；
- 隐藏成功时纯函数必须返回 false；
- 隐藏失败时原让位判据仍然保留；
- tablet 必须与 phone 同归手持档；
- 自绘 APP 顶栏只允许非手持档渲染。

第二组正例：**86 passed / 0 failed**；原对照臂 A–P 全部仍能判红。

## 4. 真机回归

| 设备 | 读数 | 结论 |
|---|---|---|
| PC 2in1 `86E0226429000417` | `buttons=desktop-skip`、`present=true` | 顶栏与系统三键保留，桌面路径未变 |
