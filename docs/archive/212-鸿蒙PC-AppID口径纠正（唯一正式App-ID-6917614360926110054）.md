# 鸿蒙 PC 项目 App ID 口径纠正与正式发布说明

更新日期：2026-10-21

## 1. 一句话结论

AGC 正式应用只有一套：`com.dshm.dshclient` /
**App ID `6917614360926110054`**。后续证书、Profile、邀测与正式发布全部继续在这个
App ID 上进行。

`6918740027110769940` 不是新应用，也不是新 AGC App ID。它是当前鸿蒙 PC
已安装 debug 包使用的本地调试 `app-identifier`。为避免卸载和丢数据，本机 Run
暂时沿用它；它不能用于 AGC 发布。本文此前的“新旧 App ID 迁移”结论作废。

## 2. 四个容易混淆的 ID

| 名称 | 本项目中的值/来源 | 作用 |
|---|---|---|
| AGC App ID / `appId` | **`6917614360926110054`（唯一正式值）** | AGC API 创建证书、Profile、测试版本和正式版本时使用的应用记录 ID |
| Profile `app-identifier` | release 必须为 `6917614360926110054` | 本机既有 debug Run 仍可使用 `6918740027110769940`，但禁止上传 AGC |
| `certId` | `2066052132238274880` | AGC 上的一张 debug 证书记录 |
| Profile ID | 例如 `2066254260579890176` | AGC 上的一次 Profile 记录；一个应用可以有多个 Profile |

`6918740027110769940` 只说明当前设备使用独立调试身份，不能反过来修改 AGC
正式应用记录。判断发布身份时以 AGC 的 `6917614360926110054` 为准。

## 3. 当前可见的事实

### 3.1 AGC 正式应用

使用当前可访问的 AGC 凭据执行：

```text
publish app-id -p com.dshm.dshclient
```

返回：

```text
App ID = 6917614360926110054
```

现有 `DSHMpcRelease.p7b` 回读结果：

```text
bundle-name = com.dshm.dshclient
app-identifier = 6917614360926110054
type = release
```

因此 AGC 正式应用、后续邀测和后续发布都仍然使用 `6917614360926110054`。

### 3.2 鸿蒙 PC 当前安装包（本地调试身份）

设备 `bm dump -n com.dshm.dshclient` 显示：

```text
bundleName = com.dshm.dshclient
appIdentifier = 6918740027110769940
versionName = 1.1.4
versionCode = 1010004
appProvisionType = debug
debug = true
```

这说明当前 PC 上安装的是本地 debug 包。为保留其 el2 数据，DevEco Run
使用同源 debug Profile；release 构建仍使用 AGC `6917614360926110054`。

### 3.3 当前 AGC 凭据范围

下文旧命令尝试查询临时 debug 身份：

```text
publish app-info -a 6918740027110769940
```

返回 HTTP 403 不影响正式发布。正确做法是忽略该临时身份，所有 Profile 查询与创建均使用
`6917614360926110054`。

### 3.4 正式 debug 证书

AGC 上可访问的正式 debug 证书为：

```text
certName = auto_debug_260086000057314119.cer
certId   = 2066052132238274880
type     = 1 (debug)
SHA256   = DF21A3C09F7954579305F85C64F80CAD86F79853EE3A887C1DEC95D218DF3A37
```

当前 PC 项目里的 Windows 开发端 debug P12 副本与该证书是同一证书身份。

## 4. 正式发布身份判断

HarmonyOS 判断两个安装包是不是同一个可覆盖升级的应用，不只看 `bundleName`。
至少还要满足：

1. `bundleName` 相同；
2. 签名证书相同；
3. Profile 中的应用身份（`app-identifier`）一致；
4. 通过覆盖安装或应用市场更新安装，而不是先卸载。

正式发布和后续邀测统一使用 `6917614360926110054`。带
`app-identifier = 6918740027110769940` 的 Profile 只用于当前设备的 IDE Run，
不能上传 AGC，也不能作为正式包验收依据。

当前设备上的旧 debug 包如果仍是 `6918740027110769940`，它与正式 AGC 应用是不同
Profile 身份。是否能在保留数据的前提下更新，必须用正式 0054 debug Profile 实测后
再下结论；不得为了换身份而卸载。

官方规则：

- DevEco 文档中的“先卸载再安装”明确会清除应用缓存数据；
- “覆盖安装，不卸载”才保留数据；
- AppGallery 邀请测试用户在应用市场内更新测试版本时，不需要先卸载，应用数据不会被清除，
  但前提仍然是同一个应用身份和兼容的签名。

## 5. 正式发布路径

### 5.1 AGC 正式发布

旧邀测用户继续在 `6917614360926110054` 这一应用身份下更新：

1. 保持 `bundleName = com.dshm.dshclient`；
2. 继续使用原 release 证书和原应用的发布 Profile；
3. 新 Profile 加入已审批的 ACL：

```text
ohos.permission.CUSTOM_SANDBOX
ohos.permission.ALLOW_EXTERNAL_NATIVE_CODE
ohos.permission.FILE_ACCESS_PERSIST
```

4. 将 VersionCode 升到高于旧测试版本的版本；
5. `assembleApp` 构建 release `.app`；
6. 上传到原 AGC 应用 `6917614360926110054` 的新邀请测试版本；
7. 测试用户只通过 AppGallery 更新，不卸载。

这条路径不要求用户手动卸载，应用市场更新会保留应用数据。

### 5.2 PC 本机调试

如果只是继续更新当前鸿蒙 PC 上的 debug 包：

- 必须使用正式 `appIdentifier = 6917614360926110054` 的 debug Profile；
- Profile 必须绑定当前设备 UDID，并与已安装包的签名身份兼容；
- 使用：

```powershell
hdc install -r <新HAP>
```

- 不要用 `hdc uninstall` 或 DevEco 的“先卸载再安装”。

Windows 原开发端已经提供正式 debug 私钥与证书；仍需 AGC 为该证书生成一份
`com.dshm.dshclient` / `6917614360926110054` 的 device-bound debug Profile。

## 6. 禁止的操作

以下操作不能作为“无损升级”方案：

```powershell
hdc uninstall com.dshm.dshclient
bm uninstall -n com.dshm.dshclient
bm uninstall -k -n com.dshm.dshclient
```

原因：

- 普通卸载默认清除 el2 应用数据；
- `-k` 只表示尝试保留数据，不改变签名/App 身份校验；
- 官方错误码文档明确说明：同包名但签名不一致，包括“保留数据卸载后”的情况，
  新包仍可能安装失败。

## 7. Profile 身份校验

曾创建过：

```text
Name: DSHM-PC-debug-20DB409A-20261021
Profile ID: 2066254260579890176
app-identifier in profile: 6917614360926110054
```

它的 `app-identifier` 正确，因为 AGC 正式应用一直就是 `6917614360926110054`。
Profile 是否可用还要继续核对 UDID、ACL 与当前签名证书是否一致。

鸿蒙 PC 安装器目录里的 `app-identifier = 6918740027110769940` debug Profile
与当前安装包同源，已复制到 `.certs/debug-local/`，仅用于本机 Run。

## 8. 最终建议

**继续在 AGC 应用 `6917614360926110054` 下发新版 release `.app`。**

本机既有 debug Run 使用 `6918740027110769940` 以保住设备数据；
AGC release 使用 `6917614360926110054`。两套身份不得混签或混传。

## 9. 上线前验收清单

1. 在测试设备上先安装旧邀测版本；
2. 创建可识别的会话、插件、工作区和设置；
3. 通过目标升级方式安装新版：
   - AGC：AppGallery 邀测更新；
   - PC debug：`hdc install -r`；
4. 检查 `files/dsh/home` 指纹和内容未变化；
5. 检查版本号、签名 profile、bundle 和 appIdentifier；
6. 检查安装返回码不是 `17700073`；
7. 只有通过上述验收后，才向邀测用户发布。
