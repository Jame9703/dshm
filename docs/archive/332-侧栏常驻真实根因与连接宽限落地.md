## 2. 侧栏：官方机制（反汇编 dsh-client-ui-layout 实证）

```js
const SIDEBAR_AUTO_COLLAPSE = 1024;                    // 视口 < 1024px 自动收起
const narrow = viewport < 1024;
sidebarCollapsed = narrow ? !layoutInfo.narrowExpanded : layoutInfo.sidebar === 0;
// 初始 layoutInfo = { sidebar: 280, narrowExpanded: false, … }  —— 内存 store，无持久化
// setViewportWidth 跨 1024 边界 ⇒ narrowExpanded 强制 false
// 右栏首次打开 ⇒ narrowExpanded 强制 false
// toggleSidebar：窄档只翻 narrowExpanded；宽档翻 sidebar（280↔0）
```

**结论**：
- 平板竖屏 / 窄窗口（<1024）下官方**默认收起**，且每次跨断点都会被重置回收起；
- "点一次出缩略图、再点才全开"是官方**两段式切换**（窄档先 rail → narrowExpanded=true 才 280 全宽），
  不是 bug；
- 状态**无持久化**，每次进页面都从收起开始。

### 2.1 修法：复活 phone 壳里**已验证**的 keep-open，同步进 entry

关键发现：**两壳严重不同步** —— `phone/src/.../WebApp.ets` 一直有
`ensureTabletExpanded()`（keep-open：非用户收起 ⇒ 800ms 防抖恢复；`manualTabletCollapsed`
记录用户意图），而 **entry（平板/PC 实际跑的）没有**。

本轮把 entry 对齐到 phone 的已验证实现：

| 项 | entry（修后） |
|---|---|
| keep-open | `ensureTabletExpanded()`：`dshm-tablet/desktop` 档 + 官方收起态 + **非用户收起** ⇒ 点一次官方 toggle（800ms 防抖） |
| 用户意图 | `manualTabletCollapsed`：点击后确认收起 ⇒ 置真，本会话停用 keep-open |
| tick 接线 | `syncState(); ensureTabletExpanded(); ensureConnectionGrace(); …` |

> 2026-10-28 删除旧自愈的理由（"与官方不同步导致抖动"）由 **800ms 防抖 +
> manualTabletCollapsed** 两个机制化解：只在官方**确认**收起且**非用户意图**时介入。

删除了两个钉旧实现的门禁：`check-sidebar-always-on`（本轮新建后又按官方真实机制重写，
误伤了 `maybeAutoExpand` 的合法分支）、`check-handheld-sidebar-recover`（钉旧一次性自愈）。
结构仍由 `check-sidebar-shim-css`（15 条）守护。

## 3. 连接：官方指示器 + 启动宽限

### 3.1 用户看到的到底是什么

「连接异常，刷新重试」= 官方 `ConnectionIndicator`（`dsh-client-ui-settings-general`，
locale 键 `connection.error`），渲染为 `button[data-phase="disconnected"]`，
**压在页面左下角**；点击 = 官方 `reconnect`。

### 3.2 机制（client.browser.js 反汇编实证）

```js
async loop() {
  while (running) {
    if (!networkAvailable && !immediateRetry) { emitState("disconnected"); … }
    …
    this.emitState("connecting");     // 退避重试
    …
    this.emitState("connected");      // 成功
  }
}
```

Web 首帧时 Host 可能还没绑定完端口（实测 `BOOT_65` = **+6846ms**）⇒ 首连必失败 ⇒
**disconnected 态被立即显示**。官方的防闪烁只有
`CONNECTING_MIN_VISIBLE_MS=800`（保住"连接中"最少 800ms），**没有启动宽限**。

### 3.3 修法：垫片级 CSS 宽限（不碰 React）

```text
CONN_GRACE_MS = 12000
宽限期内：button[data-phase="disconnected"] 藏错误文本、
          ::after 显示「正在连接本机核心…」（降透明度）
宽限后 / 出现 connected|recovered ⇒ 整个 <style id=dshm-conn-grace> 移除，官方原样
```

- **不碰 React 状态** ⇒ 不与官方组件竞争（与侧栏同一教训）；
- 只影响"从没连上过的启动窗口"；一旦 connected 就本次运行不再干预；
- 点按钮手动重连的能力保留。
