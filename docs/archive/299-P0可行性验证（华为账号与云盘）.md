## 2. 验证链（页面上七步）

| 步 | 判定 | 为什么必须有这一步 |
|---|---|---|
| ① 能力探测（账号 / 云盘） | 两个 `canIUse` 都过 | 设备不支持时**整条静默降级**，不能弹窗 |
| ② 云盘连通（**真实 list**） | `list('')` 成功 | `bucket()` 同步返回、异步查实例 —— **不抛不等于可用**，只有真发请求才算数 |
| ③ 测试文件入 cache 暂存区 | `stageIntoCache` 成功 | SDK 的 `localPath` **以 cache 为根**，不能直接传 `files/...` |
| ④ 上传 | `uploadFile` 成功 | 闸门主体 |
| ⑤ 列目录能看到 | `list` 结果含该文件 | 证明写进了**云端**而不是本地假成功 |
| ⑥ 下载并比对字节 | 长度一致且内容一致 | 证明**读回来的是同一份** |
| ⑦ 删除云文件 | `deleteFile` 成功 | 清理，且证明删除权限可用 |

登录单独一步：点官方 `LoginWithHuaweiIDButton` → 回调里看 `unionID`（脱敏尾 4 位）与
`authorizationCode`（**只显示长度，不回显**）。

## 3. 真机怎么跑（给测试端）

1. 覆盖安装本次 Beta 包（**不要卸载**，`hdc install -r`）；
2. 确认设备已登录华为账号，且 AGC 侧已打开 CloudFoundation/Drive 相关能力与协议；
3. **点左下角的「云同步」按钮**进入验证页
   （2026-10-29 追加：已提供入口，位置在窗口左下角、官方账号菜单左侧；
   它由侧栏垫片 `ensureCloudEntry()` 创建，点击经桥 `openHuaweiCloudProbe()` 跳转
   `pages/HuaweiCloudProbe`。面板/右栏打开时自动隐藏，避免遮挡）；
4. 点「华为账号登录」按钮，完成授权；
5. 点「运行 P0 验证链」，把**屏幕上七行的 ✅/❌ 与原因**截图回传；
6. 点「清空暂存目录」收尾。

### 判读规则

- **七步全 ✅** ⇒ P0 通过，可以做 P1；
- **①失败** ⇒ 设备/系统不支持，方案在这台机器上不可行（换机型或放弃）；
- **②失败** ⇒ 多半是 AGC 未配置或实例名不对，**不是代码问题**，看错误码；
- **③–⑦ 任一步失败** ⇒ 把那一行的完整原因（含 `[code]`）贴回来，我据此定位；
- **登录失败** ⇒ 页面已按错误码分好类：`1001502014` 缺 scopes、`1001500003` scope 不支持、
  `1001500001` 指纹校验（签名与 AGC 登记不一致）、`1005300001` 未接受协议、`1002012` 用户取消。

## 4. 编译期踩到的三件事（已修，记下来）

| 现象 | 根因 | 修法 |
|---|---|---|
| `'@kit.AccountKit' has no exported member named 'LoginWithHuaweiIDButtonParams'` | kit 只导出 `LoginPanel` / `LoginWithHuaweiIDButton` / `loginComponentManager`，**参数类型在命名空间里** | 用 `loginComponentManager.LoginWithHuaweiIDButtonParams` |
| `Property 'cacheDir' does not exist on type 'BaseContext'` | `BaseContext` 没有 `cacheDir` | 参数类型改 `common.Context` |
| `Duplicate identifier 'runtimeFacts'` | 与 `runtime/RuntimeSingleton` 的同名导出撞车 | 改名 `deviceSummary` |

另外一处**语义**问题（编译能过但运行会错）：
`onClickLoginWithHuaweiIDButton` 收的是标准 `AsyncCallback`，形态是 `(err, data) => void`，
**不是** `{ onReceive }` 对象。写成对象会拿不到回调、表现为"点了没反应"。

### 为什么是"自己画一颗"而不是塞进官方账号菜单

官方左下角菜单由 `dsh-client-ui-settings-account` 的 `AccountMenu` 渲染，菜单项是官方代码里的
**固定列表**。往里插一项要么改上游（违背"不 fork"），要么依赖未公开的内部 DOM 结构（改版即失效）。
所以用**独立固定定位按钮**放在左下角、与官方菜单并存：位置挨着用户的习惯位置，但不碰官方 DOM。

### 编译期又踩了一次同一个坑

首次编译报了 12 个错误，根因是**垫片模板字符串内的注释里写了反引号**

这与 `docs/292` §3.3 记录的 `check-sidebar-shim-css` 红项是**同一个坑**：
该门禁专门有"垫片体内无第二个反引号"这条判据，但它只在**跑门禁时**才拦，
而我这次是先编译、后跑门禁，所以先撞了编译器。
**教训（已在本轮遵守）**：改垫片模板后先跑 `check-sidebar-shim-css`，再编译。
