# 191 · 2in1「电脑模式」侧栏入口缺失与仅角点缩放（手持形态 + 自由窗口的 PC 模式分档）

> 2026-10-18 内测复报：部分**既有电脑模式又有平板模式**的 2in1（现场：HUAWEI MatePad Pro
> `MRO-W00`，HarmonyOS `6.1.0.135(SP9C00E125R1P4)`，API 24，DSHM 1.1.4 / 核心 `+dshm.73`）
> 打开后**左侧没有侧栏入口**，且窗口**只能从左下 / 右下角**调节大小；点网页右上角那颗按钮后
> 侧栏才恢复正常。日志包：`DSHM-sidebar-missing-logs-20261018.zip`。

## 1. 日志读数（只认这几条）

| 读数 | 说明 |
|---|---|

## 2. 根因（代码链，两处叠加）

1. **装饰策略只看形态，不看窗口态**：`EntryAbility.afterWindowStageReady()` 对主窗**无条件**
   `win.setWindowDecorVisible(false)`。在平板形态的自由窗口（电脑模式）里，这一调用把系统标题栏
   和**四边的缩放边框**一起拿掉 ⇒ 只剩左右下角的拖拽点 —— 正是"只能从左下右下调节大小"。
2. **页面分档只看形态，不看窗口态**：`platformForm()` 按 `isHandheldForm()` 答 `tablet` ⇒ Web 垫片挂
   `dshm-handheld`（手持档不渲染自绘顶栏、也没有桌面档那颗原生侧栏按钮），而**桌面档**才有的
   「官方侧栏按钮由原生顶栏替代」这套接线不会生效 ⇒ 左上没有入口、侧栏收起后只能靠网页里那颗
   按钮（初始收起态即"看不见左边"）。

> 与 `docs/113`/`150` 的"自动建工作区"无关：本条是**窗口分档**问题，不是注册表问题。

## 3. 修法（beta 已落，entry / platform 侧，`coreVersion` 不变）

| 改动 | 位置 |
|---|---|
| 新增判据 **PC 模式 = 手持形态 + 自由窗口（`WindowStatusType.FLOATING`）**，发布到 AppStorage `dshPcMode` | `EntryAbility`（`KEY_PC_MODE`） |
| PC 模式下**不隐藏**系统装饰、不隐藏三键、不设 `setWindowDecorHeight` ⇒ 四边缩放与标题栏保留；`diag-decor-caps` 记 `pc=yes kept-pc` | `EntryAbility.afterWindowStageReady` |
| 窗口状态变化跟随：进入 FLOATING ⇒ 恢复装饰（`setWindowDecorVisible(true)`）；离开 ⇒ 重新隐藏（回到沉浸）；只在该结论变化时动作 | `EntryAbility.refreshDecorCaps` |
| `platformForm()` 在 PC 模式答 `desktop`；新增桥 `platformPcMode()`；页面挂 `dshm-pc` | `WebApp.bridges` |
| 垫片可重入：首帧先答 handheld、随后 pcMode 变真时**摘掉 `dshm-handheld`**（唯一一处摘类），之后按桌面档走 | `SIDEBAR_SHIM_JS.applyHandheld` |
| PC 模式 CSS：`html.dshm-desktop:not(.dshm-pc)` 才藏官方侧栏按钮；`dshm-pc` 收起态显示浮动 ⊞、并给标题行让位 | `SIDEBAR_SHIM_JS.ensureStyle` |
| 浮动 ⊞ 的创建条件扩到 `dshm-pc` | `ensureFab` |

## 4. 门禁

- `check-feature-wiring` 新增 4 条接线断言（`PC_CLASS` / `platformPcMode` / `:not(.dshm-pc)` / pc 收起态 ⊞）。
- `check-sidebar-shim-css`、`check-decor-button-mode`、`check-handheld-back` 全绿（垫片 CSS 括号、三键配色、返回链未被破坏）。
- 全量回归门禁 36/36 绿。

## 5. 待真机复验（内测组 / 接机后）

1. MatePad Pro（电脑模式）打开 DSHM：应看到**系统标题栏 + 四边可拖拽缩放**，侧栏常驻；收起后用左上 ⊞ 呼出。
2. `files/diag-decor-caps` 应出现 `pc=yes visible=kept-pc ... status=*:FLOATING`。
3. 切到平板模式（全屏）后应回到原行为（沉浸、无标题栏）。
4. 真 2in1（`form=2in1`）与手机全屏**逐字未改**，作为对照臂复测一次。

## 6. 风险与边界

- 判据依赖 `getWindowStatus()`；读不到（801）时按原行为（隐藏装饰、手持档），不会把桌面档误开。
- 电脑模式 ↔ 最大化/全屏切换时装饰会恢复/隐藏一次（`refreshDecorCaps` 只在该结论变化时动作，不会抖动）。
- 系统装饰恢复后，页面顶栏与系统标题栏并存的问题在本档**不存在**：PC 模式沿用"手持档不画自绘顶栏"，
  入口改由 `dshm-pc` 的浮动 ⊞ 提供（展开态官方按钮就在侧栏列头左上角）。
