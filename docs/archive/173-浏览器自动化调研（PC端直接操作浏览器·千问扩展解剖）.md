# 173 · 浏览器自动化调研（PC 端「直接操作浏览器」）

> 用户 2026-10-16：「需要网页自动化的时候，直接操作 PC 上的浏览器，目前**海泰浏览器**支持较好。
> 千问办公支持的也是这个浏览器。看一下开发文档和本地千问办公的案例，先调研一下。」
>
> 本档 = **只读调研**（真机实测 + 千问扩展逆向 + 官方文档）+ 对 DSHM 的方案建议。**未改任何产品代码**；
> 所有临时探针与端口转发均已清理。

## 1. 结论速览

PC 端「网页自动化」在 HarmonyOS PC 上成立，有两条**已验证**的通道：

| 通道 | 机制 | 实测状态（PC `86E0226429000417`） |
|---|---|---|
| **A. CDP 外连** | 浏览器暴露 DevTools socket → 外部进程按 Chrome DevTools Protocol 操作页面 | ✅ **已打穿**（华为浏览器）：`hdc fport tcp:N localabstract:webview_devtools_remote_<pid>` → `GET /json/version`（`Chromium 144 / ArkWeb 7.0 / 协议 1.3`）→ `/json/list` 枚举页面 → WebSocket 连 `devtools/page/<id>` → `Runtime.evaluate` **在真实页面里执行 JS 成功**（读到 DeepSeek 页面标题） |
| **B. 扩展 + 本地桥** | 浏览器扩展（`chrome.debugger`）↔ AI 应用在本机起的 WebSocket 桥 | ✅ **已解剖**（千问办公 / WorkBuddy 同架构）；海泰浏览器已验证支持装载这类"解压版"扩展 |

**海泰「支持较好」的真相**：它允许在开发者模式下加载「已解压的扩展」，而扩展凭 `chrome.debugger` 权限
可在**浏览器内部**使用 CDP —— **不依赖浏览器开放任何外部调试端口**。这正是它相对"只认调试端口"的浏览器的优势。

## 2. 实测证据

### 2.1 CDP 线（华为浏览器 `com.huawei.hmos.browser`）

- 设备侧存在 unix socket `@webview_devtools_remote_47044`（47044 = 该浏览器进程）；
- `hdc fport tcp:19222 localabstract:webview_devtools_remote_47044` 转发成功；
- `/json/version` 返回 `Chrome/144.0.7559.59`、`ArkWeb/7.0.0.109`、**可用 `webSocketDebuggerUrl`**；
- `/json/list` 枚举到页面；用 Node（v24 内建 WebSocket）连 page target 执行 `Runtime.evaluate`
  → 返回 `"DeepSeek - 探索未至之境 | https://chat.deepseek.com/"` —— **端到端闭环**；
- 旁证：该浏览器支持 chrome 扩展（现场观测到已安装扩展的 service worker）。

### 2.2 扩展 + 桥线

| 对象 | 观测（`bm dump` / `ps` / `/proc/net/tcp`） |
|---|---|
| 海泰浏览器 `com.haitai.htbrowser`（北京海泰方圆科技，v2.0.24） | 完整浏览器（`http/https/file` browsable）+ `BrowserEmbeddedAbility`（embeddedUI 扩展）+ `StatelessAbility`/`TaskManagerAbility`；**无**意图框架配置 |
| 海泰扩展页（用户截图） | 已装 **Ultron Browser Agent 1.0.13**（WorkBuddy 所装），其 service worker **运行中**（其余扩展均"不活动"）；另有工行 U 盾等政企扩展 |
| WorkBuddy `com.tencent.workbuddy`（Electron） | 进程树内跑 `@genie/workbuddy-extensions/…/extensions/edge-sync/server/index.cjs`；127.0.0.1 起多个监听端口（HTTP 探测无响应 ⇒ 自定义加密协议）；抓到"短连接后关闭"的痕迹 ⇒ 扩展按需连桥 |
| 千问办公 `cn.qwenwork.desktop.hmos`（Electron/ArkWeb 混合） | 「连接器 → 浏览器」= **网页自动化**；引导用户把**自带扩展**（解压版）装入**海泰浏览器**（开发者模式 → 加载已解压扩展）；桥 = 127.0.0.1 多个监听端口 |

> 取文件路径备注：千问把扩展释放到 `~/.config/QwenWorkCN/chrome-extension`
> （应用视角）。该目录**跨应用不可读**（DSHM 的进程内 Python 实测 `PermissionError`）⇒ 让用户把
> 整个文件夹复制到 DSHM 工作区（`…/Download/com.dshm.dshmbeta/`，共享区）后、经 DSHM 的
> `/dshm-python/run-get` 桥读出并分析（本档 §3 的全部内容由此得来）。

## 3. 千问扩展完整解剖（manifest v3 · v1.5.1 · 23 文件）

### 3.1 manifest（权限面 = 本方案的关键）

```json
"permissions": ["debugger","tabs","tabGroups","activeTab","scripting","storage","alarms","nativeMessaging"],
"host_permissions": ["http://127.0.0.1/*","http://localhost/*","<all_urls>"],
"background": { "service_worker": "background.js", "type": "module" },
"content_scripts": [ accessibility-tree.js / page-bridge.js / visual-indicator.js（http(s) 全站注入, document_idle） ],
"key": "MIIBIjAN…"   // 固定扩展 ID
```

### 3.2 通信协议（WebSocket JSON-RPC，双向）

- **端口发现**：`defaultRelayPort` + `fallbackRelayPorts`（回退列表）+ `HEAD /` 500ms 探测；
  另有 `chrome.runtime.sendNativeMessage("<host>", {type:'getRelayClients'})` 经 **Native Messaging** 拿 relay 客户端列表（port/pid）。
- **端点**：`ws://127.0.0.1:<port>/extension/v2`（主通道）+ `ws://127.0.0.1:<port>/extension`（legacy V1 状态桥）+ `GET /app/info`（应用信息）。
- **消息**：`ping`→`pong`；`tools/discover` → `{id, result:{tools:[…]}}`（**扩展向桥注册工具清单**）；
  `tools/invoke` → `{tool, arguments}` 执行；`extensionInfo`（版本/能力/浏览器类型/clientId/displayName）；
  错误回包 `{id, error:{code,message}}`（如 `QUEUE_FULL`）；命令队列 + `waitTimeoutMs` + `v2StopRequested`（用户可中断）。

### 3.3 工具面（对模型的出口）

- 首个工具名即 `computer`：描述为"用鼠标键盘操作浏览器并截图"（**Computer-Use 风格**）；
  工具 schema 统一强制 `additionalProperties:false`；支持 `tabs_context`（拿可用 tab）等。
- 网络观测工具：可按 URL 子串过滤（如 `'/api/'`、`example.com`）、`clear` 去重、`limit ≤1000` —— **Agent 能直接"看"页面的 API 流量**。

### 3.4 页面理解（`content-scripts/accessibility-tree.js`，4.2 KB）

- DOM → **文本树**：`[ref_3] button "提交"`、`[ref_7] textbox "搜索"`…；
- **ref 机制**：`ref_N` ↔ `WeakRef(element)` 双向映射；AI 以 ref 指代元素，工具以 ref 定位/取坐标；
- role 推断（tag→role 表 + `role` 属性）、可访问名（aria-label/labelledby/title/placeholder/alt/文本）、
  状态标注（disabled/checked/readonly/required/options=N）；
- 可见性过滤（display/visibility/opacity/offsetWidth）；输出截断（默认 5 万字符）+ "用 ref_id 聚焦子树"提示。

### 3.5 页面操作（`content-scripts/page-bridge.js`，5 KB）

- `getPageText`：正文启发式提取（article/main/常见 class 清单）→ 5 万字截断；
- `fillForm`：select/checkbox/radio/input/textarea/contenteditable 全覆盖；
  **React 兼容**：走 `HTMLInputElement.prototype.value` 的 native setter + `InputEvent('insertText')`；
- `clickElement` / `scrollToElement` / `searchElements`（按关键词给元素打分排序）/ `prepareScreenshot`（临时隐藏滚动条）；
- 通道：content-script ↔ background 经 `chrome.runtime.onMessage`（GET_PAGE_TEXT/FILL_FORM/CLICK_ELEMENT/…）。

### 3.6 视觉反馈（`content-scripts/visual-indicator.js`，7.5 KB）

- 阴影 DOM 覆盖层：操作目标**绿色脉冲高亮框**（`#4CAF50`）+ 固定右上角**状态徽章**（⏳/✅/❌）；
- 让用户"看得见 AI 在操作什么" —— UX 层值得直接借鉴。

### 3.7 工程细节（值得抄的）

- `chrome.debugger.attach({tabId},"1.3")` + `Runtime.evaluate` / `Input.dispatchKeyEvent`（含 Enter/字符）/ `Page.navigate` /
  网络事件（`Page.loadEventFired` / `Page.navigatedWithinDocument` / `Page.javascriptDialogOpening` —— 含 beforeunload 策略）/ 截图；
- **tab 分组管理**（`chrome.tabGroups`，组名 "QwenWork"，冲突清理）；
- 状态再水合（重启后 `$t(tabId)` 校验 + 失效 tab 清理）；截图上下文管理；V1/V2 双协议并存（向后兼容）；
- `qwenwork-deployment.json`：`{schemaVersion, installSourceId, updateAuthority:"desktop"}` —— **桌面端对扩展有更新权**。

## 4. 对 DSHM 的方案建议（待拍板，未动代码）

### 4.1 三条路线

| 路线 | 内容 | 依赖 | 建议 |
|---|---|---|---|
| **A. CDP 外连** | DSHM 连浏览器调试 socket | 浏览器需开 DevTools socket（华为浏览器✅ / 海泰❌未开）；且 **DSHM 应用进程直连 abstract socket 的 SELinux 边界未验证**（`hdc fport` 是 PC 侧验证，非应用内） | 备选/辅助 |
| **B. 扩展 + 本地桥** | DSHM 自研扩展（参考千问结构）+ DSHM 宿主起 WebSocket 桥 | **海泰已验证支持**该模式；全程端侧（应用内桥+扩展），无新权限（扩展权限属浏览器侧） | ★ **推荐** |
| **C. embeddedUI 嵌入** | 把海泰浏览器嵌进 DSHM 界面 | 海泰有 `BrowserEmbeddedAbility`；跨应用开放度（`appIdentifierAllowList`/API26 `allow_all`）需实测/问海泰 | 观察 |

### 4.2 B 路线的 DSHM 版（草案）

```
浏览器（海泰）：DSHM 扩展（自研，可裁剪千问工具面）
   ├─ chrome.debugger（CDP）→ 页面操作/截图/网络
   ├─ content-scripts：accessibility-tree（ref 树）+ page-bridge（表单/点击）+ 视觉指示
   └─ service worker ⇄ ws://127.0.0.1:<DSHM 端口>/extension（DSHM 宿主 Node 起 WS）
       服务端 = DSHM 宿主（Node v24）内新增一个本地 WS 端点 + 一套 tools（discover/invoke）
       对 Agent 暴露：browser_* 工具（导航/读树/点击/输入/截图/取正文）
安装引导：DSHM 把扩展目录释放到用户可见路径 → 引导在目标浏览器"加载已解压扩展"（同千问体验）
```

**为什么对 DSHM 成本可控**：宿主是 Node（WS 服务端容易）；页面理解/操作的 content-script 逻辑可参照千问
（其 4 个脚本合计 ≤22 KB）；视觉反馈可后置。

### 4.3 开放问题（待决）

1. **目标浏览器**：只做海泰（用户主用），还是"任意 Chromium 系（海泰/华为/360/夸克均可加载）"？（推荐后者，扩展天然跨 Chromium）
2. **扩展分发**：跟随千问的"解压目录 + 手动加载"，还是未来争取浏览器方的商店/预装合作？
3. **端口发现**：固定端口（简单）vs nativeMessaging 名单（千问式，需注册 Native Messaging host，鸿蒙侧可行性未知）；
4. **工具面范围**：先做"读页面/导航/点击/输入/截图"最小集，还是直接对齐千问的 computer-use 全量？
5. **A 路线补验**：如选 A（对华为浏览器），需先验证 DSHM 应用进程能否直连 `@webview_devtools_remote_*`（SELinux）。
