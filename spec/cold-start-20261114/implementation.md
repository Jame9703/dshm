# PC与手机冷启动优化

## 范围与证据

区分进程冷启动、首次安装/同版本换容器解包、前台恢复，不以历史首装耗时代替当前稳态冷启。现有旧Beta归档中，profile开始后Python worker自检持续约10.26秒，主事件循环同期停顿约10.17秒，监听在该时段末出现；这证明时间重叠，不单独证明因果。当前未取得新包PC/手机配对设备测量。

现核心容器约203MB，正常SHA stamp命中时仍完整计算摘要，但不会再次解包。多Ability实例可重复进入安装检查，前面的完整SHA和事务安装没有进程级合并。

## 实施约束

- 仅把非关键自检/执行能力诊断移出profile/Web就绪前的竞争路径，保留关键包装器、工具链准备、原生适配和请求时Python懒初始化；不提前伪造READY或缩短失败等待。
- 同资源/目标的并发核心安装检查共享在途Promise，完成或失败后释放，不永久缓存失败或已完成状态；保留完整SHA、同版本换内容识别、staging校验和失败回滚。
- 所有安装事务使用进程内队列串行，避免不同请求共享staging或临时容器产生竞争；key仅处理末尾斜杠，不把包含符号链接的路径词法折叠当成真实路径等价。
- 目录授权恢复使用4个watchdog等待槽，逐URI隔离；16条全部挂起的虚拟等待由48000ms降至12000ms。超时不取消底层API，底层未完成调用可达16，不等于真实设备提速36秒。保留恢复栅栏与后续重试。
- HSP模块路径按bundle及资源身份合并在途解析并缓存成功路径值，失败可重试，返回副本避免污染；不缓存用户权限和profile内容。
- 不删除用户数据/核心stamp，不更改版本、权限、身份、设备面、语音或终端分档。改Host源后同步resfile；改核心插件才触发核心容器重打。
- 新门禁执行实际生产调度/安装入口，覆盖就绪前不启动诊断、就绪后单次、停止取消、解包补跑、按需Python，以及并发安装一次/不同目标隔离/失败重试/完成重检。

## 验收

分别报告离线次数/阶段变化与真实设备耗时。执行相关Host启动、Python、工具链、核心事务门禁，改动ETS快速检查与有效lint，再编译entry/default、phone/phone。不自动出Beta/AGC，不以编译通过宣称PC和手机实际启动已提速。当前PC未运行正式包、手机未连接，设备中位数/P95待采样。

## 已确认主要耗时区间

旧PC两次BOOT40至50约12.6至13.0秒，占Host启动区间约98%；旧手机rc.1样本约9.6秒，不能作为当前rc.3手机基线。无可用Python资源的隔离Host也存在多秒插件装载停顿，不能把Python自检的约10秒与主线程停顿时间重叠直接判为因果。

单次插桩隔离测量中，核心manifest读取1813次、595路径，重复1218次，inclusive读取约546ms；ESM解析约4.78秒是嵌套统计，不能相加或当成可省时间。本轮未缓存官方依赖解析结果或可变profile，保留插件热加载语义，基础模块图耗时仍待进一步定向优化。
