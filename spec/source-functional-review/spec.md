# Feature Specification: 当前源码独立功能审查

**Created**：2026-11-13  
**Status**：待评审  
**Input**：PC 端用户实测目前正常，平板和手机暂不可测；抛开历史文档，单从当前项目重新 review 功能实现，列出问题，先不动代码。

## Overview

仅以当前源码、配置、实际依赖与调用链独立检查三端和共享功能实现，产出可定位、可复核的问题清单。历史文档、旧审查及门禁通过记录不作为正确性依据；不修改实现、不构建、不部署、不操作设备。

## User Scenarios & Testing

### User Story 1 - 独立审查三端功能实现（Priority: P1）

用户获得 PC、平板、手机及折叠屏分支和共享能力的实现审查，知道检查覆盖范围及未覆盖边界。

**Independent Test**：每个已审功能标明当前入口、调用链与端侧差异，不以历史说法代替源码分析。

**Acceptance Scenarios**：
1. 给定当前项目，审查启动/连接/会话、文件/工作区、插件/市场、终端/VM、侧栏/输入/返回、后台/通知、设置/账号/云同步等已实现功能。
2. 给定 PC 正常这一用户反馈，不据此跳过 PC 静态分支，也不把普通平板和手机推定为正常或故障。

### User Story 2 - 获取证据充分的问题清单（Priority: P1）

用户看到按严重程度排序的缺陷、潜在风险及待真机验证项，可以决定后续是否修复。

**Independent Test**：逐条核验具体位置、触发条件、调用可达性、影响端、预期与实际差异、证据强度。

**Acceptance Scenarios**：
1. 给定可静态证明的问题，列出当前源码路径和行区间、完整因果链及影响；仅建议修复方向，不写补丁。
2. 给定依赖系统行为或设备交互的疑点，明确为风险或待验证，不冒充确认缺陷。
3. 给定候选问题，复核保护分支、调用者、默认值及上游实际实现，剔除误报并合并同根因项。

### Edge Cases

- 无问题证据：如实说明未发现，不为凑数量输出推测。
- 源码注释、历史文档与实现矛盾：以当前可达实现为证据；注释仅作线索。
- 系统 API 行为无法核验：标注证据缺口，不凭记忆判定必现故障。
- 现有检查含写入、资源生成或隐式副作用：不执行，采用只读证据；旧绿灯不能证明正确。

## Requirements

### Functional Requirements

- **FR-001**：从当前项目实际入口建立功能覆盖矩阵，审查三端分支与共享功能，不以历史文档约束实现正确性判断。
- **FR-002**：重点覆盖启动连接、会话流式状态与取消恢复、文件工作区、插件安装市场、终端与 guest VM、侧栏输入与返回、后台通知、设置账号云同步及升级数据处理。
- **FR-003**：对每个问题记录严重性、影响端、触发条件、源码位置、可达调用链、实际结果、证据强度及建议方向。
- **FR-004**：区分确认缺陷、潜在风险、需真机验证；对候选问题进行独立反证复核，剔除死代码和已有兜底覆盖的误报。
- **FR-005**：允许运行经事前检查确认无副作用的现有检查及最小逻辑复现，不运行会修改文件或设备状态的检查；不把检查通过当作无缺陷证明。
- **FR-006**：最终给出分级问题清单、审查覆盖矩阵、未验证边界；不修改问题代码、不新增功能、不生成应用补丁。

### Constraints

- **C-001**：仅允许在 `~/data/DSHM-deveco-workspace/spec/source-functional-review/` 写本轮需求、方案、任务和报告，并更新 `~/data/DSHM-deveco-workspace/spec/feature.json`。
- **C-002**：不得修改源码、配置、历史文档、资源、工作记忆或其他项目文件，不构建、部署、安装、卸载、修复或操作设备，不提交或重置现有改动。
- **C-003**：AGENTS.md 仅提供数据与签名等操作安全红线，不以其中产品描述作为功能正确性的裁判。
- **C-004**：不复用上轮已通过结论替代审查；用户 PC 正常是外部实测信息，其他端仍无本轮真机结论。
- **C-005**：经用户批准保留五阶段评审，阶段 4 改为只读审查，阶段 5 改为独立证据复核，不执行构建部署及 UI 操作。

### Key Entities

- **功能覆盖项**：端侧、入口、实现位置、调用链、审查状态和证据边界。
- **候选问题**：根因、可达触发条件、影响、源码证据、严重性和确认等级。
- **复核结论**：支持或反证材料、保留/降级/剔除决定及原因。

## Success Criteria

- **SC-001**：上述重点功能全部纳入覆盖矩阵，未深入覆盖项显式标明。
- **SC-002**：每条确认缺陷均有当前可达实现及具体位置证据，不存在只引用历史文档的结论。
- **SC-003**：候选问题全部经过反证复核；所有依赖真机的判断明确标注未验证。
- **SC-004**：除获批审查文档与索引外，项目文件和设备状态零主动改动；没有未经核验的测试通过声明。

## Assumptions

- 用户已确认完整阶段评审、仅写审查文档及允许无副作用检查。
- 本轮审查对象是当前工作区实物，不要求清理或还原已有未提交内容。
- 不承诺仅凭静态审查证明全部功能正确；不可见的系统与远端行为保留边界。

## Open Questions

无待确认需求；具体问题数量与严重性以独立审查和复核结果为准。
