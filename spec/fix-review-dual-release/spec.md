# Feature Specification: 审查问题最小修复与 Beta、AGC 双包交付

**Created**：2026-11-13  
**Status**：待需求评审  
**Input**：按照复核清单顺序修复，DSH 核心功能尽量对齐官方逻辑，非必要不修改；修复后再次复核，通过后编译 Beta 和 AGC 包供用户测试。

## Overview

按当前源码全局复核形成的11项候选及附属tmp错误逐项处理，优先保护数据及修复明确功能错误。保留DSH官方核心机制，修改限定在必要适配和防护；完成独立反证复核、同口径回归及实物核验后交付Beta和AGC三端合包，不将待测能力宣称为真机通过。

## User Scenarios & Testing

### User Story 1 - 数据与安装更新安全（Priority: P1）

用户启动、选择目录、更新插件及升级核心时，已有文件与可用安装不因探测、失败更新或弱内容判等遭到不必要破坏。

**Independent Test**：预存同名文件不变；插件新版获取/校验/落位失败可保留旧可用安装；校验错误准确反馈；容器内容变化可被可靠识别。

**Acceptance Scenarios**：
1. 目录含原探针同名文件，执行应用目录可写性检查后文件内容保持不变，失败清理只影响本次拥有的临时对象。
2. 插件换版在下载、校验或替换期间失败，不依赖重新联网下载旧版作为唯一恢复保障；保留官方manager已有重装恢复及防重复机制。
3. 完整性校验失败显示原错误，不因临时变量错误遮盖。
4. 核心同标签内容发生变化时不能仅凭相同尺寸或旧builtAt认定已安装；保持原有stage/commit/rollback数据保护。

### User Story 2 - 正确、隔离且可解释的同步（Priority: P1）

用户恢复插件、导入会话、退出同步时，安装意图完整、遗漏可见、内容校验有效，旧任务不污染退出后的状态。

**Independent Test**：npm清单往返、映射刷新/遗漏统计、退出时在途任务隔离、同尺寸不同内容处理及合法技能名碰撞测试。

**Acceptance Scenarios**：
1. npm包名及版本、GitHub等来源意图完整传递，不请求仅有版本的错误包标识。
2. 每次拉取采用当前自动工作区映射，未映射会话报告数量和原因，不将零导入混同全部成功；未知目录不自动写入，不新增手动映射UI。
3. 退出后旧任务不继续发起新的业务步骤或回填当前状态；在途系统调用不能取消时，清楚隔离结果，不能承诺撤回已完成的外部副作用。
4. 导入校验真实内容摘要；同尺寸不同内容不静默等同，已有本地内容不被无确认覆盖；有效官方会话格式保持兼容。
5. 不同合法同步单元使用不会相互覆盖的资产暂存身份，不依赖未经确认的平台快照时点保障正确性。

### User Story 3 - 后台与VM生命周期可靠（Priority: P2）

用户经历后台申请失败重试、前后台切换、VM关闭和插件重载时，引用拥有权正确、停止等待有明确信号，清理日志不抛作用域异常。

**Independent Test**：失败/成功/取消引用配平测试；QMP greeting/close早于worker退出测试；卸载回调及其他清理隔离测试。

**Acceptance Scenarios**：
1. 保活失败、取消、重试及释放均不遗留无主引用，不破坏PC既有常驻策略。
2. QMP数据或断连不能冒充worker已退出；保持有界退出，不扩展为无限等待，不改原生终端与guest分档。
3. VM插件卸载统计可执行，保留官方Cordis的异常隔离与其他清理动作。

### User Story 4 - 获得经过复核的两种测试交付（Priority: P2）

用户获取同源修复的Beta与AGC三端合包，附校验值、修复/回归证据和未验证清单。

**Independent Test**：独立反证复查、全量回归、包身份/权限/核心内容/签名与原文件恢复核验。

**Acceptance Scenarios**：
1. 修复后重新核查全局调用链和现有保护，保留官方核心默认机制；没有未解释回归或本轮已知修复倒退才进入交付出包。
2. Beta临时身份和签名配置构建后准确恢复，AGC使用既有正式发布身份，两包均含同源核心修复。
3. 提供实际包路径、大小、SHA256及适用方式，不自动上传AGC、不将AGC包作为可任意本地侧载包。
4. 真机信任策略或平板手机测试条件受限时，仍交付通过离线核验的待测包，明确缺口，不宣称全功能正常。

### Edge Cases

- 上游已有恢复或安全机制：保留并配合，不重复重写或删减。
- 条件性风险未取得事故样本：修复可证明的薄弱环节，测试反例和正常路径，不把假设扩大成已发生事故。
- 不可取消的系统调用：隔离旧任务结果及后续应用动作，不承诺撤销已提交操作。
- 文件、安装或核心替换中断：保护已有内容，清理不得误删非本次拥有对象。
- 设备授权和签名限制：不卸载清数据、不更换签名、不修改权限绕过限制。

## Requirements

### Functional Requirements

- **FR-001**：逐项处理DR1、E01、E02、B01、E04、CR2、D01、E03、E05、C01、FR1及附属tmp错误，以 `spec/source-functional-review/recheck-final.md` 的准确条件和反证为问题基准。
- **FR-002**：遵循批准的优先次序：固定名探写→npm恢复→保活/退出/映射→安装保旧/内容校验/资产隔离→VM退出/核心身份/日志及错误诊断；实现依赖需要调整时记录理由，不遗漏后置低优先问题。
- **FR-003**：DSH核心尽量保持官方逻辑，先使用既有扩展和本地适配；触及官方核心必须有必要性、行为差异及回归证据，不改无关功能，不额外追上游版本。
- **FR-004**：探写不截断或删除已有文件，清理仅限本次拥有的临时对象。
- **FR-005**：插件换版具备本地旧包保全/失败恢复，保留官方manager恢复机制；校验错误不被tmp作用域异常掩盖。
- **FR-006**：插件恢复完整表达来源、名称与版本意图，保持现有默认不覆盖本机差异版本的安全选择。
- **FR-007**：自动工作区映射及时刷新，未映射会话数量及原因可见；不新增手动映射UI，不猜测远端目标绝对路径。
- **FR-008**：退出同步隔离旧任务后续业务步骤及状态回填，明确不可撤销外部副作用的边界。
- **FR-009**：同步导入实际校验内容摘要、正确处理同尺寸不同内容且不擅自覆盖本地；资产暂存身份防碰撞，兼容有效旧数据与官方会话格式。
- **FR-010**：保活引用与调用方拥有权在失败、取消、重试、成功释放路径配平；不破坏PC常驻及生命周期代次保护。
- **FR-011**：VM停止以worker退出而非QMP数据/断连作正常完成依据，同时保留有界超时；修正卸载统计作用域，不修改原生/guest归属。
- **FR-012**：核心安装身份核验绑定实际内容，不能只按大小/旧builtAt跳过；保留现有事务切换与回滚保护，不通过擅自提应用版本规避。
- **FR-013**：为每项增加或更新相关正向、失败及反证测试，新门禁带有效变异自检；修改前后同口径回归，不能放宽检查换绿。
- **FR-014**：修复后独立重审调用链、保护和源码到随包内容一致性，所有候选有最终处置；出包前无未解释的必要检查失败。
- **FR-015**：构建并核验Beta和AGC三端合包，检查身份、模块设备面、entry18/phone9权限顺序reason、核心及资源摘要、签名和原配置恢复，提供各包大小与SHA256。
- **FR-016**：更新必要的当前状态、修复证据与工作记忆；历史只读审查文档保留为证据，不将其旧分级当作修复后的结论。

### Constraints

- **C-001**：应用保持1.1.8/1010016；不更换签名、不修改权限面、不改变三端形态与终端分档、不新增未要求产品功能。
- **C-002**：保留现有未提交改动；不提交/重置，不删除用户数据、签名凭据、历史交付和回滚资产。
- **C-003**：核心/自带插件变动必须同步物化至随包容器并核验实物；不交付源码已改而包内仍旧的产物。
- **C-004**：最终交付为供用户测试的两包，不自动上传或发布；设备受限不阻断合格离线待测包交付，但必须标注未验证项目。
- **C-005**：官方文档检索当前受本地绑定缺失影响；不得伪造查证或擅改全局工具，关键API可用当前SDK与明确证据补核并记录局限。

### Key Entities

- **问题处置项**：候选ID、成立条件、修改边界、官方机制保护、测试和独立复核结论。
- **安装/文件拥有权**：已有对象、本次临时对象、旧安装、新安装及失败恢复状态。
- **同步任务身份**：任务代次、账号/开关状态、在途步骤、结果回填与取消边界。
- **同步内容身份**：单元ID、摘要、来源、不可冲突资产路径与导入结果。
- **交付批次**：Beta/AGC身份、核心内容、包摘要、签名核验和待真机边界。

## Success Criteria

- **SC-001**：11项候选及附属错误全部有处置与验证证据；必要改动未重写无关官方核心逻辑。
- **SC-002**：预存文件、旧安装和本地导入内容在对应失败与冲突测试中不被非授权破坏，测试反例与正常路径均有结论。
- **SC-003**：修复后独立复核完成，所有可执行必需回归无未解释失败，前后OK→BAD无未处理项。
- **SC-004**：Beta与AGC两种合包均可提供真实路径、大小、摘要和包核验记录，内容同源、身份正确、正式文件恢复。
- **SC-005**：无擅自版本/权限/设备策略变更，无用户数据与签名/历史交付损失，未验证能力无虚假通过结论。

## Assumptions

- 用户已明确全部逐项处理，条件风险仅做有依据的必要防护。
- 工作区修复限定自动映射刷新和遗漏反馈，不引入手动映射界面。
- 用户接受设备受限时提供离线核验后的待测双包，应用版本不变、不自动上传AGC。
- 用户已批准本目录及更新spec/feature.json，保留旧审查证据。

## Open Questions

需求范围已明确。最终是否包含逐故事UI验证在任务阶段确认，设备不可用时如实标注；具体最小改动落点和数据兼容策略在方案阶段依据当前实现确定，不新增产品需求。
