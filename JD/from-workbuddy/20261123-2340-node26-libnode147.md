## 4. 已知风险（必须真机确认）

1. **原生 addon ABI**：现有 OHOS addon 按 ABI 137 编。独立测试里 `sharp-openharmony-arm64.node` 在 147 下 **SIGSEGV**（137 正常）；`koffi` / `system.node` 因目录无 `.codesign` 未判定。
   - 若 App 运行期用到 sharp / koffi / node-pty 等 prebuild，**必须按 ABI 147 重编或替换**，否则图片、终端、系统信息类功能会崩。
   - 建议真机优先测：图片/缩略图、终端、系统信息、插件安装、桌宠。
2. **io_uring**：147 为外部预编译件，原 24.x 的字节补丁不可用；已改为 `dshhost` 启动前 `UV_USE_IO_URING=0`。真机需确认无挂起（长会话、文件监听、插件下载）。
3. **头文件版本**：`hostruntime/src/main/cpp/node-headers` 是 **26.7.0**，与 26.13 同 major，CMake 当前按 C++20 编译；若遇 API 变更，用 brew 的 `include/node` 重新同步。

## 7. 追加修复：原生库 DT_NEEDED 137 → 147（2026-11-24，beta 实测回归）

### 现象
beta 包启动后终端报：

```text
terminals are unavailable because node-pty cannot be loaded:
Error loading shared library libnode.so.137:
  (needed by /data/storage/el1/bundle/libs/arm64/libpty.so)
```

自检报告同时显示 `read_image` 失败、sharp 不可用。

### 根因
`hostruntime/libs/arm64-v8a/` 下的 `libpty.so` 与 `libsharp-openharmony-arm64.so`
是由核心树旧原生件播种的，`DT_NEEDED` 直接写着 `libnode.so.137`。
替换成 147 后，这两个库在加载时找不到 137，于是 pty / sharp 整条链断掉。
（这两个库自身不是 NAPI addon，问题只在 NEEDED 字符串。）

### 修复
1. 两个文件原地改写：

```bash
node tools/patch-native-needed.mjs hostruntime/libs/arm64-v8a/libpty.so libnode.so.137 libnode.so.147
node tools/patch-native-needed.mjs hostruntime/libs/arm64-v8a/libsharp-openharmony-arm64.so libnode.so.137 libnode.so.147
```

修复后：
- `libpty.so` NEEDED → `libnode.so.147, libc.so`
- `libsharp-openharmony-arm64.so` NEEDED → `libvips-cpp.so, libnode.so.147, libc.so`

2. **生成端防回归**：`tools/collect-libvips.mjs` 新增 §3.6，播种后把任意
   `libnode.so.<数字>` 的 NEEDED 统一改到当前 libnode soname（等长原地改写）。
3. **发布门禁**：`tools/check-node-cli.mjs` 新增一项，扫描
   `hostruntime/libs/arm64-v8a/*.so`，任何 `libnode.so.<旧 ABI>` 直接判失败。

### 验证（Node 26 / ABI 147）
- `libpty.so`：签名后经 `LD_LIBRARY_PATH` 指向含 147 的目录，`dlopen` **成功**；
- `libsharp-openharmony-arm64.so`：连同 libvips 闭包一起签名后 `dlopen` **成功**；
- `check-node-cli`：**43 passed / 0 failed**（含新增 NEEDED 回归项）；
- `check-native-closure`：PASS；`assert-resfile-sync`：27 件一致；
- 随包 libs 中 `libnode.so.137` 出现次数：**0**。

### 说明
这是上一轮“替换 libnode”遗漏的随包原生库依赖，不是 Node 26 本身的 ABI 问题。
重编 beta 后终端与图片链应恢复；若仍有异常，再按 §4 的 addon 项排查。
