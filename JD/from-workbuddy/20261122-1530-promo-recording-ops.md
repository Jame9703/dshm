## 1. 分工（硬约束）

| 角色 | 做什么 | 不做什么 |
|---|---|---|
| **用户** | 在设备控制中心点「屏幕录制」开始/结束；手动旋转平板；确认画面无隐私 | 不操作应用界面 |
| **DevEco** | 通过 `hdc shell` 执行 `aa start/force-stop`、`uitest uiInput click`、`dumpLayout`、等待/节奏控制 | **不录屏**、不改系统设置、不卸载应用 |

> 脚本每段开始前给出 3 秒倒计时提示，用户看到提示后点录制；脚本不依赖录屏状态。

## 3. 通用脚本能力（已验证）

| 动作 | 命令 |
|---|---|
| 冷启动 | `aa force-stop <bundle>` → `aa start -a EntryAbility -b <bundle>` |
| 点击坐标 | `uitest uiInput click <x> <y>` |
| 返回 | `uitest uiInput keyEvent Back` |
| 取 UI 树 | `uitest dumpLayout -p /data/local/tmp/ui.json` → `hdc file recv` |
| 截图（校验用） | `snapshot_display -f /data/local/tmp/chk.jpeg` |
| 等待 | 脚本内 `sleep`，不要用固定长时间盲等 |

**点击不写死坐标**：沿用 `tools/device-acceptance.ps1` 的 `Click-Text` 思路 ——
`dumpLayout` → 找 `attributes.text` 匹配节点 → 取 `bounds` 中心 → `click`。
坐标随分辨率/布局变化，写死必然换机失败。

**文本输入未验证**：`uitest uiInput inputText` 在本项目没有使用记录。**所有对话输入一律用预置内容**（预置会话、预置快捷提示），不依赖脚本注入长文本；若确需输入，先单独执行一次 `uitest uiInput inputText hello` 验证，失败则改用手动输入或预置脚本。

## 6. 失败与回退

| 现象 | 处理 |
|---|---|
| `Click-Text` 找不到目标 | 停止该段，`dumpLayout` 导出一份给 WorkBuddy 改文本匹配；不要盲点坐标 |
| `inputText` 不可用 | 放弃脚本输入，改用预置会话/预置提示，或用户手动输入 |
| 启动后未到首页 | 等 `dumpLayout` 出现会话/输入框再继续；超 60s 报错 |
| 旋转后布局未重排 | 等 2s 再 `dumpLayout`；必要时再等 2s |
| 设备断连 | `hdc list targets` 为空则终止，不要继续盲跑 |

## 7. 边界

- 不录屏、不修改系统设置、不卸载应用、不清用户数据；

- 演示数据只用 `dshm-demo`，不出现真实 token、用户名、客户代码。
