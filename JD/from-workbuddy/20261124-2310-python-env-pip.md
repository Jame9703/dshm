# JD-043 端侧 Python 环境「可 pip 安装、可直接运行」交付

- 提交方：WorkBuddy
- 接收方：DevEco
- 时间：2026-11-24 23:10
- 目标：用户在 DSHM 里 `git clone` 一个 Python 项目（如 ppt-master）后，`pip3 install -r requirements.txt` 能装、`python3` 能跑
- 边界：**不内置任何项目/技能**，只补运行环境

---

## 1. 背景

端侧随包 CPython 3.12.14（musl）此前只有标准库，用户无法安装第三方包：

- pip 默认平台标签是 `harmonyos_hongmeng_kernel_..._aarch64`，与 PyPI 的 `musllinux_1_2_aarch64` 对不上 ⇒ 只会去编 sdist，必然失败；
- 直连 pypi.org 在端侧超时；
- 装进来的 `.so/.node` 未签名会被 dlopen 拒绝；
- wheel 自带的 `*.libs` 目录（Pillow/numpy）不在默认搜索路径。

本次把这些全部在 `python3` / `pip3` 包装器里固化。

---

## 2. 改动清单

| 文件 | 改动 |
|---|---|
| `hostcore/app/main.js` | ① `python3` 包装器：`LD_LIBRARY_PATH=$P/lib`、`PYTHONPATH=$PY_SITE`、枚举 `$PY_SITE/*.libs` 与 `*/*.libs`；② `pip3` 包装器：镜像源、`--platform musllinux_1_2_aarch64 --python-version 3.12 --implementation cp --abi cp312 --only-binary=:all: --target "$PY_SITE"`、`constraints.txt`、安装后自动签名；③ Python 解包收尾把 `selfsign.js` 投放到 `$P/selfsign.js` |
| `hostruntime/src/main/resources/resfile/toolchain/python/selfsign.js` | 新增（自签名工具，随包） |
| `hostruntime/src/main/resources/resfile/toolchain/python/constraints.txt` | 新增，`Pillow==10.4.0` |
| `tools/check-python-env.mjs` | 新增门禁（14 项） |

### 关键环境变量（包装器内）

```sh
P=<python 前缀>                       # 解包后的 CPython
PY_SITE=${DSHM_SANDBOX_HOME:-$HOME}/py-site
export PYTHONHOME="$P"
export LD_LIBRARY_PATH="$P/lib:...:$(枚举 *.libs)"
export PYTHONPATH="$PY_SITE"
export PIP_INDEX_URL=${PIP_INDEX_URL:-https://mirrors.aliyun.com/pypi/simple/}
export PIP_TRUSTED_HOST=${PIP_TRUSTED_HOST:-mirrors.aliyun.com}
```

`pip3 install ...` 实际执行：

```sh
"$P/bin/python3.12" -m pip install \
  --platform musllinux_1_2_aarch64 --python-version 3.12 \
  --implementation cp --abi cp312 --only-binary=:all: \
  --target "$PY_SITE" --constraint "$P/constraints.txt" "$@"
# 成功后：find $PY_SITE -name '*.so' -o -name '*.so.*' -o -name '*.node' → selfsign.js --force
```

## 4. 必须保留的两条约束

1. **Pillow 锁 10.4.0**：13.x 的 musllinux 轮子自带 `libtiff-*.so`，与 `lxml/pptx` 同进程加载会报 `libtiff... not found`；10.4.0 实测共存。约束已写进 `constraints.txt`，不要删。
2. **pip 必须带 `--platform musllinux_1_2_aarch64` 等参数**：否则 pip 走 sdist，端侧没有编译环境。

## 9. 针对《DSHM-诊断报告-开发端-2026-11-24》D1 的逐条修复

报告把 D1 归因为「无本平台 wheel + 无编译器 + dlopen 策略」三重叠加。对应处理：

| 报告结论 | 实际处理 | 证据 |
|---|---|---|
| PyPI 没有 `harmonyos_*` 标签 wheel | pip 包装器显式 `--platform musllinux_1_2_aarch64 --abi cp312 --only-binary=:all:`，直接消费 musllinux 轮子 | `pip3 install lxml` 成功拉到 `lxml-6.1.3-cp312-musllinux_1_2_aarch64` |
| 无编译器，sdist 走不通 | `--only-binary=:all:` 强制只取轮子，绝不触发 sdist | 安装日志无 build 步骤 |
| 应用目录的 `.so` dlopen 被拒 | 安装后对 `*.so/*.so.*/*.node` 调 `selfsign.js` 补 `.codesign`；预设包内的 `.so` 在构建时已签名 | 签名后 `import lxml.etree` 通过；未签名时报 `Permission denied` |
| `libc.musl-aarch64.so.1` 不存在 | 本机实测可解析：lxml/numpy 的 NEEDED 就是该 soname，仍能加载 | `import numpy 2.5.5` 成功 |
| 需要端侧 wheel 源 | 默认走阿里云镜像，`PIP_INDEX_URL` 可覆盖；不依赖 pypi.org | 端侧实测下载 423 KB/s |
| 内置 site-packages | **新增手机预设包**（见 §10） | 13 MB 压缩，离线导入通过 |

> 说明：报告测试时用的是「手工 `pip install --no-deps` + 未签名」，所以卡在 lxml；按本 JD 的包装器口径安装会自动补依赖与签名。

## 10. 手机端环境预设（新增）

- 文件：`hostruntime/src/main/resources/resfile/toolchain/python/dshm-pysite.tar.gz`（**13 MB**）
- 内容（已签名）：`pptx 1.0.2`、`lxml 6.1.3`、`Pillow 10.4.0` + `pillow.libs`、`PyYAML`、`openpyxl 3.1.5`、`et_xmlfile`、`XlsxWriter`、`typing_extensions`
- 行为（`main.js` 的 `ensurePythonSitePreset()`）：
  1. 首次启动、`$DSHM_SANDBOX_HOME/py-site` **不存在或为空**时解包；
  2. 解包后写 `.dshm-preset.json` 标记；已有用户包则**跳过**，不覆盖；
  3. 失败只记日志，不影响 Python 本体。
- 验证：解包后 `import pptx,PIL,lxml.etree,yaml,openpyxl` → `preset ok 1.0.2 10.4.0`。
- 目的：手机端即使不能 exec / 不能 pip，也能直接跑 ppt-master 的 `svg_to_pptx.py`。
